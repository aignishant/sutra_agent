## 1 · 🎬 Where we are — the story so far

Sutra has grown honest about *data*: facts in state, files in artifacts, a window packed
with only what earns a place. But there is a second kind of honesty we've been carrying
since Day 3 without formalizing: honesty about **failure**. Our Day 2 `ask()` respects 429s
instead of hammering; our Day 4 unknown-ticket demo *says* "9999 doesn't exist" instead of
inventing a summary. Good instincts. No architecture.

Here is the question that turns instinct into architecture: **when a tool blows up, who
should know?** The knowledge base times out. The DB connection drops. A bug in your own
code raises `KeyError`. Three parties could hear about it: the *model* (as a message it can
reason about), the *runtime* (as an exception it can route to policy), or *nobody* (the
error caught, stringified, and quietly folded into the chat). The 1.x world was full of
option three — every tutorial's tools ended in `except Exception as e: return f"Error:
{e}"`. ADK 2.x took a position, and it's trap #4 on our list: **exceptions flow through
the runtime**, where plugins can retry, substitute, or escalate — visibly. Today we wire
that, and we watch what option three actually costs.

## 2 · 🎯 Today's mission

Tonight, a knowledge-base outage during triage produces exactly what it should: a logged,

## 3 · 📚 Concepts

### ADK-23 — Two kinds of trouble, three doors, one rule

**The smoke-detector story.** A hotel kitchen has a smoke detector. One night a pan smokes;
the alarm shrieks; the chef silences it *by taping over the sensor*. The kitchen is quiet
now. The kitchen is not *safe* now — the next fire will be discovered by guests, not
sensors. Everyone in the story behaved locally-reasonably: the alarm was loud, the tape was
handy. The system, though, now contains a lie.

`except Exception: return "Error: …"` is the tape. The exception was the alarm. The chat
transcript is the quiet kitchen.

To do better we need one distinction and one rule. The distinction — **two kinds of
trouble** (you met it on Day 3; today it gets teeth):

| Kind | Examples | Who should handle it | Right move in a tool |
| --- | --- | --- | --- |
| **Domain failure** — expected, part of the job | ticket not found; KB has no match; user lacks permission | the **model** — it can reason about it and tell the user | **return it as a result** (`{"status": "not_found", …}`) — this is *data*, not an error |
| **System failure** — unexpected, not part of the job | timeout; connection refused; `KeyError` in your code; auth expired | the **runtime** — retry/fallback/escalate is *policy*, not reasoning | **raise** (or don't catch) — let it surface |

And the rule: **errors travel up, policy lives in one place.** In ADK 2.x, an exception in
a tool doesn't die in the tool — the runtime catches it and offers it to your plugins:

```python
async def on_tool_error_callback(self, *, tool, tool_args, tool_context, error):
    ...              # log it, count it, decide
    return {...}     # dict  -> suppress; this becomes the tool's (fallback) result
    return None      # None  -> the exception raises on through, loudly
```

That return-value contract is the whole design in miniature. **Return a dict** and you've
chosen *graceful*: the model receives your fallback as the tool result (and can be honest
with the user about it); the run continues; `after_tool` fires as normal. **Return `None`**
and you've chosen *loud*: the exception propagates, the run fails visibly, and whatever
called Sutra learns the truth. Both are legitimate. What's not legitimate is the third
door — the tape — where neither runtime nor model nor human knows anything went wrong.

💡 **Mental model: an exception is a message to the *system*; a tool result is a message to
the *model*. Swallowing an exception delivers it to *no one*.**

Why one plugin beats a hundred `try/except`s: the decisions that matter — retry how many
times? fall back to what? page whom? — are *policies*. Policies change, and they must
change everywhere at once. A plugin is the one place; per-tool `try/except` is a hundred
places, each drifting separately. (Day 14 said "cross-cutting = plugin"; errors are the
most cross-cutting concern there is. Day 72 upgrades this plugin with real backoff; the
socket we build today is where it plugs in.)

### SEC-02 — Honest failure as a safety property

Move the same idea from engineering to safety, because it grows fangs there. An agent
*acts*. Later phases give Sutra tools that write — close tickets, post replies, trigger
jobs. Now replay the taped alarm with actions attached: the KB lookup fails, the tape turns
it into quiet, the model — seeing calm data — closes ticket #4521 as "resolved per KB
article." The customer is still locked out. The audit log shows a normal, confident run.
**The fabricated calm became a fabricated action.**

That is why "fail honestly" is Principle 10 and not just taste:

1. **Errors surface** — to the runtime, to logs (tomorrow's Day 22 makes them structured),
   and to the *user* in honest language ("I couldn't reach the knowledge base") rather
   than fabricated success.
2. **Errors escalate** — repeated or critical failures reach a human; Phase 9 builds the
   machinery, today's plugin is where the counter lives.
3. **Errors are recorded** — an untracked failure is a failure that will be repeated
   (Principle 12: everything is a trace).

The uncomfortable, load-bearing corollary: **a fallback must never impersonate a
success.** `{"status": "kb_unavailable"}` is a fallback. `{"result": "No known issues"}`
is a forgery. Same mechanism, opposite safety properties — the difference is only in what
you wrote in the dict.

```python
"""Day 21 — error handling: surface, don't swallow (trap #4).

One knowledge base, three doors for the same outage:
  swallowed  — the 1.x anti-pattern: tool returns an error STRING (the tape)
  surfaced   — the tool raises; the runtime fails loudly (honest, blunt)
  safetynet  — a plugin catches the surfaced error and applies POLICY:
               log it, hand the model an honest fallback, never invent

    python -m sutra.errors swallowed
    python -m sutra.errors surfaced
    python -m sutra.errors safetynet
"""
from __future__ import annotations

import asyncio
import sys

from google.adk.agents import Agent
from google.adk.plugins import BasePlugin            # Day 14's base class
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

from sutra.config import load_env

APP = "sutra"
KB_IS_DOWN = True                                    # today's weather: outage


def search_kb_swallowed(query: str) -> dict:
    """The 1.x anti-pattern — DO NOT copy this shape after today.

    Catches its own failure and returns it as a quiet string. The runtime
    sees a SUCCESSFUL tool call; the model sees calm-looking data.

    Args:
        query: symptom keywords.

    Returns:
        Either a real result or — the tape — an apologetic string in a
        success-shaped envelope.
    """
    try:
        if KB_IS_DOWN:                               # simulate the outage
            raise ConnectionError("kb.internal:5432 timed out")
        return {"result": "KB-104: SameSite/https cookie change."}
    except Exception as e:                           # ← the tape goes on
        return {"result": f"(kb note: {e})"}         # error dressed as data


def search_kb_honest(query: str) -> dict:
    """The 2.x shape: domain failures are DATA, system failures RAISE.

    Args:
        query: symptom keywords.

    Returns:
        A real result, or a not_found DATA result for domain misses.

    Raises:
        ConnectionError: when the KB backend is unreachable (system
            failure — the runtime's business, not the model's).
    """
    if KB_IS_DOWN:
        raise ConnectionError("kb.internal:5432 timed out")   # no tape. Let it fly.
    if not query.strip():                            # a DOMAIN miss, by contrast:
        return {"status": "not_found", "query": query}        # data, not exception
    return {"result": "KB-104: SameSite/https cookie change."}


class SafetyNetPlugin(BasePlugin):
    """Error POLICY in one place: log, count, hand back an HONEST fallback.

    Example:
        Runner(..., plugins=[SafetyNetPlugin(name="safety_net")])
        On a tool exception the model receives
        {"status": "tool_unavailable", ...} — a fallback that admits
        being one. Returning None here instead would re-raise (loud mode).
    """

    def __init__(self, name: str = "safety_net") -> None:
        super().__init__(name=name)
        self.error_count = 0                         # Day 72 turns this into backoff

    async def on_tool_error_callback(self, *, tool, tool_args, tool_context, error):
        """Runtime hands us the failure; we decide the door.

        Returns:
            dict — suppress the exception; this dict IS the tool result.
            (Return None to choose the loud door instead.)
        """
        self.error_count += 1                        # errors are counted (SEC-02)
        print(f"[safety_net] tool={tool.name} error #{self.error_count}: {error!r}")
        return {                                     # honest fallback — admits itself:
            "status": "tool_unavailable",
            "tool": tool.name,
            "detail": str(error),
            "advice": ("Tell the user plainly that the knowledge base is "
                       "unreachable right now. Do NOT guess its contents."),
        }


def _agent(tool) -> Agent:
    """One lab agent around whichever KB variant a demo needs."""
    return Agent(
        name="sutra_errors_lab",
        model="gemini-3.5-flash",                    # pinned (ADK-73)
        description="Triage lab agent for error-handling demos.",
        instruction=("Use search_kb to check symptoms. Report what you find "
                     "in one sentence. If the KB cannot be reached, say so "
                     "honestly — never invent article contents."),
        tools=[tool],
    )


def _run(agent: Agent, plugins: list | None = None) -> None:
    """Wire runner+session, ask the standing outage question, print the end."""
    service = InMemorySessionService()
    runner = Runner(agent=agent, app_name=APP, session_service=service,
                    plugins=plugins or [])
    asyncio.run(service.create_session(app_name=APP, user_id="priya",
                                       session_id="s1"))
    message = types.Content(role="user", parts=[types.Part(
        text="Users keep getting logged out (ticket 4521). Check the KB.")])

    async def go() -> None:
        async for event in runner.run_async(user_id="priya", session_id="s1",
                                            new_message=message):
            if event.is_final_response() and event.content:
                print("reply:", event.content.parts[0].text.strip())

    asyncio.run(go())


def demo_swallowed() -> None:
    """Door 3, once, on purpose: the outage nobody hears about."""
    _run(_agent(search_kb_swallowed))


def demo_surfaced() -> None:
    """Door 2: the tool raises and NOTHING catches — expect a traceback."""
    _run(_agent(search_kb_honest))                   # no plugin: loud by design


def demo_safetynet() -> None:
    """Door 1: same raise, but policy answers — honest reply, logged error."""
    _run(_agent(search_kb_honest), plugins=[SafetyNetPlugin()])


def main() -> None:
    """Demo dispatcher — house pattern."""
    demos = {"swallowed": demo_swallowed, "surfaced": demo_surfaced,
             "safetynet": demo_safetynet}
    name = sys.argv[1] if len(sys.argv) > 1 else "safetynet"
    if name not in demos:
        print(f"usage: python -m sutra.errors [{'|'.join(demos)}]")
        raise SystemExit(2)
    load_env()
    demos[name]()


if __name__ == "__main__":
    main()
```

## 6 · 🎤 Interview corner

1. **"How do you handle tool errors in an agent system?"** — First by routing, not
   catching: expected domain failures ("not found") return as structured tool results the
   model can reason about; unexpected system failures raise and surface through the
   runtime, where a single plugin applies policy — log, count, then either an honest
   fallback dict (suppress-and-continue) or `None` to fail loudly. What I never do is the
   tutorial classic — `except Exception: return f"Error: {e}"` — because it delivers the
   failure to no one: not the runtime, and only nominally the model. I've run the same KB
   outage through all three doors and can describe each transcript.
2. **"Why is error honesty a *safety* issue rather than a code-quality issue?"** — Because
   agents act. A swallowed lookup failure becomes fabricated calm becomes a wrong *write* —
   my worked example is a desk closing tickets "per KB guidance" during a KB outage. So:
   fallbacks must admit being fallbacks, failures must be counted and escalatable, and the
   difference between a fallback and a forgery is literally the payload — `"status":
   "kb_unavailable"` versus invented content.
3. **"Where does retry logic belong?"** — In the policy layer, once — not scattered through
   tools. The plugin hook that sees every tool exception is where retry-with-backoff,
   fallback selection, and escalation thresholds live; tools stay simple and honest.
   (In our stack that's the Day 21 safety-net, which Day 72 upgrades to real
   `retry-after`-respecting backoff — same socket, richer policy.)
