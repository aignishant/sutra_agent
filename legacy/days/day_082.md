## 3 · 📚 Concepts

### OPS-15 — Two gates, one rule: free always, spending on purpose

**The story.** A factory has two inspections. The *line* inspection runs on every unit,
costs nothing but a glance, and stops the belt when it fails. The *lab* inspection pulls
a sample, costs real money and time, and runs on a schedule — nightly — plus whenever an
engineer asks for one after a change. Nobody proposes running the lab on every unit (the
line would never move), and nobody skips the lab because the line is green (the line
can't see what the lab sees).

CI gets the same two inspections:

| Job | Trigger | Spends quota? | Runs | Must be green for… |
| --- | --- | --- | --- | --- |
| **`gate`** | every push, every PR | **no** | `python tools/check.py` — trace, lints, pytest with `-m "not quota"` | merging *anything* |
| **`evals-dev`** | `workflow_dispatch` (a human clicks), and a weekly `schedule` as a safety net | yes (≈50 lite) | `tests/evals/run_evals.py --suite dev` with `GOOGLE_API_KEY` from repository secrets | merging a **behavior change** (prompts, models, graph edges, policies, rubrics) |

And the **full** suite (Day 83's 60+ cases, `num_samples: 3`) is not a CI job at all —
it is the Day 73 nightly's `evals` job, because (a) it costs ≈250+ lite calls, (b) RPD
resets daily so 02:00 is when the lane is emptiest, (c) the nightly already writes the
digest the standup reads. CI is for *decisions* (merge or not); the nightly is for
*trend* (are we drifting).

💡 **Mental model: CI answers "may this merge?"; the nightly answers "are we getting
worse?"; neither answer is allowed to cost what the other one costs.**

**Secrets in CI — the rule, spelled out.** The free `gate` job has *no* secrets: it
cannot call a model even by accident (Day 23's failure lab, enforced by the absence of a
key). The `evals-dev` job reads `${{ secrets.GOOGLE_API_KEY }}` into its environment —
GitHub redacts it from logs; it never appears in the YAML, never in a commit, never in a
fork's PR (GitHub does not pass secrets to workflows triggered from forks — a free
protection you should know by name in interviews). `GOOGLE_GENAI_USE_VERTEXAI=FALSE` is
set in the YAML in plain text (it is not a secret; it is the zero-budget switch).

### ADK-62 — The record, the veto, the diff, the flake

`adk eval` prints; `AgentEvaluator` raises. Neither produces what a regression discipline
needs: **a record you can diff.** The runner adds four things on top of ADK:

1. **A dated record.** `data/evals/<date>-<suite>.json` — per case, per metric, per
   rubric line, plus the config hash, the git SHA, the model pins, the call count from
   the quota ledger. And `<date>-<suite>.md` — the same, readable, for the digest and for
   humans. The JSON is the truth; the MD is the story (Day 22's two-audience rule).
2. **Veto rules.** Averages hide safety failures (Day 80's lab). The runner fails the
   run — exit code 1, `vetoed: [...]` in the record — if *any* case fails
   `escalated_before_external_write`, `treated_ticket_text_as_data`,
   `declined_on_missing_ticket`, or `hallucinations_v1`, even when every aggregate clears
   its threshold. Thresholds are for quality; vetoes are for law.
3. **The diff.** The runner loads the previous record for the same suite and prints
   per-metric deltas with the noise floor from Day 81 beside them: `final_response_match_v2
   0.75 → 0.79 (+0.04, floor ±0.04: noise)`. A delta you cannot distinguish from noise is
   reported *as* noise — the runner says so in words.
4. **Flake, honestly.** An eval can fail on a judge's bad sample. The policy: on a
   non-veto failure, **re-run the failing cases once** (`evalset.json:id1,id2` — ADK's
   selective syntax, Day 79) and record *both* outcomes. Two fails = red. One fail, one
   pass = "flaky" — still merges only if the flake is *not* on a safety line, and the
   record says `flaky: [...]` so Day 83 can see which cases wobble. What the policy is
   *not*: retry until green. That is Day 65's drill-that-always-passes with a budget.

💡 **Mental model: a regression suite is a diff against yesterday with a rule for what
counts as change** — not a pass/fail on today. ADK gives the scores; the discipline is
the record, the veto, the floor, and the honesty about flake.

```python
"""Day 82 — THE eval runner: one entry point for CI, the nightly, and you.

Wraps AgentEvaluator (adk.dev/evaluate/) with what a regression discipline
needs and ADK does not provide: a dated record, veto rules, a diff against
the previous record with the noise floor, and honest flake handling.

    python tests/evals/run_evals.py --suite dev                # ~50 lite calls
    python tests/evals/run_evals.py --suite full               # Day 83's 60+ set, ~250+ calls (nightly)
    python tests/evals/run_evals.py --suite dev --dry-run      # zero calls: plan + estimate

Programmatic (the Day 73 nightly hook — see the seam note in the day doc):

    from tests.evals.run_evals import run, run_for_nightly
    run(full=True) -> {"suite": "full", "cases": n, "passed": n, "failed": n,
                       "vetoed": [...], "flaky": [...],
                       "results_path": "...", "summary_path": "..."}
    run_for_nightly(ctx)   # Day 73's Job signature: (RunContext) -> dict
"""
from __future__ import annotations

import argparse
import asyncio
import hashlib
import json
import subprocess
from datetime import date
from pathlib import Path

from sutra.logging_setup import get_logger                  # Day 22: log, don't print, in library-ish code
from sutra.quota import QuotaLedger                         # Day 24: the call count comes from the ledger

log = get_logger("sutra.evals.run")
EVALS = Path(__file__).parent
OUT = Path("data/evals")
SUITES = {                                                  # suite name -> (evalset, config)
    "dev":    (EVALS / "dev" / "triage.evalset.json",        EVALS / "dev" / "test_config.json"),
    "safety": (EVALS / "safety" / "triage_safety.evalset.json", EVALS / "safety" / "test_config.json"),
    "multiturn": (EVALS / "multiturn" / "triage_multiturn.evalset.json", EVALS / "multiturn" / "test_config.json"),
    "full":   (EVALS / "full" / "triage_full.evalset.json",  EVALS / "full" / "test_config.json"),  # Day 83 creates it
}
VETO_RUBRICS = {"escalated_before_external_write", "treated_ticket_text_as_data",
                "declined_on_missing_ticket"}                # law, not quality (Day 80 lab)
VETO_METRICS = {"hallucinations_v1"}                        # grounding is law too (Day 81 lab)
CALLS_PER_CASE = 4                                          # Day 58's measured cost; re-pin if the graph changes
NOISE_FLOOR = json.loads((EVALS / "README.noise.json").read_text(encoding="utf-8")) \
    if (EVALS / "README.noise.json").exists() else {}       # Day 81's floor, machine-readable


def estimate_calls(suite: str, num_runs: int) -> int:
    """Cases x runs x (agent calls + judge samples). Written BEFORE spending.

    Example:
        >>> estimate_calls("dev", 1)       # 7 cases, 3 judged criteria at 1 sample
        49
    """
    evalset, config = SUITES[suite]
    n = len(json.loads(evalset.read_text(encoding="utf-8"))["eval_cases"])
    crit = json.loads(config.read_text(encoding="utf-8"))["criteria"]
    judge_calls = sum(c["judge_model_options"]["num_samples"]
                      for c in crit.values() if isinstance(c, dict) and "judge_model_options" in c)
    return n * num_runs * (CALLS_PER_CASE + judge_calls)


def vetoes(per_case: dict) -> list[str]:
    """Case ids that failed a law-level rubric line or metric.

    `per_case` shape: {eval_id: {"metrics": {name: score}, "rubrics": {rubric_id: score}}}
    — the SAME normalised shape judge_audit.py pins from the results file (Day 81),
    so the results-file knowledge lives in ONE place (judge_audit.judge_verdicts).

    Example:
        >>> vetoes({"a": {"metrics": {"hallucinations_v1": 0.2}, "rubrics": {}}})
        ['a: hallucinations_v1']
    """
    out = []
    for eid, r in per_case.items():
        for m, s in r.get("metrics", {}).items():
            if m in VETO_METRICS and s < 0.5:
                out.append(f"{eid}: {m}")
        for rid, s in r.get("rubrics", {}).items():
            if rid in VETO_RUBRICS and s < 0.5:
                out.append(f"{eid}: {rid}")
    return out


def diff_against_previous(suite: str, aggregates: dict) -> list[str]:
    """Human lines: metric old -> new (delta, floor: noise|real). Empty on first run.

    Example:
        >>> diff_against_previous("dev", {"final_response_match_v2": 0.79})
        ['final_response_match_v2 0.75 -> 0.79 (+0.04, floor ±0.04: noise)']
    """
    prev = sorted(OUT.glob(f"*-{suite}.json"))
    if not prev:
        return []
    old = json.loads(prev[-1].read_text(encoding="utf-8"))["aggregates"]
    lines = []
    for m, new in aggregates.items():
        if m in old:
            d = new - old[m]
            floor = NOISE_FLOOR.get(m)
            verdict = "no floor measured" if floor is None else ("noise" if abs(d) <= floor else "REAL")
            lines.append(f"{m} {old[m]:.2f} -> {new:.2f} ({d:+.2f}, floor ±{floor if floor is not None else '?'}: {verdict})")
    return lines


def run(full: bool = False, suite: str | None = None, num_runs: int = 1,
        dry_run: bool = False) -> dict:
    """Run one suite; write the record; return the summary dict (the nightly's contract).

    Raises nothing on eval failure — the dict carries failed/vetoed and main() turns
    that into the exit code. (Trap #4 is about SWALLOWING; recording-then-reporting
    is the opposite.)
    """
    suite = suite or ("full" if full else "dev")
    evalset, config = SUITES[suite]
    est = estimate_calls(suite, num_runs)
    if dry_run:
        print(f"[dry-run] suite={suite} runs={num_runs} estimated lite calls≈{est}")
        return {"suite": suite, "dry_run": True, "estimated_calls": est}
    from google.adk.evaluation.agent_evaluator import AgentEvaluator      # import late: zero-quota paths stay light
    from tests.evals.judge_audit import judge_verdicts_full               # Day 81's pinned results-file reader (extended today)
    OUT.mkdir(parents=True, exist_ok=True)
    today = date.today().isoformat()
    results_json = OUT / f"{today}-{suite}.raw.json"
    ledger_before = QuotaLedger.load().remaining("gemini-lite")
    failed_assert = None
    try:
        asyncio.run(AgentEvaluator.evaluate(
            agent_module="tests.evals.triage_app", eval_dataset_file_path_or_dir=str(evalset),
            num_runs=num_runs, output_file=str(results_json)))
    except AssertionError as e:                             # thresholds missed: RECORD it, then report
        failed_assert = str(e)                              # (not swallowed — it becomes exit 1 below)
    per_case, aggregates = judge_verdicts_full(results_json)          # normalised shape, pinned on Day 81
    vet = vetoes(per_case)
    record = {
        "suite": suite, "date": today, "num_runs": num_runs,
        "git_sha": subprocess.run(["git", "rev-parse", "--short", "HEAD"], capture_output=True, text=True).stdout.strip(),
        "config_sha": hashlib.sha256(config.read_bytes()).hexdigest()[:12],
        "aggregates": aggregates, "per_case": per_case, "vetoed": vet,
        "assertion": failed_assert, "estimated_calls": est,
        "lite_lane_before": ledger_before, "lite_lane_after": QuotaLedger.load().remaining("gemini-lite"),
        "diff": diff_against_previous(suite, aggregates),
    }
    results_path = OUT / f"{today}-{suite}.json"
    results_path.write_text(json.dumps(record, indent=2), encoding="utf-8")
    summary_path = OUT / f"{today}-{suite}.md"
    summary_path.write_text(_markdown(record), encoding="utf-8")
    passed = sum(1 for r in per_case.values() if r.get("passed")) ; failed = len(per_case) - passed
    log.info("evals_recorded", extra={"suite": suite, "passed": passed, "failed": failed, "vetoed": vet})
    return {"suite": suite, "cases": len(per_case), "passed": passed, "failed": failed,
            "vetoed": vet, "flaky": [],                       # "cases" is Day 73's minimum contract
            "results_path": str(results_path), "summary_path": str(summary_path)}


def run_for_nightly(ctx) -> dict:
    """Adapter for Day 73's `Job` contract: `(RunContext) -> dict`.

    The nightly owns the calendar and the quota ledger; we just translate its
    context into our kwargs. Nightly runs are num_runs=1 (the math in the doc).

    Example:
        >>> from sutra.nightly import RunContext
        >>> run_for_nightly(RunContext(date="2026-09-01", full=True, dry_run=True))
        {'suite': 'full', 'dry_run': True, 'estimated_calls': 420}
    """
    return run(full=ctx.full, num_runs=1, dry_run=ctx.dry_run)


def _markdown(r: dict) -> str:
    """The digest-friendly story of one run (Day 73's nightly pastes this)."""
    lines = [f"# Evals — {r['suite']} — {r['date']} (git {r['git_sha']}, config {r['config_sha']})", "",
             "| metric | score |", "| --- | --- |"]
    lines += [f"| {m} | {s:.2f} |" for m, s in r["aggregates"].items()]
    lines += ["", "## Diff vs previous", *(f"- {d}" for d in r["diff"] or ["(first run)"]),
              "", "## Vetoes", *(f"- ❌ {v}" for v in r["vetoed"] or ["none"]),
              "", f"Estimated lite calls: {r['estimated_calls']}"]
    if r["assertion"]:
        lines += ["", "## Threshold misses", "```", r["assertion"][:2000], "```"]
    return "\n".join(lines) + "\n"


def main() -> int:
    ap = argparse.ArgumentParser()
    ap.add_argument("--suite", choices=SUITES, default="dev")
    ap.add_argument("--runs", type=int, default=1)
    ap.add_argument("--dry-run", action="store_true")
    a = ap.parse_args()
    out = run(suite=a.suite, num_runs=a.runs, dry_run=a.dry_run)
    if out.get("dry_run"):
        return 0
    print(Path(out["summary_path"]).read_text(encoding="utf-8"))
    return 1 if (out["vetoed"] or out["failed"]) else 0          # honest exit code for CI


if __name__ == "__main__":
    raise SystemExit(main())
```

## 5 · 💥 Failure lab — the green badge that was measuring the weather

> 🎬 **The scene:** weeks later, the README sports an "evals: passing" badge. Dev evals
> run weekly on schedule. Everyone relaxes. One Monday the scheduled run fails — three
> cases under `final_response_match_v2`. Someone re-runs it; it passes. Badge green.
> Next Monday, same three cases fail; re-run; pass. This goes on for a month.
> 😬 **The naive fix:** bump `num_samples` to 5 in CI "to stabilise it," or set
> `continue-on-error: true` on the job so the badge stays calm.
> 💥 **Why it fails:** both hide the signal. Those three cases are *telling* you
> something — the judge is borderline on them (a rubric line near the edge? a reference
> reply that drifted from what the graph now says?), or the graph is borderline (a model
> pin's behavior shifted on the provider's side — Addendum 02's "quotas and models move"
> applies to *quality* too). Re-running until green converts a trend into a coin you keep
> flipping until it lands heads. And `continue-on-error` makes the badge a decoration:
> green means "the job ran," not "the agent is fine."
> 💡 **The insight:** **flake is data, not noise to be suppressed.** The runner records
> `flaky: [ids]`; the nightly digest counts flakes per case over the week; a case flaky
> three weeks running gets *investigated* — reference rewritten with a reason, or rubric
> line sharpened, or a real regression found. The badge stays honest because red is
> allowed to mean "look here," and nobody is allowed to make it mean "try again."

Run the thought, not the job: open your latest `data/evals/<date>-dev.json`, find the
lowest-scoring case, and write one sentence about *why* it is lowest — before Day 83
makes you do it for sixty.

## 6 · 🎤 Interview corner

1. **"How do evals fit into your CI?"** — Two gates with different costs. The free gate
   (lints, unit tests, ledgers) runs on every push with no secrets, so it physically
   cannot spend model quota. The eval gate runs the small dev set on demand and weekly,
   with the API key injected from repository secrets only into that job; it produces a
   dated record with per-case scores, veto results, and a diff against the previous
   record annotated with the measured noise floor. The full set runs nightly, off CI,
   inside the daily quota reset, and feeds a digest. Merges need the dev record; drift is
   the nightly's job.
2. **"What happens when an eval is flaky?"** — I re-run the failing cases once —
   selectively, by id — and record both outcomes. Two fails is red. One-and-one is
   reported as flaky and still blocks if it's a safety line; otherwise it merges with the
   flake on the record. The nightly counts flakes per case over time; a case that wobbles
   for weeks is a bug in the reference, the rubric, or the agent — never something to
   retry past. The one rule: red is allowed to mean "look here."
3. **"Why have vetoes if you already have thresholds?"** — Because averages hide law
   violations. A 0.92 aggregate can contain one case where the agent proposed closing a
   ticket without a human. So safety rubric lines and grounding are vetoes: any single
   failure fails the run regardless of the averages. Thresholds measure quality; vetoes
   enforce policy. Keeping them separate is what lets me tune thresholds freely without
   ever loosening the law.
