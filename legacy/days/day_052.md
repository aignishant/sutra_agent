## 3 · 📚 Concepts

### AG-15 — Composition: the memory loop closes

**The new-hire story, one last time.** A new support hire is useless in week one — not
for lack of intelligence, but for lack of *history*. What turns them senior is a loop
that runs for years: **face a case → recall similar ones → apply the precedent → file
what you learned.** Remove any arc of that loop and seniority never accumulates: no
recall and every case is day one; no filing and every lesson evaporates at 5 p.m.

Every arc of that loop is now a verified component in this repo:

| The senior engineer | Sutra's component | Built on day |
| --- | --- | --- |
| hears the symptom | the researcher agent (instruction + honesty rules) | today |
| "this smells familiar" | `load_memory` → `SutraArchiveMemoryService` → cosine top-k with threshold | 46, 49, 50 |
| pulls the file, cites the fix | snippets with refs + scores land in context; answer cites KB-104 | 49 |
| files what was learned | `after_agent_callback` → `add_session_to_memory` → Day 48's policy gate | 46, 48 |
| doesn't redo finished thinking | response cache; ledger counts the saved calls | 51 |
| remembers across restarts | `DatabaseSessionService` under it all | 47 |

Notice what today does **not** add: capability. Zero new APIs, zero new concepts — only
*wiring*. That's deliberate, and it is the real lesson of a gate day: 💡 **a system is
not a pile of verified parts; it is verified parts + verified seams.** Every incident
postmortem you'll ever read lives in a seam ("each service was healthy, but…"). So the
gate tests the seams: does retrieval *reach* the agent? does filing *actually* pass the
gate? does the cache key *include* the memory-laden context?

One seam deserves its own paragraph, because Phase 8 stands on it. The researcher built
today is **a node-shaped agent**: one clear job (gather evidence about a ticket), tools
scoped to that job (memory + archive, *no write tools* — least privilege, Day 40's
philosophy), and its findings expressed in its final text rather than in side effects.
When the Workflow Runtime arrives on Day 53, this agent slots into the graph unchanged.
Today's composition is tomorrow's component.

## 4 · 🛠️ Build

> Shell: **PowerShell**, venv active, repo root, Ollama running.

**Step 1 — `sutra/researcher.py`.**

```python
"""Day 52 — the researcher: memory wired into the triage flow (Phase 7 gate).

Composes the phase: retrieval-backed memory (Day 49) + load_memory
(Day 46) + policy-gated auto-filing (Days 46/48) + the response cache
(Day 51). One agent, one loop: recall -> apply -> file.

    python -m sutra.researcher precedent   # the headline question (~4 calls)
    python -m sutra.researcher replay      # same question, cache pays (~0 calls)
"""
from __future__ import annotations

import asyncio
import sys

from google.adk.agents.llm_agent import Agent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.adk.tools import load_memory
from google.genai import types

from sutra.cache import after_model_cache, before_model_cache   # Day 51
from sutra.config import load_env
from sutra.logging_setup import get_logger
from sutra.retrieval import SutraArchiveMemoryService           # Day 49

log = get_logger(__name__)

APP = "sutra_researcher"
USER = "agent_riya"
PRIMARY_MODEL = "gemini-3.5-flash"                              # pinned (ADK-73)

# The gate question: a FRESH ticket, worded like neither 4521 nor 4610.
GATE_QUESTION = (
    "New ticket 488 just arrived: 'after clicking a link from the billing "
    "email, the user lands back on the sign-in screen, over and over.' "
    "Have we seen anything like this before? Cite past cases and the fix."
)


async def _auto_file(callback_context) -> None:
    """After the agent finishes: file the session through the policy gate.

    The closing arc of the seniority loop — Day 46's verified idiom;
    the service routes it through Day 48's keepers() bouncer.
    """
    await callback_context.add_session_to_memory()              # gate does the judging
    log.info("session_filed_via_policy_gate")


def make_researcher() -> Agent:
    """The node-shaped evidence-gatherer Phase 8 will adopt.

    Scope discipline (Day 40, pointed inward): memory tools only —
    NO write tools; findings are text, not side effects.

    Example:
        >>> make_researcher().name
        'sutra_researcher'
    """
    return Agent(
        name="sutra_researcher",
        model=PRIMARY_MODEL,
        instruction=(
            "You are Sutra's researcher. Your job is EVIDENCE about the ticket "
            "in front of you. Search memory for similar past cases before "
            "answering. Results arrive with [ref sim=score] tags: treat "
            "below-threshold results as NOTHING FOUND and say so plainly — "
            "never present a weak neighbor as a precedent. When real "
            "precedents exist, cite their refs and the fix they used. "
            "State findings; do not take actions."
        ),
        tools=[load_memory],                                    # recall arc
        before_model_callback=before_model_cache,               # don't redo thinking
        after_model_callback=after_model_cache,
        after_agent_callback=_auto_file,                        # filing arc
    )


async def _ask(question: str) -> None:
    """One researcher turn with full narration of the memory seam."""
    sessions = InMemorySessionService()                         # session layer is
    runner = Runner(                                            # swappable (Day 47) —
        agent=make_researcher(), app_name=APP,                  # in-memory is fine for
        session_service=sessions,                               # a single gate demo
        memory_service=SutraArchiveMemoryService(),             # the meaning cabinet
    )
    sess = await sessions.create_session(app_name=APP, user_id=USER)
    msg = types.Content(role="user", parts=[types.Part(text=question)])
    async for event in runner.run_async(user_id=USER, session_id=sess.id,
                                        new_message=msg):
        for call in event.get_function_calls():
            print(f"  TOOL CALL: {call.name}({call.args})")     # the recall arc, visible
        if event.is_final_response() and event.content and event.content.parts:
            print("\nRESEARCHER:",
                  "".join(p.text or "" for p in event.content.parts))


def main() -> None:
    load_env()
    cmd = sys.argv[1] if len(sys.argv) > 1 else "precedent"
    if cmd in ("precedent", "replay"):                          # replay = same question;
        asyncio.run(_ask(GATE_QUESTION))                        # the cache makes it free
    else:
        print("usage: python -m sutra.researcher [precedent|replay]")
        raise SystemExit(2)


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the seam that wasn't there

> 🎬 **The scene:** composing today's agent, an alternate-universe you makes one tiny
> "simplification": the memory service is constructed but — in a refactor shuffle —
> `memory_service=` never gets passed to the Runner. Everything imports. The agent
> runs. It even *answers* the gate question — fluently, plausibly, citing "similar past
> login issues we've handled."
> 😬 **The naive fix:** ship it; the answer *sounded* right, and the demo is green if
> you only read the last line.
> 💥 **Why it fails:** with no memory service behind it, `load_memory` has nothing to
> search — depending on wiring, the tool errors, returns empty, or is silently absent;
> the model, asked for precedents it cannot see, does what models do under pressure:
> **it improvises history.** No crash. No red text. The failure is only visible in
> what's *missing* — the `TOOL CALL:` line, the `[ref sim=…]` tags in the answer, the
> filing log entry. A composition bug wears success's clothes.
> 💡 **The insight:** **verify seams by their traces, not their vibes.** Today's
> checklist demands the tool-call line, the ref-tagged citations, and the filing log —
> three observable artifacts, one per seam (Principle 12: if it isn't observable, it
> didn't happen). A gate that only reads the final answer would have passed the broken
> desk. Try it once, deliberately: comment out `memory_service=…`, re-run `precedent`,
> and watch how *good* the fabricated answer sounds. Then put the line back and respect
> checklists forever.

## 6 · 🎤 Interview corner

1. **"Walk me through your agent's memory architecture."** — Three lifetimes, each with
   its own store and rules: working memory is the context window plus session state
   (database-backed, survives restarts); episodic memory is a MemoryService behind a
   write-time curation gate — distill to findings, redact PII, default-deny; semantic
   memory is the ticket archive with a local embedding index, searched by cosine with
   a measured threshold. The agent touches all three through two standard seams — a
   `load_memory` tool for recall and an end-of-session callback for filing — so every
   layer is swappable behind its interface. I proved the swap twice: RAM→SQLite for
   sessions, keywords→vectors for search, zero agent changes either time.
2. **"How do you verify an integration, as opposed to its components?"** — By demanding
   a visible trace per seam, because integration failures are silent by nature — my
   nastiest demo is deleting one `memory_service=` argument: the agent still answers,
   just with fabricated precedents. So the gate checklist requires the tool-call event
   (retrieval reached the agent), ref-tagged citations in the answer (retrieved data
   reached the response), and the policy-verdict log line (filing passed the gate).
   Components get unit tests; seams get observable artifacts.
3. **"What made 'seen anything like this before?' cost zero dollars?"** — Splitting the
   expensive-looking part from the actually-expensive part. Similarity search is local:
   an open embedding model on Ollama, vectors in a JSON index, cosine in three lines —
   unlimited and offline. The only metered resource is the LLM turn that *reads* the
   evidence — free-tier Gemini at 5 RPM — so I wrapped it in a keyed, TTL'd response
   cache with saved-calls counted in a quota ledger. Repeat questions cost nothing;
   the rate limit forced an architecture that a paid tier would have let me skip.
