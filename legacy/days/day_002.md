## 3 · 📚 Concepts

### AG-02 — LLM mechanics: tokens, context, sampling

**The consultant with amnesia.** Imagine the world's most brilliant consultant — someone who
has read almost everything ever written. There are just three unusual things about them:

1. They charge **per word-chunk** — for every chunk you say to them AND every chunk they say
   back (tokens).
2. They have **total amnesia** — the moment a meeting ends, they forget you ever existed. If
   you want them to "remember" last week, you must bring the meeting notes and make them
   re-read everything (context & statelessness).
3. Before answering, they quietly **roll weighted dice** to pick between good phrasings — and
   you can adjust how wild those dice are (sampling).

An LLM API call is one meeting with this consultant. Every agent framework in existence is
just clever office staff arranged around them. Let's meet each quirk properly.

#### a) Tokens — the meter

Models don't read words; they read **tokens** — subword chunks, roughly 4 characters of
English each. The word "Unbelievable" might be read as three Lego bricks: `un · believ ·
able`. Every quota row, every context limit, and every latency figure is counted in tokens —
which is why Addendum 02 calls quota "the currency": on a free tier, tokens-per-minute *is*
your budget line.

*Example with real arithmetic:* ticket #4521's body ("I keep getting logged out…", ~200
words) is roughly 260 tokens. Send it to a classifier 100 times a day and you've spent ~26K
input tokens on intake alone — before a single answer token is generated. That arithmetic,
not vibes, is how Day 24's budgets and Day 70's Quota-Router will make decisions.

You get two ways to see token counts today:

- `count_tokens` **before** a call — "how big is this prompt?"
- the response's **usage metadata** after — "what did I actually pay?"

And here hides today's biggest surprise: `gemini-3.5-flash` **thinks before it answers, by
default**, and its hidden reasoning is metered as output too. Observed today: a 12-token
prompt was billed **331 thought tokens** against 35 visible ones. You pay for words you never
see. The failure lab (§5) makes this tax bite for real.

#### b) The context window & statelessness — the desk

The **context window** is the consultant's desk: everything they can consider for one meeting
— your instructions, the conversation history, the new question — must fit on the desk at
once. (Flash-class desks are huge: ~1M tokens.) And crucially: **the desk is wiped clean
after every meeting.**

The API has no session, no user profile, no "as we discussed last time." None. If a chat
product *seems* to remember you, that is the *client app* secretly re-sending the whole
transcript with every message.

💡 **Mental model: the model is a brilliant consultant with amnesia. An agent is the clerk
who maintains the dossier** — deciding what goes into the folder, what gets summarized out,
and what the next meeting needs to see. That clerk is exactly what we hand-build on Day 3,
and "what earns a place in the dossier" is the whole of Phase 3.

*Example (you will run this today):* tell the model your favorite color; then, in a
**separate call**, ask what it is — it has no idea. Re-send the exchange as history, and it
answers instantly. The difference between those two calls is the entire concept.

#### c) Sampling — the dial

Under the hood, the model's raw output is not a word — it is a **probability list over every
possible next token** ("blue: 62%, red: 15%, teal: 4%, …"). **Sampling** is how one token
actually gets picked from that list, and three knobs shape the pick:

| Knob | Plain meaning | When Sutra cares |
| --- | --- | --- |
| `temperature` | How adventurous the pick is. 0 ≈ always take the front-runner; higher (up to 2.0) flattens the odds so underdogs win more often | The classifier runs at 0 — routing must be boring and repeatable. The Writer drafting a reply can afford ~0.7 |
| `top_p` | Only sample from the smallest set of tokens whose odds add up to *p* — cuts off the long tail of nonsense | A sane default guardrail; rarely hand-tuned alongside temperature |
| `top_k` | Only sample from the *k* highest-odds tokens, full stop | Same idea, by count instead of probability mass |

⚠️ One honest caveat: even at `temperature=0`, bit-identical output is *not contractually
guaranteed* across time or model versions — infrastructure changes can perturb results. Treat
temp-0 as "very stable," not "reproducible forever." That is why evals (Phase 12) score
*behavior*, not exact strings.

```python
"""Environment loading for Sutra.

Reads KEY=VALUE lines from the repo-root .env into os.environ. Real
environment variables win over .env values. Stdlib only, by design.

Usage:
    from sutra.config import load_env
    load_env()          # now os.environ has GOOGLE_API_KEY etc.
"""
from __future__ import annotations

import os                      # the environment we are loading INTO
from pathlib import Path       # clean path handling (house style)

ROOT = Path(__file__).resolve().parents[1]   # sutra/config.py -> repo root


def load_env(path: Path | None = None) -> None:
    """Load .env into os.environ without overwriting existing variables.

    Args:
        path: an alternative .env location (tests use this); default is
            the repo root's .env.

    Example:
        >>> load_env()
        >>> "GOOGLE_API_KEY" in os.environ
        True
    """
    env_file = path if path is not None else ROOT / ".env"
    if not env_file.exists():                # no .env? fine — maybe the real
        return                               # environment already has the keys
    for line in env_file.read_text(encoding="utf-8").splitlines():
        line = line.strip()                  # ignore surrounding whitespace
        if not line or line.startswith("#") or "=" not in line:
            continue                         # skip blanks, comments, junk
        key, value = line.split("=", 1)      # split ONLY on the first '='
        # setdefault = "write only if absent": real env vars keep priority
        os.environ.setdefault(key.strip(), value.strip())
```

**Step 4 — `sutra/mechanics.py`: the first call, with honest 429 handling.**

Every model call path handles 429 ("too many requests") from day one — that's a CLAUDE.md
zero-budget rule. And "handles" means **listening, not just retrying**. Here is the war story
baked into this file: the first draft backed off 1→2→4 seconds, like every tutorial says.
Reality vetoed it *the same day*: Gemini's free window is *per minute*, and its 429 message
literally says "Please retry in 47s". Three quick exponential retries all land inside the
same minute-window and burn your attempts achieving nothing (the exact naive-fix scene of
Addendum 02 §6). So the wrapper below **prefers the server's own stated delay**, falls back
to exponential only when none is given, and after four tries **surfaces the error** — it
never quietly invents a result (Principle 10). Day 72 deepens this further (jitter,
escalation policy, cross-provider routing).

> *(Same 2026-08-14 note as above: richer comments only; code statements identical.)*

```python
"""Day 2 — LLM mechanics probes: tokens, statelessness, sampling.

Importable without side effects. Run demos with:
    python -m sutra.mechanics ask        # first call: one prompt, one answer
    python -m sutra.mechanics tokens     # see the meter: counts + usage bill
    python -m sutra.mechanics memory     # see the amnesia: history vs none
    python -m sutra.mechanics sampling   # see the dial: temp 0.0 vs 1.5
    python -m sutra.mechanics capped     # failure lab: the thinking tax
"""
from __future__ import annotations

import re                                  # to read the delay out of 429 text
import sys                                 # for the command-line demo picker
import time                                # to actually wait between retries

from google import genai                   # the raw Gemini SDK (Day 2 install)
from google.genai import errors, types     # error classes + request types

from sutra.config import load_env          # our ten-line .env loader (step 3)

# Free-tier pin — repinned 2026-08-13: gemini-2.5-flash returns 404 for new
# accounts ("no longer available to new users"); gemini-3.5-flash verified
# working on this project's key. See CHANGELOG_PLAN.md.
MODEL = "gemini-3.5-flash"
MAX_TRIES = 4                              # after 4 tries: give up HONESTLY

# 429 messages state the server's own delay, e.g. "Please retry in 36.5s."
_RETRY_IN = re.compile(r"retry in ([\d.]+)s", re.IGNORECASE)


def _retry_wait(e: errors.APIError, attempt: int) -> float:
    """The server's stated retry delay when present, else exponential backoff.

    Example:
        a 429 saying "Please retry in 36.5s"  -> returns 37.5 (their delay + 1)
        a 429 with no stated delay, attempt 2 -> returns 4.0  (2 ** 2)
    """
    if e.message and (m := _RETRY_IN.search(e.message)):
        return float(m.group(1)) + 1.0     # trust the server; +1s of margin
    return float(2**attempt)               # fallback: 1, 2, 4, 8 seconds


def ask(
    client: genai.Client,
    contents: object,
    config: types.GenerateContentConfig | None = None,
) -> types.GenerateContentResponse:
    """generate_content with honest 429 handling: back off, then surface.

    This wrapper is the ONLY door Sutra uses to call the model — so 429
    honesty protects every future day (the loop on Day 3 imports it).

    Args:
        client: an authenticated genai.Client.
        contents: a prompt string, or a list of types.Content (history).
        config: optional GenerateContentConfig (temperature, system, tools…).

    Returns:
        The full response object (text, usage metadata, candidates…).

    Example:
        >>> load_env()
        >>> client = genai.Client()
        >>> ask(client, "Say hi in three words.").text
        'Hi there, friend!'
    """
    for attempt in range(MAX_TRIES):
        try:
            return client.models.generate_content(
                model=MODEL, contents=contents, config=config
            )
        except errors.APIError as e:
            # Anything that is NOT a quota hit — or our LAST allowed try —
            # gets re-raised: never swallow errors (Principle 10).
            if e.code != 429 or attempt == MAX_TRIES - 1:
                raise
            wait = _retry_wait(e, attempt)             # how long to pause
            print(f"429: quota hit — waiting {wait:.0f}s, attempt {attempt + 1}/{MAX_TRIES}")
            time.sleep(wait)                           # actually wait it out
    raise AssertionError("unreachable")                # loop always returns/raises


def demo_ask(client: genai.Client) -> None:
    """The first call: one prompt in, one message out.

    Usage:  python -m sutra.mechanics ask     (1 model call)
    """
    response = ask(client, "In one sentence: what is a support-ticket triage desk?")
    print(response.text)                       # Sutra's first words


def demo_tokens(client: genai.Client) -> None:
    """Count tokens before a call; read the real bill after it.

    Usage:  python -m sutra.mechanics tokens  (1 model call + 1 free count)
    """
    prompt = "Why is the sky blue? Answer in one sentence."
    print("count_tokens before the call:")     # the "how big is this?" check
    print(" ", client.models.count_tokens(model=MODEL, contents=prompt))
    response = ask(client, prompt)
    print("model said:", response.text)
    print("usage metadata (the actual bill):")  # note thoughts_token_count!
    print(" ", response.usage_metadata)


def demo_memory(client: genai.Client) -> None:
    """Prove statelessness: no history → amnesia; history → recall.

    Usage:  python -m sutra.mechanics memory  (3 model calls)
    """
    setup = "My favorite color is teal. Reply with just: OK."
    first = ask(client, setup)                 # meeting 1: tell it a fact
    print("call 1:", first.text)

    second = ask(client, "What is my favorite color?")   # meeting 2: NO notes
    print("call 2, NO history:", second.text)  # it cannot know — desk was wiped

    history = [                                # meeting 3: bring the dossier —
        types.Content(role="user", parts=[types.Part(text=setup)]),        # what we said
        types.Content(role="model", parts=[types.Part(text=first.text or "OK.")]),  # what it said
        types.Content(role="user", parts=[types.Part(text="What is my favorite color?")]),  # new question
    ]
    third = ask(client, history)               # re-reads everything, fresh
    print("call 3, WITH history:", third.text)  # now it "remembers": teal


def demo_sampling(client: genai.Client) -> None:
    """Same prompt, two temperatures, three runs each.

    Usage:  python -m sutra.mechanics sampling  (6 model calls — mind the RPM!)
    """
    prompt = "Name a color. Reply with one word only."
    for temperature in (0.0, 1.5):             # boring dice, then wild dice
        answers = [
            (ask(client, prompt, types.GenerateContentConfig(temperature=temperature)).text or "").strip()
            for _ in range(3)                  # three rolls at each setting
        ]
        print(f"temperature={temperature}: {answers}")


def demo_capped(client: genai.Client) -> None:
    """Failure lab: a tiny max_output_tokens meets a thinking model.

    Usage:  python -m sutra.mechanics capped  (1 model call; read doc §5 first)
    """
    response = ask(
        client,
        "Explain why the sky is blue.",
        types.GenerateContentConfig(max_output_tokens=16),   # a hard 16-token wall
    )
    print("text:", repr(response.text))        # likely None — thoughts ate it
    print("usage metadata:", response.usage_metadata)        # the receipt


def main() -> None:
    """Tiny demo dispatcher: `python -m sutra.mechanics <name>`."""
    demos = {
        "ask": demo_ask,
        "tokens": demo_tokens,
        "memory": demo_memory,
        "sampling": demo_sampling,
        "capped": demo_capped,
    }
    name = sys.argv[1] if len(sys.argv) > 1 else "ask"
    if name not in demos:                      # unknown name -> print usage
        print(f"usage: python -m sutra.mechanics [{'|'.join(demos)}]")
        raise SystemExit(2)
    load_env()                                 # keys from .env, never from code
    demos[name](genai.Client())                # build a client, run the demo


if __name__ == "__main__":                     # run as a script, not on import
    main()
```

## 5 · 💥 Failure lab — the invisible thinking tax

> 🎬 **The scene:** you want short answers, so you cap the response:
> `max_output_tokens=16`. Cheap, controlled, tidy.
> 😬 **The naive fix:** when the reply comes back empty or truncated, you shout louder in the
> prompt — "BE BRIEF!!" — and raise the cap a little.
> 💥 **Why it fails:** `gemini-3.5-flash` **thinks before it answers, by default**, and its
> hidden reasoning is billed from the *same output budget*. Your 16 tokens were spent on
> thoughts you never saw; the visible answer got the leftovers — sometimes nothing at all.
> Run `python -m sutra.mechanics capped` and read the usage metadata: thought tokens
> consumed, `text` possibly `None`.
> 💡 **The insight:** a token cap is a **hard wall, not an instruction** — the model doesn't
> plan around it; it just stops when it hits it. Brevity belongs in the *prompt*; caps are
> for runaway *protection*. And on thinking models, **output ≠ what you see** — remember this
> on Day 24 (budgets) and Day 79 (evals on Flash-Lite), where the thinking tax changes the
> arithmetic.

Observed today, not just asserted: the `capped` demo's usage metadata is the receipt.

## 6 · 🎤 Interview corner

1. **"Why do agent builders obsess over tokens?"** — Because tokens are the unit of *all
   three* scarce resources at once: money (or free-tier quota), latency, and context space.
   An agent that re-sends a growing transcript every turn grows quadratically in total tokens
   processed — which is why context management (compaction, summarization) is an engineering
   discipline, not a nicety. Bonus point: thinking models bill hidden reasoning as output,
   so measured usage ≠ visible text — I've got the printout.
2. **"Is the LLM API stateful?"** — No: every call ships the full context, and the model
   retains nothing after. Chat "memory" is client-side transcript management. Implication
   for agents: state (history, tool results, memory) is *your* subsystem — which is exactly
   what the sessions, memory-services, and retrieval phases of this project build.
3. **"Does temperature=0 make outputs reproducible?"** — Deterministic-ish, not guaranteed:
   sampling picks the front-runner, but providers don't contractually promise bit-identical
   results across infrastructure or version changes. So: temp 0 for routing/classification
   stability, yes — but regression safety comes from evals that score *behavior*, not string
   equality.
