demo and re-read the output. Every time. For every change. Forever.

There's an old excuse for skipping tests in AI systems: *"the model is nondeterministic —
you can't unit test this stuff."* Today we take that excuse apart. Because look at your
actual codebase: the *model* is maybe five percent of it. `lookup_ticket` is a dict lookup.
The safety net's fallback is a dict literal. The JSON formatter is string work. The quota
math (tomorrow) is arithmetic. **All of that is deterministic, and deterministic code has
no excuse.** Today, pytest arrives and the deterministic 95% gets a harness. (The stochastic
5% gets its own discipline — evals — in Phase 12. Different tool for a different animal.)

## 3 · 📚 Concepts

### OPS-05 — Crash-test the car, not the driver

**The story.** Nobody crash-tests a car by studying the driver's mood. The car — brakes,
belts, crumple zones — gets deterministic, repeatable rigs: same dummy, same wall, same
speed, measurable result. The *driver* gets a different instrument entirely: a driving
exam — scenario-based, judged, allowed to have shades of grey.

Your agent system is car + driver:

| Vehicle part | In Sutra | Instrument |
| --- | --- | --- |
| Brakes, belts, airbags | tools, callbacks, plugins, formatters, quota math, state writes | **unit tests** — today |
| The driver | the model's judgment: which tool, what answer, what tone | **evals** — Phase 12 (Days 79–83) |
| The road rules | schemas, honest-error contracts, budget caps | unit tests *of the enforcement code* — today |

The excuse dies by decomposition: nondeterminism lives almost entirely in one component,
and that component has a *boundary* — the tool call, the callback hook, the context object.
Everything on your side of the boundary is plain Python. **Test to the boundary,
substitute at the boundary** — hand a tool a *fake* context (a stub with just `.state`)
instead of booting a real runner, and suddenly your test needs no framework, no network,
no key, no luck.

💡 **Mental model: the model is a component, not an atmosphere.** It has edges. Test up to
the edges deterministically; test across them with evals.

Three properties every test today must have (steal this as a checklist forever):
**fast** (milliseconds — you'll run these hundreds of times), **isolated** (no network, no
key, no shared files — green on a plane), **specific** (when it fails, the name tells you
the crime: `test_unknown_ticket_returns_not_found_not_invention`).

### OPS-06 — pytest, the house rules

pytest in one paragraph, for the first-timer: files named `test_*.py` in `tests/`,
functions named `test_*`, plain `assert` statements (pytest rewrites them so failures show
*values*, not just "False"). Run all: `uv run pytest`. Run one: `uv run pytest
tests/test_adk_tools.py::test_lookup_known_ticket`. Structure mirrors `src` (house rule
from CLAUDE.md): code in `sutra/x.py` → tests in `tests/test_x.py`.

Every test body follows **arrange-act-assert** — set the stage, do the one thing, check
the one outcome. And two agent-specific idioms you'll use today:

1. **The fake context.** ADK injects `ToolContext` into tools; your tests inject a
   five-line stand-in with the same *shape* (`.state` dict). The tool can't tell — that's
   the point. (This is duck typing earning its keep: we fake the shape, not the class.)
2. **Async hooks under test.** Plugin hooks are `async def`; a test drives them with
   `asyncio.run(hook(...))` and asserts on the returned dict. No runner, no event loop
   ceremony.

What today's tests are *not*: they don't assert on model prose, don't call
`generate_content`, don't need `.env`. A unit test that spends quota is a bug (§5 shows
the full horror of the alternative).

**Step 3 — `tests/test_adk_tools.py`: the tools rig (zero quota).**

```python
"""Day 23 — unit tests for Sutra's tools: the deterministic shell.

No model, no network, no .env. If a test here ever needs one of those,
it has crossed the boundary and belongs in evals (Phase 12) instead.
"""
from __future__ import annotations

import asyncio

import pytest

from sutra.loop import lookup_ticket, search_kb          # Day 3's tool bodies
from sutra.state_lab import remember_triage              # Day 17's state writer
from sutra.errors import search_kb_honest                # Day 21's honest tool
import sutra.errors as errors_mod                        # to flip KB_IS_DOWN


class FakeToolContext:
    """A stand-in with the SHAPE tools actually use: just .state.

    Example:
        >>> ctx = FakeToolContext()
        >>> remember_triage("high", ctx)["status"]
        'recorded'
        >>> ctx.state["severity"]
        'high'
    """

    def __init__(self) -> None:
        self.state: dict = {}                            # the only attr tools touch


# --- Day 3/4 tool bodies: pure functions, pure tests ---------------------------

def test_lookup_known_ticket_returns_its_text() -> None:
    result = lookup_ticket("4521")                       # act
    assert "logged out" in result                        # the motif ticket


def test_lookup_unknown_ticket_says_so_not_invents() -> None:
    result = lookup_ticket("9999")
    assert "9999" in result and "No ticket" in result    # honesty is a CONTRACT —
                                                         # this test enforces it forever

def test_search_kb_finds_the_logout_article() -> None:
    assert "KB-104" in search_kb("user logged out")


# --- Day 17: state writes through a FAKE context -------------------------------

def test_remember_triage_writes_all_four_scopes() -> None:
    ctx = FakeToolContext()                              # arrange: no runner needed
    out = remember_triage("high", ctx)                   # act
    assert out == {"status": "recorded", "severity": "high"}
    assert ctx.state["severity"] == "high"               # session scope
    assert ctx.state["user:last_severity"] == "high"     # user scope
    assert ctx.state["app:tickets_triaged"] == 1         # app scope, counted
    assert ctx.state["temp:debug_note"].startswith("triaged at")


def test_remember_triage_counts_across_calls() -> None:
    ctx = FakeToolContext()
    remember_triage("low", ctx)
    remember_triage("high", ctx)                         # same fake session
    assert ctx.state["app:tickets_triaged"] == 2         # the counter counts


# --- Day 21: the routing rule, both directions ---------------------------------

def test_kb_outage_raises_system_failure(monkeypatch) -> None:
    monkeypatch.setattr(errors_mod, "KB_IS_DOWN", True)  # simulate the outage
    with pytest.raises(ConnectionError):                 # system failure -> RAISE
        search_kb_honest("logged out")


def test_kb_domain_miss_is_data_not_exception(monkeypatch) -> None:
    monkeypatch.setattr(errors_mod, "KB_IS_DOWN", False) # healthy KB
    result = search_kb_honest("")                        # empty query: domain miss
    assert result == {"status": "not_found", "query": ""}   # DATA, not raise
```

"""Day 23 — unit tests for callbacks/plugins/formatting: the policy shell."""
from __future__ import annotations

import asyncio
import json
import logging

from sutra.errors import SafetyNetPlugin
from sutra.logging_setup import JsonLinesFormatter


class FakeTool:
    """Shape-fake for the hook's `tool` param: only .name is read."""

    name = "search_kb"


def test_safety_net_returns_honest_fallback() -> None:
    plugin = SafetyNetPlugin()
    result = asyncio.run(plugin.on_tool_error_callback(  # async hook, driven directly
        tool=FakeTool(), tool_args={"query": "x"},
        tool_context=None, error=ConnectionError("kb timed out"),
    ))
    assert result["status"] == "tool_unavailable"        # admits being a fallback…
    assert "kb timed out" in result["detail"]            # …and carries the truth
    assert "invent" in result["advice"] or "guess" in result["advice"].lower()


def test_safety_net_counts_errors() -> None:
    plugin = SafetyNetPlugin()
    for _ in range(3):
        asyncio.run(plugin.on_tool_error_callback(
            tool=FakeTool(), tool_args={}, tool_context=None,
            error=ConnectionError("boom")))
    assert plugin.error_count == 3                       # escalation math (Day 72) rests here


def test_json_formatter_emits_one_valid_json_line() -> None:
    record = logging.LogRecord(name="sutra.t", level=logging.ERROR, pathname=__file__,
                               lineno=1, msg="tool_error", args=(), exc_info=None)
    record.tool = "search_kb"                            # an extra= field
    line = JsonLinesFormatter().format(record)
    assert "\n" not in line                              # ONE line (JSONL law)
    row = json.loads(line)                               # valid JSON (parseable law)
    assert row["event"] == "tool_error" and row["tool"] == "search_kb"

## 5 · 💥 Failure lab — the unit test that phoned the model

> 🎬 **The scene:** a teammate (fine: past-you) wants "a real test" and writes one that
> boots the full runner, asks the actual model to triage #4521, and asserts
> `"KB-104" in reply`. It passes! Merged.
> 😬 **The naive fix:** "it's testing the real thing end to end — that's *more* honest
> than your fakes, surely."
> 💥 **Why it fails, on schedule:** Monday, the model phrases the answer as "article
> KB‑104" with a non-breaking hyphen — red. Tuesday, 5 RPM means the suite queues behind
> your own demos — red (429). Wednesday, someone runs tests on the train — red (no
> network). Thursday, the suite passes but *burned 30 requests of the day's quota on
> nothing*. By Friday everyone ignores red, which means the day a *real* regression lands,
> the suite is already furniture. One test destroyed the property that makes suites
> valuable: **red must mean broken.**
> 💡 **The insight:** determinism isn't a nice-to-have in unit tests — it's the entire
> product. Model-in-the-loop checks are legitimate and necessary, but they are a different
> instrument with different math: sampled, scored, tracked over time — that's evals
> (Phase 12), run on the cheap lane, scheduled inside quota (Day 82 puts them in CI
> nightly). The boundary rule keeps both instruments sharp: **unit tests below the model
> boundary, evals across it, nothing in between.**

## 6 · 🎤 Interview corner

1. **"How do you test a nondeterministic AI system?"** — By refusing the framing: the
   nondeterminism is one component with a clean boundary, not an atmosphere. Everything on
   my side — tools, state writes, error policy, formatters — is deterministic Python under
   ordinary pytest: fast, isolated, zero network. At the boundary I substitute fakes (a
   five-line ToolContext stand-in). Across the boundary — model judgment — I use evals
   with scoring and sampling, a separate suite with separate math. My unit suite runs in
   a second at zero cost; that's what makes it run *always*.
2. **"What's the most valuable test in your agent repo?"** — The honesty contracts. E.g.:
   unknown ticket → the tool returns an explicit not-found, and the error-plugin's
   fallback must carry `status: tool_unavailable`, never a success shape. Those tests pin
   the *safety* behavior (fail honestly) so no refactor can quietly trade it away — I
   watched pytest name that exact crime when I flipped the status on purpose.
3. **"How do you test async plugin hooks without booting the framework?"** — Drive the
   coroutine directly: `asyncio.run(plugin.on_tool_error_callback(tool=fake, …))` and
   assert on the returned dict. The hook's contract is its signature and return value;
   the runner is just the delivery van, and delivery vans don't belong in unit tests.
