## 3 · 📚 Concepts

### ADK-21 — Artifacts: the filing cabinet next to the desk

**The story, continued from yesterday.** A good support agent never staples a 40-page log
printout to the ticket folder's sticky note. They punch it, file it in the cabinet, and
write on the sticky note: *"full log → cabinet, folder 4521, doc 2, latest revision."* The
note stays light; the document stays whole; and old revisions stay in the folder behind the
new one.

| Filing cabinet | Our system | Technical name |
| --- | --- | --- |
| A filed document | Named binary data + its type | **artifact** = filename + `types.Part` (`Blob(data, mime_type)`) |
| Revisions stacked in the folder | Every save keeps the old one | **versions**, auto-numbered 0, 1, 2… |
| The cabinet itself | Pluggable storage backend | `BaseArtifactService` → `InMemoryArtifactService` (today) / `GcsArtifactService` (🅿️ cloud, paid infra) |
| "folder 4521" vs "Priya's drawer" | Session-scoped vs user-scoped files | plain filename vs **`user:`** filename prefix |

💡 **Mental model: state is the sticky note; the artifact is the document it points at.**
If it's a *fact*, put it in state. If it's a *file* — bytes with a MIME type, worth
versioning — file it as an artifact and keep only its name in the conversation.

Three load-bearing details:

1. **The payload is a `types.Part`.** The same `Part` type you've used for messages since
   Day 2 — here carrying `inline_data` (a `Blob` of raw bytes + `mime_type` like
   `"text/markdown"` or `"image/png"`). One data shape for messages, tool results, and
   files — the SDK reuses its vocabulary, and so should your mental model.
2. **Saving returns a version number, and old versions survive.** `save_artifact` never
   overwrites: it files a new revision on top and hands you its number (0 first). `load`
   with no version = latest; `load(version=0)` = the original. That is "give me yesterday's
   draft", solved by the storage layer instead of by your discipline.
3. **Scopes rhyme with yesterday.** A plain filename lives with the session — like
   no-prefix state. A `"user:"` filename follows the user across sessions — like `user:`
   state. `list_artifacts()` shows both. (No `app:` or `temp:` for files — the cabinet has
   just the two drawers; if a file must die with the invocation, don't file it at all.)

And the same quiet warning as yesterday: today's cabinet is `InMemoryArtifactService` —
correct semantics, RAM-only lifetime. The interface is what you're learning; a durable
backend slots in later without touching tool code, because tools only ever talk to
`context.save_artifact`/`load_artifact`, never to a concrete service. That indirection *is*
the design lesson.

**When NOT to use an artifact:** a value your code branches on (`severity`) — state; a bulky
intermediate passed between two tools within one invocation — `temp:` state; anything
secret — `.env`, never storage that tools can list.

```python
"""Day 18 — artifacts: files that survive turns.

A triage report becomes a real, versioned, MIME-typed file living next
to the session. Tools only ever touch context.save_artifact/load_artifact
— the concrete storage backend (in-memory today, durable later) is the
runner's business, not the tool's.

Importable with no side effects. Demos:

    python -m sutra.artifacts_lab report    # agent writes+files a report (v0)
    python -m sutra.artifacts_lab versions  # edit -> v1; load v0 AND v1 back
    python -m sutra.artifacts_lab userfile  # a "user:" file follows the user
"""
from __future__ import annotations

import asyncio
import sys

from google.adk.agents import Agent
from google.adk.artifacts import InMemoryArtifactService   # the RAM cabinet
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types

from sutra.config import load_env

APP = "sutra"


async def file_report(ticket_id: str, report_markdown: str, tool_context) -> dict:
    """Save a triage report as a versioned markdown artifact.

    The model WRITES the report text (its craft); this tool FILES it
    (our craft). Separation of duties, as everywhere in Sutra.

    Args:
        ticket_id: which ticket this report belongs to, e.g. "4521".
        report_markdown: the full report body, markdown text.
        tool_context: injected by ADK; carries the artifact methods.

    Returns:
        dict with the filename and the version number the cabinet assigned.

    Example:
        Called by the model as
        file_report(ticket_id="4521", report_markdown="# Triage…").
        First call returns {"filename": "report_4521.md", "version": 0};
        the next save of the same name returns version 1.
    """
    filename = f"report_{ticket_id}.md"              # plain name -> session-scoped
    part = types.Part(                               # the payload shape:
        inline_data=types.Blob(                      #   raw bytes…
            data=report_markdown.encode("utf-8"),    #   …of the markdown text
            mime_type="text/markdown",               #   …typed, so viewers know what it is
        )
    )
    # TODO(on the day): confirm await vs plain call on adk.dev/artifacts/ (batch note).
    version = await tool_context.save_artifact(filename, part)   # cabinet assigns 0,1,2…
    return {"filename": filename, "version": version}


report_agent = Agent(
    name="sutra_report_writer",
    model="gemini-3.5-flash",                        # pinned, as always (ADK-73)
    description="Writes a short triage report and files it as an artifact.",
    instruction=(
        "When given a ticket summary, write a SHORT markdown triage report "
        "(title, 2-bullet diagnosis, 1-line next step), then call file_report "
        "with the ticket id and the full markdown. Confirm the saved filename "
        "and version in one sentence."
    ),
    tools=[file_report],
)


def _runner() -> tuple[Runner, InMemorySessionService, InMemoryArtifactService]:
    """Build the day's runner with BOTH services attached.

    Returns:
        (runner, session_service, artifact_service) — the services are
        returned too so demos can peek into the cabinet from outside.
    """
    sessions = InMemorySessionService()
    cabinet = InMemoryArtifactService()              # today's cabinet: RAM
    runner = Runner(
        agent=report_agent,
        app_name=APP,
        session_service=sessions,
        artifact_service=cabinet,                    # TODO(on the day): confirm kwarg name
    )
    return runner, sessions, cabinet


async def _ask(runner: Runner, user_id: str, session_id: str, text: str) -> None:
    """One message in, final reply printed — same helper shape as Day 17."""
    message = types.Content(role="user", parts=[types.Part(text=text)])
    async for event in runner.run_async(
        user_id=user_id, session_id=session_id, new_message=message
    ):
        if event.is_final_response() and event.content:
            print("reply:", event.content.parts[0].text.strip())


async def _load(cabinet: InMemoryArtifactService, user_id: str, session_id: str,
                filename: str, version: int | None = None) -> str:
    """Read one artifact version straight from the service (outside a run).

    Args:
        cabinet: the artifact service to read from.
        user_id / session_id: whose drawer to open.
        filename: which document.
        version: None for latest, or an exact revision number.

    Returns:
        The artifact's bytes decoded as UTF-8 text.
    """
    part = await cabinet.load_artifact(
        app_name=APP, user_id=user_id, session_id=session_id,
        filename=filename, version=version,
    )
    return part.inline_data.data.decode("utf-8")     # bytes -> text for printing


def demo_report() -> None:
    """The agent writes a report; the tool files it as version 0.

    Usage:  python -m sutra.artifacts_lab report    (~2 model calls)
    """
    runner, sessions, cabinet = _runner()
    asyncio.run(sessions.create_session(app_name=APP, user_id="priya", session_id="s1"))
    asyncio.run(_ask(runner, "priya", "s1",
                     "Ticket 4521: users keep getting logged out. "
                     "KB-104 points at the SameSite/https cookie change. "
                     "Write and file the triage report."))
    text = asyncio.run(_load(cabinet, "priya", "s1", "report_4521.md"))
    print("\n--- report_4521.md (latest) ---\n" + text)


def demo_versions() -> None:
    """Two saves, two versions, both loadable — with ZERO model calls.

    We call the tool logic directly (it's just Python!) to show that
    versioning is the CABINET's behavior, not the model's.

    Usage:  python -m sutra.artifacts_lab versions   (0 model calls)
    """
    _, sessions, cabinet = _runner()
    asyncio.run(sessions.create_session(app_name=APP, user_id="priya", session_id="s1"))

    async def save(text: str) -> int:
        """Save one revision of the report straight through the service."""
        part = types.Part(inline_data=types.Blob(
            data=text.encode("utf-8"), mime_type="text/markdown"))
        return await cabinet.save_artifact(
            app_name=APP, user_id="priya", session_id="s1",
            filename="report_4521.md", artifact=part,
        )

    v0 = asyncio.run(save("# Triage 4521 — DRAFT\nSuspect: cookie change."))
    v1 = asyncio.run(save("# Triage 4521 — FINAL\nConfirmed: SameSite/https (KB-104)."))
    print(f"saved versions: {v0} then {v1}")         # expect: 0 then 1

    old = asyncio.run(_load(cabinet, "priya", "s1", "report_4521.md", version=0))
    new = asyncio.run(_load(cabinet, "priya", "s1", "report_4521.md"))  # latest
    print("\n--- version 0 ---\n" + old)
    print("\n--- latest ----\n" + new)               # different content, same name


def demo_userfile() -> None:
    """A "user:" artifact follows the user into a brand-new session.

    Usage:  python -m sutra.artifacts_lab userfile   (~2 model calls)
    """
    runner, sessions, cabinet = _runner()
    asyncio.run(sessions.create_session(app_name=APP, user_id="priya", session_id="s1"))

    async def save_signature() -> None:
        """File Priya's reply signature in HER drawer (user-scoped)."""
        part = types.Part(inline_data=types.Blob(
            data="— Priya, Support Desk".encode("utf-8"), mime_type="text/plain"))
        await cabinet.save_artifact(
            app_name=APP, user_id="priya", session_id="s1",
            filename="user:signature.txt", artifact=part,   # "user:" = her drawer
        )

    asyncio.run(save_signature())

    # A brand-new session — the session drawer is empty, HER drawer is not:
    asyncio.run(sessions.create_session(app_name=APP, user_id="priya", session_id="s2"))
    sig = asyncio.run(_load(cabinet, "priya", "s2", "user:signature.txt"))
    print("loaded from NEW session s2:", sig)        # survives the session boundary
    # And to show it's per-user, note what would happen for marco: his drawer
    # has no such file — the load would fail. Scopes rhyme with Day 17.


def main() -> None:
    """Demo dispatcher — house pattern."""
    demos = {"report": demo_report, "versions": demo_versions,
             "userfile": demo_userfile}
    name = sys.argv[1] if len(sys.argv) > 1 else "report"
    if name not in demos:
        print(f"usage: python -m sutra.artifacts_lab [{'|'.join(demos)}]")
        raise SystemExit(2)
    load_env()
    demos[name]()


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the sticky note that became a warehouse

> 🎬 **The scene:** before today you had exactly one place to put things — state. So when the
> Writer produced a full report, the obvious move was `state["report_4521"] = full_text`. It
> worked. Then a log file arrived: `state["log_4521"] = two_megabytes_of_text`. Also
> "worked".
> 😬 **The naive fix:** keep going — state is right there, and a dict eats anything.
> 💥 **Why it fails, three ways:** (1) **weight** — state rides with the session through
> every event append and every future persistence layer; megabyte values turn each save into
> a bulk copy and Phase 7's database rows into blobs. (2) **blast radius** — Day 17's `{key}`
> templating happily pastes state values into prompts; one careless instruction and the 2 MB
> log is *in the context window*, at 1M-token prices of attention (Day 19's whole topic).
> (3) **no history** — a state key holds the latest value only; the DRAFT you overwrote at
> 16:02 is simply gone, and "what did we almost send?" has no answer during the postmortem.
> 💡 **The insight:** **choose storage by the question you'll ask later.** "What is the
> severity?" → state (a fact, latest wins). "Show me the document — as it was yesterday" →
> artifact (bytes, typed, versioned). The sticky note points; the cabinet holds.

Observed today in the positive: `versions` answered "show me the draft AND the final" —
a question state cannot answer at all.

## 6 · 🎤 Interview corner

1. **"Where do files live in an agent system, and why not in the conversation state?"** —
   State is for small structured facts that ride with the session; files are binary, typed,
   and worth versioning, so they go through an artifact layer: named documents stored by a
   pluggable service, referenced from the conversation by filename. Keeping them out of
   state keeps sessions light, keeps prompts safe from accidental megabyte paste-ins, and
   buys version history for free — my triage report keeps DRAFT as v0 after FINAL lands as
   v1, which is exactly what you want in a postmortem.
2. **"How does your tool code stay independent of the storage backend?"** — Tools never see
   a storage class; they call `context.save_artifact`/`load_artifact` and the runner decides
   which `BaseArtifactService` implementation answers — in-memory in dev, durable in prod.
   Same interface-vs-implementation move as session services. I can swap the cabinet without
   editing a single tool.
3. **"When is an artifact the wrong choice?"** — For facts code branches on (state), for
   within-invocation intermediates (`temp:` state — don't file what you're about to shred),
   and for secrets (never in any store a tool can list). Storage choice is an API-shaped
   decision: pick by the question you'll ask later, not by what's convenient to write today.
