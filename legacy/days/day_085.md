## 1 · 🎬 Where we are — the story so far

Everything Sutra does today is started by a human typing `python -m something`. That was
right for eighty-four days: a shell is the cheapest possible interface and it never lies
about what it ran. But three things have quietly accumulated that a shell cannot serve.
Day 73's nightly wants a trigger it can be *called on*. Day 77's standup client is a

health already wired. The work is not writing it. The work is **knowing exactly what it
exposes**, because a front door that you have not read is not a door, it is a hole.

## 3 · 📚 Concepts

### ADK-64 — The server you did not write is still yours to defend

**The story.** You rent a shop. The landlord fits the front door, the shutters, the till
and a back entrance for deliveries. Handy — until the day you discover the delivery door
has no lock, because the landlord assumed you'd be putting one on. Nobody lied to you.
You simply never walked the building.

`adk api_server` is that shop. It is genuinely a lot of value for one command, and it
comes with a route table you are responsible for.

**The route table, read from `src/google/adk/cli/api_server.py` on 2026-08-20** —
grouped by what you should think about each one:

| Route | Method | Sutra's stance |
| --- | --- | --- |
| `/health` | GET | **keep.** Note the name: ADK's is `/health`, not `/healthz` |
| `/version` | GET | keep (useful in a container); it discloses the ADK version — fine for a public repo, a decision elsewhere |
| `/list-apps` | GET | keep; it is how you prove what is mounted |
| `/apps/{app_name}/app-info` | GET | keep — marked experimental upstream, so re-check at gates |
| `/run` | POST | **the main door.** Runs the agent, returns events when done |
| `/run_sse` | POST | **the main door, streaming.** What the browser client uses |
| `/run_live` | WebSocket | overlaps Day 75's hand-rolled `/ws/live` — decide, don't accumulate (Step 5) |
| `/apps/{app}/users/{user_id}/sessions[...]` | GET/POST/PATCH/DELETE | session CRUD — **read §5 before you expose this** |
| `.../sessions/{id}/artifacts[...]` | GET/POST/DELETE | artifact CRUD (Day 18's versioned artifacts, over HTTP) |
| `/apps/{app}/users/{user_id}/memory` | PATCH | writes into the memory service (Day 46) |
| `/agent-identity/finalize` | POST | 3LO credential finalisation — Day 90's topic; 🅿️ unused here |
| `/trigger/...` | POST | **only registered when `trigger_sources` is passed** — Day 73's ambient hook |

📌 **Reconciliation, stated rather than smoothed over.** The Wave-5 plan note said this
day would add `/healthz` **and** `/readyz`. Reality: ADK already serves **`/health`**, and
`sutra/live_lab.py` already serves `/healthz`. So the honest outcome is:

- `/health` — ADK's, free, keep it;
- `/healthz` — ours, from the labs; keep it as an alias so nothing that already points at
  it breaks, and say in one comment that it is an alias;
- `/readyz` — **does not exist anywhere yet**, and it is the one that actually earns its
  keep. Step 5 writes it.

The difference matters and is worth one paragraph in an interview: **liveness** ("is the
process up?") is nearly free and nearly useless — a process can be alive and unable to do
anything. **Readiness** ("can this instance serve a request right now?") is the one an
orchestrator should route on: can it open `data/sessions.db`, is `GOOGLE_API_KEY`
present, does the quota ledger have headroom (Day 70)? On Day 88 a Kubernetes readiness
probe will point at exactly this, and getting it wrong means the cluster sends traffic to
an instance that will 429 every request.

### ADK-65 — The app is an object, so your routes go on it

Two ways in, same server:

```python
# CLI — fastest, zero code, what you try first
adk api_server            # serves the agents found in the current directory

# Python — what you deploy, because you can add to it
from google.adk.cli.fast_api import get_fast_api_app
app = get_fast_api_app(agents_dir=".", web=False)
```

`get_fast_api_app` returns a `FastAPI` instance. That single fact is ADK-65: everything
FastAPI can do, you can do — mount routers, add middleware, add lifespan hooks, add your
own endpoints on the same port.

**The full signature, copied from `src/google/adk/cli/fast_api.py` on 2026-08-20** (it is
keyword-only; the arguments that matter to Sutra are marked):

```python
def get_fast_api_app(
    *,
    agents_dir: str,                      # ← where agents are discovered
    agent_loader: BaseAgentLoader | None = None,
    session_service_uri: str | None = None,   # ← "sqlite+aiosqlite:///./data/sessions.db" (Day 47)
    session_db_kwargs: Mapping[str, Any] | None = None,
    artifact_service_uri: str | None = None,
    memory_service_uri: str | None = None,
    use_local_storage: bool = True,
    eval_storage_uri: str | None = None,
    allow_origins: list[str] | None = None,   # ← CORS. Day 92 tightens this. See §5.
    web: bool,                            # ← required. True = also serve the dev UI
    a2a: bool = False,                    # ← Day 89 flips this
    task_store_uri: str | None = None,
    host: str = "127.0.0.1",
    bind_host: str | None = None,
    port: int = 8000,
    url_prefix: str | None = None,
    trace_to_cloud: bool = False,         # ← billed. Stays False (Addendum 02)
    otel_to_cloud: bool = False,          # ← billed. Stays False
    reload_agents: bool = False,
    lifespan: Lifespan[FastAPI] | None = None,   # ← where setup_tracing() belongs
    extra_plugins: list[str] | None = None,      # ← probe this (Step 4)
    logo_text: str | None = None,
    logo_image_url: str | None = None,
    auto_create_session: bool = False,
    trigger_sources: list[Literal["pubsub", "eventarc"]] | None = None,  # ← Day 73
    default_llm_model: str | None = None,
    gemini_enterprise_app_name: str | None = None,
    express_mode: bool = False,
) -> FastAPI:
```

💡 **Mental model: `adk api_server` is the demo; `get_fast_api_app` is the deployment.**
The CLI is for finding out whether the thing works. The function is what a Dockerfile's
`CMD` points at, because only the function lets you add a readiness probe, a lifespan
hook and your own routes.

Two arguments deserve care today:

- **`web: bool` is required, not optional** — you must decide whether to serve the dev UI.
  In a container it is `False`: the UI is a development affordance and shipping it widens
  the surface for nothing.
- **`extra_plugins: list[str]`** takes *strings*, not plugin objects, which implies an
  import-path loader. Sutra's five plugins are constructed with arguments
  (`AutoTracingPlugin(extra_scope_prefixes=…)`), so string-based loading may not express
  them. **Probe it in Step 4 and pick a side** — either the plugins live on the `App`
  object the agent module exports (most likely), or they are named here. Two half-wired
  plugin lists would be the worst outcome, and it would be silent.

**Step 4 — `sutra/api.py`: the app as an object.**

```python
"""Sutra's HTTP front door.

ADK builds the server; this module decides its configuration and adds the routes
ADK does not ship. It is the thing a container runs (Day 86) and the thing a
readiness probe talks to (Day 88).

Example:
    uvicorn sutra.api:app --host 0.0.0.0 --port 8080
"""

from __future__ import annotations

import contextlib
import os
from collections.abc import AsyncIterator

from fastapi import FastAPI
from google.adk.cli.fast_api import get_fast_api_app

from sutra.logging_setup import get_logger
from sutra.tracing import setup_tracing

logger = get_logger(__name__)

#: Day 47's async driver. sqlite is fine for one instance; Day 86's compose file
#: keeps it on a volume, and Day 88's note explains why more than one replica needs
#: something else.
SESSION_DB = os.getenv(
    "SUTRA_SESSION_DB", "sqlite+aiosqlite:///./data/sessions.db"
)

#: CORS. A comma-separated env var, default *empty* — same-origin only. The labs
#: used ["*"]; a deployed server must not. Day 92 audits this line.
ALLOW_ORIGINS = [o for o in os.getenv("SUTRA_ALLOW_ORIGINS", "").split(",") if o]


@contextlib.asynccontextmanager
async def _lifespan(app: FastAPI) -> AsyncIterator[None]:
    """Own the tracer provider for the server's whole life.

    setup_tracing() is idempotent (Day 84), so it is safe even if `adk web`
    already installed a provider — but installing it here means the API server
    traces even when nothing else has run yet.
    """
    setup_tracing()
    logger.info("api_startup", extra={"session_db": SESSION_DB})
    yield
    logger.info("api_shutdown")


app: FastAPI = get_fast_api_app(
    agents_dir=".",
    session_service_uri=SESSION_DB,
    allow_origins=ALLOW_ORIGINS,
    web=False,                 # no dev UI in a served app — smaller surface
    trace_to_cloud=False,      # billed; Addendum 02 forbids it
    otel_to_cloud=False,       # billed
    lifespan=_lifespan,
    trigger_sources=None,      # flipped on in Step 5 once the Day 73 hook is proven
)
```

**Step 5 — Sutra's own routes on the same app.** Append to `sutra/api.py`:

```python
from fastapi import Response

from sutra.quota import QuotaLedger


@app.get("/readyz")
async def readyz() -> Response:
    """Can this instance serve a request *right now*?

    Three honest checks, cheapest first. Returns 503 when any fails, so an
    orchestrator (Day 88) routes traffic away instead of into a 429.
    """
    problems: list[str] = []
    if not os.getenv("GOOGLE_API_KEY"):
        problems.append("no_api_key")
    try:
        import sqlite3

        sqlite3.connect("file:data/sessions.db?mode=ro", uri=True).close()
    except sqlite3.Error as exc:            # specific, not bare (house style)
        problems.append(f"session_db:{exc.__class__.__name__}")
    if not QuotaLedger().has_headroom():    # Day 70's accounting
        problems.append("no_quota")
    if problems:
        logger.warning("not_ready", extra={"problems": problems})
        return Response(status_code=503, content=",".join(problems))
    return Response(status_code=200, content="ok")


@app.get("/healthz")
async def healthz() -> Response:
    """Alias for ADK's /health. Kept so the Day 74 lab clients keep working."""
    return Response(status_code=200, content="ok")
```

## 5 · 💥 Failure lab — `user_id` is a claim, not an identity

> 🎬 **The scene:** the API works. You have been testing as `u1` all afternoon. To check
> that sessions really persist, you list them:
> `curl.exe http://127.0.0.1:8080/apps/<app>/users/u1/sessions` — there they are.
> Idly, you try a different name: `.../users/u2/sessions`. Empty list, 200 OK. Then you
> create one as `u2`, and read it back. It works. You never authenticated as anybody.
>
> Now put it together with what the sessions *contain*: every triage conversation, every
> ticket body Sutra has read, every draft reply. And with Day 84's finding that the trace
> exporter is a door. And with the fact that Day 86 is about to bind this to `0.0.0.0`
> inside a container.
>
> 😬 **The naive fix:** it's fine — the container will sit behind something that
> authenticates. Or: add an `X-API-Key` header check on `/run` and `/run_sse`.
>
> 💥 **Why it fails.** The first is a promise about a component that does not exist yet,
> made by the person least likely to be there when it is built. The second is worse,
> because it *looks* like a fix: it guards the two routes you were thinking about and
> leaves session CRUD, artifact CRUD and the memory PATCH wide open — and those are the
> routes that read data, which is what an attacker wants. `user_id` here is a **path
> parameter**: a string the caller chooses. It is not an identity, it is a *filing label*.
> ADK is not wrong to work this way — a framework cannot know your auth system — but the
> default is "the network is the perimeter", and on Day 88 the network is a cluster.
> There is a second, quieter half. CORS: the labs used `allow_origins=["*"]` because it
> made a local HTML file work. Ship that and any web page in any tab of any user's
> browser can drive `/run` — and read the response, because `*` is what makes the
> response readable. That is not an exotic attack, it is a link in an email.
>
> 💡 **The insight: authentication is not a route, it is a layer — and `user_id` from the
> client is a label, never a subject.** Two rules, both written down today and both
> enforced later:
> **(1)** Anything that filters by identity must derive that identity from something the
> caller cannot choose — a verified token, a mutual-TLS peer, a header set by a trusted
> proxy. Until such a thing exists, the honest posture is *bind to loopback*, and say so.
> **(2)** Defence stays where it already is. Sutra's real protections — Day 68's
> per-tool permissions, Day 63's approval `POLICY`, Day 67's guardrails, Day 69's data
> boundary — live on the **agent**, not the transport. That is why they still hold when
> a new door opens, and it is the strongest argument for having put them there.

Concretely, before Day 86:

- default `SUTRA_ALLOW_ORIGINS` to **empty** (done in Step 4) and make Day 92's review
  check it;
- bind to `127.0.0.1` locally; the container binds `0.0.0.0` because it must, and Day 86
  publishes the port to localhost only;
- add the row to `docs/THREAT_MODEL.md`: *entry point `sutra/api.py`, authentication
  **none**, mitigations: loopback binding + agent-level policy, owner day 92*;
- add a zero-quota test asserting `ALLOW_ORIGINS` is empty unless the env var is set, so
  nobody "temporarily" restores `["*"]`.

## 6 · 🎤 Interview corner

1. **"How is your agent exposed to callers?"** — ADK ships a FastAPI server. I use it as
   a Python object rather than the CLI — `get_fast_api_app(agents_dir=..., web=False,
   session_service_uri="sqlite+aiosqlite:///…", lifespan=...)` — because I need to add my
   own routes and a startup hook. `web=False` because the dev UI is a development
   affordance and shipping it just widens the surface. The main routes are `/run` and
   `/run_sse`; session and artifact CRUD come along with it; a `/trigger` route appears
   only if you pass `trigger_sources`, which is what my nightly job uses.
2. **"What's the difference between your health and readiness endpoints?"** — Liveness
   says the process is up, which is nearly free and nearly useless: a process can be
   alive and unable to serve anything. ADK gives me `/health` for that. I wrote `/readyz`
   myself, and it answers "can this instance serve a request right now": is the API key
   present, does the session database open read-only, does the quota ledger have
   headroom. It returns 503 with the reason when any of those fails, so an orchestrator
   routes traffic away instead of into a guaranteed 429 — and I tested the 503 path
   deliberately, because a probe you've never seen fail is a probe you don't know works.
3. **"Your API has no authentication. Why is that not a disaster?"** — It *would* be, on
   an open port, and I've written it down as such rather than discovered it later:
   `user_id` in those routes is a path parameter, a label the caller picks, not an
   identity — so session and artifact reads are open to anyone who can reach the port.
   My posture is loopback binding plus published-to-localhost in the container, empty
   CORS origins by default, and the row in the threat model that says "authentication:
   none, owner: the hardening day". What makes it survivable rather than catastrophic is
   that none of my real defences live in the transport: least-privilege tool permissions,
   the approval policy for writes, the injection guardrails and the PII boundary are all
   on the agent. A new door doesn't disarm them — which is precisely why they're there
   and not in a middleware.
