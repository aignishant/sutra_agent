## 3 · 📚 Concepts

### SK-17 — Structural tests: automate Day 25's checklist, not more

On Day 25 you were the linter — seven checklist rows, by hand. A hand process run once
is a lesson; run weekly, it is a chore that gets skipped. The fix is the same
mechanization you'd apply to any chore, with one design decision worth spelling out:

**We parse a subset of YAML on purpose.** Real frontmatter is YAML, and the stdlib has
no YAML parser. Three options:

| Option | Cost | Verdict |
| --- | --- | --- |
| add PyYAML as a dev dep | a dependency for 20 lines of need | against house style ("prefer the stdlib") — not yet earned |
| use `skills-ref` | official! but self-described demo-only, cloned not packaged | 🅿️ noted; not a production gate |
| parse the subset our rules need | ~30 honest lines | **chosen** — and the limits written down |

The subset: a `---`-delimited block; flat `key: value` lines; folded continuation
lines (indented) appended to the previous value; one nested map (`metadata:`). That
covers every skill we have and every check the spec makes mechanical. The limitation
is documented IN the parser's docstring with the escape hatch: *if a skill ever needs
exotic YAML, that's the day PyYAML enters `PACKAGES.md`* — a decision deferred until
evidence demands it, which is §2-of-CLAUDE.md thinking applied to dependencies.

💡 **Mental model: a linter is a checklist that never gets tired.** It checks the same
seven things you checked by hand on Day 25 — no more. Structure, not sense: it would
pass `evil-helper` without blinking, and (SK-18 aside) it cannot tell a routing-mush
description from a sharp one. Day 29 made that boundary a story; today it becomes a
test-suite comment.

### SK-18 — Behavioral tests: assert on events, pay the toll knowingly

A structural pass proves the binder is well-formed — not that anyone opens it. The
behavioral question is Day 26's question in test form: *given the trigger task, does
`load_skill` actually fire?* And you already know where that answer lives: the event
stream (`event.get_function_calls()`), not the final text.

But a behavioral test **spends model quota** — 2 calls per run against a 5 RPM / free
tier. Sutra's rule, established today and reused for every eval to come (Day 79 will
scale it): **quota-spending tests are opt-in, and the marker is the contract.**

```toml

markers = ["quota: spends real model calls; run explicitly with -m quota"]
addopts = "-m 'not quota'"
```

Default `uv run pytest`: free, fast, CI-safe. Friday's ritual (or the Day 73 nightly,
eventually): `uv run pytest -m quota` — deliberate, budgeted, logged by the Day 24
ledger like every other call. One test today: the flagship `ticket-triage` activation
smoke. Not ten — behavioral coverage grows with the evalset in Phase 12; today
establishes the *pattern* and its price tag.

### SK-19 — Versioning: an identity for the thing you audited

Yesterday's discipline hinged on one phrase: *the text you audited is the text that
runs*. For third-party skills, the pin is a commit hash. For first-party skills, the
equivalent is a **declared version** — because "the triage skill" is not one thing
over time, and evals, audits, and bug reports all need to name *which* one:

- **Where:** `metadata.version`, as a **quoted string** (`"1.1"` — unquoted, YAML
  makes it a float; you flagged this trap on Day 25, today a test enforces it).
- **Bump rules, tied to obligations** (the number exists to trigger the right ritual):

| Change | Bump | Obligation triggered |
| --- | --- | --- |
| typo, wording, formatting | patch (`"1.0"` → `"1.0.1"`) | none |
| new edge case, new reference | minor (`"1.1"`) | re-run behavioral smoke |
| procedure/steps/tools change | major (`"2.0"`) | re-run smoke + re-read as if third-party (Day 29 lenses) — a procedure change is a new skill wearing an old name |

- **No changelog file.** The spec has no changelog field, and we refuse to invent
  parallel bookkeeping: `git log -- skills/ticket-triage/` IS the changelog, with
  diffs attached (Principle 2 — the repo is the memory). The version is the *label*
  git history hangs off.
- **Third-party skills** never get their version bumped by us: upstream's hash is
  their version; a new hash = a new audit = an updated provenance Notes entry.

```python
"""Day 30 — spec checks for Agent Skills, as pure functions.

Automates Day 25's hand checklist against agentskills.io/specification
(checked 2026-08-18). Used by tests/test_skills.py today and by
tools/lint_skills.py from Day 31 — one set of rules, two front doors.

Deliberate limits (see Day 30 doc §3): parses the YAML SUBSET our skills
use — flat `key: value`, indented continuation lines, one nested map
(metadata). If a skill ever needs more YAML than this, stop and add
PyYAML as a dev dependency (with a PACKAGES.md row) instead of growing
this parser.

Example (zero side effects — safe anywhere):

    >>> from tools.skill_checks import check_skill
    >>> check_skill(pathlib.Path("skills/hello-desk"))
    []                                    # empty list = no problems
"""
from __future__ import annotations

import pathlib
import re

NAME_RE = re.compile(r"^[a-z0-9]+(-[a-z0-9]+)*$")   # spec: kebab, no edge/double '-'
MAX_NAME, MAX_DESC, MAX_LINES = 64, 1024, 500       # spec's three numbers
REF_RE = re.compile(                                 # relative paths the body mentions:
    r"(?:references|assets|scripts)/[A-Za-z0-9._\-/]+"   # e.g. references/rubric.md
)


def parse_frontmatter(text: str) -> dict[str, str] | None:
    """Parse the ----delimited frontmatter block into a flat dict.

    Continuation lines (indented) are folded into the previous value with a
    space, matching YAML's folded style. Keys inside `metadata:` come back
    prefixed, e.g. {"metadata.version": "1.0"}.

    Args:
        text: the full SKILL.md text.

    Returns:
        The fields as a dict, or None if no valid ---...--- block exists.

    Example:
        >>> parse_frontmatter("---\\nname: x\\ndescription: a\\n  b\\n---\\nBody")
        {'name': 'x', 'description': 'a b'}
    """
    lines = text.splitlines()
    if not lines or lines[0].strip() != "---":       # must OPEN with the fence
        return None
    fields: dict[str, str] = {}
    key = None                                       # the key continuations attach to
    prefix = ""                                      # "metadata." while inside the map
    for line in lines[1:]:
        if line.strip() == "---":                    # the CLOSING fence -> done
            return fields
        if re.match(r"^\S", line) and ":" in line:   # a new top-level key
            k, _, v = line.partition(":")
            prefix = ""                              # any nested map has ended
            if v.strip() == "" and k.strip() == "metadata":
                prefix, key = "metadata.", None      # entering the one allowed map
                continue
            key = k.strip()
            fields[key] = v.strip().strip('"')       # store; quotes are YAML's, not ours
        elif re.match(r"^\s+\S", line) and ":" in line and prefix:
            k, _, v = line.partition(":")            # a key INSIDE metadata:
            fields[prefix + k.strip()] = v.strip().strip('"')
        elif re.match(r"^\s+\S", line) and key:      # indented, no colon context ->
            fields[key] += " " + line.strip()        # folded continuation line
    return None                                      # never saw the closing fence


def check_skill(folder: pathlib.Path) -> list[str]:
    """Run every mechanical spec check on one skill folder.

    Args:
        folder: the skill directory (containing SKILL.md).

    Returns:
        A list of human-readable problems; empty means structurally valid.

    Example:
        >>> problems = check_skill(pathlib.Path("skills/ticket-triage"))
        >>> problems
        []
    """
    problems: list[str] = []
    md = folder / "SKILL.md"
    if not md.exists():                              # rule 0: the one required file
        return [f"{folder.name}: SKILL.md missing"]
    text = md.read_text(encoding="utf-8")

    fm = parse_frontmatter(text)                     # rule 1: the fence parses
    if fm is None:
        return [f"{folder.name}: no valid ---frontmatter--- block"]

    name = fm.get("name", "")                        # rules 2-4: the name contract
    if not name:
        problems.append(f"{folder.name}: 'name' missing")
    elif not NAME_RE.fullmatch(name) or len(name) > MAX_NAME:
        problems.append(f"{folder.name}: invalid name {name!r}")
    elif name != folder.name:                        # identity: label == folder
        problems.append(f"{folder.name}: name {name!r} != folder name")

    desc = fm.get("description", "")                 # rule 5: the shelf label exists
    if not desc:
        problems.append(f"{folder.name}: 'description' missing or empty")
    elif len(desc) > MAX_DESC:
        problems.append(f"{folder.name}: description over {MAX_DESC} chars")

    if len(text.splitlines()) > MAX_LINES:           # rule 6: the body budget
        problems.append(f"{folder.name}: SKILL.md over {MAX_LINES} lines")

    for ref in REF_RE.findall(text):                 # rule 7: no dead pointers
        if not (folder / ref).exists():
            problems.append(f"{folder.name}: referenced file missing: {ref}")

    version = fm.get("metadata.version", "")         # house rule (SK-19): versioned
    if not re.fullmatch(r"\d+(\.\d+){1,2}", version):
        problems.append(f"{folder.name}: metadata.version missing or not "
                        f"a quoted semver-ish string (got {version!r})")
    return problems


def check_all(skills_dir: pathlib.Path) -> dict[str, list[str]]:
    """Check every skill folder under skills_dir; return {name: problems}.

    Example:
        >>> bad = {k: v for k, v in check_all(pathlib.Path("skills")).items() if v}
        >>> bad
        {}
    """
    return {
        p.name: check_skill(p)
        for p in sorted(skills_dir.iterdir())
        if p.is_dir()
    }
```

"""Day 30 — the skills shelf under test.

Structural checks run on every `uv run pytest` (free). The behavioral

import pytest

from tools.skill_checks import check_all, check_skill, parse_frontmatter

SKILLS = pathlib.Path("skills")


def test_all_production_skills_are_spec_valid() -> None:
    """Every folder on the production shelf passes every mechanical rule."""
    problems = {k: v for k, v in check_all(SKILLS).items() if v}

def test_parser_handles_folded_descriptions() -> None:
    """The subset parser folds indented continuation lines (Day 25 style)."""
    fm = parse_frontmatter(
        "---\nname: x\ndescription: first line\n  second line\n---\nbody"
    )
    assert fm is not None and fm["description"] == "first line second line"


def test_checker_catches_a_broken_skill(tmp_path: pathlib.Path) -> None:
    """A test for the tester: plant a bad skill in tmp, expect findings.

    (tmp_path is pytest's throwaway dir — nothing touches skills/.)
    """
    bad = tmp_path / "Bad--Name"                     # wrong name, missing ref
    bad.mkdir()
    (bad / "SKILL.md").write_text(
        "---\nname: Bad--Name\ndescription: x\n---\nsee references/gone.md\n",
        encoding="utf-8",
    )
    problems = check_skill(bad)
    assert any("invalid name" in p for p in problems)
    assert any("referenced file missing" in p for p in problems)


def test_evil_fixture_passes_structure_by_design() -> None:
    """The Day 29 lesson, pinned as executable documentation: structural
    checks CANNOT catch a hostile skill. evil-helper is spec-shaped; only
    the human audit (Day 29's three lenses) rejects it. If this test ever

@pytest.mark.quota                                    # SPENDS ~2 model calls
def test_ticket_triage_still_activates() -> None:
    """Behavioral smoke: the flagship skill routes on its trigger task.

    Asserts on the EVENT STREAM (did load_skill fire for ticket-triage?),
    not on answer text — Day 26's absence-of-a-call lesson, as a test.
    Run explicitly:  uv run pytest -m quota
    """
    import asyncio

    from google.genai import types

    from google.adk.runners import InMemoryRunner
    from sutra.config import load_env
    from sutra.skill_agent import make_triage_desk

    load_env()

    async def _skill_loads() -> bool:
        runner = InMemoryRunner(agent=make_triage_desk(with_tools=True))
        session = await runner.session_service.create_session(
            app_name=runner.app_name, user_id="test"
        )
        msg = types.Content(role="user",
                            parts=[types.Part(text="Triage ticket 4521.")])
        async for event in runner.run_async(
            user_id="test", session_id=session.id, new_message=msg

            for call in event.get_function_calls():
                if (call.name == "load_skill"
                        and "ticket-triage" in str(call.args)):
                    return True                       # the binder was opened
        return False

    assert asyncio.run(_skill_loads()), (
        "ticket-triage never activated on its own trigger task — "
        "check the description before checking the body (Day 26)."
    )

## 5 · 💥 Failure lab — the green suite that tested nothing

> 🎬 **The scene:** three weeks from now. A teammate "tidies up" `ticket-triage`:
> renames `references/severity-rubric.md` to `references/rubric.md`, rewrites the
> description to the shorter "Handles ticket triage.", and — being diligent! — runs
> the tests. Imagine today had gone slightly differently: you'd written
> `test_all_production_skills_are_spec_valid` but pointed it at a *copy* of the
> skills made at test-setup time, or listed the skill folders in a hardcoded list
> that predates the rename. Green. Ship.
> 😬 **The naive fix:** "we have skill tests, we're covered."
> 💥 **Why it fails twice:** first, the stale-target trap — a structural suite is
> only as honest as its enumeration; hardcoded lists and copies drift from the real
> shelf, and a dead `references/` pointer sails through because the test examined
> yesterday's files. (Today's suite enumerates `skills/` live, every run — that
> design choice IS the defense.) Second, the coverage illusion — even the honest
> structural suite says nothing about "Handles ticket triage." being routing mush:
> that regression lives in *sense*, and only the quota-marked behavioral smoke
> (which the teammate's default `pytest` run silently deselected!) would have caught
> the skill no longer activating. Two greens, two different lies.
> 💡 **The insight:** **a test suite has a scope, and the scope must be as loudly
> documented as the tests themselves.** Today's suite states its boundary in
> executable form — `test_evil_fixture_passes_structure_by_design` pins "structure
> ≠ sense" as a permanent, running reminder, and the `quota` marker makes the
> behavioral gap visible in every default run's `deselected` count. When you read
> `2 deselected` on a Friday, that number is the suite telling you what it did NOT
> check this week — listen to it, and spend the 2 calls.

## 6 · 🎤 Interview corner

1. **"How do you test something as fuzzy as an agent skill?"** — By splitting the
   fuzzy from the mechanical. Mechanical: an always-on structural suite — spec
   frontmatter rules, name-folder identity, dead reference detection, length
   budgets, version presence — stdlib parser, free, runs on every pytest. Fuzzy:
   behavioral smokes that assert on the *event stream* — did `load_skill` fire for
   the flagship skill on its trigger task — marked and opt-in because they spend
   model quota. And one boundary test that documents what the suite can't do: our
   deliberately poisoned fixture passes structure by design, as a running reminder
   that hostile intent is caught by human audit, not lint.
2. **"Why version prose files at all?"** — Because every discipline around a skill
   needs to name *which* skill: the audit trail says what text was reviewed, evals
   say what version scored what, bug reports say where it broke. We use
   `metadata.version` with bump rules tied to obligations — patch is free, minor
   re-runs the behavioral smoke, major triggers a full re-read under third-party
   rules, since a changed procedure is a new skill wearing an old name. No parallel
   changelog file: git history on the skill folder is the changelog; the version is
   the label the history hangs off.
3. **"Your CI is green — what do you still not know about your skills?"** — Three
   honest gaps, in increasing order of danger: whether descriptions still *route*
   (sense, not structure — covered only by the opt-in behavioral lane and, later,
   the evalset); whether the procedure is still *correct* for the domain (no test
   knows our refund policy changed — only review does); and whether the text is
   *trustworthy* (a hostile-but-valid skill passes everything mechanical — that's
   what the audit-and-pin pipeline is for). Knowing precisely what green doesn't
   mean is, I'd argue, the actual skill being interviewed for.
