## 3 · 📚 Concepts

### ADK-54 — `run_live` + `LiveRequestQueue`: a conversation is a queue, not a call

**The story.** A phone call is one object: dial, talk, hang up. A **two-way radio net**
is different: the channel is open, and what travels is a *stream of small messages* in
both directions — "over", "copy", bursts of speech — with no notion of "the request"
and "the response". ADK models the live session exactly so:

| Radio net | ADK live | Verified symbol |
| --- | --- | --- |
| keying the mic, sending bursts | you *put* things on a queue | `LiveRequestQueue()`; `send_content(Content)` for text, `send_realtime(Blob)` for audio frames |
| the channel itself | one `run_live` call, alive until closed | `runner.run_live(user_id, session_id, live_request_queue, run_config)` → `async for event in …` |
| "out" | close the queue; the generator ends | `queue.close()` |
| what the radio can carry | text **or** audio per message (not both) | `LiveRequest.content` xor `LiveRequest.blob` (+ `activity_start/end`, `close`) |

Three consequences shape the server code. (1) **Two concurrent loops**: one task reads
the browser's WebSocket and *feeds* the queue; another consumes `run_live` events and
*writes* them to the WebSocket. They share only the queue. (2) **Audio is frames**:
16-bit little-endian PCM, any rate you declare in the MIME type (`audio/pcm;rate=16000`
is native); you send them continuously while the person speaks — the model's automatic
VAD decides when a turn ended. (3) **The session has a clock**: audio-only sessions
cap at 15 minutes; `session_resumption` lets a reconnect pick up the context, and
`context_window_compression` keeps long sessions inside the model's window — you set
both and you still design for sessions measured in minutes.

💡 **Mental model: a live session is a queue you feed and a stream you drain — there is
no "request" any more, only messages in flight both ways.**

### ADK-55 — Audio config and the live event stream

**The story.** The radio operator has three dials: *what comes back* (voice or text),
*which voice*, and *do I also get a written transcript*. Then, listening, four things
matter: is this a piece or the end, did they stop, what did they actually say, and
what did **I** say as the machine heard it.

The dials (adk.dev part 4, verified):

```python
RunConfig(
    streaming_mode=StreamingMode.BIDI,
    response_modalities=["AUDIO"],          # or ["TEXT"] - audio for the radio
    speech_config=types.SpeechConfig(       # which voice
        voice_config=types.VoiceConfig(
            prebuilt_voice_config=types.PrebuiltVoiceConfig(voice_name="Kore"))),
    input_audio_transcription=types.AudioTranscriptionConfig(),    # what you said
    output_audio_transcription=types.AudioTranscriptionConfig(),   # what it said
    session_resumption=types.SessionResumptionConfig(),            # survive reconnects
    max_llm_calls=40,                       # Day 7's fuse, live edition (Day 59's habit)
)
```

(`voice_name`: the prebuilt voices are listed on ai.google.dev's Live docs — adk.dev's
own example uses one; pick one and record it. The model may return a different default
if the name is unknown — `TODO(read the current voice list the day you run this)`.)

The listening rules, per field (adk.dev part 3, verified) — this table *is* the
client:

| Event field | Meaning | Client action |
| --- | --- | --- |
| `content.parts[i].inline_data` (mime `audio/pcm;rate=24000`) | a slice of the model's voice | base64 → PCM → queue into the speaker; **output is always 24 kHz** |
| `content.parts[i].text` with `partial=True` | a piece of text (TEXT modality) | append (Day 7) |
| `output_transcription` | what the voice said, as text | show it — it's your record |
| `input_transcription` | what the machine heard *you* say | show it — honesty check on the mic |
| `turn_complete=True` | the model finished this turn | unlock the UI; keep listening |
| `interrupted=True` | your voice cut it off | **flush the playback queue now**; the rest of that generation is gone server-side too ("canceled and discarded") |
| `usage_metadata` | token counts | bill the ledger (Day 24) — live turns are not free *requests* even when free of charge |

The caveat from yesterday lives here too: **no model callbacks on this path**. Tonight's
live agent therefore has **no tools at all**; Day 76 adds read-only tools and Day 77's
standup agent gets its brakes from Day 68's permission tiers and its instruction —
never from a `before_model_callback` that won't run.

💡 **Mental model: the live client is a small state machine keyed on four fields —
audio part, transcription, `turn_complete`, `interrupted` — and `interrupted` is the
one that must act immediately.**

```python
live_agent = Agent(

def live_config(modality: str = "AUDIO") -> RunConfig:
    """The radio's dials (adk.dev/live/dev-guide/part4, verified 2026-08-19)."""
    return RunConfig(
        streaming_mode=StreamingMode.BIDI,
        response_modalities=[modality],           # "AUDIO" for voice, "TEXT" for smoke
        input_audio_transcription=types.AudioTranscriptionConfig(),
        output_audio_transcription=types.AudioTranscriptionConfig(),
        session_resumption=types.SessionResumptionConfig(),
        max_llm_calls=40,                         # the fuse, live edition
    )


def event_to_client(event) -> dict | None:
    """Shrink one live event to the four things the browser acts on.

    Returns None for events with nothing client-relevant (keeps the socket quiet).
    Audio bytes are base64 so they fit in a JSON text frame (simple > clever today).

    Example:
        >>> event_to_client(type("E", (), {"content": None, "partial": None,
        ...     "turn_complete": True, "interrupted": None,
        ...     "input_transcription": None, "output_transcription": None})())
        {'turn_complete': True}
    """
    out: dict = {}
    if event.content and event.content.parts:
        for p in event.content.parts:
            if getattr(p, "inline_data", None) and p.inline_data.data:
                out.setdefault("audio", []).append({
                    "mime": p.inline_data.mime_type,              # e.g. audio/pcm;rate=24000
                    "b64": base64.b64encode(p.inline_data.data).decode()})
            elif getattr(p, "text", None) and event.partial:
                out["text"] = out.get("text", "") + p.text
    for name in ("input_transcription", "output_transcription"):
        tr = getattr(event, name, None)
        if tr and getattr(tr, "text", None):
            out[name] = tr.text
    if getattr(event, "turn_complete", None):
        out["turn_complete"] = True
    if getattr(event, "interrupted", None):
        out["interrupted"] = True                  # the one the client must act on NOW
    return out or None


@app.websocket("/ws/live")
async def ws_live(ws: WebSocket, modality: str = "AUDIO") -> None:
    """One WebSocket = one live session. Two loops share one queue.

    Browser -> server JSON: {"type":"text","text":…} | {"type":"audio","b64":…,"rate":16000}
                            | {"type":"close"}
    Server -> browser JSON: event_to_client(...) dicts.
    """
    await ws.accept()
    queue = LiveRequestQueue()                                   # the radio channel
    sid = (await _live_runner.session_service.create_session(
        app_name=_live_runner.app_name, user_id="browser")).id
    log.info("live_open", extra={"session_id": sid, "model": LIVE_MODEL})

    async def uplink() -> None:                                  # browser -> queue
        try:
            while True:
                msg = await ws.receive_json()
                if msg["type"] == "text":
                    queue.send_content(types.Content(
                        role="user", parts=[types.Part(text=msg["text"])]))
                elif msg["type"] == "audio":
                    queue.send_realtime(types.Blob(
                        mime_type=f"audio/pcm;rate={msg.get('rate', 16000)}",
                        data=base64.b64decode(msg["b64"])))
                elif msg["type"] == "close":
                    break
        except WebSocketDisconnect:
            pass
        finally:
            queue.close()                                        # "out" - ends run_live

    up = asyncio.create_task(uplink())
    try:
        async for event in _live_runner.run_live(                # queue -> events -> browser
            user_id="browser", session_id=sid,
            live_request_queue=queue, run_config=live_config(modality),
        ):
            if (payload := event_to_client(event)) is not None:
                await ws.send_json(payload)
            if getattr(event, "usage_metadata", None):           # bill it (Day 24)
                log.info("live_usage", extra={"session_id": sid,
                         "total": event.usage_metadata.total_token_count})
    except WebSocketDisconnect:
        pass
    finally:
        up.cancel()
        queue.close()
        log.info("live_closed", extra={"session_id": sid})
```

```html
<hr>
<h2>Live (bidi) <small>— model voice, Live quota</small></h2>
<button id="live-start">Start live</button>
<button id="live-stop">Stop</button>
<div id="live-log"></div>
<script>
// Day 75: two-way path. Mic -> 16 kHz PCM16 frames -> WebSocket -> LiveRequestQueue.
// Model audio (24 kHz PCM16) <- WebSocket <- run_live events -> speaker.
let ws = null, audioCtx = null, micNode = null, playHead = 0;
const WS = "ws://localhost:8766/ws/live";
const logLine = (s) => { const d = document.createElement("div"); d.textContent = s; $("live-log").prepend(d); };

function floatTo16(f32) {                       // Float32 [-1,1] -> Int16 little-endian
  const out = new Int16Array(f32.length);
  for (let i = 0; i < f32.length; i++) out[i] = Math.max(-1, Math.min(1, f32[i])) * 0x7fff;
  return out;
}
function b64(bytes) { let s = ""; bytes.forEach(b => s += String.fromCharCode(b)); return btoa(s); }
function playPcm24k(b64data) {                  // schedule one 24 kHz PCM16 slice
  const raw = Uint8Array.from(atob(b64data), c => c.charCodeAt(0));
  const i16 = new Int16Array(raw.buffer);
  const buf = audioCtx.createBuffer(1, i16.length, 24000);
  const ch = buf.getChannelData(0);
  for (let i = 0; i < i16.length; i++) ch[i] = i16[i] / 0x8000;
  const src = audioCtx.createBufferSource(); src.buffer = buf; src.connect(audioCtx.destination);
  playHead = Math.max(playHead, audioCtx.currentTime); src.start(playHead); playHead += buf.duration;
}
function flushPlayback() { playHead = 0; audioCtx.close(); audioCtx = new AudioContext({sampleRate: 24000}); }

$("live-start").onclick = async () => {
  audioCtx = new AudioContext({sampleRate: 24000});
  ws = new WebSocket(WS);
  ws.onmessage = (e) => {                        // the four-field state machine
    const m = JSON.parse(e.data);
    if (m.audio) m.audio.forEach(a => playPcm24k(a.b64));
    if (m.input_transcription)  logLine("you: " + m.input_transcription);
    if (m.output_transcription) logLine("sutra: " + m.output_transcription);
    if (m.interrupted) { logLine("[interrupted]"); flushPlayback(); }   // act NOW
    if (m.turn_complete) logLine("[turn complete]");
  };
  ws.onopen = async () => {
    const stream = await navigator.mediaDevices.getUserMedia({audio: true});
    const micCtx = new AudioContext({sampleRate: 16000});           // native Live input rate
    const src = micCtx.createMediaStreamSource(stream);
    micNode = micCtx.createScriptProcessor(4096, 1, 1);             // simple > AudioWorklet today
    micNode.onaudioprocess = (ev) => {
      if (ws.readyState !== 1) return;
      const i16 = floatTo16(ev.inputBuffer.getChannelData(0));
      ws.send(JSON.stringify({type: "audio", rate: 16000, b64: b64(new Uint8Array(i16.buffer))}));
    };
    src.connect(micNode); micNode.connect(micCtx.destination);
    logLine("[live: listening]");
  };
};
$("live-stop").onclick = () => { if (ws) { ws.send(JSON.stringify({type: "close"})); ws.close(); ws = null; } logLine("[live: closed]"); };
</script>
```

## 5 · 💥 Failure lab — the session that never hung up

> 🎬 **The scene:** the demo is lovely; you show three colleagues, each opens the page,
> clicks Start live, chats, and then — as people do — closes the tab without Stop. The
> fourth person clicks Start live and gets… nothing: the socket opens and the model
> never answers.
> 😬 **The naive fix:** "the Live API is flaky today," retry, refresh, blame the Wi-Fi.
> 💥 **Why it fails:** nothing is flaky. Every closed tab left a `run_live` generator
> alive on the server with its queue open — and Live sessions are a **counted,
> tier-based resource** ("concurrent sessions: tier-based", adk.dev part 1). Three
> zombies ate the free tier's concurrency; the fourth session queued or was refused.
> Unlike an HTTP request, a live session has a *lifetime you must end*: the queue's
> `close()` ends the generator; a dropped WebSocket must *trigger* that close — which is
> why `ws_live` closes the queue in `uplink()`'s `finally` **and** in the outer
> `finally`, and cancels the uplink task. Reproduce it: comment out both `queue.close()`
> calls, open and kill two tabs, watch the log never print `live_closed`, and watch the
> third session stall. Then restore the closes and watch every disconnect log
> `live_closed` within a second.
> 💡 **The insight:** **a stateful connection is a resource with a lifetime; the
> disconnect path is part of the protocol, not an error path.** Stateless HTTP (Day 74's
> SSE, the 2026 MCP) forgives sloppy clients; bidi sockets do not. Count your sessions
> the way Day 24 counts requests — and put a 15-minute cap in your head, because the API
> has one in its rules.

## 6 · 🎤 Interview corner

1. **"How does a bidirectional voice agent differ from a chat agent, architecturally?"**
   — There is no request/response any more: the client continuously feeds a queue
   (text, PCM frames at a declared rate, activity signals) while the server drains an
   event stream (audio slices, transcriptions, `turn_complete`, `interrupted`). That
   means two concurrent loops sharing one queue, a state machine in the client keyed on
   those four fields — with `interrupted` requiring an *immediate* playback flush — and
   a session with a lifetime you must end explicitly because it's a counted resource.
   In ADK that's `run_live` + `LiveRequestQueue` + a BIDI `RunConfig`; the agent object
   is unchanged from the text version.
2. **"What audio format do you send, and why does it matter?"** — Raw 16-bit
   little-endian PCM; input natively 16 kHz (the API resamples if I declare another
   rate in the MIME type `audio/pcm;rate=…`), output always 24 kHz — so the player
   must schedule buffers at 24 kHz or everything sounds wrong. I capture with a 16 kHz
   AudioContext, convert Float32 to Int16, and ship frames as base64 in JSON — simple
   and debuggable; binary frames are the optimisation I'd do second.
3. **"Your demo depends on a preview API with a free tier — what's your fallback?"** —
   The same page has a push-to-talk loop: browser `SpeechRecognition` → the SSE text
   endpoint → `speechSynthesis`. Zero audio quota, works anywhere Chrome/Edge runs, and
   it's the default path for the standup agent; Live is the upgrade, used inside limits
   I read in AI Studio and recorded with a date — and I close every session, because
   a zombie session is the outage nobody diagnoses.
