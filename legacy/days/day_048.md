## 1 · 🎬 Where we are — the story so far

The desk now has real furniture: drawers that survive the night (Day 47) and a filing
cabinet any session can search (Day 46). And with that, a trap has quietly armed itself.

Here is the trap. Filing is one line — `add_session_to_memory(session)` — and one-line
powers get used without thought. The lazy default is to file **everything**: every
greeting, every "let me check that for you", every half-finished thought, every user
email address that wanders through a transcript. For a week, nothing bad happens. Then
three slow disasters mature at once: search drowns (every query matches a hundred
pleasantries), the desk starts *confidently recalling things that were never decisions*
("last time we told the user to clear cookies" — no, we *considered* it), and one day you
realize the cabinet contains data nobody should have kept.

Human institutions solved this centuries ago, and not by remembering harder. A hospital
does not staple every hallway conversation into the patient chart. A court records the
*verdict*, not the jury's lunch order. **What to write down is a designed decision** —
and institutions write that decision down too. Today Sutra gets its version: a retention
policy as code.

## 3 · 📚 Concepts

### AG-12 — A taxonomy: three kinds of remembering, three scopes

**The hospital story.** Follow one patient through a hospital and count the *different*
memories in play:

- The nurse's **scratchpad** during a procedure — vital right now, shredded tonight.
- The **patient chart** — the curated history of *this patient*: diagnoses, allergies,
  what worked. Follows the patient across visits.
- The **medical literature** — what the *institution* knows about medicine in general.
  No patient's name in it; every doctor draws on it.

Three memories, three lifetimes, three access patterns — and no doctor confuses them.
Now map them onto everything you've built:

| Hospital | Kind (cog-sci name) | Sutra mechanism | Lifetime |
| --- | --- | --- | --- |
| Nurse's scratchpad | **working memory** | the context window + session state (`temp:` for true scratch) | one conversation (or one turn) |
| Patient chart | **episodic memory** | `MemoryService` entries scoped per user (Day 46) | across sessions, per user |
| Medical literature | **semantic memory** | the ticket archive + KB (`data/tickets.db`, Day 39) — searchable by *meaning* from Day 49 | the desk's lifetime, shared |

And the scope axis you've had since Day 17 runs straight through it: session state /
`user:` / `app:` are exactly *whose* memory something is. The taxonomy's payoff is
diagnostic: when someone says "the agent should remember X," you now ask **which row?** —
"remember the user prefers short answers" is chart (`user:` + memory entries); "remember
that SameSite cookies caused 4521" is literature (the archive); "remember what tool call
we're waiting on" is scratchpad (session, maybe `temp:`), and *filing it would be a bug*.

💡 **Mental model: memory is not one place — it is three lifetimes.** Most "agent memory
is broken" complaints are really *a fact filed under the wrong lifetime*.

### AG-13 — Curation: forgetting is a feature

Three principles, each of which you will enforce in code within the hour:

**1. Distill, don't transcribe.** The unit of memory is a *finding*, not a transcript.
"Ticket 4521: root cause SameSite/Secure cookie flags, fix KB-104" is a finding. The
forty turns that produced it are exhaust. Filing exhaust doesn't just waste space — it
*degrades recall*, because every search now competes with noise (Day 46's keyword
matcher and Day 49's vectors both rank against everything in the store). A cabinet's
value is what you can *find*, and findability is bought with exclusion.

**2. Forgetting is protective, not lossy.** Some things must not be remembered:
- **PII** — even in a synthetic-data project, the discipline is real (SEC-12/13 land
  Day 69; the free-tier-may-train caveat from Addendum 02 makes this non-negotiable:
  never let a real name/email/phone even *transit* toward storage).
- **Speculation** — half-formed hypotheses recalled later sound like conclusions.
  Memory launders uncertainty into confidence; file only what was *concluded*.
- **The stale** — a memory that says "the vendor status page is down" was true for an
  hour. Facts with expiry dates need the date stored with them (our entries carry
  `recorded_at` for exactly this).

**3. The gate must be code, not vibes.** A policy that lives in a doc gets skipped on a
busy Tuesday. From today, Sutra has one function — `distill(session_text) →
list[MemoryCandidate]` → `apply_policy(…)` — and the *only* road into
`add_session_to_memory` runs through it. Tested, grep-able, auditable. (This is the
Day 40 allowlist philosophy pointed inward: the REGISTRY governed what comes *in* from
servers; the memory policy governs what stays *behind* from conversations.)

**Step 1 — `sutra/memory_policy.py`.**

```python
"""Day 48 — the memory gate: what Sutra keeps, redacts, and refuses.

One road into the filing cabinet. Sessions get distilled into
MemoryCandidate lines; apply_policy() keeps findings, kills noise and
speculation, and redacts PII patterns before anything is stored.
Pure stdlib on purpose: curation must not depend on a model call.

Run the demos (zero quota):

    python -m sutra.memory_policy show      # print the policy table
    python -m sutra.memory_policy distill   # a messy session, filtered
    python -m sutra.memory_policy redact    # PII goes in, [REDACTED-*] comes out
"""
from __future__ import annotations

import re
import sys
from dataclasses import dataclass, field
from datetime import date

from sutra.logging_setup import get_logger

log = get_logger(__name__)

# ---------------------------------------------------------------------------
# The policy, as data — so `show` can PRINT it and tests can CHECK it.
# Three verdicts exist. There is no fourth ("keep it just in case" is spelled DROP).
# ---------------------------------------------------------------------------

KEEP_MARKERS = (
    "root cause", "resolved", "fix:", "workaround", "decision:", "prefers",
)
DROP_MARKERS = (
    "maybe", "might be", "not sure", "hello", "thanks", "checking", "one moment",
)

# PII patterns: redact BEFORE storage, never after. Synthetic-only project,
# but the pipeline behaves as if data were real (SEC-12/13 discipline).
PII_PATTERNS: dict[str, re.Pattern[str]] = {
    "EMAIL": re.compile(r"[\w.+-]+@[\w-]+\.[\w.]+"),
    "PHONE": re.compile(r"(?<!\d)(?:\+?\d[\s-]?){9,14}\d(?!\d)"),
}


@dataclass
class MemoryCandidate:
    """One line that WANTS to enter memory, plus its fate.

    Attributes:
        text: the candidate finding (post-redaction if it survives).
        verdict: "KEEP" | "DROP" — set by apply_policy.
        reason: which rule decided (audit trail — Principle 12).
        recorded_at: ISO date; stale-fact hygiene starts with a date.

    Example:
        >>> MemoryCandidate("Ticket 4521: root cause was cookie flags.")
        MemoryCandidate(text='Ticket 4521: root cause was cookie flags.', ...)
    """
    text: str
    verdict: str = "PENDING"
    reason: str = ""
    recorded_at: str = field(default_factory=lambda: date.today().isoformat())


def redact(text: str) -> tuple[str, list[str]]:
    """Replace PII patterns with [REDACTED-<KIND>] markers.

    Args:
        text: raw candidate text.

    Returns:
        (clean_text, kinds_found) — kinds_found lists which patterns hit,
        so callers can log redactions without logging the PII itself.

    Example:
        >>> redact("mail rita@example.com about it")
        ('mail [REDACTED-EMAIL] about it', ['EMAIL'])
    """
    kinds: list[str] = []
    for kind, pattern in PII_PATTERNS.items():        # each pattern sweeps the text
        if pattern.search(text):
            kinds.append(kind)                        # record WHAT was found…
            text = pattern.sub(f"[REDACTED-{kind}]", text)  # …never the value itself
    return text, kinds


def distill(session_text: str) -> list[MemoryCandidate]:
    """Split a session's text into candidate lines (one per sentence-ish line).

    Deliberately dumb: the interesting judgment lives in apply_policy,
    and Day 49's retrieval layer is where *meaning* gets handled.

    Args:
        session_text: the raw conversation text to consider for filing.

    Returns:
        One MemoryCandidate per non-empty line.

    Example:
        >>> len(distill("a\\n\\nb"))
        2
    """
    return [MemoryCandidate(line.strip())
            for line in session_text.splitlines() if line.strip()]


def apply_policy(candidates: list[MemoryCandidate]) -> list[MemoryCandidate]:
    """Give every candidate a verdict + reason; redact keepers.

    The order is the policy: (1) redact, (2) drop noise/speculation,
    (3) keep explicit findings, (4) default-DROP. The default matters
    most: memory is opt-in (Day 46), so unclassified lines do NOT sneak in.

    Args:
        candidates: from distill().

    Returns:
        The same list, verdicts filled in. Callers store only KEEPs.

    Example:
        >>> got = apply_policy([MemoryCandidate("root cause: dns")])
        >>> got[0].verdict
        'KEEP'
    """
    for cand in candidates:
        cand.text, kinds = redact(cand.text)          # PII never survives to storage
        lower = cand.text.lower()
        if kinds:
            log.info("memory_redaction", extra={"kinds": kinds})
        if any(m in lower for m in DROP_MARKERS):     # noise & speculation out first
            cand.verdict, cand.reason = "DROP", "noise/speculation marker"
        elif any(m in lower for m in KEEP_MARKERS):   # explicit findings in
            cand.verdict, cand.reason = "KEEP", "finding marker"
        else:                                         # everything else: DEFAULT DROP
            cand.verdict, cand.reason = "DROP", "default-deny (no finding marker)"
    return candidates


def keepers(session_text: str) -> list[str]:
    """The one public road to the cabinet: distill → policy → texts to store.

    Day 46's filing call (and Day 52's auto-filing callback) MUST route
    through this — it is the whole point of today.

    Example:
        >>> keepers("Resolved: ticket 4610 was the same cookie bug. thanks!")
        ['Resolved: ticket 4610 was the same cookie bug.']
    """
    return [c.text for c in apply_policy(distill(session_text)) if c.verdict == "KEEP"]


# --- demos ------------------------------------------------------------------

MESSY_SESSION = """Hello! One moment, checking that for you.
Might be a proxy issue, not sure yet.
Root cause: session cookie missing SameSite and Secure flags.
Fix: apply KB-104; user confirmed resolved.
User callback number is +91 98765 43210 if we need them.
Thanks for your patience!"""


def demo_show() -> None:
    """Print the policy as a table — the doc IS the code."""
    print("KEEP if line contains:", ", ".join(KEEP_MARKERS))
    print("DROP if line contains:", ", ".join(DROP_MARKERS))
    print("REDACT patterns:", ", ".join(PII_PATTERNS))
    print("default verdict: DROP (memory is opt-in)")


def demo_distill() -> None:
    """The messy session through the gate; every fate printed with its reason."""
    for c in apply_policy(distill(MESSY_SESSION)):
        print(f"{c.verdict:4} [{c.reason}] {c.text}")


def demo_redact() -> None:
    """PII in, markers out — and note what we log (kinds) vs never log (values)."""
    clean, kinds = redact("Reach me at rita@example.com or +91 98765 43210.")
    print("stored form:", clean)
    print("logged form:", {"kinds": kinds})


def main() -> None:
    demos = {"show": demo_show, "distill": demo_distill, "redact": demo_redact}
    name = sys.argv[1] if len(sys.argv) > 1 else "show"
    if name not in demos:
        print(f"usage: python -m sutra.memory_policy [{'|'.join(demos)}]")
        raise SystemExit(2)
    demos[name]()


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the desk that remembered a guess

> 🎬 **The scene:** before today's gate existed, someone filed a whole session including
> the line "might be a proxy issue, not sure yet." Three weeks later a similar ticket
> arrives; the researcher searches memory; the snippet comes back — *shorn of its
> hedging context* — and the draft reply opens: "This is a known proxy issue."
> 😬 **The naive fix:** prompt the agent to "double-check memories before using them."
> 💥 **Why it fails:** the model has nothing to check *against* — the memory is the
> evidence, and it arrives wearing the authority of the filing cabinet. Retrieval strips
> provenance: a guess and a verdict come back in the same font. The model isn't being
> gullible; the *store* is lying about confidence levels. This is memory laundering:
> uncertainty in, institutional fact out.
> 💡 **The insight:** **curation is where truth-maintenance happens — at write time, not
> read time.** Store conclusions, not deliberations; stamp dates on facts that can rot;
> default-deny everything else. A smaller, honest memory beats a complete, lying one —
> the same Principle-10 honesty rule, applied to the past instead of the present.

Observed today: `demo_distill` — the "might be a proxy issue" line dies at the gate with
its reason printed, and the test `test_speculation_is_dropped_with_reason` pins it there
forever.

## 6 · 🎤 Interview corner

1. **"How would you design memory for a long-running agent?"** — Start with the
   taxonomy, not the database: working memory (the context window + session state),
   episodic (per-user curated findings), semantic (the shared knowledge base). Each gets
   its own lifetime, scope, and mechanism — in my project that's session services, a
   MemoryService behind a policy gate, and a SQLite archive with embedding search. Then
   the part most designs skip: a write-time curation policy as tested code — distill to
   findings, redact PII before storage, default-deny. Memory quality is decided at write
   time; read-time cleverness can't recover it.
2. **"Why is forgetting a feature and not a bug?"** — Three concrete reasons from
   building one: recall precision (every stored noise-line competes with real findings
   in ranking — exclusion is how findability is bought); truth maintenance (stored
   speculation gets recalled as fact later — memory launders uncertainty); and safety
   (PII that is never stored can never leak, be subpoenaed, or train someone's free
   tier). My default verdict is DROP with a logged reason — opt-in memory, auditable
   kills.
3. **"Session state vs long-term memory — where's the line?"** — Ask "who needs this,
   and for how long?" This conversation → session state. This user, across
   conversations → episodic memory, through the curation gate. Everyone, forever → the
   knowledge base. And genuinely transient scratch gets a naming convention that means
   *never persisted* (`temp:` in ADK) — retention policy in the key name, greppable in
   review.
