## 3 · 📚 Concepts

### SEC-12 — Data boundaries: know where it lives, decide where it may go

**The story.** A good hospital knows, for every filing cabinet, *what's in it* and
*who may carry a folder out of the room*. Not because every nurse is suspect — because
"we'll be careful" is not an answer an auditor accepts. Sutra has grown a dozen cabinets
in ten weeks without ever writing the list. Tonight you write it.

**The inventory (the run-day version lives in `docs/DATA_BOUNDARY.md`; this is the
shape):**

| Store | What's in it | Sensitivity | May go to a free model? | May go to memory? | May go to logs? |
| --- | --- | --- | --- | --- | --- |
| `data/tickets.db` (Day 39) | synthetic tickets + KB | synthetic-by-rule; *treated as* customer data | **redacted** body only | via `keepers()` only (Day 48) | ids + kinds, never bodies |
| `data/sessions.db` (Day 47) | full event transcripts | private (contains everything the model saw) | it *is* the model's input — hence redaction at the door | no (memory is distilled, Day 48) | no |
| `data/cache.db` (Day 51) | hashed prompts → responses | private (prompts!) | n/a (cache *avoids* the model) | no | key hashes only |
| `data/approvals.db` (Day 63) | payloads humans approved, hashed | integrity-critical | no — never sent to a model | no | ids + hashes |
| `data/tasks.db` (Days 43/60) | task rack, `processed_writes` | operational | no | no | ids |
| `data/archive_index*.json` (Day 49) | chunks + **local** embeddings | private (text chunks) | embeddings computed by **Ollama, locally** — never a cloud embedder (the Day 49 decision earns its keep today) | it *is* a memory service | no |
| `logs/*.jsonl`, `logs/quota.json` (Days 22/24) | structured events, quota | operational; must be PII-free | no | no | **scrubbed** (today) |
| `.env` | keys | secret | never | never | never |
| `tests/fixtures/**` | injection fixtures, evil-helper | synthetic, quarantined | only in red-team runs | never | kinds |

Three rules fall straight out of the table:

1. **The model door is the boundary.** Everything that crosses it is disclosed to a free
   provider. So redaction happens *there*, on every agent — a plugin's
   `before_model_callback` (adk.dev/safety's "PII Redaction Plugin" pattern) — not in
   each tool, not in each agent.
2. **Logs are a store too.** Day 22's formatter made logs structured; today it makes
   them *clean*: the plugin's `on_event_callback` scrubs event text before Day 22's
   handler writes it, and the guard/redaction logs already follow Day 48's rule: **log
   the kinds, never the values**.
3. **Some stores never meet a model.** Approvals, tasks, the cache, `.env`. Not
   "redacted" — *excluded*. A table row that says "no" is a permission (Day 68) for
   data instead of tools.

**What counts as PII here.** Day 48's `PII_PATTERNS` knew EMAIL and PHONE. Today widens
the set for the door: credit-card-shaped numbers (Luhn-ish 13–19 digits), IBAN-shaped
strings, national-id shapes you care about (keep it to one or two — a regex zoo is
theatre), IPv4 addresses, API-key/token shapes (`sk-…`, `AIza…`, 32+ hex), street
addresses are *out of scope* (no reliable regex; the synthetic rule covers them).
Redaction replaces values with `[REDACTED-KIND]` — the kind survives so the model can
still reason ("the customer gave a phone number") without the value.

💡 **Mental model: redaction is a one-way valve on the model door.** PII that never
crosses can never be trained on, cached, logged, or leaked by a future injection
(Day 66's 9802 gets weaker still: there is nothing personal *in* the archive rows the
model ever saw).

### SEC-13 — The free-tier training caveat, in the provider's words

**The story.** A free clinic treats you for free — and the consent form says your case
notes may be used to train students. Nothing sinister; it's the deal. You would still
not bring your neighbour's medical records to that clinic.

| Lane | What the provider says (read and dated on the day — the doc quotes the 2026-08-19 reading; **re-read at the Phase 10 gate**) | Sutra's rule |
| --- | --- | --- |
| **Gemini free tier** | pricing page, Free Tier column: "Used to improve our products: **Yes**" | synthetic or redacted input only; never a real customer's text |
| **Groq free** | `TODO(run day: read console.groq.com → Terms / Privacy → data retention & training for free accounts; quote + date)` | same rule — assume "may be used" until the quote says otherwise |
| **OpenRouter `:free`** | `TODO(run day: openrouter.ai/docs → Privacy, Logging & Data Collection → free models may be routed to providers that log/train; quote + date)` | same rule; additionally, free routes may *log prompts* — the breadth lane is the most exposed |

The rule the repo can actually enforce: **no real identities in anything committed

gate, because Dec 2025 taught us that free-tier terms move without much notice.

💡 **Mental model: free tokens are paid for with the prompt.** That's the price. Sutra
pays it only with data that was never anyone's.

```python
"""Day 69 — the data boundary: redact at the model door, scrub the logs.

Reuses Day 48's redact() + PII_PATTERNS (memory cabinet) and WIDENS the
pattern set for the model door. One plugin, two hooks:
  before_model_callback -> redact every part about to cross to a free lane
  on_event_callback     -> scrub event text before Day 22's handler logs it
Also: the synthetic-data lint used by tests (and optionally tools/check.py).

Importable with no side effects. Demo from the repo root:

    python -m sutra.data_boundary redact   # sample PII in, markers out (0 quota)
    python -m sutra.data_boundary lint     # scan seeds/fixtures/docs for real-looking identities
"""
from __future__ import annotations

import re
import sys
from pathlib import Path

from google.adk.plugins.base_plugin import BasePlugin       # Day 14 (verified 08-19)

from sutra.logging_setup import get_logger
from sutra.memory_policy import PII_PATTERNS as _MEMORY_PATTERNS, redact as _redact_memory  # Day 48

log = get_logger("data_boundary")

# Day 48's set (EMAIL, PHONE) + the door's additions. Keep the zoo small:
# each pattern must have a reason a reviewer accepts in one line.
DOOR_PATTERNS: dict[str, re.Pattern[str]] = {
    **_MEMORY_PATTERNS,
    "CARD":  re.compile(r"\b(?:\d[ -]?){13,19}\b"),                      # card-shaped runs
    "IBAN":  re.compile(r"\b[A-Z]{2}\d{2}[A-Z0-9]{11,30}\b"),             # IBAN shape
    "IPV4":  re.compile(r"\b(?:\d{1,3}\.){3}\d{1,3}\b"),                  # addresses in tickets
    "TOKEN": re.compile(r"\b(?:sk-[A-Za-z0-9]{16,}|AIza[0-9A-Za-z_-]{20,}|[a-f0-9]{32,})\b"),
}

# The synthetic-data rule, as data: identities in committed files must use
# reserved example domains / numbers. Real-looking = not on this list.
SYNTHETIC_EMAIL_DOMAINS = ("example.com", "example.org", "example.net", "acmecloud.example")
_EMAIL = re.compile(r"[\w.+-]+@([\w-]+\.[\w.-]+)")
LINT_ROOTS = ("sutra_mcp/seed_db.py", "tests/fixtures", "docs/days", "skills")


def redact_for_model(text: str) -> tuple[str, list[str]]:
    """Replace every PII-shaped value with [REDACTED-KIND]; return kinds hit.

    Example:
        >>> redact_for_model("card 4111 1111 1111 1111, ip 10.0.0.7, mail a@b.org")
        ('card [REDACTED-CARD], ip [REDACTED-IPV4], mail [REDACTED-EMAIL]', ['CARD', 'IPV4', 'EMAIL'])
    """
    kinds: list[str] = []
    for kind, pattern in DOOR_PATTERNS.items():
        if pattern.search(text or ""):
            kinds.append(kind)
            text = pattern.sub(f"[REDACTED-{kind}]", text)
    return text, kinds


def lint_synthetic(roots: tuple[str, ...] = LINT_ROOTS) -> list[str]:
    """Find real-looking emails in committed text. Returns 'path:line: domain' hits.

    Example:
        >>> lint_synthetic(("tests/fixtures",))   # clean repo
        []
    """
    hits = []
    for root in roots:
        p = Path(root)
        files = [p] if p.is_file() else list(p.rglob("*.*")) if p.exists() else []
        for f in files:
            if f.suffix.lower() not in {".py", ".json", ".md", ".txt", ".yaml", ".yml", ".sql"}:
                continue
            for n, line in enumerate(f.read_text(encoding="utf-8", errors="ignore").splitlines(), 1):
                for m in _EMAIL.finditer(line):
                    if not m.group(1).lower().endswith(SYNTHETIC_EMAIL_DOMAINS):
                        hits.append(f"{f}:{n}: {m.group(1)}")
    return hits


class DataBoundaryPlugin(BasePlugin):
    """Redact PII on the model door; scrub event text before it is logged.

    Usage:
        Runner(agent=..., plugins=[DataBoundaryPlugin(), PermissionPlugin(), ...])
    Order note (Day 14: plugins fire in list order, before agent callbacks):
    put this FIRST so the guardrails' judge (Day 67) also sees redacted text.
    """

    def __init__(self) -> None:
        super().__init__(name="data_boundary")
        self.kinds_seen: dict[str, int] = {}

    def _scrub_parts(self, parts) -> list[str]:
        """Redact text + function_response parts in place; return kinds hit."""
        hit: list[str] = []
        for part in parts or []:
            if part.text:
                part.text, k = redact_for_model(part.text); hit += k
            if part.function_response is not None:           # tool results cross too
                resp = part.function_response.response or {}
                for key, val in list(resp.items()):
                    if isinstance(val, str):
                        resp[key], k = redact_for_model(val); hit += k
        return hit

    async def before_model_callback(self, *, callback_context, llm_request):
        """The valve: nothing PII-shaped crosses to the model."""
        hit: list[str] = []
        for content in llm_request.contents or []:
            hit += self._scrub_parts(content.parts)
        if hit:
            for k in hit:
                self.kinds_seen[k] = self.kinds_seen.get(k, 0) + 1
            log.info("pii_redacted_at_door", extra={"kinds": sorted(set(hit)),
                                                    "agent": callback_context.agent_name})
        return None                                           # always carry on

    async def on_event_callback(self, *, invocation_context, event):
        """Logs are a store: scrub event text before Day 22's handler sees it."""
        if event.content and event.content.parts:
            self._scrub_parts(event.content.parts)
        return None                                           # None = event unchanged otherwise
        # TODO(run day: if your Day 22 logger reads event text BEFORE plugins
        # run on_event, scrub inside JsonLinesFormatter instead - print-then-pin.)


def demo_redact() -> None:
    sample = ("Customer Rita (rita.k@gmail.com, +91 98765 43210) paid with card "
              "4111 1111 1111 1111 from 203.0.113.9; token sk-abcdefghijklmnop1234.")
    clean, kinds = redact_for_model(sample)
    print("KINDS :", kinds)                                   # logged
    print("CLEAN :", clean)                                   # what the model sees
    # NOTE: the sample itself is synthetic (reserved test ranges); the demo
    # prints the raw string only because it is a lab - library code never does.


def demo_lint() -> None:
    hits = lint_synthetic()
    print("\n".join(hits) if hits else "synthetic-data lint: clean")
    raise SystemExit(1 if hits else 0)


def main() -> None:
    demos = {"redact": demo_redact, "lint": demo_lint}
    name = (sys.argv[1:] or ["redact"])[0]
    if name not in demos:
        print(f"usage: python -m sutra.data_boundary [{'|'.join(demos)}]"); raise SystemExit(2)
    demos[name]()


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the redaction that broke the tool

> 🎬 **The scene:** proud of the valve, you widen `DOOR_PATTERNS` with an "ID" rule:
> any 4-digit number → `[REDACTED-ID]`. Customer ids, order numbers, safe. Run a normal
> triage of #4521.
> 😬 **The naive fix:** "the model doesn't need ids; it needs symptoms."
> 💥 **Why it fails:** the *model* asks `lookup_ticket(ticket_id="[REDACTED-ID]")` —
> because the user turn it received said "triage ticket [REDACTED-ID]". Day 67's
> `screen_query` refuses the malformed id (good!), the model retries twice, the run ends
> honest-but-useless — and the cache (Day 51) now holds a redacted prompt that will never
> hit again. Over-redaction isn't "extra safe": it removes the *handles* the agent needs
> to act, and it does so silently on the far side of a plugin nobody reads while
> debugging the agent. (Day 14's failure lab, wearing privacy clothes.)
> 💡 **The insight:** **redact values that identify people, not values that identify
> work.** A ticket id is a handle to synthetic data inside your boundary; an email is a
> person. Keep the pattern set small, give every pattern a one-line reason, and test the
> *negative* case (`test_plain_ticket_text_is_untouched`) as seriously as the positive
> one. Run it: add the 4-digit rule, watch `uv run pytest` go red on the negative test
> before you ever spend a model call; remove it.

## 6 · 🎤 Interview corner

1. **"You're on free tiers — what happens to your data?"** — On Gemini's free tier the
   pricing page says, in the Free Tier column, "Used to improve our products: Yes" (I
   quote it with the date I read it, and re-read it at every phase gate). So the rule is
   structural: company data is synthetic by construction — enforced by a lint over seeds,
   fixtures and docs — and anything that *could* be personal is redacted at the model
   door by a plugin on every agent, with kinds logged and values never. Ollama is the
   only lane allowed to see unredacted text, and embeddings are computed locally for that
   reason.
2. **"Where exactly is your data boundary?"** — The model call. I keep an inventory of
   every store (tickets, sessions, cache, approvals, tasks, index, logs, `.env`) with a
   flow matrix: may it go to a free model, to memory, to logs. Some stores are
   redacted on the way out; some never meet a model at all (approvals, tasks, cache
   contents, keys); logs are scrubbed because logs are a store too. Redaction at the door
   means a future injection can't exfiltrate what the model never held.
3. **"How do you avoid redaction breaking the agent?"** — Small pattern set, each with
   a reason; redact identities, not handles (ticket ids stay); a negative test that plain
   ticket text passes through unchanged; and the valve runs *first* in the plugin order
   so every downstream layer — guards, cache, judge — sees the same redacted text and
   caching keys stay stable.
