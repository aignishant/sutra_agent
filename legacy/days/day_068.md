tools, Sutra takes two. Today the same discipline turns inward: **every node gets
exactly the tools its job needs, and a door enforces it even if someone later forgets.**

## 3 · 📚 Concepts

### SEC-10 — Least privilege: reach is a design decision

**The story.** A hospital gives every employee a badge. The badge opens *some* doors:
the cleaner's opens supply rooms and wards, the pharmacist's opens the drug cabinet, the
receptionist's opens the front desk and nothing else. Nobody thinks the receptionist is
untrustworthy. The badge encodes the *job*, not the *person* — and when a badge is
stolen, what it opens is the blast radius.

An agent's badge is its tool list. Until today Sutra handed out master keys, because a
long tool list is the easy default and the model "will only use what it needs." That last
clause is a prediction about a model's behavior; least privilege replaces it with a
fact about the building.

**The tiers** — every tool Sutra owns is classified once:

| Tier | Meaning | Examples | What governs it |
| --- | --- | --- | --- |
| **READ** | observes; no external effect | `lookup_ticket`, `search_kb`, `similar_tickets`, `load_memory`, `reindex_status`, the browser's `observe` (Day 71) | permissions table only |
| **WRITE_GATED** | changes the world; *always* behind Day 63's gate | `close_ticket`, `post_reply`, `escalate_to_engineer`, `reindex_start` | permissions table **and** a `POLICY` row ≠ "never" (tested!) |
| **NEVER** | exists in code, no role may hold it at runtime | lab/debug tools (`seed_fixture_tickets`, anything in `*_lab.py`), raw SQL, shell | permissions table; the plugin refuses it for *everyone* |

**The roles** — the graph's stations, by job, with what the job needs:

| Role | Node(s) | Tools it may hold | Why not more |
| --- | --- | --- | --- |
| `intake` | `intake` (function) | — | deterministic; no model, no tools |
| `classifier` | `classify_station` | — | structured output from the ticket text only (a tool-less classifier is *also* a smaller injection surface) |
| `researcher` | `archive_clerk_v2`, `kb_clerk`, `evidence_analyst`, `make_researcher()` | `lookup_ticket`, `search_kb`, `similar_tickets`, `load_memory` | reads only; never writes; never posts |
| `writer` | draft box writer | **none** | it turns *findings* into prose; findings are text in its input, not tools in its hand |
| `critic` | draft box critic | `load_skill`/`load_skill_resource` (the kb-answer-style skill) | reads the style guide; changes nothing |
| `closer` | the approval gate's successor (Day 64) | `close_ticket` (keyed) | the *only* holder of a write tool; runs only after a verdict |
| `operator` | `python -m sutra.approvals …` CLI (a human) | approve/reject | not an agent — the human's badge |

💡 **Mental model: a tool a node doesn't hold is a sentence the attacker cannot make it
say.** Guards lower the rate of bad calls; permissions set the *set* of possible calls.
9802 is not "caught" today — it becomes **unrepresentable**: the writer has no archive
tool to call, and the findings it receives (Day 52's analyst output) are prose, not raw
rows.

Two ADK facts make this cheap: `Agent(tools=[...])` is the declaration — the model is
never even told about tools outside the list (they don't appear in `tools_dict`); and
`tool_filter` on `McpToolset` (Day 40) does the same thing for tools you don't own. Least
privilege is one table feeding both.

### SEC-11 — Enforcement: the door that doesn't trust the table

**The story.** The badge system has a second half: the *reader on the door*. Even if a
badge was mis-programmed — a receptionist somehow issued a pharmacy key — the pharmacy
door logs every open with a name, and the audit notices. Construction-time permission
(the tool list) is the badge; a runtime check at the tool door is the reader.

Why both? Because tool lists drift. Phase 11 adds the nightly job and the standup agent;
Phase 14 adds integrations; a contributor copy-pastes an agent with `tools=[...]` from
another file. Day 14's failure lab already showed that the only control that survives
"an agent nobody has written yet" is the plugin on the runner. So:

- **`PermissionPlugin.before_tool_callback`** looks up *who is calling* (the agent's
  name → its role via `ROLE_OF`) and *what* (`tool.name`), asks `may(role, tool)`, and
  on `False` returns Day 13's legible refusal
  `{"status": "permission_denied", "role": …, "tool": …, "advice": …}` — the tool never
  runs — and logs `permission_denied` (name, tool, invocation). Unknown agent name →
  role `unknown` → may hold nothing → **fail closed**, same reflex as `policy_for()`.
- **Two tables must agree.** Every `WRITE_GATED` tool must have a `POLICY` row whose
  gate is not `"never"`; every tool with a `POLICY` gate of `"always"` must be
  `WRITE_GATED`; no role but `closer` may hold a `WRITE_GATED` tool. That is a *unit
  test*, so the agreement is checked at every `make check`, not remembered.
- **Agent-auth vs user-auth** (adk.dev/safety): Sutra's tools run with *Sutra's*
  identity (agent-auth) — the archive is read with one service credential, and the
  permissions table is how we avoid "all users share the same level of access" becoming
  "every node shares the same level of access." User-auth (per-human OAuth) is 🅿️ for
  Phase 14's integrations; note it, don't build it.

💡 **Mental model: construction bounds what *can* be asked; the door bounds what *will*
be done; the test bounds what *drifts*.** Three cheap mechanisms, one table.

**Step 2 — `sutra/permissions.py` (zero quota).**

```python
"""Day 68 — permissions: which role may hold which tool, enforced twice.

Construction-time: agents are built FROM this table (tools_for(role)), so a
node cannot reach a tool its job does not need. Runtime: PermissionPlugin
refuses any call that disagrees with the table, and logs it. The table is
cross-checked against Day 63's approval POLICY by tests.

Importable with no side effects. Demo from the repo root:

    python -m sutra.permissions show     # the matrix, role x tool (0 quota)
"""
from __future__ import annotations

import sys
from enum import Enum

from google.adk.plugins.base_plugin import BasePlugin      # Day 14 (verified 08-19)

from sutra.logging_setup import get_logger

log = get_logger("permissions")


class Tier(str, Enum):
    """How dangerous a tool is - classified once, per tool, here."""
    READ = "read"                 # observe only
    WRITE_GATED = "write_gated"   # changes the world; ALWAYS behind Day 63's gate
    NEVER = "never"               # exists in code; no role may hold it at runtime


# Every tool Sutra owns, classified. Adding a tool without a row here is a
# test failure (see tests) - the same "unclassified = fail closed" reflex as
# policy_for() on Day 63.
TIERS: dict[str, Tier] = {
    "lookup_ticket": Tier.READ,
    "search_kb": Tier.READ,
    "similar_tickets": Tier.READ,
    "load_memory": Tier.READ,
    "preload_memory": Tier.READ,
    "load_skill": Tier.READ,
    "load_skill_resource": Tier.READ,
    "reindex_status": Tier.READ,
    "reindex_start": Tier.WRITE_GATED,
    "escalate_to_engineer": Tier.WRITE_GATED,
    "close_ticket": Tier.WRITE_GATED,
    "post_reply": Tier.WRITE_GATED,
    "seed_fixture_tickets": Tier.NEVER,      # Day 66 lab helper
    "run_skill_script": Tier.NEVER,          # Day 28: scripts stay off at runtime
}

# Role -> the tools its JOB needs. Short lists are the point.
ROLE_TOOLS: dict[str, frozenset[str]] = {
    "intake": frozenset(),
    "classifier": frozenset(),
    "researcher": frozenset({"lookup_ticket", "search_kb", "similar_tickets", "load_memory"}),
    "writer": frozenset(),                   # findings arrive as TEXT, not tools
    "critic": frozenset({"load_skill", "load_skill_resource"}),
    "closer": frozenset({"close_ticket"}),   # the ONLY holder of a write tool
    "unknown": frozenset(),                  # an agent we did not classify: nothing
}

# Agent name -> role. Names as built in sutra/graph.py / researcher.py /
# delegation.py. TODO(run day: reconcile with your actual agent names;
# the test below fails loudly on any graph agent missing here).
ROLE_OF: dict[str, str] = {
    "classify_station": "classifier",
    "archive_clerk_v2": "researcher",
    "kb_clerk": "researcher",
    "evidence_analyst": "researcher",
    "sutra_researcher": "researcher",        # Day 52's make_researcher()
    "draft_writer": "writer",                # Day 57's box - adjust to your names
    "draft_critic": "critic",
    "ticket_closer": "closer",               # Day 64's successor node
}


def role_of(agent_name: str) -> str:
    """Map an agent name to its role; unknown names get 'unknown' (fail closed).

    Example:
        >>> role_of("draft_writer"), role_of("some_new_agent")
        ('writer', 'unknown')
    """
    return ROLE_OF.get(agent_name, "unknown")


def may(role: str, tool: str) -> bool:
    """The one question the door asks. NEVER-tier tools are refused for all.

    Example:
        >>> may("researcher", "search_kb"), may("writer", "search_kb"), may("closer", "close_ticket")
        (True, False, True)
        >>> may("closer", "seed_fixture_tickets")
        False
    """
    if TIERS.get(tool, Tier.NEVER) is Tier.NEVER:     # unclassified == NEVER
        return False
    return tool in ROLE_TOOLS.get(role, frozenset())


def tools_for(role: str, registry: dict[str, object]) -> list[object]:
    """Build a role's tool list FROM the table (construction-time privilege).

    Args:
        role: a key of ROLE_TOOLS.
        registry: tool name -> the actual tool object / function, e.g.
            {"lookup_ticket": lookup_ticket, "search_kb": search_kb, ...}.

    Example:
        >>> tools_for("writer", {"search_kb": object()})
        []
    """
    return [registry[name] for name in sorted(ROLE_TOOLS[role]) if name in registry]


def _caller(tool_context) -> str:
    """The calling agent's name. ONE place to fix if the attribute differs.

    TODO(run day: verify - tool_context.agent_name, else
    tool_context._invocation_context.agent.name; print-then-pin.)
    """
    return getattr(tool_context, "agent_name", None) or "unknown"


class PermissionPlugin(BasePlugin):
    """The door reader: refuse tool calls the table does not allow; log them.

    Usage:
        Runner(agent=..., plugins=[PermissionPlugin(), GuardrailPlugin(), ...])
    """

    def __init__(self) -> None:
        super().__init__(name="permissions")
        self.denied = 0

    async def before_tool_callback(self, *, tool, tool_args, tool_context):
        """Caller x tool -> allow (None) or a legible refusal dict."""
        caller = _caller(tool_context)
        role = role_of(caller)
        if may(role, tool.name):
            return None                                    # allowed: tool runs
        self.denied += 1
        log.warning("permission_denied", extra={"agent": caller, "role": role,
                                                "tool": tool.name})
        return {"status": "permission_denied", "role": role, "tool": tool.name,
                "advice": "This role may not use this tool. Continue with what "
                          "you have, or state that the step needs another role."}


def show() -> None:
    """Print the matrix. Spends nothing."""
    tools = sorted(TIERS)
    print(f"{'role':12}" + "".join(f"{t[:14]:>16}" for t in tools))
    for role in ROLE_TOOLS:
        print(f"{role:12}" + "".join(f"{'x' if may(role, t) else '.':>16}" for t in tools))
    print("\ntiers:", {t: TIERS[t].value for t in tools})


def main() -> None:
    if (sys.argv[1:] or ["show"])[0] != "show":
        print("usage: python -m sutra.permissions show"); raise SystemExit(2)
    show()


if __name__ == "__main__":
    main()
```

```python
"""Day 68 — privilege is a table; tables are tested."""
from __future__ import annotations

import asyncio

from sutra.approvals import POLICY, policy_for                 # Day 63
from sutra.permissions import (ROLE_OF, ROLE_TOOLS, TIERS, PermissionPlugin,
                               Tier, may, role_of, tools_for)


def test_writer_holds_nothing_and_closer_holds_only_close() -> None:
    assert ROLE_TOOLS["writer"] == frozenset()
    assert ROLE_TOOLS["closer"] == {"close_ticket"}


def test_only_closer_may_hold_write_gated_tools() -> None:
    for role, tools in ROLE_TOOLS.items():
        for t in tools:
            if TIERS[t] is Tier.WRITE_GATED:
                assert role == "closer", f"{role} holds write tool {t}"


def test_every_write_gated_tool_has_a_real_gate_row() -> None:
    for tool, tier in TIERS.items():
        if tier is Tier.WRITE_GATED:
            assert policy_for(tool).gate != "never", f"{tool} is write-gated but POLICY says never"
    for tool, row in POLICY.items():                      # and the reverse
        if row.gate == "always":
            assert TIERS.get(tool) is Tier.WRITE_GATED, f"{tool} gated 'always' but not WRITE_GATED"


def test_unknown_agent_and_unclassified_tool_fail_closed() -> None:
    assert role_of("brand_new_agent") == "unknown"
    assert not may("unknown", "search_kb")
    assert not may("closer", "some_tool_nobody_classified")


def test_tools_for_builds_from_the_table() -> None:
    reg = {"lookup_ticket": "L", "search_kb": "S", "close_ticket": "C"}
    assert tools_for("researcher", reg) == ["L", "S"]
    assert tools_for("writer", reg) == []


def test_plugin_refuses_and_counts() -> None:
    class Tool:  name = "close_ticket"
    class Ctx:   agent_name = "draft_writer"
    out = asyncio.run(PermissionPlugin().before_tool_callback(
        tool=Tool(), tool_args={}, tool_context=Ctx()))
    assert out["status"] == "permission_denied" and out["role"] == "writer"


def test_every_graph_agent_has_a_role() -> None:
    """Drift guard: a new agent in sutra/graph.py must be classified."""
    from google.adk.agents import Agent
    import sutra.graph as g
    names = {a.name for a in vars(g).values() if isinstance(a, Agent)}
    missing = names - set(ROLE_OF)
    assert not missing, f"unclassified graph agents: {sorted(missing)}"
```

## 5 · 💥 Failure lab — the convenient master key

> 🎬 **The scene:** Phase 11's nightly job (Day 73) needs to re-index the archive, run
> evals, and write a digest. The quick way: one `nightly_agent` with
> `tools=[reindex_start, reindex_status, lookup_ticket, search_kb, similar_tickets,
> post_reply]` — "it's a trusted internal job, it runs at 3 a.m., nobody's attacking
> the nightly."
> 😬 **The naive fix:** add `"nightly": "researcher"` to `ROLE_OF` so the plugin stops
> complaining, and give the researcher role `reindex_start` and `post_reply` "just for
> the nightly."
> 💥 **Why it fails:** you have just put a WRITE_GATED tool into the role held by
> *every evidence clerk in the triage graph* — the nodes that read strangers' tickets
> all day. The test `test_only_closer_may_hold_write_gated_tools` goes red, which is the
> table defending itself; but imagine you "fix" the test too. Now an injected ticket
> read by `kb_clerk` at 2 p.m. can ask for `post_reply`, the plugin says yes (the role
> allows it), and only the approval gate stands between the forged reply and a customer.
> One layer left out of three, for a job that ran at 3 a.m. *The nightly wasn't the
> target — the role was.*
> 💡 **The insight:** **roles are per job, never per convenience.** The nightly gets its
> *own* role (`"nightly": {"reindex_start", "reindex_status"}` — and `reindex_start`
> stays WRITE_GATED with its `"never"`-gate POLICY row because it is internal and
> re-runnable, the tests will make you say so explicitly), the digest is written by a
> `digest_writer` role with no tools at all, and `post_reply` stays with the closer
> behind the gate. When a new job appears, the first question is not "which existing
> role fits?" but "what is the smallest badge this job needs?"

## 6 · 🎤 Interview corner

1. **"How do you apply least privilege to an LLM agent?"** — At construction: every tool
   is classified (read / write-gated / never) and every role's tool list is built from
   one table, so the writer node literally holds zero tools and the archive clerks hold
   no write tools — the model isn't told tools exist outside its list. At runtime: a
   plugin at the tool door checks caller × tool and refuses with a logged, legible
   denial, because tool lists drift and copy-paste happens. And in tests: the permission
   table is cross-checked against the approval policy so a write tool can't exist
   without a gate row.
2. **"Give an example where permissions, not guards, fixed a security issue."** — An
   injected ticket asking the writer to quote similar tickets. Guards caught the obvious
   phrasings and flagged leaks in drafts, but the real fix was that the writer never
   needed archive access — findings arrive as analyst prose. After the change the attack
   isn't "caught," it's unrepresentable: there is no tool to call.
3. **"What happens when someone adds a new agent and forgets all of this?"** — Three
   things, in order: the agent's tool list is whatever they wrote (maybe too much); the
   permission plugin maps the unknown name to role `unknown`, which may hold nothing, so
   every tool call is refused and logged — fail closed; and a drift test that enumerates
   the graph's agents fails in `make check` until the agent is classified. Forgetting
   makes things *stop*, not leak.
