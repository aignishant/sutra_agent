## 3 · 📚 Concepts

### SK-20 — A lint is a test with a different front door

Yesterday you wrote the checks; today they get a second entry point. Why two doors to
the same rules?

| Front door | Caller | What it's for |
| --- | --- | --- |
| `tests/test_skills.py` | pytest, humans mid-work | rich diffs, tmp_path fixtures, sits with the rest of the suite |
| `tools/lint_skills.py` | the gate, CI, scripts | one process, one exit code, greppable one-line-per-skill output |

The load-bearing decision is what they *share*: both import `tools/skill_checks.py`.
The rules live once. A lint that re-implements its test suite's rules drifts from it
within a month, and then green means two different things depending on which door you
knocked on — the exact "two sources of truth" disease the skills themselves were
cured of on Day 27.

💡 **Mental model: rules are a library; test and lint are two front doors into the
same building.** (You'll meet this pattern again on Day 82 when evals join CI.)

One boundary repeated from yesterday, because the gate makes it easy to forget:
this lint checks **structure, not sense, not safety**. `evil-helper` would pass it.
The gate going green says "spec-shaped", never "audited" — the provenance ledger
remains the only place THAT claim lives.

### OPS-08 — The gate: one command, honest exit, no `make` required

Three design rules make a repo gate trustworthy, and each comes from a failure you've
already touched:

1. **One entry point, everywhere.** `make` isn't guaranteed on Windows (your own
   machine!). So the gate's brain is `tools/check.py` — pure Python, stdlib
   `subprocess` — and the `Makefile`'s `check:` target is a one-line wrapper around
   it. PowerShell users, CI, and `make` users all execute the *same* file, so there
   is no "works in make but not in PowerShell" split-brain. (Same shared-core move
   as SK-20, one level up.)
2. **Fail loud, fail fast, exit honest.** The gate runs its stages in order and
   stops at the first red, propagating exit code 1. An exit code is a contract with
   every future caller — CI (Day 82), the nightly job (Day 73), a git hook if you
   ever add one. A gate that prints errors but exits 0 is worse than no gate: it
   *launders* red into green (Principle 10, tooling edition).
3. **Cheap stages first.** trace (ms) → lints (ms) → pytest (seconds). A gate that
   answers fast gets run often; the ordering is UX, and UX is compliance.

And the `:free` lint deserves its one paragraph of respect: it is two dozen lines
guarding against the single most expensive typo this repo can contain. An
`openrouter/deepseek-r1` (no suffix) is not a style problem — it is a **billing
event** waiting for the day a paid key exists (Addendum 02's warning: "a missing
`:free` can bill a paid model"). The lint makes the invariant mechanical: strings
change, rosters change (Day 9 watched the free floor shrink!), but the *suffix rule*
holds forever without anyone remembering it.

**Step 2 — `tools/lint_skills.py`** (the CLI door onto Day 30's rules):

```python
"""Day 31 — skills lint: the gate's front door onto tools/skill_checks.py.

One line per production skill, exit 1 if anything is wrong. The rules
themselves live in skill_checks (Day 30) — this file only formats and
exits. tests/fixtures/ is deliberately NOT scanned: that shelf is
quarantine (Day 29), and evil-helper is SUPPOSED to be there.

Usage:
    python tools/lint_skills.py            # lints ./skills
"""
from __future__ import annotations

import pathlib
import sys

from tools.skill_checks import check_all               # ONE source of rules


def main() -> int:
    """Lint every skill under ./skills; print one line each; return 0/1.

    Example:
        >>> main()                       # on a healthy shelf:
        OK  hello-desk
        OK  kb-answer-style
        OK  ticket-triage
        0
    """
    skills_dir = pathlib.Path("skills")
    if not skills_dir.is_dir():                        # no shelf at all?
        print("lint_skills: no skills/ directory found")
        return 1                                       # a gate never shrugs
    failed = False
    for name, problems in check_all(skills_dir).items():
        if problems:
            failed = True
            for p in problems:                         # every finding, greppable
                print(f"FAIL {p}")
        else:
            print(f"OK  {name}")
    return 1 if failed else 0


if __name__ == "__main__":
    raise SystemExit(main())                           # the exit code IS the API
```

**Step 3 — `tools/lint_free_suffix.py`** (Addendum 02 §7, mechanized):

```python
"""Day 31 — the ':free' lint: every openrouter/ model string must end ':free'.

Guards Addendum 02 section 7's billing rule. Scans Python source only
(sutra/, tools/, tests/) — docs discuss model names in prose and are
exempt. Skips itself: this file must contain the pattern in order to
search for it, and a lint that flags its own source is the oldest bug
in linting.

Usage:
    python tools/lint_free_suffix.py
"""
from __future__ import annotations

import pathlib
import re
import sys

# An openrouter model string: 'openrouter/' then at least vendor/model,
# captured with its optional ':free' tail so we can inspect the tail.
PATTERN = re.compile(r"openrouter/[A-Za-z0-9._\-]+(?:/[A-Za-z0-9._\-]+)+(?::free)?")
SCAN_DIRS = ("sutra", "tools", "tests")                # code, not prose


def main() -> int:
    """Scan for suffix-less openrouter strings; print findings; return 0/1.

    Example:
        >>> main()                       # healthy repo:
        free-suffix lint: all openrouter/ strings OK
        0
    """
    me = pathlib.Path(__file__).resolve()              # self-exemption (docstring)
    bad: list[str] = []
    for d in SCAN_DIRS:
        for path in pathlib.Path(d).rglob("*.py"):
            if path.resolve() == me:
                continue
            for lineno, line in enumerate(
                path.read_text(encoding="utf-8").splitlines(), start=1
            ):
                for hit in PATTERN.findall(line) or []:
                    pass                               # findall w/ groups is awkward —
                for m in PATTERN.finditer(line):       # finditer keeps the full match
                    if not m.group(0).endswith(":free"):
                        bad.append(f"{path}:{lineno}: {m.group(0)!r} "
                                   "is missing ':free' (Addendum 02 §7)")
    for b in bad:
        print("FAIL", b)
    if not bad:
        print("free-suffix lint: all openrouter/ strings OK")
    return 1 if bad else 0


if __name__ == "__main__":
    raise SystemExit(main())
```

typed the listing verbatim, removing those two dead lines is your cleanup; the lint
below you will build no such mercy for.)*

**Step 4 — `tools/check.py` + the `Makefile` (OPS-08).**

```python
"""Day 31 — THE gate: every guardian, one command, one honest exit code.

Stages run cheapest-first and stop at the first failure. This file is
the single entry point on every platform: `make check` wraps it, CI
(Day 82) calls it, the nightly job (Day 73) will call it, PowerShell
users run it directly.

Usage:
    python tools/check.py
"""
from __future__ import annotations

import subprocess
import sys
import time

STAGES: list[tuple[str, list[str]]] = [           # (name, argv) — order matters:
    ("trace",       [sys.executable, "tools/trace.py"]),          # ms — ledgers
    ("skills-lint", [sys.executable, "tools/lint_skills.py"]),    # ms — the shelf
    ("free-lint",   [sys.executable, "tools/lint_free_suffix.py"]),  # ms — billing
    ("pytest",      ["uv", "run", "pytest", "-q"]),               # seconds — code
]


def main() -> int:
    """Run every stage; print a summary table; return the first failure.

    Example:
        >>> main()                        # a green day ends like:
        ...
        check: ALL GREEN (4 stages)
        0
    """
    for name, argv in STAGES:
        started = time.perf_counter()
        print(f"--- {name}: {' '.join(argv)}")
        code = subprocess.call(argv)              # inherit stdout/stderr: no hiding
        secs = time.perf_counter() - started
        if code != 0:                             # first red stops the line —
            print(f"check: FAILED at stage '{name}' "
                  f"(exit {code}, {secs:.1f}s)")  # …loudly, with the culprit named
            return code                           # honest propagation (Principle 10)
        print(f"--- {name}: OK ({secs:.1f}s)\n")
    print(f"check: ALL GREEN ({len(STAGES)} stages)")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## 5 · 💥 Failure lab — the gate that lied politely

> 🎬 **The scene:** a hypothetical cousin of your `check.py` — same stages, but its
> author wanted "a nicer summary", so it runs ALL stages, collects results, prints a
> pretty table with two ❌ marks… and returns `0`, because the author only ever read
> the table, never the exit code. It lives happily for months. Then Day 82 wires it
> into CI.
> 😬 **The naive fix:** "CI is green, merge it." The table said ❌ twice, but nothing
> and nobody reads tables in CI — machines read exit codes.
> 💥 **Why it fails:** the gate has two audiences with two languages. Humans read
> text; every *caller* — CI, the nightly job, `make`, a git hook — reads exactly one
> integer. A gate that speaks honest text and dishonest integers passes every human
> inspection and lies to every machine, which is the worst possible split: the
> automation you built specifically so humans could stop checking is the only party
> being deceived. And the failure is silent for as long as the repo happens to be
> healthy — it detonates precisely on the first real regression, which sails through
> a green CI while the pretty ❌ scrolls past unread. You drilled the antidote in
> step 5: you *watched* `$LASTEXITCODE` become 1, twice, on purpose.
> 💡 **The insight:** **a gate's exit code is its testimony; the printout is only
> commentary.** Verify the integer the day you build the gate (and every time you
> refactor it), fail fast so the culprit stage is unambiguous, and never "improve"
> a gate into running-everything-and-summarizing without preserving the honest
> nonzero exit. Principle 10 applies to tooling exactly as it applies to agents:
> the gate must never fabricate a green to cover a red.

Observed today: two planted breaks, two honest reds with the culprit named, two
`$LASTEXITCODE = 1` readings — then green restored.

## 6 · 🎤 Interview corner

1. **"What does 'green' mean in your repo, and how is it enforced?"** — One command:
   `make check`, whose brain is a stdlib Python runner so Windows-without-make, CI,
   and Unix all execute the identical file. Four stages, cheapest first:
   traceability (every concept ID accounted for), a skills lint (spec structure of
   our agent-skill library), a billing lint (every OpenRouter model string must end
   `:free` — on a zero-budget project a missing suffix is a latent billing event,
   so it's linted, not remembered), then the test suite. First red stops the line
   and propagates exit 1 — I drill the red path deliberately, because a gate you've
   never seen fail is a gate you can't trust.
2. **"Why maintain both a pytest suite and standalone lints over the same rules?"**
   — Different callers, same rules, one implementation. The checks live in one
   module; pytest wraps them for humans (fixtures, rich diffs), a thin CLI wraps
   them for machines (one line per finding, exit code). What I refuse to do is
   implement the rules twice — duplicated rule sets drift, and then "green" means
   different things depending on the door you entered through. The same
   single-brain principle repeats one level up: `make check` wraps the Python
   runner rather than duplicating the stage list in Makefile syntax.
3. **"Your quality gate is green. What do you explicitly know it has NOT told
   you?"** — Three things, by design. Behavior: the gate runs the free lane only —
   quota-spending behavioral smokes and evals are scheduled separately, so green
   ≠ "the agent still routes correctly" (the deselected-count in pytest's output
   states that gap on every run). Safety: the skills lint validates structure; a
   hostile-but-well-formed skill passes — trust lives in the audit-and-provenance
   pipeline, not the gate. And freshness: the gate can't see that a provider
   changed its free tier overnight — that's the weekly phase-gate ritual. A gate's
   value is knowing its edges as precisely as its checks.
