## 3 · 📚 Concepts

### SEC-15 — Honest backoff: wait like you were told, then say so

**The story.** You call a clinic's phone line. Busy tone. A good caller waits a bit and
tries again — a bit longer each time — and if the recording says *"call back in five
minutes,"* they wait five minutes, not ten seconds. A bad caller redials in a loop and
jams the line for everyone. And a *dishonest* caller, after failing to get through, tells
the patient "I spoke to the doctor, you're fine."

Three behaviours, three rules:

| Rule | Mechanism | Why |
| --- | --- | --- |
| **The server's word wins** | parse `retry-after` (Groq/OpenRouter header), `"retry in Ns"` (Gemini message text), `X-RateLimit-Reset` (OpenRouter); wait that (+1 s margin), not your own guess | the provider knows its window; guessing shorter burns the next minute's budget (Addendum 02 §6's scene) |
| **Otherwise, exponential + jitter** | 1 → 2 → 4 → 8 s (`base × factor^attempt`, capped), ± a little jitter | a burst of callers who all back off identically re-collide; jitter spreads them |
| **Give up loudly after N** | `max_tries = 4` (Day 2's number, kept); then raise `BackoffExhausted` carrying lane, attempts, last delay, and the provider's message | an agent that keeps trying is indistinguishable from a hung one; a typed failure can be routed, logged, resumed |
| **Never invent a result** | the helper returns the real value or raises — there is no third return; callers that want a fallback must produce an *explicit* failure object (`{"status": "rate_limited", …}`) that downstream code routes on | Principle 10, and Day 21's honest-fallback shape; trap #4 (swallowing) is the thing we are not doing |

💡 **Mental model: backoff is politeness with a deadline; honesty is what you say when
the deadline passes.** "I could not reach the model after 4 tries over 15 s; escalated"
is a perfectly good sentence for an agent to say. "Here's the answer" when there is none
is the one sentence it may never say.

**Where the retries live (and why not everywhere).** Three layers already exist; know
them so you don't stack four retries on four retries (which turns a 30 s throttle into a
4-minute hang):

1. **The SDK.** google-genai retries 429/503 up to four times (~1 s → 60 s cap) by
   itself — verified today. ADK's native Gemini calls inherit this. So on the primary
   lane the *first* round of waiting is already done for you.
2. **`with_backoff()` (today).** For paths that call the SDK directly (Day 2's `ask()`,
   Day 67's `judge()`, Day 49's embedder `POST /api/embed`, Day 34's MCP client calls)
   and for LiteLLM lanes (whose retry defaults differ — `TODO(probe)`). One policy,
   one log shape, one exception.
3. **The runtime hooks.** When a retried call *still* fails, ADK raises through
   `on_model_error_callback` / `on_tool_error_callback`. That is where
   `SafetyNetPlugin` lives — and today it learns to tell a 429 from a bug: on 429 it
   tells the router to mark the lane dry for the server's delay, logs `quota_escalated`
   with the resume command, and **re-raises** (returns `None`). Not a sleep-and-retry
   inside the hook — a hook that sleeps holds the run's thread and hides the wait from
   everything else; Phase 9 made pauses *free* (a parked run costs rows), so the honest
   move is: raise, let the durable run end, resume when the window opens.

**Why not `ReflectAndRetryToolPlugin` for this.** ADK's built-in retries *tool* failures
by *asking the model to reflect and try again* — great for a malformed argument, exactly
wrong for quota: reflection is a model call, on the lane that just said no. Adopt it
later for tool-argument errors if you like (note it for Phase 12's eval of tool-use
quality); keep 429s on the deterministic path.

### OPS-13 — The runbook: the incident you will definitely have

**The story.** Day 65 taught the shape: write the procedure *before* the incident, as
numbered commands, so morning-brain follows steps instead of panic-brain improvising.
Quota exhaustion is Sutra's most likely incident by a mile — it *will* happen during a
demo, a nightly run (Day 73), or an eval sweep (Phase 12). So it gets the second runbook.

The runbook answers four questions in order: **(1) what fired** (the `quota_escalated`
log line's fields: lane, attempts, server delay, invocation id); **(2) is it the window
or the day** (`python -m sutra.quota report` — RPM resets in a minute, RPD at midnight
Pacific for Gemini — `TODO(confirm reset time for your project in AI Studio)`);
**(3) what to do now** (wait / reroute — `routed_agent` on another lane — / Ollama for
the job / resume: `python -m sutra.graph resume <invocation_id>` — Phase 9's gift);
**(4) what to record** (the ledger note; a CHANGELOG line if a limit moved). That is the
whole document; shorter is better.

💡 **Mental model: a runbook is a retry policy for humans.** Same honesty: it says when
to stop trying and who to tell.

```python
"""Day 72 — honest backoff: wait what the server said, else 1-2-4-8s, then escalate.

One policy for every call path (SDK calls, LiteLLM lanes, MCP, the
embedder). The helper returns the real result or raises BackoffExhausted -
there is no third return value, so no caller can accidentally treat "gave
up" as "answered" (Principle 10; trap #4 avoided by design).

Importable with no side effects. Demo from the repo root:

    python -m sutra.backoff dialects   # parse the three providers' retry hints (0 quota)
    python -m sutra.backoff fake       # a stub that 429s three times, then answers (0 quota)
"""
from __future__ import annotations

import random
import re
import sys
import time
from collections.abc import Callable
from dataclasses import dataclass
from typing import TypeVar

from sutra.logging_setup import get_logger

log = get_logger("backoff")
T = TypeVar("T")

_RETRY_IN = re.compile(r"retry in ([\d.]+)\s*s", re.IGNORECASE)      # Gemini message text (Day 2)


class BackoffExhausted(RuntimeError):
    """We waited honestly and it still failed. Carries the facts for the runbook."""

    def __init__(self, *, lane: str, attempts: int, waited: float, last: str) -> None:
        super().__init__(f"{lane}: gave up after {attempts} tries / {waited:.0f}s waited: {last}")
        self.lane, self.attempts, self.waited, self.last = lane, attempts, waited, last


@dataclass(frozen=True)
class RetryPolicy:
    """The numbers, in one place, with their reasons.

    Attributes:
        max_tries: total attempts incl. the first (Day 2 chose 4; kept).
        base: first wait in seconds. factor: growth per attempt (1,2,4,8).
        cap: never wait longer than this on OUR guess (server hints may exceed it).
        jitter: +/- fraction of the computed wait, so bursts de-synchronize.
    """
    max_tries: int = 4
    base: float = 1.0
    factor: float = 2.0
    cap: float = 30.0
    jitter: float = 0.2

    def wait_for(self, attempt: int, server_hint: float | None, rnd: Callable[[], float] = random.random) -> float:
        """Seconds to sleep before attempt+1. Server hint wins (+1s margin).

        Example:
            >>> RetryPolicy().wait_for(0, None, rnd=lambda: 0.5)   # no jitter at 0.5
            1.0
            >>> RetryPolicy().wait_for(2, 36.5)
            37.5
        """
        if server_hint is not None:
            return server_hint + 1.0                     # trust the server; +1s margin
        raw = min(self.cap, self.base * self.factor ** attempt)
        return raw * (1 + self.jitter * (2 * rnd() - 1))  # +/- jitter


def parse_retry_after(err: BaseException) -> float | None:
    """Pull the server's stated delay (seconds) out of a 429, any dialect, or None.

    Looks, in order, at: a `retry-after` header (Groq/OpenRouter via the
    exception's response, if present), OpenRouter's X-RateLimit-Reset (ms
    epoch), and Gemini's "Please retry in 36.5s" message text.
    TODO(run day: pin the attribute path for LiteLLM exceptions after
    printing one real Groq 429 - see the doc banner).

    Example:
        >>> class E(Exception): message = "429 RESOURCE_EXHAUSTED. Please retry in 36.5s."
        >>> parse_retry_after(E())
        36.5
    """
    headers = getattr(getattr(err, "response", None), "headers", None) or {}
    hdr = {str(k).lower(): v for k, v in dict(headers).items()} if headers else {}
    if "retry-after" in hdr:
        try:
            return float(hdr["retry-after"])
        except ValueError:
            pass                                         # HTTP-date form: fall through
    if "x-ratelimit-reset" in hdr:
        try:
            reset_ms = float(hdr["x-ratelimit-reset"])
            return max(0.0, reset_ms / 1000 - time.time())
        except ValueError:
            pass
    text = str(getattr(err, "message", "") or err)
    if m := _RETRY_IN.search(text):
        return float(m.group(1))
    return None


def is_rate_limit(err: BaseException) -> bool:
    """True for a 429 in any dialect we know. Unknown errors are NOT retried.

    Example:
        >>> class E(Exception): code = 429
        >>> is_rate_limit(E())
        True
    """
    if getattr(err, "code", None) == 429 or getattr(err, "status_code", None) == 429:
        return True
    name = type(err).__name__.lower()
    return "ratelimit" in name or "resourceexhausted" in name


def with_backoff(fn: Callable[[], T], *, lane: str, policy: RetryPolicy = RetryPolicy(),
                 sleep: Callable[[float], None] = time.sleep,
                 on_wait: Callable[[float], None] | None = None) -> T:
    """Call fn(); on 429 wait honestly and retry; after max_tries raise BackoffExhausted.

    Non-429 errors are re-raised immediately (we only know how to wait for
    quota). There is no fallback value: the caller gets the result or an
    exception, never a guess.

    Args:
        fn: zero-arg callable doing the real work.
        lane: ledger key for logging/escalation ("gemini", "groq", ...).
        policy: the numbers. sleep: injectable for tests. on_wait: hook
            (the router uses it to mark the lane dry for that long).

    Example:
        >>> with_backoff(lambda: "ok", lane="gemini")
        'ok'
    """
    waited = 0.0
    for attempt in range(policy.max_tries):
        try:
            return fn()
        except Exception as e:                           # noqa: BLE001 - classified right below
            if not is_rate_limit(e):
                raise                                    # not ours: surface it (trap #4)
            if attempt == policy.max_tries - 1:
                log.error("quota_escalated", extra={"lane": lane, "attempts": attempt + 1,
                                                    "waited_s": round(waited, 1),
                                                    "advice": "see docs/runbooks/rate_limit_429.md"})
                raise BackoffExhausted(lane=lane, attempts=attempt + 1, waited=waited, last=str(e)) from e
            hint = parse_retry_after(e)
            wait = policy.wait_for(attempt, hint)
            log.warning("quota_backoff", extra={"lane": lane, "attempt": attempt + 1,
                                                "wait_s": round(wait, 1), "server_hint": hint})
            if on_wait:
                on_wait(wait)                            # e.g. router.mark_dry(lane, wait)
            sleep(wait)
            waited += wait
    raise AssertionError("unreachable")
```

```python
"""Day 72 — the waits and the honesty, pinned without sleeping or spending."""
from __future__ import annotations

import pytest

from sutra.backoff import BackoffExhausted, RetryPolicy, parse_retry_after, with_backoff


class Fake429(Exception):
    code = 429
    def __init__(self, msg="429 RESOURCE_EXHAUSTED", headers=None):
        super().__init__(msg); self.message = msg
        if headers is not None:
            self.response = type("R", (), {"headers": headers})()


def test_waits_1_2_4_8_then_raises_never_returns() -> None:
    sleeps: list[float] = []
    def boom(): raise Fake429()
    with pytest.raises(BackoffExhausted) as ei:
        with_backoff(boom, lane="gemini", policy=RetryPolicy(jitter=0), sleep=sleeps.append)
    assert sleeps == [1.0, 2.0, 4.0]                 # 3 waits between 4 tries
    assert ei.value.attempts == 4 and ei.value.lane == "gemini"


def test_server_hint_beats_our_guess() -> None:
    sleeps: list[float] = []
    calls = {"n": 0}
    def flaky():
        calls["n"] += 1
        if calls["n"] < 3: raise Fake429("Please retry in 36.5s.")
        return "answer"
    assert with_backoff(flaky, lane="gemini", sleep=sleeps.append) == "answer"
    assert sleeps == [37.5, 37.5]                    # hint + 1s margin, not 1,2


def test_header_dialect_groq() -> None:
    assert parse_retry_after(Fake429(headers={"retry-after": "12"})) == 12.0


def test_non_429_is_surfaced_immediately() -> None:
    def bug(): raise ValueError("a real bug")
    with pytest.raises(ValueError):
        with_backoff(bug, lane="gemini", sleep=lambda s: None)


def test_on_wait_hook_sees_every_wait() -> None:
    seen: list[float] = []
    def boom(): raise Fake429()
    with pytest.raises(BackoffExhausted):
        with_backoff(boom, lane="groq", policy=RetryPolicy(jitter=0),
                     sleep=lambda s: None, on_wait=seen.append)
    assert seen == [1.0, 2.0, 4.0]
```

## 5 · 💥 Failure lab — the retry that never ended, and the one that lied

> 🎬 **The scene:** the nightly job (Day 73, tomorrow) runs 60 eval cases on the lite
> lane. Case 31 hits a 429. Your first-draft policy had `max_tries=10` and no cap —
> "the nightly has all night" — and the SDK below it retries four times per attempt.
> 😬 **The naive fix:** more tries is more robust. And for the *day* job, a friendlier
> idea: when the retries run out, return `{"verdict": "pass"}` so the eval report isn't
> full of holes.
> 💥 **Why it fails, twice:** (1) ten outer tries × four inner SDK retries × exponential
> waits = a single call can hang for **many minutes**, holding the run, holding the
> ledger's minute window hostage, and — on a daily cap — retrying into a wall that
> will not move until midnight. Nothing logs "this is hopeless" because every layer
> thinks the layer above will decide. (2) The friendly fallback is the worst line in the
> codebase: a green eval that never ran. Phase 12 will make behaviour changes merge on
> green evalsets; a fabricated pass silently approves a regression. The *model* never
> lied — your retry helper did.
> 💡 **The insight:** **bound the waiting and type the failure.** Know every retry layer
> (SDK, helper, hooks) and make exactly one of them own the *policy*; cap total tries
> and total wait; distinguish *window* (wait) from *day* (stop); and make "gave up" a
> typed exception that downstream code must handle visibly — an eval case becomes
> `status: skipped (quota)`, a triage run becomes a resumable pause, a guard becomes
> "suspicious." Run it: set `max_tries=10, cap=None` in the fake demo and watch the
> clock; then try to write a `with_backoff(..., default=...)` parameter and notice the
> tests won't let you — `test_waits_1_2_4_8_then_raises_never_returns` is there to stop
> exactly this.

## 6 · 🎤 Interview corner

1. **"How do you handle rate limits honestly?"** — One helper for every call path:
   honour the server's stated delay (`retry-after` header on Groq/OpenRouter, "retry in
   Ns" in Gemini's message), otherwise 1→2→4→8 s with jitter, capped; after four tries
   raise a typed `BackoffExhausted` with lane, attempts and waited time — it returns the
   real result or raises, there is no default-value parameter, by test. Non-429 errors
   surface immediately. I know the three retry layers (SDK, my helper, ADK's error hooks)
   and exactly one owns the policy, so a throttle is seconds, not minutes.
2. **"What does the agent do when it finally gives up?"** — It says so. The error hook
   logs `quota_escalated` with the invocation id and the resume command, tells the
   router to mark the lane dry for the server's delay, and re-raises — no sleeping in the
   hook (it would hold the thread) and no fabricated reply (it would lie). Because runs
   are durable, a 429-killed triage is a *paused* triage: wait out the window, `resume`,
   and the reinstated events spend nothing. There's a runbook for the human side: what
   fired, window or day, wait/reroute/resume, record.
3. **"Why not use the framework's retry plugin?"** — ADK's `ReflectAndRetryToolPlugin`
   retries *tool* failures by asking the model to reflect — a great fit for a malformed
   argument, the wrong fit for quota, because reflection is a model call on the lane that
   just refused. 429s stay on a deterministic path; I'd adopt the reflect-and-retry plugin
   for tool-argument errors, and measure it in evals.
