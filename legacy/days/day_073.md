## 1 · 🎬 Where we are — the story so far

For seventy-two days, every Sutra run began the same way: *you* typed a command. Even
the durable runs of Phase 9 — parked overnight, resumed in the morning — were parked
*by you* and resumed *by you*. The desk has a brain, brakes, memory, an approval trail,

runs the evals hook (a placeholder tonight; Phase 12 fills it), and writes a one-page
**digest** that tomorrow's standup agent (Day 77) will read out loud.

## 3 · 📚 Concepts

### AG-24 — Ambient agents: the night shift has no supervisor

**The night-shift story.** A hospital's day shift has a charge nurse: someone notices a
mistake and fixes it in minutes. The night shift is three people and a pager. So night
procedures are *different* in kind — not "the same, but at night": every action is
checklisted so it can be done half-asleep, every checklist has a "done" box so the
next person doesn't repeat it, and the rule for anything unclear is *write it down and
leave it for the morning* — never improvise. Fewer eyes means **more structure**, not
more trust.

An **ambient agent** is the night shift: a process that acts on a trigger — a clock, a
message, a new row — with no human typing. Everything Sutra learned about brakes now
tightens one notch:

| Daytime Sutra (Phases 1–10) | Ambient Sutra (tonight) | Why it tightens |
| --- | --- | --- |
| you re-run a failed command | the scheduler re-runs it *for* you — at 02:31, 02:32… | **idempotence is mandatory**, not polite: a per-date ledger says which jobs are done |
| a 429 prints and you wait | nobody reads the print | `with_backoff` (Day 72) tries honestly, then the job records **"skipped: quota"** in the digest and stops — never loops till dawn |
| you watch quota on the ledger | the job must *ask* before spending | the evals job checks `QuotaLedger.remaining()` / routes via the Quota-Router; tonight's jobs spend **zero** |
| an error stops you | an error must reach *the morning* | every exception is caught at the **job** boundary, written to the digest, and re-raised into the log — trap #4: surfaced, never swallowed |
| you decide what's worth doing | the digest decides what you read first | the morning reading is the product; a job with no line in the digest didn't happen (Principle 12) |

And one bright line that Phase 9 drew and the night keeps: **ambient jobs never
write anything customer-visible.** Re-indexing, evaluating, summarising — internal.
Closing a ticket at 02:30 with nobody to approve it is exactly what `POLICY` forbids
(`close_ticket` = `always` gated). The nightly job *can* file an approval request; it
can never grant one.

💡 **Mental model: an ambient agent is a checklist with a clock — the fewer the eyes,
the stricter the checklist.** Idempotent jobs, a per-date done-ledger, and "when in
doubt, write it in the digest and stop."

### ADK-51 — Scheduled runs: ADK's trigger door, and the clock outside it

**The mailbox story.** A café gets deliveries two ways: the owner drives to the market
(pull — `python -m sutra.nightly run`), or a supplier drops parcels in the back-door
mailbox and a bell rings (push — a **trigger**). ADK 2.x builds the back-door mailbox
into `api_server` (verified adk.dev/runtime/ambient-agents/):

- start with `adk api_server --trigger_sources "pubsub" <agents_dir>`; ADK mounts
  `POST /apps/{app_name}/trigger/pubsub` (and `/trigger/eventarc`);
- a Pub/Sub push delivery posts `{"message": {"data": "<base64>"}, ...}`; ADK decodes
  the base64 and runs the app's agent with it — concurrency and retries are env knobs
  (`ADK_TRIGGER_MAX_CONCURRENT`, `ADK_TRIGGER_MAX_RETRIES`);
- the **clock is not ADK's**: in the cloud, Cloud Scheduler publishes to the Pub/Sub
  topic on a cron line; Pub/Sub pushes to `api_server` on Cloud Run. Scheduler → topic →
  endpoint. ADK owns the endpoint only.

Two zero-budget consequences (Addendum 02, Day 86–88 amendment): the *endpoint* is
free and local — you run it and poke it with curl today; the *clock and bus* (Cloud
Scheduler, Pub/Sub) bill → 🅿️ documented, not run. So Sutra's real clock tonight is
the laptop's: **Windows Task Scheduler** (`schtasks`) — and the job it runs is the
pull entrypoint, `python -m sutra.nightly run`, which needs no server at all. The day
you attach a billing account, the trigger endpoint is already there and the
`nightly` module is what the triggered agent would call.

💡 **Mental model: ADK owns the mailbox, not the clock.** `api_server` triggers = the
door; Scheduler/Pub/Sub (cloud) or `schtasks`/cron (laptop) = the bell.

```python
"""Day 73 — the nightly job: Sutra's first ambient behaviour.

Three jobs, one per-date ledger, one digest:

    reindex  -> rebuild data/archive_index.json (Day 49; local embeddings, 0 calls)
    evals    -> THE HOOK: tonight a zero-quota placeholder (pytest -q);
                Day 82 replaces it with tests/evals/run_evals.py:run(ctx)
    digest   -> data/digests/<date>.md: queue, approvals, quota, job results

Laws (AG-24): idempotent per date (data/nightly/<date>.json remembers what is
done); a job's exception is written into the digest AND re-raised into the
log (trap #4 - surfaced, never swallowed); nothing customer-visible is ever
written at night (POLICY still gates every write tool).

    python -m sutra.nightly run [--job NAME] [--date YYYY-MM-DD] [--force] [--dry-run]
    python -m sutra.nightly status [--date YYYY-MM-DD]
"""
from __future__ import annotations

import argparse
import json
import sqlite3
import subprocess
import sys
import traceback
from dataclasses import dataclass, field
from datetime import date
from pathlib import Path
from typing import Callable

from sutra.logging_setup import configure, get_logger   # house rule (Day 22)
from sutra.quota import QuotaLedger                      # Day 24's accountant

log = get_logger("nightly")

NIGHTLY_DIR = Path("data/nightly")        # one JSON ledger per date: which jobs ran
DIGEST_DIR = Path("data/digests")         # the morning reading, one .md per date
TICKETS_DB = Path("data/tickets.db")      # Day 39 archive (read-only here)
TASKS_DB = Path("data/tasks.db")          # Day 60's processed_writes lives here
APPROVALS_DB = Path("data/approvals.db")  # Day 63's store (read-only here)


@dataclass
class RunContext:
    """Everything a job may know. Day 82's evals runner receives exactly this.

    Args:
        date: ISO date the run is FOR (not necessarily today - --date lets you
            re-run a missed night honestly, under its own name).
        full: True on gate/nightly runs (full evalset), False for dev-size.
        dry_run: describe, don't do.
        ledger: the quota accountant - ask before spending.

    Example:
        >>> ctx = RunContext(date="2026-09-01", full=True)
        >>> ctx.ledger.remaining("gemini-lite")["rpm_used"]
        0
    """
    date: str
    full: bool = True
    dry_run: bool = False
    ledger: QuotaLedger = field(default_factory=QuotaLedger.load)


@dataclass(frozen=True)
class Job:
    """One row of the night checklist.

    Args:
        name: the registry key and the ledger key.
        run: callable(ctx) -> dict of facts for the digest. Must be idempotent
            for the same ctx.date (the ledger protects you, but design it so).
        spends_model_calls: if True the job must consult ctx.ledger first.
    """
    name: str
    run: Callable[[RunContext], dict]
    spends_model_calls: bool = False


# ---------------------------------------------------------------------------
# the jobs
# ---------------------------------------------------------------------------
def job_reindex(ctx: RunContext) -> dict:
    """Rebuild the archive embedding index (Day 49). Local Ollama, zero quota."""
    if ctx.dry_run:
        return {"would": "rebuild data/archive_index.json"}
    from sutra.retrieval import build_index        # lazy: keeps import side-effect free
    n = build_index()                               # Day 49 returns the row count
    return {"rows_indexed": n}


def evals_placeholder(ctx: RunContext) -> dict:
    """THE HOOK, tonight's body: run the zero-quota pytest suite.

    Day 82 swaps this for `tests.evals.run_evals.run` with the SAME signature:
    run(ctx: RunContext) -> dict with at least {"cases", "passed", "failed"}.
    """
    if ctx.dry_run:
        return {"would": "uv run pytest -q  (placeholder until Day 82)"}
    proc = subprocess.run([sys.executable, "-m", "pytest", "-q"],
                          capture_output=True, text=True, check=False)
    last = proc.stdout.strip().splitlines()[-1:] or [""]   # pytest's summary line
    return {"exit_code": proc.returncode, "summary": last[0]}


def _count(db: Path, sql: str) -> int | None:
    """One COUNT(*) against one store; None (not 0!) if the store is missing.

    Example:
        >>> _count(Path("does/not/exist.db"), "SELECT COUNT(*) FROM x") is None
        True
    """
    if not db.exists():
        return None                                  # honest: unknown != zero
    con = sqlite3.connect(f"file:{db}?mode=ro", uri=True)   # read-only (Day 39)
    try:
        return con.execute(sql).fetchone()[0]
    finally:
        con.close()


def queue_snapshot() -> dict:
    """The desk's state as numbers - read-only, zero quota. Day 77 reuses this."""
    return {
        "tickets_total": _count(TICKETS_DB, "SELECT COUNT(*) FROM tickets"),
        "tickets_closed": _count(TASKS_DB,
            "SELECT COUNT(*) FROM processed_writes WHERE tool='close_ticket'"),
        "approvals_pending": _count(APPROVALS_DB,
            "SELECT COUNT(*) FROM approvals WHERE status='pending'"),
    }


def job_digest(ctx: RunContext, results: dict | None = None) -> dict:
    """Write data/digests/<date>.md from rows alone. Zero model calls.

    Args:
        ctx: the run context (date names the file).
        results: the other jobs' facts for this date (from the ledger).
    """
    DIGEST_DIR.mkdir(parents=True, exist_ok=True)
    snap = queue_snapshot()
    spent = ctx.ledger.requests_today                 # {provider: requests}
    lines = [f"# Sutra digest — {ctx.date}", "",
             "## Queue", f"- tickets in archive: {snap['tickets_total']}",
             f"- closed (processed_writes): {snap['tickets_closed']}",
             f"- approvals pending: {snap['approvals_pending']}", "",
             "## Quota spent today (requests per lane)"]
    lines += [f"- {k}: {v}" for k, v in sorted(spent.items())] or ["- none recorded"]
    lines += ["", "## Jobs", "| job | status | facts |", "| --- | --- | --- |"]
    for name, rec in sorted((results or {}).items()):
        lines.append(f"| {name} | {rec['status']} | `{json.dumps(rec.get('facts'))}` |")
    out = DIGEST_DIR / f"{ctx.date}.md"
    if not ctx.dry_run:
        out.write_text("\n".join(lines) + "\n", encoding="utf-8")
    return {"path": str(out), "pending_approvals": snap["approvals_pending"]}


JOBS: dict[str, Job] = {                              # the night checklist, in order
    "reindex": Job("reindex", job_reindex),
    "evals":   Job("evals", evals_placeholder, spends_model_calls=True),
    "digest":  Job("digest", lambda ctx: job_digest(ctx, _ledger_load(ctx.date))),
}


# ---------------------------------------------------------------------------
# the per-date ledger: "done" boxes on the checklist
# ---------------------------------------------------------------------------
def _ledger_path(day: str) -> Path:
    return NIGHTLY_DIR / f"{day}.json"


def _ledger_load(day: str) -> dict:
    p = _ledger_path(day)
    return json.loads(p.read_text(encoding="utf-8")) if p.exists() else {}


def _ledger_save(day: str, data: dict) -> None:
    NIGHTLY_DIR.mkdir(parents=True, exist_ok=True)
    _ledger_path(day).write_text(json.dumps(data, indent=2), encoding="utf-8")


def run_night(day: str, only: str | None = None, *, force: bool = False,
              dry_run: bool = False) -> dict:
    """Run the checklist for one date; skip boxes already ticked.

    Returns the ledger for that date. Exceptions inside a job are recorded
    ("failed", with the traceback's last line) AND re-raised after the digest
    is written - so the morning sees it and the log has it (trap #4).

    Example:
        >>> run_night("2026-09-01", dry_run=True)["reindex"]["status"]
        'dry-run'
    """
    ctx = RunContext(date=day, dry_run=dry_run)
    ledger = _ledger_load(day)
    failures: list[BaseException] = []
    for name, job in JOBS.items():
        if only and name != only:
            continue
        if ledger.get(name, {}).get("status") == "ok" and not force:
            log.info("nightly_skip_done", extra={"job": name, "date": day})
            print(f"{name:8} already done for {day} (use --force to redo)")
            continue
        if job.spends_model_calls and not dry_run:
            left = ctx.ledger.remaining("gemini-lite")        # ask before spending
            log.info("nightly_quota_check", extra={"job": name, **left})
        try:
            facts = job.run(ctx)
            ledger[name] = {"status": "dry-run" if dry_run else "ok", "facts": facts}
            print(f"{name:8} {'dry-run' if dry_run else 'ok'}  {facts}")
        except Exception as exc:                            # job boundary ONLY
            ledger[name] = {"status": "failed",
                            "facts": {"error": traceback.format_exc().strip().splitlines()[-1]}}
            log.exception("nightly_job_failed", extra={"job": name, "date": day})
            print(f"{name:8} FAILED  {exc}")
            failures.append(exc)
        if not dry_run:
            _ledger_save(day, ledger)                       # tick the box NOW
    if failures:                                            # digest written first,
        raise failures[0]                                   # then surface - never hide
    return ledger


def main() -> None:
    """CLI: run / status."""
    configure()
    ap = argparse.ArgumentParser(prog="python -m sutra.nightly")
    sub = ap.add_subparsers(dest="cmd", required=True)
    r = sub.add_parser("run");    r.add_argument("--job"); r.add_argument("--date")
    r.add_argument("--force", action="store_true"); r.add_argument("--dry-run", action="store_true")
    s = sub.add_parser("status"); s.add_argument("--date")
    a = ap.parse_args()
    day = a.date or date.today().isoformat()
    if a.cmd == "run":
        run_night(day, a.job, force=a.force, dry_run=a.dry_run)
    else:
        led = _ledger_load(day)
        for name in JOBS:
            print(f"{name:8} {led.get(name, {}).get('status', '—')}")


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the job that ran the night away

> 🎬 **The scene:** it is Day 83. The evals job is real now and spends ~40 Flash-Lite
> calls. One night Ollama is down, so `reindex` raises; you wrote the loop the obvious
> way — `while True: try: run_all() except: sleep(60)` — "retry until it works, it's
> the night, nobody's waiting."
> 😬 **The naive fix:** keep retrying; the index will come back eventually.
> 💥 **Why it fails:** `run_all()` re-runs *every* job on every retry, and the evals
> job is not behind a done-box — so each minute burns another 40 calls on the lane
> Phase 12 needs in the morning. By 04:00 you have spent the day's Flash-Lite RPD on
> a job that already passed at 02:31, the digest was never written (the loop never
> reached it), and the morning standup has nothing to say except "429". The night
> turned one broken dependency into three: index, quota, and visibility.
> 💡 **The insight:** **at night, a retry loop is a quota furnace unless every job
> has a done-box.** The per-date ledger makes "retry the night" safe — only failed
> boxes re-run; `with_backoff` bounds each attempt; the digest is written even when
> something failed (that's why `run_night` records first and raises after). And the
> scheduler is the retry loop: one run per night, failures left for the morning.
> Run `python -m sutra.nightly run` with Ollama stopped and watch it do exactly that.

## 6 · 🎤 Interview corner

1. **"What changes in an agent's design when it runs unattended?"** — The brakes
   tighten: every job becomes idempotent under a per-run ledger so the scheduler's
   retries can't repeat side effects; spending is gated by a quota check instead of by
   a human noticing; errors are caught only at the job boundary, recorded into a
   morning digest, and re-raised into the log — never swallowed; and unattended jobs
   never perform customer-visible writes, because the approval policy still gates
   them and nobody is there to approve. My nightly job does re-index, evals, and
   digest, and a second run the same night is a no-op by construction.
2. **"How would you schedule an ADK agent in production vs on a laptop?"** — ADK owns
   the endpoint, not the clock: `api_server --trigger_sources pubsub` mounts a Pub/Sub
   push endpoint that decodes and runs; in GCP, Cloud Scheduler publishes on a cron
   line and Pub/Sub pushes to Cloud Run. I ran that endpoint locally with a
   Pub/Sub-shaped POST. On the laptop the clock is Task Scheduler/cron calling a pull
   entrypoint — same module, zero cost; the cloud wiring is ready the day it's paid for.
3. **"What's in your nightly digest, and why no LLM in it?"** — Queue counts,
   approvals pending, quota spent per lane, and a table of job results — all from
   database rows, so the morning can audit it. No model call by default: a summary you
   can't verify at 02:30 is a liability; a voice agent can narrate it in the morning
   with a human listening (Day 77).
