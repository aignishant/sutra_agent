## 3 · 📚 Concepts

### ADK-29 — Database-backed sessions: same drawer, real wood

**The hotel-front-desk story.** A tiny hotel keeps guest records in the receptionist's
*head*. Fast! Perfectly accurate! Until the receptionist goes home. The night shift walks
in and every guest is a stranger — mid-stay, mid-complaint, mid-anything. The fix is not a
smarter receptionist; it is the **guest ledger on the counter**: any shift picks it up and
continues where the last one stopped.

| Hotel | Our system | Technical name |
| --- | --- | --- |
| Receptionist's head | sessions in process RAM | `InMemorySessionService` (Day 8) |
| The ledger on the counter | sessions in a database file | `DatabaseSessionService` |
| "Any shift picks it up" | any *process* picks it up | persistence across restarts |
| The ledger's grammar | tables ADK creates & owns | SQLAlchemy-managed schema |

The beautiful part is how little changes. Day 8 taught that the session service rides the
**runner**, not the agent. That design decision pays out today in one line:

```python
# yesterday                                   # today
InMemorySessionService()              →       DatabaseSessionService(db_url=DB_URL)
```

Agent untouched. Tools untouched. `create_session` / `get_session` / the whole CRUD from
Day 8 — identical. Only the furniture under the API became real. 💡 **Mental model: the
session service is a socket; today we plug persistence into it.** (File this pattern — the
memory service has the same socket shape, and Day 49 plugs a retrieval brain into *that*.)

**The one rule that bites: async drivers.** ADK's runtime is async (you've been writing
`async for event in runner.run_async(…)` since Day 8). A database driver that *blocks*
would freeze the event loop — so the service demands async drivers, and for SQLite that
means the URL names one explicitly:

```
sqlite+aiosqlite:///./data/sessions.db
└──┬─┘ └───┬───┘   └────────┬────────┘
 dialect  async driver    relative path (three slashes, then ./)
```

Plain `sqlite:///./data/sessions.db` — the form every SQLAlchemy tutorial shows — fails
here. That's the failure lab, run on purpose so the error message is an old friend.

**What lands in the file?** Everything Day 17 taught, minus one deliberate exception:
events, and state at its scopes — session state, `user:`, `app:` — persist; **`temp:`
does not** (that prefix *means* "do not persist"; today is the day the name cashes out).

**Concurrency, honestly.** The docs note in-process locking, plus row-level locking on
the server databases (PostgreSQL/MySQL/MariaDB). Read that as: SQLite is the right
single-host answer (and plenty for Sutra), and when Phase 13 containerizes with multiple
replicas, the *same one-line swap* points `db_url` at PostgreSQL — the deploy story was
inside the constructor all along.

```python
"""Day 47 — persistent sessions: the desk that survives the night.

Same lab shape as Day 8's run_agent.py, with one line changed: the
session service is DatabaseSessionService over data/sessions.db. The
point of the day is proof-by-murder: talk, kill the process, talk
again with the same session id, and watch the conversation continue.

Run from the repo root:

    python -m sutra.persist_lab talk 4521-chat   # one turn, then exits (process dies!)
    python -m sutra.persist_lab talk 4521-chat   # run AGAIN: it remembers
    python -m sutra.persist_lab inspect          # list sessions from a cold process
    python -m sutra.persist_lab broken           # failure lab: the sync-driver trap
"""
from __future__ import annotations

import asyncio
import sys

from google.adk.agents.llm_agent import Agent
from google.adk.runners import Runner
from google.adk.sessions import DatabaseSessionService       # today's one change
from google.genai import types

from sutra.config import load_env
from sutra.logging_setup import get_logger

log = get_logger(__name__)

APP = "sutra_persist_lab"
USER = "agent_riya"
PRIMARY_MODEL = "gemini-3.5-flash"                           # pinned (ADK-73)

# The URL anatomy matters: dialect+DRIVER — aiosqlite is the async driver
# the runtime requires. The sync form (no +aiosqlite) is demo `broken`.
DB_URL = "sqlite+aiosqlite:///./data/sessions.db"

COUNT_KEY = "turn_count"                                     # plain session scope — persists


def make_agent() -> Agent:
    """The lab agent: numbered turns make persistence visible.

    Returns:
        A pinned-model Agent whose instruction asks it to number its
        replies from {turn_count?} — so a resumed session visibly
        continues the count instead of restarting at 1.

    Example:
        >>> make_agent().name
        'persist_lab'
    """
    return Agent(
        name="persist_lab",
        model=PRIMARY_MODEL,
        instruction=(
            "You are Sutra's continuity probe. State {" + COUNT_KEY + "?} is how many "
            "turns this conversation has had before this one. Begin every reply with "
            "'(turn N)' where N is that count plus one, then answer briefly."
        ),
    )


def make_runner() -> tuple[Runner, DatabaseSessionService]:
    """Build the runner over the persistent store.

    Returns:
        (runner, session_service) — the service is returned too so demos
        can use the Day 8 CRUD directly.

    Example:
        >>> runner, svc = make_runner()      # creates data/sessions.db on first use
    """
    svc = DatabaseSessionService(db_url=DB_URL)              # the whole day, one line
    runner = Runner(agent=make_agent(), app_name=APP, session_service=svc)
    return runner, svc


async def _talk(session_name: str) -> None:
    """One turn in a named session; create it only if it doesn't exist.

    Args:
        session_name: OUR stable id for the conversation (passed as the
            session_id), so a later process can find the same drawer.
    """
    runner, svc = make_runner()
    sess = await svc.get_session(                            # look for yesterday's drawer
        app_name=APP, user_id=USER, session_id=session_name
    )
    if sess is None:                                         # first run: make it
        sess = await svc.create_session(
            app_name=APP, user_id=USER, session_id=session_name,
            state={COUNT_KEY: 0},                            # the visible counter
        )
        print(f"[created NEW session {session_name!r}]")
    else:                                                    # later runs: found on disk
        print(f"[FOUND session {session_name!r} on disk — "
              f"{len(sess.events)} past events, state={dict(sess.state)}]")

    turns = sess.state.get(COUNT_KEY, 0)
    msg = types.Content(role="user", parts=[types.Part(
        text=f"Continuity check number {turns + 1}. One sentence, please."
    )])
    async for event in runner.run_async(
        user_id=USER, session_id=session_name, new_message=msg,
    ):
        if event.is_final_response() and event.content and event.content.parts:
            print("AGENT:", "".join(p.text or "" for p in event.content.parts))

    # Bump the counter THROUGH the service (the Day 17 rule: state changes
    # travel as event deltas, never by scribbling on a fetched session).
    from google.adk.events import Event, EventActions        # local import: demo-only
    await svc.append_event(
        session=await svc.get_session(app_name=APP, user_id=USER,
                                      session_id=session_name),
        event=Event(
            author="persist_lab",
            actions=EventActions(state_delta={COUNT_KEY: turns + 1}),
        ),
    )
    print(f"[state {COUNT_KEY} -> {turns + 1}; process exits NOW — that's the murder]")


async def _inspect() -> None:
    """Cold-process proof: list what the database knows, zero model calls."""
    _, svc = make_runner()
    listed = await svc.list_sessions(app_name=APP, user_id=USER)
    for s in listed.sessions:                                # whatever survived, honestly
        print(f"session {s.id!r}")
    if not listed.sessions:
        print("(no sessions on file — run the talk demo first)")


def demo_broken() -> None:
    """Failure lab: the sync-driver URL. Read doc §5 BEFORE running."""
    try:
        svc = DatabaseSessionService(db_url="sqlite:///./data/broken.db")  # no +aiosqlite
        asyncio.run(svc.create_session(app_name=APP, user_id=USER))
    except Exception as err:                                 # noqa: BLE001 — lab: we WANT to see it
        print(f"{type(err).__name__}: {err}")                # read this message out loud
        print("→ the async runtime refused a blocking driver. "
              "The fix is in the URL: sqlite+aiosqlite:///")


def main() -> None:
    """Demo dispatcher; `talk` takes the session name as a second arg."""
    load_env()
    cmd = sys.argv[1] if len(sys.argv) > 1 else "talk"
    if cmd == "talk":
        _name = sys.argv[2] if len(sys.argv) > 2 else "4521-chat"
        asyncio.run(_talk(_name))
    elif cmd == "inspect":
        asyncio.run(_inspect())
    elif cmd == "broken":
        demo_broken()
    else:
        print("usage: python -m sutra.persist_lab [talk <name>|inspect|broken]")
        raise SystemExit(2)


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the tutorial URL that freezes the desk

> 🎬 **The scene:** wiring the database, you copy a connection string from a SQLAlchemy
> tutorial: `sqlite:///./data/sessions.db`. It's the canonical form; ten thousand blog
> posts agree.
> 😬 **The naive fix:** when it errors, add retries, or "just run it sync somewhere" —
> wrap the call in `asyncio.to_thread`, or hunt for a flag to make ADK stop complaining.
> 💥 **Why it fails:** the complaint IS the safety feature. ADK's runtime is an event
> loop; every `async for event in run_async(…)` you've written since Day 8 shares one
> thread of execution. A synchronous driver **blocks that thread** for every disk touch —
> under load, one slow write freezes *every* concurrent conversation at the desk, and
> nothing in the logs says why (the classic "it's just slow sometimes" outage). The
> service refusing the sync driver at startup converts a production heisenbug into an
> immediate, readable error.
> 💡 **The insight:** **in an async system, a blocking dependency is not slower — it is a
> different, wrong architecture,** and the best frameworks make it fail loudly at the
> door instead of quietly at 2 a.m. Read the driver name in the URL as a contract term:
> `+aiosqlite` is you promising the event loop you won't stand in its way.

Observed today, not just asserted: `python -m sutra.persist_lab broken` — the error
names the driver problem at construction/first-use, before any conversation existed.

## 6 · 🎤 Interview corner

1. **"How do you make an agent's conversations survive a restart?"** — Persist the
   session layer, and design so persistence is a deployment choice, not an agent
   change. In ADK the session service rides the runner: swapping
   `InMemorySessionService` for `DatabaseSessionService(db_url=…)` is one line, and the
   agent/tools don't know it happened. I proved it the honest way — one turn, kill the
   process, second turn from a new process continuing the same numbered conversation.
   Detail that shows real contact: on SQLite the URL must name an async driver
   (`sqlite+aiosqlite:///`) because a blocking driver would freeze the shared event loop.
2. **"SQLite for session storage — production-ready or a toy?"** — It's the right answer
   for a single host and the wrong one for replicas. Right: transactional, zero-ops, and
   ADK adds in-process locking. Wrong: multiple container replicas need row-level
   locking and a network database — same constructor, PostgreSQL URL. The interesting
   engineering point is that the migration cost is one config value *because* the
   interface was designed as a socket; I keep session storage, task state, and the
   read-only archive as three separate databases so each can graduate independently.
3. **"What state should NOT survive a restart?"** — Anything scoped as scratch. ADK
   encodes it in the key itself: the `temp:` prefix means never persisted, while
   session/`user:`/`app:` scopes are durable. Having the retention policy in the *name*
   means you can audit it with grep — which beats a policy that lives in someone's
   memory of the code.
