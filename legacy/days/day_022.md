perfect customer records and no operational records will run fine right up until the first
bad afternoon, and then nobody can reconstruct it.

Today Sutra gets its **flight recorder**: structured logging. Not prettier print — a
different data structure. One line per happening, every line machine-readable JSON, written
to a file that outlives the terminal. (OpenTelemetry tracing — the industrial-strength
sibling — arrives Day 84. Today builds the habit and the format it will inherit.)

## 3 · 📚 Concepts

### OPS-04 — Logs are data, or they are foam

**The flight-recorder story.** After an incident, two airlines investigate. Airline A has a
cockpit voice recorder: hours of ambient talk — someone *mentions* the altitude somewhere.
Airline B has the flight data recorder: altitude, heading, throttle — **named fields,
sampled every second**. Airline A *reads and hopes*; airline B *queries and knows*. Both
"kept records." Only one kept *data*.

`print("KB failed again for 4521!")` is cockpit chatter. Today we build the other recorder:

```json
{"ts": "2026-08-18T14:02:11Z", "level": "ERROR", "event": "tool_error",
 "tool": "search_kb", "ticket_id": "4521", "error": "ConnectionError: kb.internal:5432",
 "invocation_id": "inv-7f3a", "attempt": 3}
```

Same happening — but now `"how many tool_errors per tool since Monday?"` is a *filter*,
not an archaeology dig.

| Chatter (`print`) | Flight data (structured log) |
| --- | --- |
| a sentence, shaped by mood | named fields, shaped by schema |
| goes to the terminal, then nowhere | goes to a file/stream that outlives the process |
| always "on", one volume | leveled: DEBUG/INFO/WARNING/ERROR, tunable without edits |
| findable by grep-luck | queryable by field |

Four working rules carry the whole practice:

1. **One line, one event, valid JSON** (aka *JSON Lines*): tools from PowerShell one-liners
   to log pipelines eat this format. Multi-line prose logs break every parser downstream.
2. **Log fields, not sentences.** The message key stays short and *stable*
   (`"event": "tool_error"`); the variability lives in fields. If you're formatting values
   into the message string, you're writing chatter with extra steps.
3. **Thread a correlation id.** Ten log lines matter mostly in *relation*: same run or
   different runs? ADK already names each doorbell-press (the invocation, Day 17) — put
   that id on every line and one run's story reassembles with a single filter. This exact
   idea, grown up, is Day 84's *trace id*.
4. **Levels are policy, print is anarchy.** DEBUG = development detail, INFO = normal
   operations ("run started"), WARNING = degraded-but-working (a retry), ERROR = a failure
   that surfaced (Day 21's exceptions land here). The reader picks the volume at *config*
   time — no code edits to quiet a noisy module.

💡 **Mental model: a log line is a row in tomorrow's incident-investigation table. Write
rows, not remarks.**

And the boundaries, stated once: logs are **operational** truth — the *conversation* truth
already lives in session events (don't duplicate transcripts into logs); **secrets and raw
user text stay out** (log ids and shapes, not payloads — the repo goes public in Phase 14,
and pasted keys-in-logs is a classic breach); logs directory is **gitignored** (they're
runtime residue, like `.env` — with the same "never commit" discipline, Principle 9's
cousin).

```python
"""Day 22 — structured logging: the flight recorder.

One JSON object per line, to stderr AND logs/sutra.jsonl. Library code
gets loggers from here and never calls print() again (house rule).

    python -m sutra.logging_setup demo      # writes 3 sample lines, 0 quota
    python -m sutra.logging_setup logbook   # one FULLY-RECORDED triage run
"""
from __future__ import annotations

import json
import logging
import sys
import time
from pathlib import Path
from typing import Any

LOG_DIR = Path("logs")                               # gitignored (step 2)
LOG_FILE = LOG_DIR / "sutra.jsonl"                   # .jsonl = JSON Lines

# Attributes every LogRecord has; anything NOT here that we find on a
# record is a field the caller attached via `extra=` — we forward those.
_STDLIB_ATTRS = frozenset(vars(logging.makeLogRecord({})))


class JsonLinesFormatter(logging.Formatter):
    """Formats each record as ONE JSON object on ONE line.

    Example:
        logger.info("tool_call", extra={"tool": "search_kb", "ticket_id": "4521"})
        -> {"ts": "...", "level": "INFO", "logger": "sutra.logbook",
            "event": "tool_call", "tool": "search_kb", "ticket_id": "4521"}
    """

    def format(self, record: logging.LogRecord) -> str:
        row: dict[str, Any] = {
            "ts": self.formatTime(record, "%Y-%m-%dT%H:%M:%S")   # when
                  + f".{int(record.msecs):03d}",
            "level": record.levelname,                # how serious
            "logger": record.name,                    # which module spoke
            "event": record.getMessage(),             # SHORT STABLE name, not prose
        }
        for key, value in vars(record).items():       # forward the extra= fields
            if key not in _STDLIB_ATTRS and not key.startswith("_"):
                row[key] = value                      # e.g. tool, ticket_id, ms
        if record.exc_info:                           # exceptions ride along too
            row["exc"] = self.formatException(record.exc_info).splitlines()[-1]
        return json.dumps(row, ensure_ascii=False, default=str)  # ONE line, always


def configure(level: int = logging.INFO) -> None:
    """Install the flight recorder once, process-wide.

    Args:
        level: minimum level that gets recorded (policy knob, not code).

    Example:
        >>> configure()                       # at every entry point, once
        >>> logging.getLogger("sutra.x").info("hello", extra={"n": 1})
        (line appears on stderr and in logs/sutra.jsonl)
    """
    LOG_DIR.mkdir(exist_ok=True)                      # the shelf must exist
    root = logging.getLogger("sutra")                 # OUR namespace root, not ""
    if root.handlers:                                 # configure() is idempotent —
        return                                        # calling twice must not dup lines
    root.setLevel(level)
    formatter = JsonLinesFormatter()
    for handler in (logging.StreamHandler(sys.stderr),        # live view
                    logging.FileHandler(LOG_FILE, encoding="utf-8")):  # history
        handler.setFormatter(formatter)
        root.addHandler(handler)


def get_logger(name: str) -> logging.Logger:
    """The one door modules use: get_logger(__name__).

    Args:
        name: module name; will be nested under the 'sutra' namespace.

    Returns:
        A logger whose lines flow through the JSON handlers.
    """
    short = name.removeprefix("sutra.")               # avoid sutra.sutra.x
    return logging.getLogger(f"sutra.{short}")


def demo() -> None:
    """Three sample rows — watch stderr, then open the file. Zero quota."""
    configure()
    log = get_logger("demo")
    log.info("run_start", extra={"invocation_id": "inv-demo", "user_id": "priya"})
    log.warning("retry", extra={"invocation_id": "inv-demo",
                                "tool": "search_kb", "attempt": 1})
    try:
        raise ConnectionError("kb.internal:5432 timed out")
    except ConnectionError:
        log.error("tool_error", exc_info=True,
                  extra={"invocation_id": "inv-demo", "tool": "search_kb",
                         "ticket_id": "4521"})
    print(f"\nwrote to {LOG_FILE} — open it: every line is one JSON object")


def logbook() -> None:
    """One triage run, fully recorded: the Day 21 agent + a logging plugin.

    We reuse Day 21's honest agent and safety net, but every hook now
    writes ROWS. (~2 model calls.)
    """
    configure()
    log = get_logger("logbook")
    import asyncio                                    # local: demo-only deps
    from google.adk.runners import Runner
    from google.adk.sessions import InMemorySessionService
    from google.genai import types
    from sutra.config import load_env
    from sutra.errors import SafetyNetPlugin, _agent, search_kb_honest

    load_env()
    service = InMemorySessionService()
    runner = Runner(agent=_agent(search_kb_honest), app_name="sutra",
                    session_service=service, plugins=[SafetyNetPlugin()])
    asyncio.run(service.create_session(app_name="sutra", user_id="priya",
                                       session_id="s1"))
    message = types.Content(role="user", parts=[types.Part(
        text="Users keep getting logged out (ticket 4521). Check the KB.")])

    async def go() -> None:
        started = time.monotonic()
        log.info("run_start", extra={"user_id": "priya", "ticket_id": "4521"})
        async for event in runner.run_async(user_id="priya", session_id="s1",
                                            new_message=message):
            # The event stream (Day 7) is our microphone — each event
            # becomes one operational row with FIELDS, not transcripts:
            row = {"author": event.author,
                   "final": bool(event.is_final_response())}
            if getattr(event, "usage_metadata", None):        # cost fields, if present
                row["total_tokens"] = event.usage_metadata.total_token_count
            log.info("event", extra=row)
            if event.is_final_response() and event.content:
                print("reply:", event.content.parts[0].text.strip())
        log.info("run_end",
                 extra={"ticket_id": "4521",
                        "ms": int((time.monotonic() - started) * 1000)})

    asyncio.run(go())


def main() -> None:
    """Demo dispatcher — house pattern."""
    demos = {"demo": demo, "logbook": logbook}
    name = sys.argv[1] if len(sys.argv) > 1 else "demo"
    if name not in demos:
        print(f"usage: python -m sutra.logging_setup [{'|'.join(demos)}]")
        raise SystemExit(2)
    demos[name]()


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — grep-luck at 2 a.m.

> 🎬 **The scene:** three weeks from now, the nightly job (Day 73) misbehaves: some
> tickets got re-triaged twice. You have terminal scrollback from *tonight only* and a
> folder of prose logs from the era when messages were sentences: "KB failed again!",
> "retrying…", "done ✔". You need: which tickets, which tool, first occurrence, how often.
> 😬 **The naive fix:** grep. `Select-String "again"` … 400 matches. `Select-String
> "4521"` … matches a token count that happens to contain 4521. Two hours of regex
> archaeology produce a *guess*.
> 💥 **Why it fails:** prose logs store information in *phrasing*, and phrasing drifts —
> one dev wrote "KB failed", another "kb error", a third localized the message. Fields
> that were never recorded (ticket id, attempt number, duration) cannot be extracted by
> any regex because they aren't *there*. The data died at write time, politely, without an
> error — the same silent failure mode as Day 21's tape, one layer up.
> 💡 **The insight:** **logs are written once and read a hundred times, always under
> pressure — optimize for the reader.** A stable event name, fields for everything
> variable, a correlation id, valid JSON per line: with those, the 2 a.m. question is a
> `Where-Object` one-liner. Without them, it's grep-luck. (And the discipline compounds:
> Day 24 reads *these rows* to count quota; Day 84's OTel traces are these rows with a
> pedigree.)

## 6 · 🎤 Interview corner

1. **"How do you make an agent system debuggable in production?"** — Layers of record,
   each structured: the conversation lives in session events; facts in state deltas; and
   the *operational* story — which tool, how long, what failed, what it cost — as
   structured logs: one JSON object per line, stable event names, variability in fields,
   a correlation id tying each run's rows together. I can filter a day of logs to one
   run's skeleton in one command; that's the difference between investigating and
   remembering.
2. **"print-debugging works fine for you — why bother?"** — Because print stores facts in
   phrasing, and phrasing can't be queried, leveled, or kept. The honest comparison I use:
   "how many search_kb failures per ticket since Monday?" — against my JSONL that's a
   two-clause filter; against prose it's regex archaeology over messages three developers
   spelled differently. Plus levels are runtime policy: I can turn DEBUG on for one module
   during an incident without touching code.
3. **"What do you deliberately keep OUT of logs?"** — Secrets and raw user payloads — log
   ids and shapes, not contents; our repo goes public, and free-tier data rules make this
   non-negotiable anyway. Also transcripts (the session log already owns conversation
   truth — duplicating it doubles storage and creates two versions of one story). And the
   files themselves stay out of git: runtime residue, same shelf discipline as `.env`.
