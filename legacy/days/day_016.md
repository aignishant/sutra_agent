## 3 · 📚 Concepts

### ADK-18 — Built-ins: capabilities you switch on, not write

Compare the three ways Sutra has gained a power:

| How | Example | Who runs the code | You audit |
| --- | --- | --- | --- |
| Hand-written function | `lookup_ticket` (Day 10) | your process | every line |
| Generated from a spec | `get_vendor_status` (Day 15) | your process (httpx) | the spec + endpoint |
| **Built-in** | `google_search`, code execution | **Google's platform** | the *configuration* and the *outputs* |

The wiring is almost insultingly small — that's the point and the danger:

```python
from google.adk.tools import google_search
from google.adk.code_executors import BuiltInCodeExecutor

searcher = Agent(..., tools=[google_search])          # a TOOL: the model may choose it
coder    = Agent(..., code_executor=BuiltInCodeExecutor())  # an EXECUTOR: how code parts run
```

Note the asymmetry you must be able to explain: search is a **tool** (a choice the model
makes per turn), code execution is an **executor** (a capability of the agent — the model
emits code blocks, the executor runs them and feeds results back). ADK renamed and moved
these apart deliberately (v1.0 notes) — tools are *what an agent can use*, executors are
*how something is performed*.

**⚠️ The exclusivity wall** (limitations page, verified): on the Gemini API, using these
specific built-ins in an agent **excludes other tools in that same agent** — and built-ins
generally don't ride in sub-agents. So "just add `google_search` to the triage agent" is
not a plan. The blessed patterns:

1. **Specialist agents** — a dedicated `searcher` and a dedicated `coder`, each owning its
   built-in and nothing else, composed from outside via `AgentTool.create()` (an agent
   wrapped *as a tool* — Day 55 makes this a first-class pattern).
2. **`bypass_multi_tools_limit=True`** — Python-only, for `GoogleSearchTool`/
   `VertexAiSearchTool` specifically, when you truly must mix.

Sutra chooses pattern 1: it matches the Phase-8 graph anyway (Researcher = the search
specialist). The constraint is, again, an architecture hint wearing a warning label.

### AG-07 — Grounding vs retrieval: the newspaper and the filing cabinet

Two questions sound alike and are not:

- *"Is AcmeCloud down **right now**?"* — about the **live, public** world. No copy of
  anything you own can answer it. That's **grounding**: reach out to the web at answer
  time, cite what you found.
- *"Have we seen a ticket like #4521 **before**?"* — about **your own, private** history.
  Google cannot answer it; your archive can. That's **retrieval**: search *your* corpus,
  usually by meaning (embeddings — Day 49's whole story).

| | Grounding | Retrieval |
| --- | --- | --- |
| Source | live public web | your private corpus |
| Freshness | this minute | as fresh as your index |
| Privacy | query leaves the building | can stay fully local |
| Cost meter | search requests (5,000/mo free today) | your own compute (≈ $0 local) |
| Wrong tool when… | asked about private tickets | asked about this morning's outage |

💡 **Mental model: grounding reads the newspaper; retrieval reads your filing cabinet.**
An agent that reads the newspaper to learn your own company's history is leaking questions
and burning quota; one that reads the filing cabinet for breaking news is confidently
stale. The Researcher will need *both*, and the skill is knowing which question it's
holding. Also non-negotiable: grounded answers **show their receipts** — the
`groundingMetadata` sources aren't decoration; surfacing them is both the API's display
requirement and Principle 10 in UI form.

### AG-32 + SEC-01 — The sandbox: blast radius made physical

🎬 A thirty-second thought experiment. The model writes `df = pd.read_csv(...)` — fine.
Prompt-injected (Day 66's monster, previewed), it writes
`import os; os.system("type .env")` — and if that runs **where your keys live**, you're
done. The model cannot be trusted to only write nice code, because *its inputs* can't be
trusted. So the rule is never "generate safe code"; it is **"run all generated code where
code can do no harm."**

That place is a **sandbox**: a disposable, isolated box — no credentials, minimal
network, destroyed after use. Where is ours? Read the wiring again:
`BuiltInCodeExecutor` runs the code **on Google's side**, in their sandbox. Today's
containment story is: *the code never touches your laptop at all.* Your `.env`, your
repo, your disk — out of reach by construction, not by politeness.

**SEC-01 — write the policy down** (§4 Step 5 makes you say it aloud):

> Sutra never executes model-generated code in the app process. Today: only via
> `BuiltInCodeExecutor` (provider-side sandbox). If code must ever run near our data:
> a dedicated sandbox provider (ADK ships `e2b` and `daytona` extras 🅿️ — Day 39 meets
> them, Day 71 drills them), least-privilege, no secrets mounted, disposable.

🅿️ **Parked:** the sandbox *provider* practice (e2b/daytona microVMs, kill switches,
egress rules) is deliberately Day 71's — it belongs with computer use, the biggest
blast radius in the whole plan. Today you learn the law; there you enforce it yourself.

**Step 1 — `sutra/builtin_tools.py` (zero quota).**

```python
"""Day 16 — built-in tools with brakes: the searcher and the coder.

Two SPECIALIST agents (the exclusivity wall makes mixing built-ins with
custom tools a trap - see doc section 5). Search = a tool the model may
choose; code execution = an executor the agent owns. All generated code
runs provider-side, never on this machine (SEC-01).

Importable with no side effects. Run demos from the repo root:

    python -m sutra.builtin_tools ground    # ask the live web (~2 calls + 1-2 search reqs)
    python -m sutra.builtin_tools compute   # model writes & runs real Python (~2 calls)
"""
from __future__ import annotations

import sys

from google.adk.agents import Agent
from google.adk.code_executors import BuiltInCodeExecutor   # verified import (2026-08-18)
from google.adk.runners import InMemoryRunner
from google.adk.tools import google_search                  # verified import (2026-08-18)
from google.genai import types

from sutra.config import load_env

# --- The searcher: one built-in tool, NOTHING else (exclusivity wall) -------
searcher_agent = Agent(
    name="sutra_searcher",
    model="gemini-3.5-flash",                       # pinned - ADK-73, always
    instruction="""You answer questions about the CURRENT, PUBLIC state of
the web (outages, vendor status, news). Always ground your answer with
search; report what the sources say and never present a guess as found.""",
    tools=[google_search],                          # the whole toolkit. On purpose.
)

# --- The coder: an EXECUTOR, not a tool -------------------------------------
coder_agent = Agent(
    name="sutra_coder",
    model="gemini-3.5-flash",
    instruction="""You solve numeric questions by WRITING AND RUNNING Python
code, never by mental arithmetic. Show the result plainly. If the code
errors, show the error honestly and try once more.""",
    code_executor=BuiltInCodeExecutor(),            # code parts now RUN (provider-side)
)

# Synthetic response-time sample for the compute demo (minutes). Synthetic
# always - real data never rides a free endpoint (Addendum 02 section 7).
RESPONSE_TIMES = [4, 7, 3, 9, 12, 5, 6, 41, 8, 5, 7, 90, 6, 4, 11, 5, 38, 7, 6, 9]


def _run(agent: Agent, question: str) -> None:
    """Harness with extra eyes: prints code, code results, and sources."""
    runner = InMemoryRunner(agent=agent)
    session = runner.session_service.create_session_sync(
        app_name=runner.app_name, user_id="day16"
    )
    for event in runner.run(user_id="day16", session_id=session.id,
                            new_message=types.Content(
                                role="user",
                                parts=[types.Part(text=question)])):
        for part in (event.content.parts if event.content else []):
            if getattr(part, "executable_code", None):          # the model's code...
                print("--- code the model wrote ---")
                print(part.executable_code.code)
            if getattr(part, "code_execution_result", None):    # ...and the sandbox's reply
                print("--- sandbox output ---")
                print(part.code_execution_result.output)
        # Grounded answers must show receipts (display requirement + Principle 10):
        meta = getattr(event, "grounding_metadata", None)       # TODO(confirm exact
        if meta and getattr(meta, "grounding_chunks", None):    # attr name in 2.6 API ref)
            print("--- sources ---")
            for chunk in meta.grounding_chunks:
                web = getattr(chunk, "web", None)
                if web:
                    print(f"  {web.title} - {web.uri}")
        if event.is_final_response() and event.content:
            print("\nANSWER:",
                  "".join(p.text or "" for p in event.content.parts).strip())


def demo_ground() -> None:
    """Usage: python -m sutra.builtin_tools ground   (~2 calls + search spend)."""
    _run(searcher_agent,
         "Is GitHub currently reporting any incident or outage on its "
         "official status page? Answer from live sources.")


def demo_compute() -> None:
    """Usage: python -m sutra.builtin_tools compute  (~2 calls, 0 search spend)."""
    _run(coder_agent,
         "Here are response times in minutes: "
         f"{RESPONSE_TIMES}. Compute the mean, median and 95th percentile. "
         "Which tickets (by value) look like outliers?")


def main() -> None:
    demos = {"ground": demo_ground, "compute": demo_compute}
    name = sys.argv[1] if len(sys.argv) > 1 else "compute"
    if name not in demos:
        print(f"usage: python -m sutra.builtin_tools [{'|'.join(demos)}]")
        raise SystemExit(2)
    load_env()
    demos[name]()


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the tool that refuses company

> 🎬 **The scene:** the obvious "improvement": one super-agent with everything —
> `tools=[google_search, lookup_ticket, search_kb]`. Ticket in, web checked, KB cited,
> one agent, beautiful.
> 😬 **The naive fix:** it's just a list — append to it, ship it.
> 💥 **Why it fails:** run it. Depending on version you get an explicit error at
> construction/first-call — or, worse, quiet degradation where custom tools stop being
> offered to the model. The limitations page says it plainly: these built-ins *exclude
> other tools in the same agent* (and won't ride in sub-agents). The capability isn't a
> normal tool your process runs — it's fused into the model+platform call itself, and the
> platform's contract for that call is exclusive. The failure isn't a bug you patch;
> it's a boundary you design around.
> 💡 **The insight:** **built-ins are specialists' powers — give each its own agent and
> compose agents.** A dedicated searcher wrapped via `AgentTool.create()` into the triage
> flow is the blessed pattern (and secretly better design: the Researcher was always
> going to be its own node — Phase 8 says hi). `bypass_multi_tools_limit=True` exists for
> the search tools when you must mix — a flag to know, quote, and rarely use.

Run it: build the mixed agent in a scratch few lines, watch it fail (or degrade), delete
it. ~1 model call, priceless scar.

## 6 · 🎤 Interview corner

1. **"When do you give an agent web search vs a RAG pipeline?"** — By where the truth
   lives. Live public facts (outages, versions, news) → grounding: search at answer time,
   citations mandatory — it's metered, and the query leaves the building. Private
   history (our tickets) → retrieval over our own corpus: fresh as our index, can stay
   fully local, free at the margin. The bug I watch for is *misrouting*: newspaper
   questions sent to the filing cabinet come back stale; filing-cabinet questions sent to
   the newspaper leak data and quota. My Researcher holds both and routes by question.
2. **"An agent writes its own code — how do you run that safely?"** — Never in my
   process; that's policy, not preference. Model inputs can be adversarial (prompt
   injection), so generated code is untrusted by definition. My current setup executes it
   provider-side (`BuiltInCodeExecutor` — the sandbox isn't even on my machine); for
   code that must touch my data, disposable microVM sandboxes (e2b/daytona are
   first-class ADK extras) with no secrets, minimal egress, and short lives. Blast
   radius before capability — the power and its containment ship together.
3. **"Any surprises wiring 'official' built-in tools?"** — Two worth scars. Exclusivity:
   on the Gemini API these built-ins can't share an agent with other tools — I restructured
   to specialist agents composed via agent-as-tool, which improved the architecture
   anyway. And metering: grounding introduced a *second* currency (search requests/month)
   beside token quota — my accounting layer tracks both, because a free allowance you
   don't meter is a paid allowance with extra steps.
