## 3 · 📚 Concepts

### ADK-01 — What ADK is (and is not)

**The workshop story.** For four days you built a car by hand: engine (the loop), fuel
lines (the transcript), brakes (`MAX_STEPS`), steering (the dispatch table). It drives!
But every new feature — persistence, streaming, multiple drivers — means more hand-built
plumbing, and you would spend the next 90 days building infrastructure instead of
building *Sutra*.

ADK is the **factory chassis**: Google's open-source framework that ships the loop, the
transcript management, the tool dispatch, the streaming, the sessions — pre-built,
tested, and standardized — so your effort goes into what is *unique* about your system
(the triage graph, the guardrails, the evals). The map, piece by piece:

| You hand-built (Days 3–4) | ADK ships | ADK's name for it |
| --- | --- | --- |
| `run_loop()` — the think→act→observe cycle | the runtime that drives agents | the **Runner** (Day 8) |
| `transcript = [...]` rebuilt every call | managed conversation history | a **Session** (Day 8) |
| `TOOLS` dict + `**fc.args` dispatch | tool declaration *and* execution | **FunctionTool** (Day 10) |
| printed `CALL:`/`RESULT:` lines | structured, inspectable turn records | **Events** (Day 7) |
| `MAX_STEPS` | a configurable call budget | `RunConfig.max_llm_calls` (Day 7) |
| the `SYSTEM` string | first-class persona field | `instruction` (Day 6) |

💡 **Mental model: ADK is your Day 3 loop, industrialized.** Nothing conceptually new
enters the building today — the parts just get names, tests, and a warranty.

And what ADK is **not**: it is not a model (Gemini is the model; ADK drives it), it is
not a hosted service (it runs wherever your Python runs — your laptop today), and it is
not magic (every behavior traces back to a mechanism you have already built by hand).

One more fact worth saying in an interview: ADK 2.0's headline change is that agents are
now **nodes in a workflow graph** — composition happens in a graph runtime, not only in
agent trees (trap #1). We meet the graph properly in Phase 8; today's single agent is
simply a graph of one node, and we lose nothing by not looking down yet.

### ADK-02 — The `Agent` class and the discovery convention

**The job-description story.** On Day 4 you employed the model through a stack of loose
paperwork: a `SYSTEM` string here, a `TOOL` bundle there, a loop holding it together. An
ADK `Agent` is all of that paperwork stapled into a single **job description**:

| Field | Plain words | Day 3–4 ancestor |
| --- | --- | --- |
| `name` | who this employee is (unique id; other agents route by it later) | — (we only had one) |
| `model` | which brain to rent, **by exact name** | the `model=` string in `ask()` |
| `description` | one line for *other agents* deciding whether to delegate here | — (multi-agent, Phase 8) |
| `instruction` | the persona + standing orders | the `SYSTEM` string |
| `tools` | the menu | the `TOOL` bundle + `TOOLS` dict |

Verified constructor (adk.dev quickstart, checked 2026-08-18):

```python
from google.adk.agents.llm_agent import Agent

root_agent = Agent(
    model="...",           # the brain, pinned (§3d)
    name="...",            # unique identifier
    description="...",     # for OTHER agents, later
    instruction="...",     # the persona
    tools=[...],           # the menu (empty today — see below)
)
```

**Why `tools=[]` today, when Day 4 just built two tools?** Because passing a plain Python
function into `tools=[...]` triggers ADK's automatic schema generation and dispatch — the
grown-up version of the "automatic function calling" convenience we *deliberately
refused* on Day 4. That refusal had a reason: build by hand first. We have now built it
by hand. So on **Day 10** the tools return through the front door as `FunctionTool`s, and
you will recognize every part. Today's agent talks; it does not act. One new thing at a
time.

**The discovery convention** — how `adk run` finds your agent. ADK's CLI does not take a
file path; it takes a **folder**, and expects (verified on the quickstart page):

```
<agent_folder>/
    __init__.py      # makes it a package; exposes the agent module
    agent.py         # defines a module-level variable named exactly `root_agent`
    .env             # keys (ADK loads this automatically)
```

The magic words are the variable name **`root_agent`** — that exact name, at module
level, in `agent.py`. Our product package `sutra/` already *is* a package with an
`agent.py`-shaped hole in it, so Sutra's layout and ADK's convention snap together: the
agent folder is simply `sutra`, and the command is `adk run sutra` from the repo root.
(Our `.env` lives at the repo root rather than inside `sutra/` — Day 1's
`load_env()`/python-dotenv discipline already finds it there; if `adk run` ever fails
with a missing-key error, the fix is written in §5's footnote, not a reshuffle of your
secrets.)

### ADK-73 — Pin the model, always

**The "chef's choice" story.** A restaurant menu has a line: *"Fish of the day —
market price."* Convenient — until the day the fish changes and your favorite dish tastes
different, costs more, and nobody warned you. `model=` left empty, or set to a floating
alias, is fish of the day.

The concrete history (Addendum 01, dated 2026-08-12): **since ADK 2.2 the framework's
default model is a preview model** (`gemini-3-flash-preview` at the time the addendum was
written). Previews rotate, get renamed, and carry tighter free-tier quotas. An agent
built without an explicit `model=` therefore *changed brains silently* when 2.2 landed —
same code, different model, different answers, different quota. Your eval scores (Phase
12) would drift overnight and you would hunt a bug in your code that lives in a default.

The subtler trap is the one the official docs themselves use in examples (checked
2026-08-18): the **floating alias** `"gemini-flash-latest"`. It always works, and it
never tells you what it did. Today it may resolve to one model; after Google's next
release, another. That is not a pin — that is fish of the day with extra steps. §5 makes
this observable.

Sutra's rule, forever (and it is a *plan* rule, not a style preference):

1. **Every agent names its model explicitly** — a real, versioned model string.
2. The pin lives in **one named constant** (`PRIMARY_MODEL` in `sutra/agent.py`), so
   "what brain does Sutra use?" has exactly one answer in the codebase.
3. The pinned string was **looked up, not remembered**: ours is `gemini-3.5-flash`,
   repinned 2026-08-13 after `gemini-2.5-flash` returned 404 for new accounts (the full
   war story is in `CHANGELOG_PLAN.md` — and note it *still appeared in docs and
   `models.list()` while being dead*; only a live call told the truth).

💡 **Mental model: an unpinned model is a dependency without a version number.** You
would never write `google-adk==whatever`; don't write its equivalent for the brain.

**Step 3 — `sutra/agent.py`: the job description.**

Create `sutra/agent.py` with the full listing below. It is short on purpose — the point
of today is how *little* is left once the framework absorbs your plumbing.

```python
"""Day 5 — Sutra's first ADK agent.

Four days of hand-built machinery (loop, transcript, dispatch, brake)
collapse into one Agent definition. The parts did not disappear — ADK
now runs them for us: the Runner is Day 3's loop, a Session is the
transcript, Events are the printed CALL/RESULT lines (Days 7-8 open
each box).

No tools yet — they return through the front door as FunctionTools on
Day 10, now that we have built tool calling by hand (Principle 4).

Importable with no side effects (constructing an Agent makes no network
call). Run it from the repo root with:

    adk run sutra        # terminal chat; Ctrl+C to exit
"""
from __future__ import annotations

from google.adk.agents.llm_agent import Agent   # verified: adk.dev quickstart 2026-08-18

# THE model pin (ADK-73). One constant, one answer to "which brain?".
# gemini-3.5-flash: repinned 2026-08-13 after gemini-2.5-flash closed to
# new accounts (see CHANGELOG_PLAN.md). Never a floating alias like
# "gemini-flash-latest" — an alias is fish of the day, not a pin.
PRIMARY_MODEL = "gemini-3.5-flash"

# The persona. Day 4 shrank our SYSTEM prompt to persona + honesty; it
# moves here unchanged in spirit. Day 6 is a whole day on writing these.
INSTRUCTION = """You are Sutra, a support-ticket triage assistant.
You cannot see any ticket data yet - your tools arrive in a few days.
If asked about a specific ticket, say plainly that you cannot look it
up yet. Never invent ticket contents or knowledge-base articles."""

# The magic name: `adk run` / `adk web` look for exactly `root_agent`
# at module level in agent.py. Rename it and discovery breaks (see 5).
root_agent = Agent(
    model=PRIMARY_MODEL,          # pinned EXPLICITLY - the whole point of ADK-73
    name="sutra_triage",          # unique id; other agents will route to it by name
    description="Triage assistant for the Sutra support desk.",  # read by OTHER agents (Phase 8)
    instruction=INSTRUCTION,      # the standing orders (Day 6 deepens this)
    tools=[],                     # empty ON PURPOSE - FunctionTools land Day 10
)
```

"""One-off pin proof - reads the model name out of the response metadata."""
import asyncio
from google.adk.runners import InMemoryRunner   # Day 8 opens this box properly
from google.genai import types
from sutra.agent import root_agent

async def main() -> None:
    runner = InMemoryRunner(agent=root_agent)            # loop-in-a-box, defaults inside
    session = await runner.session_service.create_session(
        app_name=runner.app_name, user_id="pin_proof")   # one throwaway session

        user_id="pin_proof",
        session_id=session.id,
        new_message=types.Content(role="user", parts=[types.Part(text="Say OK.")]),

            print("answer:", event.content.parts[0].text)
            # LlmResponse carries usage/model metadata; field name may vary by
            # version - print the raw event if the line below errors, and read it.
            print("served by:", getattr(event, "model_version", None) or "(inspect event)")

asyncio.run(main())

## 6 · 🎤 Interview corner

1. **"You've hand-rolled an agent loop and used a framework. When is a framework the
   right call?"** — When its abstractions map onto mechanisms you already understand.
   I built the loop, transcript management, tool dispatch, and a step budget by hand
   first; when I adopted ADK, every framework concept had a hand-built ancestor —
   Runner↔my loop, Session↔my transcript, FunctionTool↔my dispatch table. That order
   matters: the framework saves me code, but it can't hide a mechanism from me, so when
   it misbehaves I debug the mechanism, not the mystery. If I couldn't have written a
   rough version of it, I'm not adopting it — I'm gambling on it.
2. **"Why is leaving the model unpinned a real bug and not a style nit?"** — Because the
   default is a moving target with real blast radius. ADK 2.2 changed the framework
   default to a preview model: any unpinned agent silently swapped brains — answers,
   latency, and free-tier quota all shifted with zero diff in the repo. Same trap with
   floating aliases like `gemini-flash-latest`. I pin a concrete model in one constant,
   record the lookup date in a ledger, and re-check it at every phase gate — the same
   discipline as version-pinning a dependency, because that's exactly what it is.
3. **"What breaking changes bit people migrating to ADK 2.x?"** — Four documented traps:
   composition moved from agent-trees to a graph workflow runtime; event fields were
   renamed/extended (2.0 added `node_info` and `output` to the Event schema, which breaks
   strict downstream validators); custom agents must *yield* events instead of appending
   them to the session, because the runner owns persistence; and tools must let
   exceptions propagate — a broad `except Exception` now silently disables the
   framework's retry and human-in-the-loop machinery. My rule on top: never copy 1.x
   tutorial code; verify every symbol against current docs the day I use it.
