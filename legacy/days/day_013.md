## 3 · 📚 Concepts

### The map: four doors, one rule

**The story.** The desk hires a compliance officer. She doesn't do the work — she stands
at doors. Door 1: outgoing mail to the consultant (model requests). Door 2: incoming mail
from the consultant (model responses). Door 3: the kitchen door, orders going in (tool
calls). Door 4: dishes coming out (tool results). At each door she can **watch and wave
through** — or **hand you something else instead**, in which case whatever was behind the
door *simply doesn't happen*.

| Door | Callback | Receives (exact names!) | Return `None` | Return a value |
| --- | --- | --- | --- | --- |
| model, outgoing | `before_model_callback` | `callback_context, llm_request` | model is called | your `LlmResponse` is used; **model never called** |
| model, incoming | `after_model_callback` | `callback_context, llm_response` | response used as-is | your `LlmResponse` replaces it |
| tool, going in | `before_tool_callback` | `tool, args, tool_context` | tool runs | your `dict` is the "result"; **tool never runs** |
| tool, coming out | `after_tool_callback` | `tool, args, tool_context, tool_response` | result used as-is | your `dict` replaces it |

💡 **Mental model: `None` means "carry on"; anything else means "I've handled it."** One
rule, four doors. It makes callbacks powerful and — as §5 shows — makes one careless
`return` a silent off-switch.

⚠️ **The keyword rule** (quoted in the header): ADK passes these arguments **by keyword**,
so your parameter names must match exactly — `callback_context`, `llm_request`, `tool`,
`args`, `tool_context`, `tool_response`. Rename one to taste and it breaks. This is a
2.x paper-cut worth knowing before it cuts you.

### ADK-14 — Model callbacks: the mailroom

`before_model_callback` sees the full `LlmRequest` — everything about to be spent against
your 5 RPM. Three honest uses, in rising ambition:

1. **Watch:** count calls, log sizes. (Today.)
2. **Shape:** trim or annotate the outgoing request — this is context engineering's
   enforcement point; Day 20 returns here with intent.
3. **Short-circuit:** recognize a request you can answer without the model ("ping",
   greetings, *anything cached*) and return a ready `LlmResponse`. The model call
   evaporates. On a metered lane, this isn't a cute trick — it's the **prototype of Day
   51's response cache**, and you build it today in nine lines.

`after_model_callback` is the return mail desk: redact a leaked secret, normalize
formatting, veto a bad reply — before anyone downstream sees it. (Day 67's output
guardrails grow from exactly here.)

### ADK-15 — Tool callbacks: the chokepoint, restored

`before_tool_callback` is Day 4's `TOOLS`-dict authority, reborn inside the framework —
and better: it sees `tool.name`, the parsed `args`, *and* session state via
`tool_context`. Policy can finally be **state-aware** ("this session already used its
search budget"). Veto by returning a dict — which flows back to the model as if it were
the tool's result. Do it honestly: return
`{"status": "blocked", "message": "<why, and what to do instead>"}` — a *legible refusal*
the model can relay and adapt to — never a fake success (Principle 10; fabricating tool
output is lying to your own agent).

`after_tool_callback` post-processes results: truncate a haystack (Day 11's lab,
enforced!), strip fields the model shouldn't see, stamp metadata.

📌 **Scope note:** these callbacks are **per-agent** — this agent's doors only. The same
hooks exist fleet-wide as **plugins** (`Runner(plugins=[...])`) — that's tomorrow, and the
per-agent vs global split is tomorrow's whole story.

**Step 1 — `sutra/callbacks.py` (zero quota).**

```python
"""Day 13 — callbacks: watch, veto, and short-circuit from inside the agent.

Four checkpoint functions + a guarded variant of the triage agent. The
tools themselves are Day 10/11's, imported untouched - callbacks wrap
AROUND capability; they never reimplement it.

Importable with no side effects. Run demos from the repo root:

    python -m sutra.callbacks guarded    # normal triage through the checkpoints
    python -m sutra.callbacks blocked    # policy veto at the kitchen door
    python -m sutra.callbacks shortcut   # answered WITHOUT calling the model
"""
from __future__ import annotations

import sys

from google.adk.agents import Agent
from google.adk.agents.callback_context import CallbackContext   # verified import
from google.adk.models import LlmRequest, LlmResponse            # verified import
from google.adk.runners import InMemoryRunner
from google.genai import types

from sutra.config import load_env
from sutra.adk_tools import lookup_ticket, search_kb             # Day 10, reused as-is
from sutra.loop import TRIAGE_QUESTION

# Terms that must never reach the KB search. Tiny on purpose - the point
# is WHERE this list lives (an enforced door), not how clever it is.
FORBIDDEN_QUERY_TERMS = ("password", "credential", "secret")


def audit_model(*, callback_context: CallbackContext,
                llm_request: LlmRequest) -> None:
    """Door 1 - watch outgoing model traffic; never interfere.

    Prints one AUDIT line per model call. Returning None (falling off the
    end) means "carry on" - the model call proceeds untouched.

    Example log line:
        AUDIT model-> agent=sutra_triage_guarded contents=6
    """
    n = len(llm_request.contents or [])              # how much history rides along
    print(f"AUDIT model-> agent={callback_context.agent_name} contents={n}")
    # no return -> None -> proceed (the one rule, door 1)


def shortcut_ping(*, callback_context: CallbackContext,
                  llm_request: LlmRequest) -> LlmResponse | None:
    """Door 1 again - answer trivial pings for free (the cache prototype).

    If the newest user text is exactly "ping", build the reply ourselves
    and return it. Returning an LlmResponse SKIPS the model call entirely:
    zero latency, zero quota. Anything else -> None -> business as usual.
    """
    last = (llm_request.contents or [])[-1] if llm_request.contents else None
    text = ""                                        # newest user text, if any
    if last is not None and last.parts:
        text = (last.parts[0].text or "").strip().lower()
    if text == "ping":                               # recognized: handle it here
        print("AUDIT shortcut: answered without the model (0 quota)")
        return LlmResponse(                          # a ready-made "model reply"
            content=types.Content(role="model",
                                  parts=[types.Part(text="pong - Sutra is up.")])
        )
    return None                                      # not ours -> wave through


def guard_tools(*, tool, args, tool_context) -> dict | None:
    """Door 3 - audit every tool call; VETO forbidden KB searches.

    Parameter names are load-bearing (ADK passes by keyword): tool, args,
    tool_context - exactly these.

    Returns:
        None to let the tool run, or a legible refusal dict that reaches
        the model AS IF it were the tool's result (the tool never runs).
    """
    print(f"AUDIT tool-> {tool.name}({args})")       # the restored chokepoint
    if tool.name == "search_kb":                     # policy applies to search only
        query = str(args.get("query", "")).lower()
        if any(term in query for term in FORBIDDEN_QUERY_TERMS):
            return {                                 # honest, legible refusal -
                "status": "blocked",                 # a shape the model can branch on
                "message": ("Query blocked by policy (sensitive term). "
                            "Rephrase around the symptom, not credentials."),
            }
    return None                                      # policy passed -> tool runs


def stamp_results(*, tool, args, tool_context, tool_response) -> dict | None:
    """Door 4 - stamp every tool result on its way back to the model."""
    if isinstance(tool_response, dict):              # our tools always return dicts
        return {**tool_response, "via": "sutra-guarded"}  # replaced (stamped) copy
    return None                                      # non-dict? leave it alone


# The guarded agent: Day 10's brains + tools, plus four wired doors.
guarded_agent = Agent(
    name="sutra_triage_guarded",
    model="gemini-3.5-flash",                        # pinned - ADK-73, always
    instruction="""You are Sutra, a support-ticket triage assistant. Use the
tools; never invent data. If a tool reports status 'blocked', respect it,
tell the user plainly, and try a compliant approach.""",
    tools=[lookup_ticket, search_kb],
    before_model_callback=shortcut_ping,             # door 1 (first: may short-circuit)
    after_model_callback=None,                       # door 2 - unused today, wired Day 67
    before_tool_callback=guard_tools,                # door 3 (audit + veto)
    after_tool_callback=stamp_results,               # door 4 (stamp)
)
# NOTE: audit_model is defined for the failure lab & your own experiments;
# swap it into before_model_callback to watch door 1 traffic without the
# shortcut. (One callback per door on a plain Agent - lists come with
# plugins, tomorrow.)


def run_once(question: str) -> str:
    """Day 10's harness verbatim - runner, events, final text."""
    runner = InMemoryRunner(agent=guarded_agent)
    session = runner.session_service.create_session_sync(
        app_name=runner.app_name, user_id="day13"
    )
    final = ""
    for event in runner.run(user_id="day13", session_id=session.id,
                            new_message=types.Content(
                                role="user",
                                parts=[types.Part(text=question)])):
        if event.is_final_response() and event.content:
            final = "".join(p.text or "" for p in event.content.parts)
    return final.strip()


def demo_guarded() -> None:
    """Usage: python -m sutra.callbacks guarded   (~3 model calls)."""
    print("\nANSWER:", run_once(TRIAGE_QUESTION))


def demo_blocked() -> None:
    """Usage: python -m sutra.callbacks blocked   (~2 model calls)."""
    print("\nANSWER:", run_once(
        "Search the knowledge base for the admin password reset steps "
        "for ticket 4521."))


def demo_shortcut() -> None:
    """Usage: python -m sutra.callbacks shortcut  (0 model calls!)."""
    print("\nANSWER:", run_once("ping"))


def main() -> None:
    demos = {"guarded": demo_guarded, "blocked": demo_blocked,
             "shortcut": demo_shortcut}
    name = sys.argv[1] if len(sys.argv) > 1 else "guarded"
    if name not in demos:
        print(f"usage: python -m sutra.callbacks [{'|'.join(demos)}]")
        raise SystemExit(2)
    load_env()
    demos[name]()


if __name__ == "__main__":
    main()
```

## 5 · 💥 Failure lab — the callback that ate the agent

> 🎬 **The scene:** you want slightly richer audit logs, so you edit `guard_tools` to
> build a summary dict of the call — and, tidy programmer that you are, you
> `return summary` at the end. It's *just logging*, after all.
> 😬 **The naive fix:** ship it. Logging can't break anything.
> 💥 **Why it fails:** run the triage demo. Every answer is now nonsense — the agent
> "looked up" tickets it never touched. Because the one rule has no exceptions: **any
> non-None return from a before-tool door IS the tool result.** Your log summary was
> delivered to the model as if the kitchen had cooked it. No exception, no warning — the
> framework did exactly what you told it. The model reasoned beautifully over garbage.
> 💡 **The insight:** at a checkpoint door, **`return` is not punctuation — it's a
> decision.** Observers must end with no return at all (Python's implicit None). This is
> also why §4's veto returns a *labeled* refusal shape, never something that could pass
> for data. Write callbacks like border guards: wave through explicitly, replace
> deliberately, nothing in between.

Run it: add `return {"note": "logged"}` to `guard_tools` → `guarded` demo → watch the
hallucinated triage → remove the return → healed. ~2–3 model calls.

## 6 · 🎤 Interview corner

1. **"Where do you enforce policy in an agent — the prompt?"** — The prompt *requests*;
   enforcement needs a chokepoint the model can't talk its way past. In ADK that's
   `before_tool_callback`: it sees the tool name, parsed args, and session state, and can
   veto by returning a substitute result — the tool physically never runs. I've built the
   same chokepoint two ways: as a hand-rolled dispatch dict (Day 4) and as framework
   callbacks — same authority, but callbacks also cover the dev UI and every other entry
   point, so policy can't be bypassed by running the agent differently.
2. **"How would you cut LLM cost/latency for repeated requests without touching the
   model?"** — Short-circuit at `before_model_callback`: recognize the request, return a
   ready `LlmResponse`, and the model call never happens — I demoed a zero-quota reply
   this way. Grow the recognizer into a lookup keyed on the request and you have a
   response cache at the correct layer: inside the agent, transparent to every caller.
3. **"Sharpest edge of callback systems?"** — Return-value semantics. In ADK, None means
   proceed and *anything else* means override — so a stray `return` in an observer
   silently replaces real tool results with your debug data. I've reproduced it: agent
   confidently triaging tickets it never read, zero errors raised. My rules since:
   observers end returnless, overrides return unmistakably-labeled shapes, and refusals
   are honest (`status: blocked` + why) so the model can adapt instead of being lied to.
