# 3.3 — Giving up honestly

## One-line answer

Escalating means **somebody** is told, not that the **customer** is told everything: the raw 429 body
that reaches a user unfiltered leaks the model name, the internal quota metric, the numeric limit and
the word *billing* — four details, in 433 characters, where 68 would have been true.

## The story

The dentist's receptionist tells you the appointment is cancelled.

She does not tell you that the dentist is in hospital, or which hospital, or what happened. You get
the fact that concerns you — no appointment today, here is Thursday — and the rest stays behind the
desk, where it belongs, in a file that the practice manager can read.

The alternative is not more honest. It is a receptionist repeating the phone call she just took, to a
stranger, in a waiting room.

## The idea in plain language

[1.3](../01-who-hears-it/1.3-retry-substitute-escalate.md) named *escalate* as the third and final
response: stop, let it out, put it in front of a human. [2.3](../02-four-hooks/2.3-the-two-that-can-only-witness.md)
showed the two hooks that fire on the way out. This part is about the sentence at the end of that
path, and the mistake it is easy to make there.

Escalating feels like the honest option, and it is — but "honest" gets confused with "verbatim". An
exception object is written for a developer. It contains hostnames, model identifiers, quota metric
names, internal limits, URLs to a provider's billing documentation, and sometimes the arguments the
failing call was made with, which is where customer data lives. Handing that to whoever typed the
question is not honesty. It is a category error about who the audience is.

The correct shape has two outputs from one failure, and it is the `user_visible` field from
[1.2](../01-who-hears-it/1.2-an-error-is-a-fact.md) finally being used:

| Audience | What they get | Why |
| --- | --- | --- |
| the log | the whole exception, unmodified | an operator has to be able to search for the exact string |
| the caller | one sentence per status, from a fixed set | they need to know it failed and that nothing was answered |

Two properties make the caller's sentence right rather than merely short.

**It says nothing was answered.** *"Nothing was answered"* is the clause that stops a user from
treating a failure message as a partial result. Without it, *"Sutra has reached its request limit"*
sits ambiguously next to whatever else is on screen.

**It comes from a fixed set, keyed by status.** Not generated, not formatted from the exception —
looked up. A lookup table cannot leak, because nothing from the exception passes through it. That is
the mechanism below, and it is why the leak count is `none` rather than *"probably fine"*.

## Why Sutra needs it

Because Sutra's repository goes public in Phase 14, and its errors go to a customer before that.

The 429 body in the measurement below names `gemini-3.7-flash` and
`generativelanguage.googleapis.com` and `limit: 20`. That is Sutra's model choice, its provider and
its tier, disclosed to whoever happened to be the twenty-first request of the day. None of it is a
catastrophe on its own; all of it is information nobody decided to publish.

The version that is a catastrophe is one step away. A tool that fails while looking up a customer
record raises an exception whose message contains the query, and the query contains the customer's
email address. `SEC-02` is *honest error surfacing*, and the security half of that phrase is this
part: an error path is a data-egress path, and it is the one nobody reviews.

Day 66 onwards is the safety phase, and every input-sanitisation lesson there has an output-side twin
that starts here.

## The mechanism

The real 429 body, classified, and sent to two audiences — with the redaction switched off to count
what would have escaped.

```python
# days/day-21-errors-surface-not-swallow/lab/give_up_honestly.py
"""Escalating means somebody is told. It does not mean the customer is told everything."""

import os

REDACT = os.environ.get("REDACT", "1") == "1"

# The real body, captured from a live refusal on 2026-09-03.
RAW = (
    "429 RESOURCE_EXHAUSTED. {'error': {'code': 429, 'message': 'You exceeded your current "
    "quota, please check your plan and billing details. For more information on this error, "
    "head to: https://ai.google.dev/gemini-api/docs/rate-limits. * Quota exceeded for metric: "
    "generativelanguage.googleapis.com/generate_content_free_tier_requests, limit: 20, model: "
    "gemini-3.7-flash Please retry in 57.991539991s.', 'status': 'RESOURCE_EXHAUSTED'}}"
)

# What a caller may see, per status. Nothing here names a host, a model or a quota.
PUBLIC = {
    "quota_exhausted": "Sutra has reached its request limit for today. Nothing was answered.",
    "unavailable": "A system Sutra depends on is unreachable. Nothing was answered.",
    "internal": "Sutra hit an internal error. It has been logged and nothing was answered.",
}

LEAKS = ("gemini-3.7-flash", "generativelanguage.googleapis.com", "limit: 20", "billing")


def classify(raw: str) -> str:
    """Which public message this failure maps to."""
    if "429" in raw and "free_tier_requests" in raw:
        return "quota_exhausted"
    if "TimeoutError" in raw or "ConnectionError" in raw:
        return "unavailable"
    return "internal"


def to_user(raw: str) -> str:
    """The sentence the caller gets."""
    if not REDACT:
        return raw
    return PUBLIC[classify(raw)]


def to_log(raw: str) -> str:
    """The record an operator gets. Always the whole thing."""
    return raw


user_sees = to_user(RAW)
leaked = [needle for needle in LEAKS if needle in user_sees]

print(f"REDACT={'1' if REDACT else '0'}")
print(f"  classified as: {classify(RAW)}")
print(f"  the log gets:   {len(to_log(RAW))} chars (the whole body)")
print(f"  the user gets:  {len(user_sees)} chars")
print(f"  internal details leaked to the user: {leaked or 'none'}")
print(f"\n  {user_sees}")
```

**Line by line:**

- `RAW` is not invented. It is the body of a live refusal captured on 2026-09-03, which is why it
  contains a documentation URL and the phrase *"check your plan and billing details"* — a provider
  writing for a developer, quite reasonably, with no idea who will end up reading it.
- `PUBLIC` is a **lookup table, not a formatter.** Nothing from `RAW` is interpolated into these
  strings. That is the security property: a template with a `{}` in it can leak whatever fills the
  `{}`, and this cannot.
- Each `PUBLIC` value ends in *"Nothing was answered."* — the clause that prevents a failure message
  being read as a partial result.
- `to_log(raw)` returns the body **unmodified**, and it exists as a named function purely to make the
  asymmetry explicit in the code. Redaction is a property of the *caller-facing* path only; an
  operator who cannot search for the exact provider string cannot do their job.
- `LEAKS` is the audit, and it is the honest way to make this claim. Rather than asserting that the
  redaction is safe, the file names four specific things that must not appear and checks.
- `classify` keys on `free_tier_requests` — the quota metric name from
  [3.1](3.1-which-429-is-it.md), reused. One classification, two uses: deciding whether to retry, and
  deciding what to say.
- `classify` **falls through to `"internal"`** rather than raising on an unrecognised error. That is
  the right default here and the opposite of [1.2](../01-who-hears-it/1.2-an-error-is-a-fact.md)'s
  advice about `KeyError` — because the alternative is a user-facing path that can itself throw, and
  the most conservative public message is the correct answer for an error you do not recognise.

```bash
cd days/day-21-errors-surface-not-swallow/lab
REDACT=1 uv run python give_up_honestly.py
REDACT=0 uv run python give_up_honestly.py
```

**Line by line:**

- `REDACT=0` is the ablation: the same failure with the filtering removed, so the leak can be counted
  rather than imagined.
- Pure Python over a string constant. No ADK, no key, no network, no quota.

Measured on 2026-09-03:

```text
REDACT=1
  classified as: quota_exhausted
  the log gets:   433 chars (the whole body)
  the user gets:  68 chars
  internal details leaked to the user: none

  Sutra has reached its request limit for today. Nothing was answered.

REDACT=0
  classified as: quota_exhausted
  the log gets:   433 chars (the whole body)
  the user gets:  433 chars
  internal details leaked to the user: ['gemini-3.7-flash', 'generativelanguage.googleapis.com', 'limit: 20', 'billing']
```

**Four leaks, named.** The model Sutra runs on, the provider endpoint, the exact numeric limit, and an
invitation to check billing details — delivered to a support engineer, or a customer, who asked about
a ticket. Nobody chose to publish any of it. It escaped because the exception was the most convenient
string available at the moment somebody needed one.

**433 characters against 68**, and the 68 carry every fact the caller actually needs: it failed, it was
a limit, it is for today, and nothing was answered. The 365 characters of difference are entirely
addressed to a developer.

**And the log line is identical in both arms.** That is the part to hold on to. Redacting the
user-facing sentence costs the operator nothing — the whole body is still recorded, still searchable,
still exact. This is not a trade-off between honesty and safety. It is two audiences.

## When it breaks

The failure of this design is a status it has never seen, and it is worth being precise about which
way it fails:

```text
Traceback (most recent call last):
  File "give_up_honestly.py", line 41, in to_user
    return PUBLIC[classify(raw)]
           ~~~~~~^^^^^^^^^^^^^^^
KeyError: 'rate_limited'
```

That is what happens if `classify` gains a return value that `PUBLIC` has no entry for — a two-line
change in two places, made by two people, a week apart. It raises **inside the error handler**, which
means the user gets nothing at all and your log records a `KeyError` where the real failure should be.
[2.2](../02-four-hooks/2.2-the-two-that-can-rescue.md)'s *When it breaks* is the same shape, and the
same rule applies: the error path must be the most boring code in the repo. Use
`PUBLIC.get(status, PUBLIC["internal"])` and let the classifier grow without taking the handler with
it.

The other failure has no error text, because it is a leak: somebody adds
`f"{PUBLIC[status]} ({error})"` to make debugging easier during an incident, and it ships. The
redaction was never a boundary, only a habit, and a habit is one hurried commit deep.

## In production

**Test the redaction with the real body, and make the leak list a fixture.** The `LEAKS` tuple above is
an assertion waiting to be moved into the suite — a list of strings that must never appear in a
user-facing message, checked against every public string the system can produce. It costs nothing to
run and it turns a habit into a boundary.

**What changes at scale** is that the number of ways a message can escape grows faster than the
redaction does. Once there is an API surface, a web UI, a Slack integration and an email digest, each
one has its own path from exception to text, and the redaction has to live at the point the message is
*built* rather than at each point it is displayed. One function, used by all four, is the only version
that survives.

**The failure that only appears with real traffic** is the exception whose *arguments* are the leak. A
database timeout raised by a driver often includes the query, and Sutra's queries contain ticket ids,
email addresses and names. `unavailable` as a public status is fine; the exception behind it may be a
data-protection incident sitting in a log that has a broader audience than you think. Which is Day
22's problem as much as today's, and the reason logging is the next day rather than a later one.

**The review comment a senior engineer leaves:** *"this returns `str(error)` to the caller on the
give-up path. That body names our model and our quota. Map the status to a fixed public string and
keep the raw exception in the log."*

**The interview question:** *"what does your agent say to the user when it gives up?"* The answer that
shows you have read a leaked one: *"a fixed sentence chosen by status, never the exception. The raw
error goes to the log unmodified, because an operator needs to search for the exact string. When we
checked ours unredacted, the 429 body handed the user our model name, the provider endpoint, our
numeric quota and the word billing — none of which we'd decided to publish."*
