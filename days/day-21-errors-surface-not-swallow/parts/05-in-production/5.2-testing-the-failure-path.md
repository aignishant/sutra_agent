# 5.2 — Testing the failure path without quota

## One-line answer

A tool that always raises and a model that always fails are the easiest things in the world to write,
so the whole error policy is testable with **no key and no network** — and reintroducing trap #4 turns
five of eight tests red, one of them with the message `assert [] == ['tool', 'agent', 'run']`.

## The story

The generator behind the surgery gets tested on the first Monday of the month.

Somebody walks out, throws the main breaker, and stands there with a clipboard while the lights flicker
and come back. It takes a couple of minutes and it is faintly ridiculous, because the mains has never
failed.

What the tests have found, over four years: a fuel filter nobody had changed, a battery that would not
crank in January, and — the good one — an automatic changeover that worked perfectly and took
forty-five seconds, during which the fridge holding the vaccines was off. That last one was not a
broken generator. It was a correct generator revealing a requirement nobody had written down.

You cannot find that by looking at the generator.

## The idea in plain language

Everything this day built is a **failure path**, and failure paths have a structural problem: they only
run when something is broken. In normal operation the classifier is never called, the substitute is
never built, the redaction never applies, and the hooks never fire. The code carrying Sutra's honesty
is the code least exercised by using Sutra.

The good news is that it is unusually cheap to test, and the reason is the same as
[Day 20's](../../../day-20-context-engineering-compaction/parts/05-in-production/5.2-testing-compaction-without-quota.md):
both seams are injectable.

**A failing tool is a one-line function.** `def lookup_article(article_id): raise TimeoutError(...)`.
No mocking library, no patching, no network stub. Failure is the easiest behaviour to write.

**A failing model is a `BaseLlm` that raises.** The `Flaky` class from
[2.4](../02-four-hooks/2.4-the-ladder.md) is nine lines and produces a 429 on demand, deterministically,
as many times as you ask.

**And the plugin is where you assert.** A recording plugin captures which hooks fired, in what order,
which is the observation everything else in the day was built on.

What is worth asserting falls into four groups, and the fourth is the one people leave out.

1. **That the exception arrives.** An unrescued tool error reaches the caller, unchanged.
2. **That the ladder is intact.** `["tool", "agent", "run"]`, in order.
3. **That the rescue works.** Returning a dict stops the exception and the run continues.
4. **That the contracts hold in the negative.** The agent hook *cannot* suppress even when it returns
   something; the substitute *does* carry its marker. These are assertions that the framework's
   documented limits are real — the pair that
   [2.3](../02-four-hooks/2.3-the-two-that-can-only-witness.md) and
   [3.2](../03-policy/3.2-a-substitute-must-say-so.md) measured by hand.

## Why Sutra needs it

Because [4.1](../04-failure-lab/4.1-the-swallowed-exception.md) is a bug a test can catch and nothing
else can.

A `try`/`except` added to a tool passes every existing test. It does not change the tool's signature,
it does not change its return type on the happy path, and the suite goes green. The only observable
difference is a hook count, and the only thing that watches a hook count is a test that was written to.

And [5.1](5.1-one-policy-not-a-hundred.md) left one loose end: with policy in a plugin, `Runner(agent=...)`
instead of `Runner(app=...)` silently installs nothing. That is a one-word mistake that disables the
entire error surface, and a test asserting the ladder fires is the only thing standing in front of it.

These tests also cost nothing to run, which is what decides whether they stay. Anything needing a key
gets marked `live` and skipped by `./m check`, which means it never runs, which means it protects
nothing.

## The mechanism

Eight cases over one failing tool and one recording plugin.

```python
# days/day-21-errors-surface-not-swallow/lab/test_errors_demo.py
"""The failure path, asserted rather than hoped for - and with no key and no network."""

BOOM = "kb.internal:8080 timed out after 5s"


def lookup_article(article_id: str) -> dict[str, Any]:
    """The knowledge base is down. This raises, on purpose, every time."""
    raise TimeoutError(BOOM)


class Recording(BasePlugin):
    """Records which hooks fired; rescues only if given a fallback."""

    def __init__(self, name: str, fallback: dict[str, Any] | None = None) -> None:
        super().__init__(name=name)
        self.heard: list[str] = []
        self.fallback = fallback

    async def on_tool_error_callback(
        self, *, tool: Any, tool_args: dict[str, Any], tool_context: Any, error: Exception
    ) -> dict[str, Any] | None:
        self.heard.append("tool")
        return dict(self.fallback) if self.fallback else None

    async def on_agent_error_callback(
        self, *, agent: Any, callback_context: Any, error: Exception
    ) -> None:
        self.heard.append("agent")
        return {"suppress": "please"}  # notification-only: this must not work

    async def on_run_error_callback(self, *, invocation_context: Any, error: Exception) -> None:
        self.heard.append("run")


def test_an_unrescued_tool_error_reaches_the_caller() -> None:
    """Trap #4: the exception is not absorbed by the framework."""
    plugin = Recording("p")
    _, raised = asyncio.run(_run(plugin))
    assert isinstance(raised, TimeoutError)
    assert BOOM in str(raised)


def test_the_hooks_fire_in_order_tool_then_agent_then_run() -> None:
    """The escalation ladder, asserted so a refactor cannot silently reorder it."""
    plugin = Recording("p")
    asyncio.run(_run(plugin))
    assert plugin.heard == ["tool", "agent", "run"]


def test_returning_a_dict_from_the_tool_hook_stops_the_exception() -> None:
    """The rescue path: one hook turns a failure into a marked substitute."""
    plugin = Recording("p", fallback={"status": "unavailable", "reason": BOOM})
    reply, raised = asyncio.run(_run(plugin))
    assert raised is None
    assert "unavailable" in (reply or "")


def test_the_agent_hook_cannot_suppress_even_when_it_returns_something() -> None:
    """on_agent_error_callback is notification-only, and the docstring says so."""
    plugin = Recording("p")
    _, raised = asyncio.run(_run(plugin))
    assert raised is not None, "returning a value from on_agent_error_callback suppressed the error"


def test_the_substitute_says_a_failure_happened() -> None:
    """SEC-02: a rescue that reads like a real result is the bug this day is about."""
    plugin = Recording("p", fallback={"status": "unavailable", "reason": BOOM})
    reply, _ = asyncio.run(_run(plugin))
    assert "unavailable" in (reply or "")
    assert BOOM in (reply or ""), "the substitute dropped the reason"


@pytest.mark.parametrize(
    ("message", "retryable"),
    [
        ("429 ... generate_requests_per_minute, limit: 10", True),
        ("429 ... generate_content_free_tier_requests, limit: 20", False),
        ("500 INTERNAL", False),
    ],
)
def test_only_a_per_minute_ceiling_is_worth_retrying(message: str, retryable: bool) -> None:
    """Classification is the whole of retry policy."""
    assert ("429" in message and "per_minute" in message) is retryable
```

**Line by line:**

- `Recording.__init__` calls `super().__init__(name=name)` — required, because `BasePlugin` takes a
  mandatory `name` ([2.1](../02-four-hooks/2.1-the-runtime-owns-the-error.md) has the `TypeError` you
  get without it). The `fallback` argument is what turns one plugin class into both the rescuing and
  the non-rescuing case.
- `self.heard` is **per instance** rather than a module-level list. Each test builds its own plugin, so
  the tests cannot contaminate each other, and `plugin.heard` is a fact about that run only.
- `return dict(self.fallback) if self.fallback else None` is the ablation switch, expressed as
  constructor state. One class, two behaviours, no environment variables in a test suite.
- `on_agent_error_callback` **returns a dict on purpose**, and the test named after it asserts that the
  exception still arrives. That is the negative assertion: it pins ADK's documented *"the exception is
  always re-raised"* so an upgrade that changed it would be a red test rather than a surprise.
- `assert isinstance(raised, TimeoutError)` checks the **type**, not just that something raised. The
  claim from [2.4](../02-four-hooks/2.4-the-ladder.md) is that the exception survives the climb
  unchanged, and the type is how you check that.
- `assert plugin.heard == ["tool", "agent", "run"]` asserts **order**, not membership. A set comparison
  would pass if the ladder reversed, and the ordering is a documented property worth pinning.
- `assert BOOM in (reply or ""), "the substitute dropped the reason"` — the message is the point. A bare
  assertion failure here would say `assert '...' in ''`; the message says which contract broke.
- `(reply or "")` guards against `reply` being `None` when a test's premise fails. Without it, the
  failure is `TypeError: argument of type 'NoneType' is not iterable`, which tells you nothing about
  what you were asserting.
- The parametrised test asserts the classifier's **logic**, inline, rather than importing it. That is a
  deliberate compromise: it duplicates the expression from
  [3.1](../03-policy/3.1-which-429-is-it.md), and once that classifier lives in `sutra/errors.py` this
  test should import it instead. Duplicated logic in a test is a placeholder, and worth flagging as one.


**Line by line:**

- Eight cases against a raising tool and recording models: no key, no network, no quota.

Measured on `google-adk` 2.7.1 with `pytest` 9.1.1 on 2026-09-03:

```text
........                                                                 [100%]
8 passed
```

Eight, because the parametrised test counts as three.

**Now reintroduce trap #4.** Change the tool's body from `raise TimeoutError(BOOM)` to
`return {"error": f"Error: {BOOM}"}` — the exact four-line habit from
[4.1](../04-failure-lab/4.1-the-swallowed-exception.md), reduced to one line:

```text
FFFFF...                                                                 [100%]
test_errors_demo.py:109: assert False
test_errors_demo.py:117: AssertionError: assert [] == ['tool', 'agent', 'run']
test_errors_demo.py:125: assert 'unavailable' in ("{'error': 'Error: kb.internal:8080 timed out after 5s'}")
test_errors_demo.py:139: assert 'unavailable' in ("{'error': 'Error: kb.internal:8080 timed out after 5s'}")

FAILED test_errors_demo.py::test_an_unrescued_tool_error_reaches_the_caller
FAILED test_errors_demo.py::test_the_hooks_fire_in_order_tool_then_agent_then_run
FAILED test_errors_demo.py::test_returning_a_dict_from_the_tool_hook_stops_the_exception
```

**Five red, three green**, and the three that survived are the parametrised classifier cases —
correctly, because they never touch the runner. A suite where *everything* goes red on one change is
testing one thing five times.

**`assert [] == ['tool', 'agent', 'run']` is the best error message in this day.** An empty list. Not a
reordered ladder, not a missing rung — **nothing fired at all**. That is
[4.1](../04-failure-lab/4.1-the-swallowed-exception.md)'s measurement arriving as a test failure, and
it is the assertion that catches the one bug no other signal can.

**And two of the failures are useful in a way that is easy to miss.** The `'unavailable' in "{'error':
...}"` failures show the *swallowed error string* in the assertion output. The test tells you both that
the rescue did not happen and what the tool returned instead, which is most of a diagnosis before you
have opened a file.

## When it breaks

**One of the eight tests is weaker than its name, and finding it was the point of running the suite
red.** `test_an_unrescued_tool_error_reaches_the_caller` failed with:

```text
test_errors_demo.py:109: assert False
```

`assert False` — because `isinstance(None, TimeoutError)` is `False` and the assertion carries no
message. It is a correct test with an unhelpful failure. The fix is
`assert isinstance(raised, TimeoutError), f"nothing raised; the tool returned instead: {raised}"`, and
the habit is the one from
[Day 20](../../../day-20-context-engineering-compaction/parts/05-in-production/5.2-testing-compaction-without-quota.md)
and [Day 19](../../../day-19-context-engineering-selection/parts/06-in-production/6.1-testing-what-goes-in-the-window.md):
**break the suite on purpose and read the messages**, because that is the only time you ever see them.

That is three consecutive days on which deliberately failing a green suite has exposed a weak
assertion. It is not a coincidence; it is the technique.

**And what these tests cannot catch** is worth stating plainly. They assert the *plumbing*: hooks fire,
exceptions arrive, substitutes carry markers. They say nothing about whether the classifier's
categories are right, whether the public messages are actually free of internal detail
([3.3](../03-policy/3.3-giving-up-honestly.md)'s `LEAKS` list belongs here and is not yet in the
suite), or whether a real provider's error bodies still match the strings being matched on.

## In production

**Assert the ladder, and treat it as a canary for plugin installation.** The single most valuable test
in this file is `plugin.heard == ["tool", "agent", "run"]`, because it fails for two entirely different
and equally silent causes: a tool that swallows, and a `Runner` built with `agent=` instead of `app=`.
One assertion, two invisible bugs.

**What changes at scale** is that you need the other half: a small, separately-marked suite that runs
against the *real* provider and asserts that the classifier still recognises today's error bodies. That
one costs quota and belongs on a schedule, not on every commit — which is Day 79's eval work, and the
same split as Day 20 arrived at. Structure tested for free on every change; reality tested with real
calls on a timer.

**The failure that only appears with real traffic** is still the wording change from
[3.1](../03-policy/3.1-which-429-is-it.md). No amount of local testing catches a provider renaming a
quota metric, because your fixtures are copies of yesterday's body. What local tests buy you is the
certainty that when the classification breaks, the breakage is in the classification and not in the
plumbing underneath it.

**The review comment a senior engineer leaves:** *"good coverage of the hooks, but the retry test
reimplements the classifier instead of importing it. Once that lives in `sutra/errors.py`, import it —
otherwise the test passes while the real one is wrong."*

**The interview question:** *"how do you test error handling in an agent?"* The answer that shows you
have written it: *"with fakes at both seams — a tool that always raises and a model that always 429s,
which are the easiest objects to write in the whole system. The plugin records which hooks fired, so I
can assert the ladder and its order. Then I break it on purpose: putting a try/except back in the tool
turns five of eight tests red, and one of them says `assert [] == ['tool', 'agent', 'run']`, which is
the only signal that catches a swallowed exception."*
