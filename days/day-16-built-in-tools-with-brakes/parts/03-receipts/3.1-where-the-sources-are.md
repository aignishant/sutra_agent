# 3.1 — Where the sources are

## One-line answer

A grounded answer arrives with its sources attached to the **event**, not to the text:
`event.grounding_metadata.grounding_chunks[i].web` holds the title and the URL of each page the model
consulted, and if you do not read them off the event as it goes past, nothing later can reconstruct
them.

## The story

The project was due on Monday and it was finished on Sunday night.

Six pages, neat, printed. The teacher read the second paragraph out loud and asked one question:
*"Where did you get this?"*

You knew you had not made it up. You had read it somewhere on Thursday, in one of maybe nine tabs,
and you had typed it into your own words and moved on because the writing was going well. On Sunday
night the tabs were closed. The history was there but it was four days of history, and the sentence
did not contain the name of the place it came from.

The facts were fine. The essay was fine. But the answer to the only question that was asked was
gone, and it had been gone since Thursday, when you did not write down where you were standing.

## The idea in plain language

When Gemini answers with search switched on, the response carries a second half.

The first half is what you already know: text, in parts, in the content of an event. That is what
Sutra has printed since [Day 5](../../../day-05-first-adk-agent/LESSON.md).

The second half is **grounding metadata**, an object hanging off the same event, containing what the
platform did on the other side of the partition
([1.3](../01-switched-on/1.3-the-request-that-leaves-your-process.md)). ADK exposes it as
`event.grounding_metadata`, and the field names below were read from `google-genai` 2.19.0's own type
definitions on 2026-09-03 rather than from a tutorial:

| Field | What it holds |
| --- | --- |
| `web_search_queries` | the queries the platform decided to run — the closest thing to a log of what it did |
| `grounding_chunks` | the pages it consulted; each has a `web` with `title` and `uri` |
| `grounding_supports` | which span of the answer rests on which of those pages ([3.2](3.2-the-offsets-are-in-bytes.md)) |
| `search_entry_point` | pre-built HTML you are expected to display ([3.3](3.3-the-receipt-you-must-show.md)) |

Two things about this object decide how you have to write code around it.

**It is on the event, not in the text.** The answer is a string; strings do not have attachments. So
the sources are only available where the event is, which is inside the loop consuming the run. Pass
the text on and the sources stay behind, exactly like Thursday's tabs.

**It can be absent, and absent is not an error.** `grounding_metadata` is `None` on ordinary events,
and it is `None` on a grounded call where the model chose not to search — which it is entitled to do,
because the built-in is a permission and not an instruction. Code that assumes the object is there
crashes on the day the model answers from memory, and code that never checks reports "no sources" and
"did not search" as the same thing.

## Why Sutra needs it

Because Principle 10 says Sutra never fabricates a result, and a grounded answer with no visible
sources is indistinguishable from a fabricated one.

That is not a philosophical point. Sutra's whole output is a triage note that a support engineer will
act on: *"AcmeCloud is reporting a degraded auth cluster in the EU."* If that sentence is on a screen
with two links under it, the engineer can check it in seconds. Without the links it is a rumour with
good grammar, and the engineer's only options are to trust it or to redo the work.

There is a second, harder reason arriving in Phase 10. On Day 66 the injection work starts, and the
attack that matters here is a web page written to be found by a search and to contain instructions.
The defence is not clever prompting; it is that a human can see *which page* the claim came from. The
sources are the evidence trail, and they exist for exactly this.

## The mechanism

This is the day's first script that spends a request. It asks one question, prints everything that
came back with the answer, and refuses to invent anything if the quota is gone:

```python
# days/day-16-built-in-tools-with-brakes/lab/ground.py
"""One grounded question, and everything that arrived with the answer.

Spends 1 model request (free tier: 20 per day) and 1-2 search requests
(free tier: 5,000 per month). Run it once.

    cd days/day-16-built-in-tools-with-brakes/lab
    uv run python ground.py
"""

from __future__ import annotations

from google.adk.agents import Agent
from google.adk.events import Event
from google.adk.runners import InMemoryRunner
from google.adk.tools import google_search
from google.genai import types
from google.genai.errors import ClientError

from sutra.config import load_env, require_free_tier

MODEL = "gemini-3.7-flash"
QUESTION = "Is GitHub reporting an incident on its official status page right now?"

searcher = Agent(
    name="sutra_researcher",
    model=MODEL,
    description="Answers questions about the current public web, with sources.",
    instruction=(
        "You answer questions about the CURRENT public state of the internet. "
        "Search before answering. Report what the sources say, and say plainly "
        "when the sources do not settle the question."
    ),
    tools=[google_search],
)


def show(event: Event) -> None:
    """Print the queries, the sources and the supports carried by one event."""
    meta = event.grounding_metadata
    if meta is None:
        return

    print("--- queries the platform ran ---")
    for query in meta.web_search_queries or []:
        print("   ", query)

    print("--- sources ---")
    for index, chunk in enumerate(meta.grounding_chunks or []):
        if chunk.web is not None:
            print(f"  [{index}] {chunk.web.title} - {chunk.web.uri}")

    print("--- which span rests on which source ---")
    for support in meta.grounding_supports or []:
        if support.segment is not None:
            print(f"  {support.grounding_chunk_indices} <- {support.segment.text!r}")

    entry = meta.search_entry_point
    print("--- search entry point ---")
    print("   rendered_content:", "present" if entry and entry.rendered_content else "absent")


def main() -> None:
    load_env()
    require_free_tier()

    runner = InMemoryRunner(agent=searcher)
    session = runner.session_service.create_session_sync(app_name=runner.app_name, user_id="day16")
    try:
        for event in runner.run(
            user_id="day16",
            session_id=session.id,
            new_message=types.Content(role="user", parts=[types.Part(text=QUESTION)]),
        ):
            show(event)
            if event.is_final_response() and event.content:
                answer = "".join(part.text or "" for part in event.content.parts).strip()
                print("\nANSWER:", answer)
    except ClientError as error:
        if error.code == 429:
            print("429: the free tier is spent for today. No answer, and none invented.")
            raise SystemExit(1) from error
        raise


if __name__ == "__main__":
    main()
```

**Line by line:**

- `from sutra.config import load_env, require_free_tier` — Day 1's loader and Day 5's guard. The
  guard is what stops this script from quietly using a billing-account backend if
  `GOOGLE_GENAI_USE_VERTEXAI` is set in your shell (Principle 15).
- `description=` on the agent — carried over from
  [2.3](../02-one-at-a-time/2.3-the-specialist-you-write-yourself.md). It does nothing in this
  script, and it is written anyway so that the same agent can be lifted into the desk without
  changing it.
- `instruction=` — three sentences, and the third is the one that matters: *say plainly when the
  sources do not settle the question*. A grounded model with a weak instruction will happily fill the
  gap between what it found and what you asked with something plausible.
- `def show(event: Event)` — the whole receipts reader, and it starts with `if meta is None: return`
  because most events in a run carry no metadata at all.
- `meta.web_search_queries or []` — the `or []` is not decoration. Every field on this object is
  `Optional`, so any of them can be `None` even when the object exists, and iterating `None` is a
  `TypeError` in the middle of a run you have already paid for.
- `chunk.web is not None` — a `GroundingChunk` may hold a `web`, a `maps`, an `image` or a
  `retrieved_context`, and only one of them is set. With `google_search` on the Gemini API it is
  `web`, and checking is what makes the code honest rather than lucky.
- `support.grounding_chunk_indices` — a list of positions into `grounding_chunks`. This is the join
  between a sentence and its sources, and [3.2](3.2-the-offsets-are-in-bytes.md) is entirely about
  the other half of that structure.
- `event.is_final_response()` — ADK's own predicate for "this is the answer, not an intermediate
  step". Printing on every event instead would print partial text several times.
- `except ClientError as error: if error.code == 429` — the honest failure path. ADK raises its own
  `_ResourceExhaustedError` for a 429, and that class subclasses `google.genai.errors.ClientError`,
  which is the public name you can catch. The script prints one line and exits non-zero. It does not
  retry in a loop, because a **daily** ceiling is not a minute ceiling and retrying spends nothing
  but your patience (`docs/PACKAGES.md`, 2026-08-25).
- `raise SystemExit(1) from error` — a non-zero exit, so a caller or a CI step can tell the difference
  between "no incident found" and "never ran".

## When it breaks

**`AttributeError: 'NoneType' object has no attribute 'grounding_chunks'`**

The event carried no metadata and you reached through it anyway. It happens on the very first event
of any run, because that event is your own message going in. The guard is the `if meta is None:
return` at the top of `show`.

**`TypeError: 'NoneType' object is not iterable`**

The metadata object exists and one of its lists does not. Every field on `GroundingMetadata` is
optional; a response can carry `web_search_queries` and no `grounding_supports`, or chunks with no
supports. This is why every loop in `show` ends in `or []`.

**The answer prints and the sources block is empty.**

No error at all, and two very different causes that look identical:

1. the model did not search — it answered from memory, which it is allowed to do, and the honest
   report is *"answered without searching"* rather than *"no sources found"*;
2. the sources were dropped at a boundary — the specialist was wrapped in an `AgentTool` with
   `propagate_grounding_metadata` left at its default of `False`
   ([2.3](../02-one-at-a-time/2.3-the-specialist-you-write-yourself.md)).

Telling them apart is the first diagnostic step, and `web_search_queries` is what does it: a
non-empty query list with no chunks means the search happened and the receipts were lost on the way.

## In production

**Capture the metadata at the event and carry it with the answer, or accept that you never had it.**

The practical version of this is a small structure — the answer text, the list of `(title, uri)`, and
the queries — built inside the event loop and returned as one object. Everything downstream takes
that object rather than a string. This sounds obvious and is skipped constantly, because the first
version of any agent returns a string and the sources are added "later", by which time the loop that
had them is three layers away.

**What changes at scale** is that sources become a storage question. A support desk answering
thousands of tickets keeps the citation list with the ticket, not just on the screen, because the
question *"what was the evidence for what we told this customer in March?"* is asked by people who are
unhappy. That is a row in a table, and it is worth designing before the first incident rather than
after.

**What fails under real traffic** is trusting the count. Grounded responses vary: some carry twelve
chunks, some carry two, some carry none because the model decided it knew the answer. A UI that
renders "Sources:" unconditionally will print an empty heading on a meaningful fraction of answers, and
users read an empty sources list as an error. Render the heading only when there is something under it,
and say *"answered without searching"* when there is not.

**The review comment**: *"this function returns `answer.text`, so the citations die here. Return the
sources with it, or explain how the UI is supposed to get them."*

**The interview question**: *"how do you know a grounded answer is actually grounded?"* The answer that
shows you have done it: *"the queries and the chunks come back on the event. If the query list is
empty, it never searched, and that is a different failure from finding nothing."*
