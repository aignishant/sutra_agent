# 3.3 — The receipt you must show

## One-line answer

Displaying the citations is not a nice touch you add if there is room: the grounding documentation
states it as a requirement, the response ships pre-built HTML for the search suggestions, and Sutra's
version of that requirement is a renderer that prints nothing at all rather than an empty heading.

## The story

The ingredients are printed on the side of the packet.

Not because the company wanted to. The list is small, it is ugly, it uses words the marketing
department would never choose, and it is on every packet in the aisle. Somebody decided a long time
ago that if you are going to sell people food, they get to read what is in it, and the label became
the price of being allowed on the shelf.

You do not read it most weeks. You read it the week your niece comes to stay and cannot have nuts,
and then you read every packet in the cupboard, and the ones with a clear label are the ones you
trust. The label is not for the average shopper on an average day. It is for the one person who has a
reason to check, and it has to be there before they need it, because the moment they need it is not
the moment to start writing it.

## The idea in plain language

Two things arrive with a grounded answer that are meant for the person reading it, and the
documentation is explicit about the second one. From
`adk.dev/grounding/google_search_grounding/`, read on 2026-09-03:

> A critical part of using grounding is to correctly display the information, including citations and
> search suggestions, to the end-user.

**Citations** are the sources from [3.1](3.1-where-the-sources-are.md): titles and URLs, one per
consulted page.

**Search suggestions** are the `search_entry_point` field, and it is different in kind from
everything else on the metadata object. Its `rendered_content` is a block of **HTML the platform
wrote**, styled, ready to embed in a page. You are not asked to build the search-suggestion UI; you
are handed it and asked to display it.

That HTML is worth stopping on for a second, because embedding markup you did not write is a decision
and not a formality. It is provider-supplied and it is not user input, so this is not the injection
problem of Day 66 — but it is still third-party markup entering your page, which means it belongs
somewhere your content-security policy accounts for, and it means a text-only surface cannot show it
at all. There is a second field, `sdk_blob`, documented as *"JSON representing array of tuples"*, for
callers that want the data rather than the markup.

Sutra has no web page yet. The interfaces so far are a terminal and, from Day 85, an API. So Sutra's
version of the display requirement is a small pure function that turns metadata into a citation block
— and the rule that makes it a *good* one is: **an empty sources list renders nothing, not an empty
heading**. A heading with nothing under it reads as a broken feature; silence reads as an answer that
did not need sources, which is what it is.

## Why Sutra needs it

Because the first place this bites is the interface Sutra is building towards, and the second is the
reason the whole day is called *with brakes*.

Day 85 puts an API server in front of Sutra, and Days 74–78 build a browser client for voice. Both are
surfaces where a grounded answer is shown to a person, and both are the point at which "we have the
sources somewhere" has to become "the sources are on the screen". A renderer written today is a
function those surfaces call; a renderer not written today is a field that quietly stops being
carried, because nothing is reading it.

The other reason is Principle 10 again, in its sharpest form. Sutra is allowed to be wrong. Sutra is
not allowed to be **unfalsifiable**. An answer with its sources attached can be checked in seconds by
the engineer reading it; the same answer without them is a claim that costs an afternoon to verify,
which in practice means it will be believed instead.

## The mechanism

The renderer, and a fixture you build by hand so it can be run and tested with no key and no request:

```python
# days/day-16-built-in-tools-with-brakes/lab/render_sources.py
"""Rendering a citation block, against a fixture you build yourself. Zero model calls."""

from google.genai import types


def render_sources(meta: types.GroundingMetadata | None) -> str:
    """A citation block for a terminal, or an empty string when there is nothing to cite."""
    if meta is None or not meta.grounding_chunks:
        return ""
    lines = ["Sources:"]
    for index, chunk in enumerate(meta.grounding_chunks, start=1):
        if chunk.web is None:
            continue
        title = chunk.web.title or "(untitled)"
        lines.append(f"  [{index}] {title} - {chunk.web.uri}")
    return "\n".join(lines) if len(lines) > 1 else ""


FIXTURE = types.GroundingMetadata(
    web_search_queries=["github status incident"],
    grounding_chunks=[
        types.GroundingChunk(
            web=types.GroundingChunkWeb(
                title="githubstatus.com", uri="https://www.githubstatus.com/"
            )
        ),
        types.GroundingChunk(
            web=types.GroundingChunkWeb(title=None, uri="https://example.invalid/")
        ),
    ],
    search_entry_point=types.SearchEntryPoint(rendered_content="<style>...</style><div>...</div>"),
)

print(render_sources(FIXTURE))
print("---")
print(repr(render_sources(None)))
print("---")
print(repr(render_sources(types.GroundingMetadata(web_search_queries=["x"]))))
```

**Line by line:**

- `def render_sources(meta: types.GroundingMetadata | None) -> str:` — it takes the metadata object
  and returns a string. No printing inside, no event, no runner. That is what makes it testable
  without a model, which is the whole argument of
  [8.1](../08-in-production/8.1-testing-a-built-in-without-spending-a-request.md).
- `if meta is None or not meta.grounding_chunks: return ""` — the two shapes of "nothing to cite",
  handled in one line: no metadata at all, and metadata with no chunks. Both return the empty string
  rather than a heading.
- `enumerate(..., start=1)` — numbering from one, because these numbers are shown to a person.
  Everywhere else in this day the indices are the API's own, counted from zero
  ([3.2](3.2-the-offsets-are-in-bytes.md)), and mixing the two conventions in one output is how a
  citation ends up pointing at the wrong source.
- `if chunk.web is None: continue` — the same guard as
  [3.1](3.1-where-the-sources-are.md): a chunk can be a maps result or a retrieved context, and only
  a web chunk has a title and a URL.
- `chunk.web.title or "(untitled)"` — the title is `Optional[str]` in the type definition and pages do
  come back without one. `None` printed into a citation line reads as a bug; `(untitled)` with a
  working URL is still a usable receipt.
- `return "\n".join(lines) if len(lines) > 1 else ""` — the empty-heading rule made explicit. If every
  chunk was skipped, `lines` still holds `"Sources:"` and nothing else, and returning that would print
  the heading with nothing under it.
- `FIXTURE = types.GroundingMetadata(...)` — a metadata object built by hand. It is not a captured
  API response and it is not pretending to be one: it exists so the renderer's behaviour can be shown
  and asserted without spending a request. The second chunk deliberately has `title=None`, because
  that is the case the renderer exists to survive.

## When it breaks

**The sources heading prints and nothing is under it.**

No exception. It happens when every chunk in the list is a non-web chunk, or when the list is empty
but present. The reader sees a heading and concludes the citations are broken. This is the case the
`len(lines) > 1` check exists for, and it is the first thing to break when someone simplifies the
function.

**The HTML shows up as visible tags.**

`rendered_content` is markup, and a surface that escapes HTML — a Markdown renderer, a terminal, a
JSON field displayed as text — shows the tags themselves instead of the widget. That is not a bug in
the metadata; it is the field being sent somewhere it cannot be used. Either render it as HTML in a
surface that can, or use `sdk_blob` and build your own. There is no error text for this one: it looks
wrong to a person and looks fine to every test you have.

**The citations are right and point somewhere you did not expect.**

Not an error either, and the reason the `TODO(me)` above asks you to look at the real values: the
`uri` on a grounding chunk is not guaranteed to be the plain address of the page. Open the first two
links your own run produces before you build any interface on top of them, and note in your build
brief what you actually got. If your interface shows link text as well as the link, show `title` as
the text rather than a raw URL you have not read.

## In production

**Make the renderer a pure function, and make the surface call it.**

Every interface Sutra grows — the terminal today, the API on Day 85, the browser client in Phase 11 —
needs the same three behaviours: cite when there is something to cite, say nothing when there is not,
and never invent a source. One function, tested once, called from three places. The alternative, which
is what happens by default, is three slightly different implementations of the citation block, two of
which have the empty-heading bug.

**What changes at scale** is that citations become a product surface with rules attached. The
provider's display requirement is one input. A second is your own: whether you show every source the
model consulted or only the ones a support actually points at, whether you cap the list, and what you
do about the same page appearing twice. All of those are decisions that are easy while the function
is small and awkward once three surfaces have opinions.

**The review comment**: *"this renders `Sources:` unconditionally. On an answer the model did not
search for, that is an empty heading, and an empty heading looks like a bug to everyone who sees
it."*

**The interview question**: *"you are asked to show citations for a grounded answer. What is in the
response, and what does the provider require you to do with it?"* The strong answer names both halves
— the source list and the pre-rendered search-suggestion HTML — and says that displaying them is
stated as a requirement rather than left to taste.
