# 7.1 — The plugins ADK already ships

## One-line answer

`google-adk` 2.7.1 ships nine working plugins in `google/adk/plugins/`, and reading two of them —
`ReflectAndRetryToolPlugin` and `ContextFilterPlugin` — confirms from the framework's own source the
two rules this day derived by measurement.

---

## The story

You take a flat and start making the list of things to buy.

A geyser, because it is a cold-water tap and you are not doing that all winter. A ceiling fan for the
back room. A water filter. You price all three, you argue with yourself about which brand, and you set
aside a weekend for the plumber.

Then you actually walk round the flat properly, and there is a geyser. Behind the bathroom door,
already plumbed in, switch on the wall outside. It was there the day you signed and you had looked at
that wall four times without registering it.

The annoyance is not the money. It is that you had spent two evenings researching geysers when the
question that would have saved both was *what is already here?* — and that question takes ten minutes
and you only ask it once you have stopped assuming you know.

---

## The idea in plain language

You have written four plugins today. Before writing a fifth, it is worth knowing what is already
installed.

`google-adk` 2.7.1 ships these, in `google/adk/plugins/`:

| Plugin | What it does | Hooks it overrides |
| --- | --- | --- |
| `LoggingPlugin` | logs at every callback point | twelve |
| `DebugLoggingPlugin` | captures complete debug information to a file | twelve |
| `ContextFilterPlugin` | filters the model context to reduce its size | `before_model` |
| `ReflectAndRetryToolPlugin` | self-healing retry for tool failures, with the error fed back to the model | `after_tool`, `on_tool_error` |
| `ReflectAndRetryModelPlugin` | the same idea for model failures | `before_model`, `after_model` |
| `SaveFilesAsArtifactsPlugin` | saves files embedded in user messages as artifacts | `on_user_message`, `before_agent` |
| `MultimodalToolResultsPlugin` | lets a function tool return a list of parts directly | `before_model`, `after_tool` |
| `AutoTracingPlugin` | auto-instruments functions with OpenTelemetry spans | `before_run` |
| `GlobalInstructionPlugin` | applies an instruction to every agent in the app | `before_model` |

A tenth, `BigQueryAgentAnalyticsPlugin`, ships in the package but needs an extra that is not installed
here — the script below reports it as unavailable rather than pretending it is absent.

Two of those are Sutra's future, already written. `AutoTracingPlugin` is **ADK-74** (Addendum 01
Part 4), and Day 84 turns it on. `ContextFilterPlugin` is the shape Day 24's context-budget work needs.

But the reason this part exists is not the catalogue. It is that **reading the shipped plugins is the
cheapest available review of your own.** These are written by the people who wrote the hooks, they run
in production for other people, and where they agree with something you worked out by measurement,
your conclusion is a good deal firmer than it was.

Two agreements are worth pointing at, because this day derived both the hard way.

**`ReflectAndRetryToolPlugin` keys its state by `invocation_id` and takes a lock.** Its docstring says
*"Provides self-healing, concurrent-safe error recovery for tool failures"*, and inside it there is a
`ScopedFailureTracker` holding `_scoped_failure_counters` and an `asyncio` lock, with the scope key
resolved from `tool_context.invocation_id`. That is
[4.3](../04-the-meter/4.3-one-instance-every-run.md), in the framework's own code. The plugin author
had the same problem you measured — one instance, many concurrent runs — and solved it the same way,
and then went one step further and added the lock.

**`ContextFilterPlugin` takes its name as a constructor parameter with a default.** Its signature is
`def __init__(self, num_invocations_to_keep=None, custom_filter=None, name="context_filter_plugin",
remove_amount=1)`. That is [1.3](../01-where-a-plugin-lives/1.3-a-name-and-only-one-of-it.md)'s
production shape: a default name so the common case is one argument, and an override so the same class
can be installed twice.

Note also what those two have in common structurally: **configuration in `__init__`, cheap work in the
hooks.** `ContextFilterPlugin` validates `remove_amount >= 1` at construction and raises `ValueError`
there — not on the first request, when it would be
[3.3](../03-the-rule-at-this-layer/3.3-a-plugin-that-raises-takes-the-run-with-it.md)'s
application-wide outage.

---

## Why Sutra needs it

**Because Day 84 is one line if you know this exists and a week if you do not.** ADK-74's whole point
is that OpenTelemetry across the application is a plugin somebody already wrote.

**Because Day 72's retry ladder should start from `ReflectAndRetryToolPlugin` rather than from
scratch.** Addendum 02 §6 requires backoff with `retry-after` on every model path. Whether the shipped
plugin is the right fit is a real decision — its strategy is to feed the error back to the model to
reflect on, which is not the same as sleeping and retrying — but it is a decision to make after
reading it, not before.

**Because `CLAUDE.md`'s anti-patterns list starts with adding a dependency to avoid writing ten
lines** — and the inverse is just as real: writing two hundred lines to avoid reading a dependency you
already have installed.

## The mechanism

The catalogue, from the package rather than from this table.

```python
# lab/shipped.py - what is already installed. Zero model calls.
import importlib
import inspect
import pkgutil

import google.adk.plugins as plugins_package
from google.adk.plugins import BasePlugin

found: list[tuple[str, str, list[str]]] = []
unavailable: list[tuple[str, str]] = []

for module in sorted(pkgutil.iter_modules(plugins_package.__path__), key=lambda m: m.name):
    if module.name in {"base_plugin", "plugin_manager"}:
        continue
    try:
        imported = importlib.import_module(f"{plugins_package.__name__}.{module.name}")
    except ImportError as error:
        unavailable.append((module.name, str(error)))
        continue
    for name, obj in vars(imported).items():
        if not inspect.isclass(obj) or not issubclass(obj, BasePlugin) or obj is BasePlugin:
            continue
        if obj.__module__ != imported.__name__:
            continue
        hooks = sorted(attr for attr in vars(obj) if attr.endswith("_callback"))
        summary = (inspect.getdoc(obj) or "").splitlines()[0]
        found.append((name, summary, hooks))

for name, doc, hooks in sorted(found):
    print(name)
    print(f"  {doc}")
    print(f"  overrides {len(hooks)}: {', '.join(h.removesuffix('_callback') for h in hooks)}")

for name, error in unavailable:
    print(f"{name}: not importable here ({error})")
```

**Line by line:**

- `pkgutil.iter_modules(plugins_package.__path__)` — walks the modules inside the package directory.
  `google.adk.plugins`' own `__init__` imports most of its members lazily through a `__getattr__`, so
  a plain `dir()` on the package would miss the ones nobody has touched yet.
- `if module.name in {"base_plugin", "plugin_manager"}: continue` — the machinery, not the plugins.
  `BasePlugin` would otherwise appear as its own subclass candidate and `PluginManager` is not a
  plugin at all.
- `issubclass(obj, BasePlugin) and obj is not BasePlugin` — the filter that finds plugins by what they
  **are** rather than by a naming convention. A class called `Helper` that subclasses `BasePlugin`
  would be found; a class called `SomethingPlugin` that does not, would not.
- `if obj.__module__ != imported.__name__: continue` — modules import each other, so without this the
  same class is reported once per module that imports it. Comparing the class's own `__module__`
  against the module being scanned keeps each to its definition site.
- `vars(obj)` rather than `dir(obj)` — `vars` is the class's **own** namespace, so it lists only the
  hooks this plugin actually overrides. `dir` would include all fourteen inherited no-ops and every
  plugin would look identical.
- `except ImportError` around the import, collecting into `unavailable` — one shipped plugin
  (`bigquery_agent_analytics_plugin`) imports `google.api_core`, which arrives with an extra Sutra has
  not installed. Reporting it as unavailable rather than letting the script die is the difference
  between a catalogue and a crash, and it tells you the truth: the plugin exists, you just cannot use
  it yet.
- Results are collected into `found` and printed **after** the loop, sorted by class name. Iterating
  by module name would order `_reflect_retry_model_plugin` first because an underscore sorts before
  letters, which is a fact about filenames and not about plugins.
- `inspect.getdoc(obj).split("\n")[0]` — the summary line of the docstring. `getdoc` cleans the
  indentation, which a raw `__doc__` does not.
- `h.removesuffix("_callback")` — every hook ends in the same eleven characters, and dropping them
  makes the list readable at a glance. `removesuffix` is a `str` method from Python 3.9; the project
  is on 3.12.

Read the `overrides` column. Seven of the nine override **one or two** hooks. That is
[2.1](../02-the-fourteen-doors/2.1-fourteen-doors-six-you-already-know.md)'s production note, written
by somebody else: a plugin overrides the fewest hooks that answer its question. The two that override
twelve are both loggers, whose question genuinely is "what happened everywhere".

Verified against the installed `google-adk` 2.7.1 on 2026-08-29 by running this script.

## When it breaks

**💥 The lazy import that is not there yet.**

```text
AttributeError: module 'google.adk.plugins' has no attribute 'ContextFilterPlugin'
```

`google.adk.plugins.__init__` exposes only four names lazily — `DebugLoggingPlugin`, `LoggingPlugin`,
`ReflectAndRetryModelPlugin`, `ReflectAndRetryToolPlugin` — plus `BasePlugin` and `PluginManager`. The
rest are imported from their own modules:

```python
from google.adk.plugins.context_filter_plugin import ContextFilterPlugin
```

**💥 The constructor argument that fails at startup, on purpose.**

```text
ValueError: remove_amount must be at least 1
```

`ContextFilterPlugin` validates in `__init__`. This is the error you want: it happens when the `App`
is built, not on the thousandth request. Copy the habit.

**💥 You installed a shipped plugin and your own stopped seeing traffic.** No error.
`ContextFilterPlugin` and `GlobalInstructionPlugin` both work at `before_model_callback`, and
[3.1](../03-the-rule-at-this-layer/3.1-is-not-none-and-this-time-it-means-it.md)'s rule does not care
who wrote a plugin. Registration order is registration order, and a shipped plugin returning a value
skips yours exactly as one of yours would.

## In production

**What a professional writes instead of the teaching version** is often nothing, because the plugin
exists. The judgement is whether the shipped one's *strategy* matches the requirement, and that is a
reading exercise rather than a feature-list comparison. `ReflectAndRetryToolPlugin` retries by handing
the error text back to the model so it can try different arguments. That is genuinely clever and it is
**not** what a 429 needs — a rate limit is not fixed by rephrasing the call, it is fixed by waiting.
Adopting it for Addendum 02's backoff requirement would be adopting the right-shaped thing with the
wrong behaviour.

**What degrades at scale** is `LoggingPlugin` in production. Twelve hooks, one log line each, on every
agent — including `on_event_callback`, which under streaming fires per chunk
([2.1](../02-the-fourteen-doors/2.1-fourteen-doors-six-you-already-know.md)). It is a development
tool. `DebugLoggingPlugin` writes to a **file**, which is worse under load and is why its name says
debug.

**The failure that only shows with real traffic** is a version bump changing a shipped plugin's
behaviour under you. Your own plugins are pinned by being yours; these are pinned only by
`google-adk==2.7.1`. A minor release that adds a hook to `ContextFilterPlugin` changes what your
application does with no diff in your repository — which is Principle 7's argument for exact pins and
`docs/PACKAGES.md` rows, arriving at the plugin layer.

**The review comment a senior engineer leaves:** *"We wrote a retry plugin. ADK ships one — did we
read it? If its reflect-and-retry strategy is wrong for rate limits, say so in the docstring so the
next person does not re-litigate this."*

**The interview question:** *"Would you write a tracing plugin or use one?"* — "Use ADK's
`AutoTracingPlugin` — tracing is exactly the case where a gap is worse than the whole feature, and
hand-wiring spans across every agent guarantees gaps. I would read the shipped ones before writing any
plugin, actually, for two reasons: half of what I want already exists, and the ones I do not use are
the best available review of the ones I write. Reading `ReflectAndRetryToolPlugin` is how I confirmed
that per-invocation state keyed on `invocation_id` is the expected pattern rather than my own
invention — it does exactly that, with a lock. Where I would not use a shipped one is where the
strategy is subtly wrong for my case: that retry plugin feeds the error back to the model to reflect
on, which is right for a malformed tool argument and useless for a 429."
