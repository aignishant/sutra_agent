# 2.3 — The names moved

## One-line answer

The plugin hooks take the same information as yesterday's agent callbacks under **different parameter
names** — `tool_args` for `args`, `result` for `tool_response` — so a working callback copied into a
plugin class raises a `TypeError` at the first tool call.

---

## The story

You change banks, and you have to fill in the same information again.

At the old bank the form said **Full name**, **Father's name**, **Present address**. At the new one it
says **Applicant name**, **Parent / guardian name**, **Current address**.

It is the same information. You know it perfectly. And you still make a mistake on the second form,
because your hand is filling in the boxes in the order and shape it learned at the first bank, and
this form is not that form.

Nobody is being difficult. Two organisations named their boxes independently, and the cost lands on
the person who knows the answers well enough to stop reading the labels.

---

## The idea in plain language

Yesterday's rule was that **ADK calls your callback by keyword, so the parameter names are an
interface, not a style choice**
([13/1.2](../../../day-13-callbacks-four-doors/parts/01-the-four-doors/1.2-the-names-are-the-contract.md)).
That rule is unchanged at this layer. What changed is some of the names.

| Door | Agent callback takes | Plugin hook takes |
| --- | --- | --- |
| before tool | `tool, args, tool_context` | `tool, tool_args, tool_context` |
| after tool | `tool, args, tool_context, tool_response` | `tool, tool_args, tool_context, result` |
| tool error | `tool, args, tool_context, error` | `tool, tool_args, tool_context, error` |
| before model | `callback_context, llm_request` | `callback_context, llm_request` |
| after model | `callback_context, llm_response` | `callback_context, llm_response` |
| model error | `callback_context, llm_request, error` | `callback_context, llm_request, error` |

The model doors are identical. The tool doors are not: `args` became `tool_args` everywhere, and the
after-tool door's `tool_response` became `result`.

Three more differences that are not names but bite the same way:

**Every plugin hook is `async def`.** Agent callbacks may be either — ADK checks whether the result is
awaitable and awaits it if so. Plugin hooks are always awaited, so a plain `def` fails.

**Every plugin hook is a method**, so it takes `self` first, and `self` is where a plugin keeps the
state that makes it worth being a class at all.

**Every plugin hook is keyword-only.** The `*` in the signature means nothing can be passed
positionally, so there is no way to get lucky by having the arguments in the right order.

Why the names differ at all is worth one honest sentence: an agent's callback is scoped to that agent,
so `args` is unambiguous, while a plugin sees every tool of every agent and the parameter sits next to
`invocation_context` and `callback_context` in a reader's head. `tool_args` says which args. It is a
defensible choice that costs one `TypeError` per person.

---

## Why Sutra needs it

**Because today you move a callback up a layer.** Day 13's `audit_tool_calls` is a working agent
callback with `args` in its signature. The build brief asks you to decide whether it belongs in a
plugin, and if you decide it does, this is the edit — not a copy.

**Because the failure is silent in review and loud at runtime.** The two functions look identical in a
diff. `git diff` shows a plausible move. The `TypeError` arrives the first time a tool is called,
which in a test suite that mocks tools may be never.

**Because Day 39's MCP toolsets multiply the tool doors.** Once tools arrive from an MCP server rather
than from your own module, a plugin at the tool door is auditing functions you did not write, and the
signature you must get right is still this one.

---

## The mechanism

The same guard, written twice, once wrongly.

```python
# lab/moved_names.py - copy a callback into a plugin and it breaks. Zero model calls.
import asyncio

from google.adk.agents import LlmAgent
from google.adk.apps import App
from google.adk.plugins import BasePlugin
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types
from stateless import ReactiveModel


def lookup_ticket(ticket_id: str) -> dict:
    """Look up a support ticket by its id."""
    return {"status": "ok", "ticket_id": ticket_id}


def agent_audit(tool, args, tool_context):
    """Day 13's shape: a plain function, `args`, no self, sync is fine."""
    print(f"      agent callback: {tool.name}({args})")


class CopiedPlugin(BasePlugin):
    """The same body, moved into a class without changing the names."""

    def __init__(self) -> None:
        super().__init__(name="copied")

    async def before_tool_callback(self, *, tool, args, tool_context):
        print(f"      plugin: {tool.name}({args})")


class FixedPlugin(BasePlugin):
    """The same body, with the name this layer actually passes."""

    def __init__(self) -> None:
        super().__init__(name="fixed")

    async def before_tool_callback(self, *, tool, tool_args, tool_context):
        print(f"      plugin: {tool.name}({tool_args})")


async def drive(label: str, plugin: BasePlugin) -> None:
    print(f"  {label}")
    agent = LlmAgent(
        name="desk",
        model=ReactiveModel(model="scripted"),
        instruction="x",
        tools=[lookup_ticket],
        before_tool_callback=agent_audit,
    )
    app = App(name="sutra", root_agent=agent, plugins=[plugin])
    runner = Runner(app=app, session_service=InMemorySessionService())
    session = await runner.session_service.create_session(app_name=app.name, user_id="u")
    try:
        async for _ in runner.run_async(
            user_id="u",
            session_id=session.id,
            new_message=types.Content(role="user", parts=[types.Part(text="hi")]),
        ):
            pass
    except RuntimeError as error:
        print(f"      RuntimeError: {error}")


async def main() -> None:
    await drive("a. the plugin kept `args`", CopiedPlugin())
    await drive("b. the plugin uses `tool_args`", FixedPlugin())


asyncio.run(main())
```

**Line by line:**

- `def agent_audit(tool, args, tool_context)` — deliberately left on the agent in **both** cases, so
  the output shows the two layers side by side and you can see that the agent-level `args` is still
  correct. Only the plugin's copy is wrong.
- `async def before_tool_callback(self, *, tool, args, tool_context)` in `CopiedPlugin` — the bug,
  written out. Everything about this method is right except one identifier.
- `except RuntimeError as error` — the wrapper from
  [1.1](../01-where-a-plugin-lives/1.1-the-rule-nobody-has-to-remember.md). A `TypeError` inside a
  plugin reaches you as a `RuntimeError` naming the plugin, so catching `TypeError` here would catch
  nothing.
- Both cases build a **fresh** agent inside `drive` rather than sharing one, because an `LlmAgent`
  carries its callbacks and reusing the object across two runs would make it unclear which run wired
  what.
- `ReactiveModel` rather than Day 13's counter-based `ScriptedModel`, so the second run starts from
  the top of the script without a reset.

The output:

```text
  a. the plugin kept `args`
      RuntimeError: Error in plugin 'copied' during 'before_tool_callback' callback: CopiedPlugin.before_tool_callback() got an unexpected keyword argument 'tool_args'
  b. the plugin uses `tool_args`
      plugin: lookup_ticket({'ticket_id': '4521'})
      agent callback: lookup_ticket({'ticket_id': '4521'})
```

Read the error message in **a** carefully, because it says the opposite of what you did. You wrote
`args`. The message complains about `tool_args` — the argument ADK *passed*, which your method has no
parameter for. Yesterday's
[13/1.2](../../../day-13-callbacks-four-doors/parts/01-the-four-doors/1.2-the-names-are-the-contract.md)
made the same point at the agent layer: **the error names the keyword the framework sent, not the one
you typed**, so the fix is never in the word the message contains.

Case **b** also shows the ordering from
[13/4.2](../../../day-13-callbacks-four-doors/parts/04-where-the-rule-bites/4.2-the-plugin-goes-first.md)
holding: plugin first, agent callback second.

Verified against the installed `google-adk` 2.7.1 — `PluginManager.run_before_tool_callback` passes
`tool=`, `tool_args=`, `tool_context=`, and `run_after_tool_callback` adds `result=` — and against
`adk.dev/plugins/`, on 2026-08-29.

## When it breaks

**💥 The copied signature.**

```text
RuntimeError: Error in plugin 'copied' during 'before_tool_callback' callback:
CopiedPlugin.before_tool_callback() got an unexpected keyword argument 'tool_args'
```

**💥 The after-tool door, where two names moved at once.**

```text
RuntimeError: Error in plugin 'copied' during 'after_tool_callback' callback:
CopiedPlugin.after_tool_callback() got an unexpected keyword argument 'tool_args'
```

The message names only the **first** unexpected keyword, so fixing `tool_args` and rerunning gets you
the same error about `result`. Two round trips for one copy-paste. Change both before you rerun.

**💥 You dropped the `*`.**

```text
(no error - and no protection)
```

Without the `*` the parameters are positional-or-keyword. ADK still calls by keyword, so it still
works — but the signature no longer documents that positional use is impossible, and the next person
to read it may write a direct call in a test that passes arguments positionally and works by
accident. Keep the `*`.

## In production

**What a professional writes instead of the teaching version** does not maintain two copies of a rule
at two layers. When a rule moves up, it moves — and what stays behind is nothing, not a duplicate. The
shape that survives is a plain function holding the logic, called from whichever layer owns it:

```python
def _audit_line(tool_name: str, arg_names: list[str], invocation_id: str) -> str:
    """The rule. Knows nothing about which layer called it."""
    return f"{invocation_id} {tool_name} args={sorted(arg_names)}"


class AuditPlugin(BasePlugin):
    async def before_tool_callback(self, *, tool, tool_args, tool_context):
        print(_audit_line(tool.name, list(tool_args), tool_context.invocation_id))
```

**Line by line:**

- `_audit_line` takes primitives — a name, a list of keys, an id — and not ADK objects. That is what
  makes it callable from an agent callback, a plugin hook, or a unit test that constructs none of
  them, and it is why moving the rule between layers becomes a three-line change instead of a rewrite.
- `list(tool_args)` passes the **keys** and never the values. Yesterday's
  [13/3.1](../../../day-13-callbacks-four-doors/parts/03-the-tool-doors/3.1-the-chokepoint-restored.md)
  made argument values a security decision, and moving the audit up a layer does not move that
  decision — it widens it, because now it applies to tools you have not seen.
- The hook itself is two lines and holds no logic, so the signature is the only thing that can be
  wrong in it, and the thing that can be wrong is checked by running it once.

**What degrades at scale** is having the same concern in both layers with drifting implementations.
Two audit formats in one log file is worse than one, because the parser you eventually write handles
whichever it saw first.

**The failure that only shows with real traffic** is the plugin whose tool hook is never exercised in
tests. If your test suite drives agents whose tools are stubbed at a level above the tool door, a
signature error at that door has no way to surface until a real tool call happens. That is why
[7.2](../07-in-production/7.2-testing-a-plugin-without-a-model.md)'s suite includes one test that runs
a whole agent with a real tool rather than only calling hooks directly.

**The review comment a senior engineer leaves:** *"This plugin's hook signature is untested. One test
that actually triggers a tool call, or the first `tool_args` typo ships."*

**The interview question:** *"You have a working agent callback and you want it applied to every
agent. What changes?"* — "Four things, and only one of them is the logic. It becomes a method on a
`BasePlugin` subclass, so it takes `self`. It becomes `async def`, because plugin hooks are always
awaited. The parameters become keyword-only. And at the tool doors the names change — `args` becomes
`tool_args`, and on the after-tool door `tool_response` becomes `result`. The logic itself does not
change, which is the argument for keeping it in a plain function that neither layer owns, so moving it
is a call-site edit."
