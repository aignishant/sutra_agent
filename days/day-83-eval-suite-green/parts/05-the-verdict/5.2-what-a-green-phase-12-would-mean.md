# 5.2 — What a green Phase 12 would have meant

## One-line answer

Run exactly the same eight checks, print two sentences instead of their findings, and the gate exits
`0` with every one of those findings still true — which is the whole of how a phase ships green, and
it takes no dishonesty from anybody.

## The story

💥 **The monthly report that goes upstairs.**

🎬 **The scene.** End of the month. Six teams each send a page to a manager, who has to send one page
onwards. The pages have detail in them: what shipped, what did not, the two things that are worrying
somebody. The manager's page has room for six lines.

😬 **The naive fix.** Summarise. Each team gets a line, and a line is a status. Green, green, amber,
green, green, green. It is accurate — nobody has said anything false, and the amber is genuinely the
one that needed flagging.

💥 **Why it fails.** The two worrying things were in the *body* of two of the green pages, from teams
whose overall status really is fine. They were the kind of thing you mention because a person reading
carefully would want to know. There is no field for them on the manager's page, so they do not travel,
and the version that reaches the top of the building is six statuses with no worries attached.

💡 **The insight.** Nobody lied and nothing was suppressed. **The compression had no slot for a
finding**, and a report format decides what can be reported. Every month the same shape holds, and
the top of the building comes to believe there are no worries anywhere, because it has never received
one.

## The idea in plain language

This part is the ablation for the whole day. Turn off the one thing this day is about — the reporting
of findings — and see what is left.

`gate.py --headline` runs all eight criteria, identically, in the same order, with the same exit
codes coming back. The only difference is that each criterion's output is captured instead of printed,
and the gate prints a summary in its place.

Nothing is faked. The evalset still round-trips. The judge's margin is still +0.0%. Three tool calls
still render as zero. Zero result files are still tracked and five ledger rows are still missing. Every
finding in this day remains exactly as true after `--headline` as before it.

The gate exits `0`.

That is the mechanism by which measured systems ship green, and it is worth being precise about who
did what. Nobody wrote a false statement. Nobody deleted a check. Somebody chose an output format —
because eight blocks of output is a lot and a summary is easier to read — and the format had no slot
for a finding.

## Why Sutra needs it

Because this is the fourth time this phase has produced the same shape and the repetition is the
point:

| Day | The report that hides the finding | Exit |
| --- | --- | --- |
| 79 | a suite whose cases cannot fail | `0` |
| 81 | accuracy printed without its baseline | `0` |
| 82 | a nightly that found a regression and reported that it ran | `0` |
| 83 | a gate that reports how many checks ran | `0` |

Four days, four instruments, one failure mode: **the arm that hides the finding is the arm that
exits zero.** A phase about measurement keeps producing it because measurement is where it lives — a
measuring system fails by returning a confident number, not by crashing.

And because the honest verdict from part [5.1](5.1-the-verdict.md) is about to be written into a
ledger, and the alternative needs to have been seen to be resisted.

## The mechanism

The whole difference is one keyword argument:

```python
        results.append((criterion, run(criterion.script, quiet=headline)))
```

**Line by line:**

- `quiet=headline` passes `capture_output=True` down to `subprocess.run`, so the criterion's stdout
  goes into a variable that is never read. The criterion still runs, still computes, still returns
  its exit code.
- The exit codes are still collected into `results`, so the gate has every finding available. It
  simply does not print them.
- One argument. That is the entire distance between the two verdicts, which is the measurement this
  part exists to make.

And then the summary:

```python
    if headline:
        print(f"Phase 12 - evals: {len(CRITERIA)} checks ran, 0 errors.")
        print("The eval suite is in place: evalsets, rubrics, a judge and regression discipline.")
        return 0
```

**Line by line:**

- `{len(CRITERIA)} checks ran` is true. Eight checks ran.
- `0 errors` is true. Not one criterion raised; the four failures are results, not errors, and a
  summary that counts errors is counting the wrong thing precisely because failures are the normal,
  expected output of a working gate.
- The second sentence is true item by item: Day 79 built the evalset, Day 80 the rubric, Day 81 the
  judge, Day 82 the regression discipline. Every clause is a fact.
- `return 0` before the verdict block is ever reached. The verdict is not suppressed; it is not
  computed, because the code path that computes it is after the return.

Run both:

```bash
cd days/day-83-eval-suite-green/lab
uv run python gate.py --headline; echo "exit: $?"
```

**Line by line:**

- Same script, same eight criteria, one flag.

Measured on 2026-09-06:

```text
Phase 12 - evals: 8 checks ran, 0 errors.
The eval suite is in place: evalsets, rubrics, a judge and regression discipline.
exit: 0
```

Two sentences and a zero. Compare that against part [5.1](5.1-the-verdict.md)'s eighteen lines from
the same eight runs.

## When it breaks

It does not break. That is the finding, and it is worth sitting with: there is no error text for this
part because nothing in the `--headline` run is wrong. Every character of that output is accurate.

What is missing is a list, and the list is exactly what part [5.1](5.1-the-verdict.md) prints:

```text
  the rubric judge is shown 0 of 3 recorded tool calls
  the judge's margin over its baseline is +0.0%
  270 requests against an allowance nobody has measured
  0 eval result files are tracked; the history is gitignored
  5 days of this phase have no PROGRESS row; 10 IDs stay open
```

Five findings, each one a sentence, and none of them will fit in a status. A reader of the headline
version would take away *"the eval suite is in place"* and would be right — the suite is in place. It
is also unbelievable in five specific ways, and there is no field on the form for that.

**The version of this that is genuinely dangerous** is not the flag. Nobody would deliberately run
`--headline` on a phase gate. It is the same compression happening by accident, three months from
now, when eight criteria have become twenty, the output is four hundred lines, and somebody
reasonably adds a summary at the end — and then somebody equally reasonably starts reading only the
summary. Neither person has done anything wrong and the report has lost its findings.

## In production

**What a professional does.** Puts the findings in the summary, not below it. A status line reads
`3 pass, 4 fail, 1 unknown` followed by the four names, and the format is designed so that a
finding cannot be dropped without deleting a line somebody has to justify. The rule of thumb is that
the summary must be shorter than the detail and must contain every conclusion — compression is
allowed to remove evidence, never findings.

**What degrades at scale.** The pressure is one-directional and structural. As a system grows, the
number of readers grows faster than the number of investigators, and every reader wants a shorter
report. Nobody ever asks for a longer one. So the format drifts towards the status line on its own,
without a decision, which is why the countermeasure has to be a format rule rather than good
intentions.

**The failure that only shows with real traffic.** The summary becomes the interface. Once a
dashboard, an alert or another team's check reads the summary line, the detail stops being read at
all — and at that point a finding that is not in the summary does not exist in any operational sense.
Day 82 part 3.3 measured this exactly: a regression named in capitals on stdout, and an exit code of
`0`, because the machine-readable channel was the one that did not carry the finding.

**The review comment a senior engineer leaves:** *"The summary is fine, but it has to carry the four
failing criterion names. Right now somebody could delete a check and the headline would not change,
and that is the test of whether a summary is doing its job."*

**The interview question:** *"Your CI dashboard is all green and production is on fire. What went
wrong with the dashboard?"* The answer that shows experience does not say the checks were wrong. It
asks what the green summarises, and whether any check that fails is capable of changing that colour —
because a summary that cannot be made red by a real finding is decoration.
