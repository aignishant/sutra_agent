# 2.1 — Criterion 1: the evalset survives a round trip

## One-line answer

Nine tool calls go into the file and nine come back, so the data the suite runs on is intact — and
the same check reports the one detail that decides criterion 4: what comes back is an
`IntermediateData`, which is a different type from the one some of ADK's own evaluators look for.

## The story

The parcel repacked at the depot.

You hand over a box at the counter. Somewhere between there and the destination it is opened,
scanned, put in a bigger crate with forty others, taken out again, and re-taped. What arrives is your
box, and the person receiving it checks two things before signing: is everything on the packing slip
inside, and is it the shape it went in as.

The first question is the obvious one and it is usually fine. The second one is why the packing slip
also says *fragile, this way up* — because a box can arrive with every item present and still be
useless, if the way it travelled changed something about it that the slip did not record.

## The idea in plain language

An evalset is a file. Day 79 part 2.1 established that: cases written into `<name>.evalset.json`, and
whatever is in that file is what the suite runs against tomorrow.

A file is a round trip. Objects are built in memory, serialised to JSON, and parsed back — and
serialisation is exactly the point where a thing can arrive complete and changed. Criterion 1 checks
both halves of the packing slip:

**Is everything there?** Every tool call written out must come back, in order, with its name. This is
the check that catches a case quietly losing its trajectory, which would turn Day 79's
`tool_trajectory_avg_score` into a metric comparing two empty lists — and two empty lists match, so
the case would pass.

**What shape did it come back as?** ADK's `Invocation` carries its tool calls in a field called
`intermediate_data`, and that field can hold **two different types**: `IntermediateData`, which is a
list of function calls, or `InvocationEvents`, which is a list of events with authors and contents.
Both are valid. They are not interchangeable, and criterion 1 prints which one came back because
part [2.4](2.4-criterion-4-the-rubric-can-see.md) is entirely about a piece of ADK that only reads
one of them.

That is the whole criterion. It is the cheapest one in the gate and it exists because everything
downstream reads the file rather than the objects.

## Why Sutra needs it

Because the reading in part [1.2](../01-reading-the-gate/1.2-what-full-evalset-green-asks.md) says
*evalset* means the file as loaded from disk, not the set as built in memory. Every other criterion
in this gate is a statement about data that has been through this round trip, so if the round trip
loses something, seven criteria are measuring the wrong thing and none of them say so.

And because Day 82's regression discipline compares two runs of the same evalset. A case that loses
its tool calls in serialisation loses them identically on both nights, so the comparison is stable,
green, and about nothing.

## The mechanism

The check counts tool calls on both sides of the file:

```python
def tool_calls(eval_set: EvalSet) -> list[str]:
    """Every tool name in the whole set, in order, however the invocation stores them."""
    names = []
    for eval_case in eval_set.eval_cases:
        for invocation in eval_case.conversation:
            data = invocation.intermediate_data
            names += [call.name for call in getattr(data, "tool_uses", []) or []]
    return names
```

**Line by line:**

- A flat list of names rather than a count, because a count of nine is equal to a different nine. The
  comparison is `written != read_back` on the lists, so a reordering is a failure too.
- `getattr(data, "tool_uses", [])` rather than `data.tool_uses` — `intermediate_data` is optional and
  can be either of the two types, and only one of them has a `tool_uses` attribute. The `getattr` is
  the honest way to write "however this invocation happens to store them"; a plain attribute access
  would raise `AttributeError` on the `InvocationEvents` shape and the criterion would report a crash
  where the truthful answer is a different layout.
- `or []` catches the third case: the attribute exists and is `None`, which is what a case with no
  tool calls looks like.

The round trip itself is three lines:

```python
    path = Path(tempfile.gettempdir()) / f"{EVAL_SET}.evalset.json"
    path.write_text(before.model_dump_json(indent=2), encoding="utf-8")
    after = EvalSet.model_validate_json(path.read_text(encoding="utf-8"))
```

**Line by line:**

- `model_dump_json` and `model_validate_json` are pydantic's, and `EvalSet` is a pydantic model, so
  this is the same code path ADK's own `LocalEvalSetsManager` uses. The criterion is not simulating
  the round trip; it is doing it.
- `tempfile.gettempdir()` rather than the lab directory: the file is evidence for one run and nothing
  reads it afterwards, so it does not belong beside the code. Day 82's `history.py` made the opposite
  choice for the opposite reason — its files are the history and the point was where they land.
- `encoding="utf-8"` on both. On Windows `write_text` defaults to the system code page, and an
  evalset containing a currency symbol or an em dash round-trips through `cp1252` differently from
  how it round-trips through UTF-8. This is the same trap Day 81 part 1.3 hit from the other side,
  where printing a prompt containing `→` raised `UnicodeEncodeError`.

Run it:

```bash
cd days/day-83-eval-suite-green/lab
uv run python c1_roundtrip.py; echo "exit: $?"
```

**Line by line:**

- No arguments: the criterion's normal arm. The fault injection is a flag and part
  [1.1](../01-reading-the-gate/1.1-a-gate-on-the-instruments.md)'s red-alarm test supplies it.

Measured on 2026-09-06:

```text
evalset: desk, 3 cases
desk: as recorded

  written out:  9 tool calls  ['ticket', 'refund_limit', 'request_approval', 'ticket', 'refund', 'open_tickets', 'ticket', 'refund_limit', 'request_approval']
  read back:    9 tool calls  ['ticket', 'refund_limit', 'request_approval', 'ticket', 'refund', 'open_tickets', 'ticket', 'refund_limit', 'request_approval']
  file:         12679 bytes
  the loaded invocation carries intermediate_data as IntermediateData

  every tool call written out came back
exit: 0
```

Nine out, nine back, same order, 12,679 bytes for three conversations. And the fourth line is the one
to remember: **`IntermediateData`**. Note it and carry it two parts forward.

## When it breaks

The interesting failure is not a lost tool call. It is a set that never had any, because then nothing
is lost and the check has nothing to say. That is why the criterion has a second refusal:

```python
    if not read_back:
        print("\n  nothing was lost, because nothing was written: the set exercises no tool call")
        return 1
```

**Line by line:**

- A comparison of two empty lists succeeds, and succeeding is the wrong answer. This is Day 79 part
  2.3's always-green case in its serialisation form: the assertion holds because there is nothing to
  assert about.
- `return 1` rather than a warning. A criterion that cannot distinguish "intact" from "empty" is not
  a criterion.

That branch is what the red-alarm test triggers:

```bash
uv run python c1_roundtrip.py --drop-tools; echo "exit: $?"
```

Measured on 2026-09-06:

```text
  written out:  0 tool calls  []
  read back:    0 tool calls  []
  file:         10269 bytes
  the loaded invocation carries intermediate_data as IntermediateData

  nothing was lost, because nothing was written: the set exercises no tool call
exit: 1
```

The file is 10,269 bytes rather than 12,679, so a fifth of the content is gone, and the equality
check on the two lists is perfectly satisfied. Two and a half thousand bytes of difference, and only
the emptiness test notices.

The failure this criterion does **not** catch has no error text either: a case whose tool calls
survive but whose arguments do not. `tool_calls()` reads `call.name` and never looks at `call.args`,
so a trajectory of the right shape with the wrong ticket id round-trips as intact. Note that this is
a gap in the *criterion*, not in the metric — `TrajectoryEvaluator` does compare arguments, and part
[2.2](2.2-criterion-2-the-suite-goes-red.md) measures it scoring 0.00 on a right-shaped call with the
wrong ticket. Extending the criterion to match is one line and it is left as a `TODO(me)` in the hub.

## In production

**What a professional does.** Treats the serialisation boundary as a test surface, not a detail. Any
system whose test fixtures live in files gets one round-trip test — write, read, compare — and it is
written on the day the file format is chosen rather than after the first case is quietly emptied.
The cost is a few minutes and the alternative is a suite that is green about nothing.

**What degrades at scale.** Bytes. Three conversations are 12,679 bytes; four hundred cases with
per-turn tool arguments are tens of megabytes, and at that size the round trip stops being
instantaneous and somebody proposes a faster format. The check survives a format change unaltered,
which is the argument for having it before the change rather than after.

**The failure that only shows with real traffic.** A schema migration. ADK's `Invocation` gained
`InvocationEvents` as an alternative shape for `intermediate_data`; a file written by an older
version and read by a newer one is exactly the situation where a field arrives complete and shaped
differently, and nothing about it raises. This criterion prints the type for that reason, and part
[2.4](2.4-criterion-4-the-rubric-can-see.md) is what the printed type turns out to mean.

**The review comment a senior engineer leaves:** *"Compare the args too, not just the names. A case
that calls `ticket(4688)` and a case that calls `ticket(4689)` are the same trajectory by this check
and different tests."*

**The interview question:** *"Your test fixtures are JSON. What can go wrong?"* The answer that shows
experience does not say "corruption". It says that a field can be present, valid and a different
shape from the one a consumer expects, and that nothing in a schema-flexible format will tell you.
