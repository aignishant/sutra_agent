# 4.1 — Criterion 7: there is a previous run to compare against

## One-line answer

Day 82 built a correct comparison between two eval runs and this repository is keeping zero of them —
two result files exist on disk, git is tracking neither, and each is caught by a different ignore
rule written for a different good reason.

## The story

*"Was your blood pressure like this last year?"*

A reading is taken, and it is a bit high. Not alarming, just higher than the doctor would like. And
the only question that decides what happens next — is this new, or is this you — cannot be answered,
because the last time it was measured was at a different clinic, on a machine whose printout went
home in somebody's bag and is not in the file.

So the choice is between treating a number that might have been that person's normal for a decade,
and waiting six months to take a second reading and find out. Both are worse than the option that was
available for free at every previous visit: writing it down.

Nobody decided not to keep the old readings. There just was not a place they went.

## The idea in plain language

Day 82 established that a regression is a claim about **two** runs. Its `compare.py` walks both,
classifies every difference into the desk, the judge or the data, and refuses to guess when the
provenance is missing. That code is correct and this criterion asks the question underneath it: is
there a second run?

The answer needs no eval to run. It is two questions to git:

- **How many eval result files does the repository track?** ADK writes an `.evalset_result.json` per
  run through `LocalEvalSetResultsManager`, so the count of tracked files is the count of runs that
  survive the machine that produced them.
- **What does git say about the place they land?** The manager writes into
  `<agents_dir>/<app_name>/.adk/eval_history/`, and Day 82 part 2.2 found that this repository's
  `.gitignore` line 24 is `.adk/` — written on Day 0 because that is also where ADK's session stores
  go, and the repository goes public in Phase 14.

Two correct decisions, made months apart by people solving different problems. ADK chose a sensible
place for its own state; this repository chose, correctly, not to publish its own state. The
composition is a regression suite with no history, and nothing reports it, because a file not being
committed is not an event.

## Why Sutra needs it

Because Phase 12's whole fourth day is a comparison, and a comparison with one operand is not a
weaker comparison — it is not one. Day 82's `compare.py`, `history.py` and the `sutra/regress.py`
build brief are all correct and all currently pointed at an empty room.

And because the fix is smaller than the writing about it: one path in a config, pointed anywhere that
is not `.adk/`, plus the decision to commit that directory. Day 82 part 5.2 put it first on a list of
nine and priced it at half an hour, and the reason it is first is that eight other items assume there
is a yesterday.

## The mechanism

The criterion asks git rather than looking at the filesystem:

```python
    tracked = [line for line in git("ls-files").splitlines() if line.endswith(SUFFIX)]
    on_disk = [p for p in ROOT.rglob(f"*{SUFFIX}") if ".venv" not in p.parts]
```

**Line by line:**

- Two different questions, deliberately. `ls-files` is what the repository *keeps*; `rglob` is what
  happens to be on this machine right now. The gap between them is the whole finding, and either one
  alone tells you nothing — zero tracked files with zero on disk means nothing has run, and zero
  tracked with two on disk means runs are happening and being discarded.
- `".venv" not in p.parts` — the virtual environment contains ADK's own test fixtures, and counting
  those as this repository's eval history would be a nonsense. Filtering on `parts` rather than on
  the string catches it wherever in the path it appears.
- `endswith(SUFFIX)` where `SUFFIX` is `.evalset_result.json`, which is
  `_EVAL_SET_RESULT_FILE_EXTENSION` in `google.adk.evaluation.local_eval_set_results_manager`. It is
  a library constant, so it is read from the library rather than guessed.

And then it asks git what it thinks of the canonical location:

```python
    rule = git("check-ignore", "-v", CANONICAL)
```

**Line by line:**

- `check-ignore -v` prints the exact rule that matched, in the form `<file>:<line>:<pattern>`, or
  nothing at all if the path would be tracked. That is the difference between *"it seems to be
  ignored"* and a citation.
- `CANONICAL` is a path that does not exist. `check-ignore` answers about paths, not about files, so
  the question *"if a result landed here, would we keep it?"* can be asked before anything lands
  there — which is the only time the answer is useful.

Run it:

```bash

```

**Line by line:**

- No flag. This criterion has no fault to inject, because it is already red.

Read the two rule citations, because they are not the same rule. The canonical location is caught by
**line 24**, `.adk/`, which exists to keep session state out of a repository that goes public. The two
files that actually exist are caught by **line 34**, `days/*/lab/`, which exists because the learner's
lab code is theirs and not the curriculum's.

Two files, zero kept, two different correct rules. Neither rule is wrong and neither was written with
eval history in mind.

## When it breaks

The temptation is to fix line 24, and that is the wrong fix. `.adk/` is where ADK puts session stores
— conversation contents, user turns, whatever the desk was told — and Phase 14 makes this repository
public. Relaxing the rule to keep eval results would commit those too, which is Principle 9 traded
away for a convenience.

The right fix moves the results, not the rule:

```python
HISTORY = ROOT / "evals" / "history"
manager = LocalEvalSetResultsManager(agents_dir=str(HISTORY))
```

**Line by line:**

- A path outside `.adk/`, so line 24 stays exactly as written.
- `agents_dir`, not a history directory. The manager appends `<app_name>/.adk/eval_history` itself, so
  results land in `evals/history/sutra/.adk/eval_history/`. That is the library's layout and fighting
  it means not using the library's manager.
- Committing that directory makes `git log` over it the regression history, with authorship and dates
  attached, for nothing.

The failure this criterion cannot see is the one that arrives after the fix: a history that exists and
is **wrong**. Day 82 part 1.3's four provenance fields — the desk's version, the judge's model, the
evalset's hash, the timestamp — are not in ADK's result record, and a directory full of results with
no provenance supports a comparison that cannot attribute anything. The count goes green and the
comparison still says *cannot tell*.

There is no error text for any of this. The whole finding is a `0` in a column that nobody had a
reason to print.

## In production

**What a professional does.** Decides where the history lives on the day the first run happens, not
on the day somebody needs to compare. History that starts accumulating now exists when it is needed;
history that starts on the morning of the incident starts empty, and the incident is the one thing
that cannot wait five nights.

**What degrades at scale.** A committed directory is fine at one file a night and a problem at four
hundred cases with per-invocation results — Day 82 part 5.2 put it at roughly three megabytes a year
for nine cases. That is the point where `EvalSetResultsManager` being an interface earns its keep and
an object store replaces the directory, and the switch is easy only if the path was never hard-coded
in twenty places.

**The failure that only shows with real traffic.** The history is on the runner. A CI job writes its
results into its own workspace, the workspace is destroyed when the job ends, and every night's run
is the first night. Locally everything looks right, because a developer's machine keeps files. This is
the same shape as the `.gitignore` finding with a different mechanism: the results are written
correctly, into a place that does not survive.

**The review comment a senior engineer leaves:** *"Point the results manager at `evals/history/` and
commit it, today. Do not touch line 24. And add the provenance sidecar in the same change, because a
directory of results we cannot attribute is a slower way to reach `cannot tell`."*

**The interview question:** *"You have a regression suite. Where do the results go?"* The answer that
shows experience names a location, says who else can read it, and says how long it is kept — and the
tell is whether the person has ever checked that the location is not inside something the repository
ignores or the runner deletes.
