# 3.2 — Criterion 6: the phase fits a free-tier day

## One-line answer

The judged half of the suite wants 270 requests a night on a lane whose daily allowance nobody has
ever measured, so the criterion exits `2` — neither pass nor fail — and the fifth day in a row that
the same missing number has decided the answer is itself the finding.

## The story

The caterer who asks how many are coming.

A wedding, and the food has to be ordered. The caterer asks the only question that matters and gets
*"a good crowd — everyone will come."* He asks again, differently: how many invitations went out? The
family is not sure; some were phone calls. Two hundred? Three?

He can cook for two hundred and he can cook for three hundred, and either number is a decision he can
act on. What he cannot do is cook for *a good crowd*. And the family is not being difficult — they
genuinely do not know, because nobody counted, and counting was a five-minute job that nobody thought
was a job.

So he quotes for three hundred, and on the day there are a hundred and forty, and the difference is
somebody's money.

## The idea in plain language

Phase 12 built eight checks. Six of them cost nothing — they compare recorded data, read files or
count labels. Two need a model to grade something, and those two are the whole bill.

Day 82's cadence table has the arithmetic, and it is worth reading the multiplication rather than the
total:

| Check | Requests | How |
| --- | --- | --- |
| `rubric_based_multi_turn_trajectory` | 30 | 3 conversations × 5 samples × 2 runs |
| `final_response_match_v2` | 240 | 24 cases × 5 samples × 2 runs |
| | **270** | one nightly run |

The `× 5` is `JudgeModelOptions.num_samples`, whose default is 5 in `google-adk==2.7.1`. The `× 2` is
`AgentEvaluator.evaluate`'s `num_runs`, whose default is 2. Neither is decoration — Day 81 part 4.1
says what each buys — and together they are a factor of ten on top of the case count.

So: 270 requests a night, on `gemini-2.5-flash-lite`.

And then the question the criterion exists to ask: **270 out of how many?**

Nobody knows. Google's rate-limit page does not publish a free-tier table; it says the limits can be
viewed in a signed-in console. The only allowance this repository has ever *observed* is 20 requests
a day on `gemini-2.5-flash`, read off a live 429 on 2026-08-25 and recorded in `docs/PACKAGES.md`.
Flash-Lite is a different lane and its number has been a `TODO(me)` since Day 78's criterion 3.

That is why this criterion has a third exit code. `270 ≤ ?` is not a comparison, and answering it
either way would be inventing the missing operand.

## Why Sutra needs it

Because this is the fifth consecutive day the same missing number has decided an answer. Day 78's
criterion 3 could not be determined for want of it; Day 79 part 4.2 chose Flash-Lite as the workhorse
without it; Day 81 part 4.1 priced a judged suite against it; Day 82 part 5.1 priced a bisection at
9,180 requests against it. Five days, five lists, one measurement, and the measurement is one
controlled burn against a free-tier key.

And because Principle 15 is that zero budget is a feature. A budget denominated in requests per day
only works if the denominator is known, and a repository that has been writing *"unmeasured"* in that
slot for five days has been running on an assumption rather than a budget.

## The mechanism

The allowance is a constant with a deliberate value:

```python
FLASH_LITE_ALLOWANCE: int | None = None
```

**Line by line:**

- `None`, not a guess and not a zero. `0` would be a measurement meaning "nothing is allowed"; a
  guessed integer would propagate into every arithmetic downstream and come back out as a percentage
  with two decimal places. `None` is the only value that cannot be accidentally computed with.
- The type annotation says `int | None`, so the missing case is part of the declared contract rather
  than an accident somebody has to discover.

And the criterion refuses rather than deciding:

```python
    if allowance is None:
        print(f"\n  {NIGHTLY_REQUESTS} requests against an unknown number is not a comparison")
        print("  this criterion cannot be determined, and saying so is the result")
        return 2
```

**Line by line:**

- The `None` check comes **before** the comparison, so there is no code path in which an unknown
  allowance is treated as a number.
- `return 2`, which part [1.1](../01-reading-the-gate/1.1-a-gate-on-the-instruments.md) maps to
  `CANNOT DETERMINE`. A shell can branch on it, a CI job can route it differently from a failure, and
  the gate counts it separately in the verdict.
- The second printed line is doing real work. Without it a reader sees a non-zero exit and concludes
  the suite does not fit, which is a claim nobody has evidence for.

Run it:

```bash
cd days/day-83-eval-suite-green/lab
uv run python c6_fits.py; echo "exit: $?"
```

**Line by line:**

- No flag: the allowance as measured, which is to say not measured.

Measured on 2026-09-06:

```text
the judged half of the suite, per nightly run:

  rubric_based_multi_turn_trajectory       30  3 conversations x 5 samples x 2 runs
  final_response_match_v2                 240  24 cases x 5 samples x 2 runs
                                          270  total

  the lane it runs on: gemini-2.5-flash-lite
  its daily allowance: unmeasured since day 78, five days ago
  the only allowance this repository has observed: 20/day,
  on gemini-2.5-flash, read off a live 429 on 2026-08-25

  270 requests against an unknown number is not a comparison
  this criterion cannot be determined, and saying so is the result
exit: 2
```

Every number on the left of that output is known exactly. The one number that would turn it into an
answer is missing, and it is the cheapest of them to obtain.

## When it breaks

It breaks by somebody supplying the missing number from memory, and the ablation is what that looks
like:

```bash
uv run python c6_fits.py --assume-generous; echo "exit: $?"
```

Measured on 2026-09-06:

```text
  the lane it runs on: gemini-2.5-flash-lite
  its daily allowance: 1500   <- assumed, not measured

  270 of 1500 requests: 18%
  the nightly fits, on an allowance nobody has checked
exit: 0
```

**18%.** A comfortable-looking figure with a percent sign, computed from a number somebody typed
because the free tier felt generous. It exits `0`, so a pipeline is satisfied, and the `<- assumed,
not measured` annotation is the only thing standing between that output and a decision.

The composite failure needs no error text and this repository has the receipt for its first step
already:

```text
1. a number is unknown, so somebody assumes one to unblock the work
2. the assumption is written into a constant and stops being annotated
3. the schedule is built around 18% headroom
4. the real allowance is lower, and the night runs out mid-suite
5. the run reports on the cases it reached                      (day 78, part 3.2)
6. the shrunken run is compared against a full one              (day 82, part 2.3)
```

Step 5 is Day 78's measured finding — a partial run that reports as a full one — and step 6 is Day
82's, a comparison whose two sides are not the same suite. Both were found separately and neither
needs anything to go wrong except an assumed constant.

The one error text that *does* exist here is the refusal that would arrive at step 4, and this
repository recorded it on 2026-08-25:

```text
429 RESOURCE_EXHAUSTED
generativelanguage.googleapis.com/generate_content_free_tier_requests
Please retry in ~53s
```

Day 78 part 1.1 is the branch that reads the quota name and stops rather than sleeping, because a
per-day quota does not refill in fifty-three seconds.

## In production

**What a professional does.** Measures the limit once, deliberately, and records it with a date.
For a free tier that means one controlled burn: a loop of trivial requests on a key doing nothing
else, run until the 429 arrives, with the count and the timestamp written down. It costs one day of
that key's allowance and it converts every downstream capacity question from an argument into
arithmetic.

**What degrades at scale.** Allowances move. Free rosters changed in December 2025, which is why this
repository has a rule against inventing model names, and the same applies to quotas: a number
measured once is a number that starts going stale immediately. The professional version is not one
measurement but a dated row that gets re-measured on a schedule, which is what `docs/PACKAGES.md` is
for.

**The failure that only shows with real traffic.** The allowance is shared. One key, one project, and
the nightly is not the only thing using it — a developer testing locally at eleven at night is
spending from the same bucket the eval suite is about to draw on. Day 78 part 5.1 measured this as
the nightly competing with the day, and it means the useful number is not the allowance but the
allowance minus whatever else lives on that key, which nobody tracks.

**The review comment a senior engineer leaves:** *"This has been unmeasured for five days and it is
blocking five different decisions. Burn a key on Saturday, write the number in PACKAGES.md with the
date, and then we can have the schedule conversation with actual numbers."*

**The interview question:** *"How do you budget for an API you do not control?"* The answer that shows
experience measures the limit rather than reading it, records the date, and — the part most people
miss — reports *cannot determine* rather than guessing when it has not been measured yet.
