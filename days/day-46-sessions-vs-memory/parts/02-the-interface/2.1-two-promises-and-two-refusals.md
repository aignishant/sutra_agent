# 2.1 — Two promises, and two polite refusals

## One-line answer

`BaseMemoryService` makes exactly two things compulsory — `add_session_to_memory` and
`search_memory` — and offers two more, `add_events_to_memory` and `add_memory`, which any
implementation may decline with a `NotImplementedError` that tells you what to call instead.

## The story

You stand at a cash machine on a Sunday.

Whichever machine it is, whichever bank owns it, two things are certain. You can take money out, and
you can see what is left in the account. Those two are not negotiable; a machine that could not do
them would not be a cash machine.

Some machines do more. This one has a slot for depositing cash. That one prints a mini statement.
The one outside the market does neither, and you find that out in the most useful possible way: the
screen says so. It does not take your envelope and lose it. It does not print a blank slip. It says
*this machine does not accept deposits*, and it says it before you have committed anything.

That is the difference between a promise and an offer. The two compulsory things you can plan your
Sunday around. The extras you have to check for — and the machine's job is to make checking cheap by
refusing clearly instead of failing strangely.

## The idea in plain language

An **interface** is a list of methods that anything calling itself a memory service must provide. In
Python that is written as an **abstract base class**: a class whose methods are declared but not
implemented, so that trying to build an object from it directly fails, and so that anyone writing a
real implementation is told exactly what they owe.

`BaseMemoryService` in `google.adk.memory` declares four methods. Two are marked `@abstractmethod`
and two are not, and that distinction is the whole content of this part.

| Method | Status | What it does |
| --- | --- | --- |
| `add_session_to_memory(session)` | **required** | Put a whole finished session into the store. |
| `search_memory(*, app_name, user_id, query)` | **required** | Ask the store a question, get a `SearchMemoryResponse`. |
| `add_events_to_memory(*, app_name, user_id, events, session_id=None, custom_metadata=None)` | optional | Put *some* events in — a delta, not the whole session. |
| `add_memory(*, app_name, user_id, memories, custom_metadata=None)` | optional | Put finished memory items in directly, bypassing events entirely. |

**Required** here has a precise, mechanical meaning: Python refuses to construct a subclass that has
not implemented them. You cannot ship a memory service that forgets to implement `search_memory`,
because the object will not exist.

**Optional** has an equally precise meaning, and it is not "you may leave it out and it will do
nothing". The base class provides a body for each optional method, and that body raises
`NotImplementedError` with a sentence saying what to call instead. Declining is a defined behaviour,
not an accident.

Why have optional methods at all? Because the three implementations that ship with ADK are backed by
genuinely different machinery. Filing a *delta* — "just the last two events, please" — is natural for
a store that appends, and impossible to do usefully for a store whose unit is a whole session.
Writing a finished memory *directly*, with no conversation behind it, makes sense for a managed
service that lets you assert a fact, and makes no sense for a store that only holds events. Rather
than force every implementation to fake both, the interface lets each one say what it actually
supports.

One more term. `SearchMemoryResponse` is what `search_memory` returns. It is a pydantic model with
exactly one field, `memories`, a list of `MemoryEntry`. There is no count, no score, no cursor and no
"did I find everything" flag — [2.3](2.3-what-comes-back-is-not-a-session.md) is that list, opened.

## Why Sutra needs it

Sutra is going to write a class in `sutra/memory/service.py` that wraps a memory service, and
section 4's policy says every retrieval must be capped. A wrapper has to implement the interface it
wraps, which means knowing precisely which methods it owes and which it may pass through.

More importantly, this is where the two Vertex-backed services stop being mysterious. They are parked
under Addendum 02 because they need a billing account —
[6.2](../06-in-production/6.2-the-two-services-we-park.md) is that decision, stated with its reason —
but the reason you can talk about them at all in an interview is that they implement *this* interface
and no other. Anything true of `BaseMemoryService` is true of Memory Bank. Anything the interface
does not promise is a per-implementation surprise, and knowing which is which is the difference
between "I read about it" and "I know what I would get".

## The mechanism

Build the smallest legal memory service, then call all four methods on it.

```python
# days/day-46-sessions-vs-memory/lab/surface.py
class BareMinimum(BaseMemoryService):
    """The smallest thing that is legally a memory service: it implements the two."""

    def __init__(self) -> None:
        self.filed: list[str] = []

    async def add_session_to_memory(self, session) -> None:
        self.filed.append(session.id)

    async def search_memory(self, *, app_name: str, user_id: str, query: str):
        return SearchMemoryResponse()
```

**Line by line:**

- `class BareMinimum(BaseMemoryService)` — inheriting from the abstract base is what makes Python
  check the contract. Drop either method below and constructing this class raises
  `TypeError: Can't instantiate abstract class BareMinimum without an implementation for abstract
  methods 'add_session_to_memory', 'search_memory'`.
- `async def add_session_to_memory(self, session)` — **positional**, not keyword-only. This is the one
  method on the interface whose argument is not keyword-only, and it is worth noticing because the
  other three all are. It takes the `Session` object itself, so an implementation can read
  `session.app_name`, `session.user_id`, `session.id` and `session.events` from it.
- `self.filed.append(session.id)` is the whole implementation. A legal memory service is allowed to
  throw the events away and keep the id; nothing in the interface says otherwise. That is the point
  of [2.2](2.2-the-silence-that-lets-you-swap.md).
- `async def search_memory(self, *, app_name, user_id, query)` — the `*` makes every argument
  keyword-only, and the signature must match, because ADK calls it with keywords from
  `Context.search_memory`.
- `return SearchMemoryResponse()` returns an empty response. The default for `memories` is an empty
  list, so this is a service that files things and finds nothing — legal, useless, and exactly what
  the contract permits.
- There is **no `__init__` on the base class** to call, so `BareMinimum.__init__` does not need
  `super().__init__()`. `BaseMemoryService` is a pure ABC with no state of its own.

Now call all four:

```python
# days/day-46-sessions-vs-memory/lab/surface.py (continued)
    print("BaseMemoryService.__abstractmethods__:")
    print(f"    {sorted(BaseMemoryService.__abstractmethods__)}")
    print("\nevery public method on the interface:")
    for name, _member in inspect.getmembers(BaseMemoryService, inspect.isfunction):
        if name.startswith("_"):
            continue
        required = name in BaseMemoryService.__abstractmethods__
        print(f"    {name:24} {'required' if required else 'optional'}")

    bare = BareMinimum()
    await bare.add_session_to_memory(session)
    result = await bare.search_memory(app_name=APP, user_id=USER, query="cookie")
    for call in (
        bare.add_events_to_memory(app_name=APP, user_id=USER, events=session.events),
        bare.add_memory(app_name=APP, user_id=USER, memories=[]),
    ):
        try:
            await call
        except NotImplementedError as err:
            print(f"    NotImplementedError   -> {err}")
```

**Line by line:**

- `BaseMemoryService.__abstractmethods__` is a `frozenset` Python builds for you from the
  `@abstractmethod` decorators. Reading it is better than reading the source, because it is the same
  data Python itself uses to decide whether your subclass may be constructed. If you ever need to
  know what an ABC demands, ask the class rather than the documentation.
- `inspect.getmembers(BaseMemoryService, inspect.isfunction)` lists the methods. `isfunction` rather
  than `ismethod`, because on the class (as opposed to an instance) they are plain functions.
- `if name.startswith("_"): continue` drops the dunder methods. There is nothing private on this
  interface, so what remains is the four.
- The tuple of two **coroutine objects** is built before the loop, which means both calls are created
  and neither has run — calling an `async def` does not execute it. They run one at a time inside the
  `try`, at the `await`.
- `except NotImplementedError as err` catches the specific exception the base class raises. Not
  `Exception`. The whole value of this design is that the refusal has a type you can catch, and a
  wrapper that wants to fall back from `add_events_to_memory` to `add_session_to_memory` catches
  exactly this.

Read the two `NotImplementedError` messages closely, because they are unusually well written and
they are doing real work. Each one says what is not supported **and what to call instead**. That is
the cash machine telling you it does not take deposits: a refusal you can act on without opening the
source.

And look at the last two lines. `InMemoryMemoryService` **does** implement `add_events_to_memory` —
it appends events, deduplicating on `event.id` — and does **not** implement `add_memory`. So the two
optionals are genuinely independent, and "supports one optional" tells you nothing about the other.

`.../in_memory_memory_service.py`, and against `https://adk.dev/sessions/memory/`, which lists the
same four under *"Ingesting Information"* and *"Searching Information"*. The documentation page does
**not** say which two are abstract; that fact comes from the source.

## When it breaks

Leave out one of the required methods and the failure is loud and early:

```text
Traceback (most recent call last):
  File "...\surface.py", line 41, in <module>
    bare = BareMinimum()
           ^^^^^^^^^^^^^
TypeError: Can't instantiate abstract class BareMinimum without an implementation for abstract method 'search_memory'
```

This is the good failure. It happens at construction, before any request, and it names the method.

The bad failures are the ones the ABC machinery cannot see, because **it checks that a method with
that name exists and checks nothing else**. Two of them, both measured on 2026-09-05.

Rename the parameters — `async def search_memory(self, *, app, user, q)`, which reads perfectly well
— and the class constructs, imports cleanly, and dies at the first call:

```text
TypeError: Renamed.search_memory() got an unexpected keyword argument 'app_name'
```

Write `def` where the base wrote `async def`, and the class again constructs and imports, and the
failure is stranger still:

```text
TypeError: object SearchMemoryResponse can't be used in 'await' expression
```

Nothing in either message says "you implemented the interface wrongly", and both arrive *inside a
tool call* rather than at startup — so the traceback surfaces in the middle of a run, pointing at
ADK's code. If you write a memory service, copy the signature from the base class character for
character, `async` included.

The third break is a `NotImplementedError` that nobody catches. A wrapper that helpfully forwards
`add_events_to_memory` to whatever it wraps will work against `InMemoryMemoryService` and explode
against a service that declines it:

```text
NotImplementedError: This memory service does not support adding event deltas. Call add_session_to_memory(session) to ingest the full session.
```

The message tells you the fix. The point is that the fix belongs in your wrapper, as a `try` that
falls back to filing the whole session, rather than in an assumption that every store appends.

## In production

**What a professional writes instead of the teaching version.** Nobody subclasses `BaseMemoryService`
to return an empty response. What they do write, and often, is a **decorator** — a service that wraps
another one and adds a cross-cutting concern: a cap on results (section 4's rule 2), a log line per
search, a metric, a redaction pass over what is filed. Such a wrapper implements the two required
methods by delegating, and forwards the two optional ones inside a `try/except NotImplementedError`
that falls back to the required path. Writing it any other way makes the wrapper less capable than
the thing it wraps, which is how a "harmless" logging layer silently removes a feature.

**What degrades at scale or under concurrency.** The interface is silent on two things that matter
enormously at scale, and the silence is deliberate: it does not say whether `search_memory` is
bounded, and it does not say whether it is fast. `InMemoryMemoryService` walks every event under the
bucket on every call and returns every match, so both the latency and the response size grow linearly
with the store. A managed service returns a top-k. Code written against the interface must therefore
assume the worst — that a search may return thousands of entries — and cap the result itself. That is
not paranoia; it is
[5.4](../05-failure-lab/5.4-the-store-that-outgrew-its-value.md), measured at 500 filed cases.

**The review comment a senior engineer leaves:** *"Your wrapper forwards `add_memory` straight
through. Two of the three shipped implementations raise `NotImplementedError` for it, so any code
that uses your wrapper works on one backend and breaks on the others, with the failure arriving at
runtime rather than at startup. Either catch it and fall back, or do not expose the method at all."*

**The interview question:** *"What does a memory service interface have to promise?"* An honest
answer: *"Less than people expect, and the gaps are the interesting part. In ADK it is two methods —
put a finished session in, and search — plus two optional ones for writing deltas and writing
memories directly, which an implementation may decline with a typed exception that names the
alternative. What it deliberately does not promise is how matching works, whether results are ranked,
or how many come back. That silence is what lets you swap a keyword store for a vector store without
touching the agent, and it is also what makes writing against the interface dangerous if you assume
the results are few and good. I cap the result count in my own wrapper for exactly that reason."*
