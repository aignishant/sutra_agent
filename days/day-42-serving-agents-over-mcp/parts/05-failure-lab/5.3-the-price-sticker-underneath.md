# 5.3 — The price sticker underneath

## One-line answer

A 429 raised inside a served agent escapes as `str(exception)` in a text block, so the caller's model
reads five hundred characters of your provider's internal quota body — your tier, your metric, your
project's ceiling — as the answer to a support question.

## The story

You buy a kitchen scale and there is a price sticker on the box. When you get home you peel it off,
because it is right where you want to put the label with the date, and underneath there is another
sticker.

The one underneath is not for you. It has a different number on it, a much smaller one, and a code
that means something to somebody in a warehouse. Nobody chose to show it to you. Nobody chose to hide
it either — the first sticker was simply put on top of the second, and stickers come off.

You have not been given a secret, exactly. But you have learned a thing about the shop that the shop
would not have told you if asked, and you did not have to do anything clever to learn it. It was on
the box the whole time, one layer down.

## The idea in plain language

Day 34's
[4.3](../../../day-34-building-sutra-mcp-tools/parts/04-two-kinds-of-no/4.3-the-message-that-escaped.md)
established the mechanism, and it is one line of the MCP SDK:

```text
raise ToolError(f"Error executing tool {self.name}: {e}") from e
```

Every exception that escapes a tool body has its `str()` put into a text block and sent to the
caller. Not to a log. To the caller, and therefore into a model's context, and therefore into a
transcript somebody may keep.

That was already a problem when the tool was a database read and the exception was a
`FileNotFoundError` carrying a path. It is a bigger problem when the tool is a model loop, because
the exceptions a model loop raises are **provider exceptions**, and a provider's exception message is
written for the provider's own engineers. It contains whatever the provider found useful to put in
it, and nobody at your company chose any of it.

The specific one you will meet is the 429. Addendum 02 makes handling it mandatory on every model
path in this repository, and this part is why: on a served endpoint, an unhandled 429 is not just a
failure, it is a disclosure.

## Why Sutra needs it

Because [4.2](../04-what-a-call-costs/4.2-the-family-data-pack.md) established that Sutra's served
endpoint runs out of quota after six calls, so this is not an edge case — **on a busy day it is the
majority of responses**.

And because the day's whole security posture, from
[3.3](../03-tool-or-peer/3.3-the-guillotine-and-the-press.md), is that a stranger sending one string
learns nothing about Sutra's insides. Serving a read-only agent achieves that for the *tools*. The
error path throws it away for free, at the exact moment you are least likely to be watching.

## The mechanism

`lab/throttled.py` injects the refusal so the caller's view of it can be read exactly. No model is
called; the body is the real one Day 2 recorded off a live free-tier refusal:

```python
class Throttled(Exception):
    """A quota refusal, carrying the delay the provider asked for."""

    def __init__(self, body: str, retry_after: int) -> None:
        super().__init__(body)
        self.retry_after = retry_after


class Desk(BaseAgent):
    """A desk agent whose first model call is refused for quota."""

    guarded: bool = False
    attempts: int = 0

    def _ask_model(self) -> str:
        """Stand-in for one generation. Refused the first time, fine the second."""
        self.attempts += 1
        if self.attempts == 1:
            raise Throttled(QUOTA_BODY, RETRY_AFTER_SECONDS)
        return "KB-104 explains the logout loop."

    async def _run_async_impl(self, ctx: InvocationContext) -> AsyncGenerator[Event, None]:
        if not self.guarded:
            answer = self._ask_model()
        else:
            try:
                answer = self._ask_model()
            except Throttled as exc:
                await asyncio.sleep(exc.retry_after * LAB_SCALE)
                print(f"  server log: quota refusal, waited {exc.retry_after}s, retrying once")
                try:
                    answer = self._ask_model()
                except Throttled:
                    answer = "The desk is out of capacity right now. Retry after 47 seconds."
        yield Event(
            author=self.name,
            invocation_id=ctx.invocation_id,
            content=types.Content(role="model", parts=[types.Part(text=answer)]),
        )
```

**Line by line:**

- `Throttled` carries `retry_after` as an **attribute**, not only inside the message text. That is
  the difference between an error you can act on and an error you can only print: the guarded arm
  reads `exc.retry_after` rather than trying to parse `47s` back out of a string.
- `RETRY_AFTER_SECONDS = 47` and `LAB_SCALE = 0.01` are separate constants so the lab finishes while
  the *number that matters* stays the one the provider sent. Scaling the wait is a lab convenience;
  inventing the wait would be a lie.
- `if self.attempts == 1:` makes the first call fail and the second succeed, which is the realistic
  shape of a per-minute limit clearing. Day 24's
  [2.1](../../../day-24-token-accounting-and-budgets/parts/02-two-ceilings/2.1-two-ceilings-one-clears.md)
  is the distinction: the per-minute ceiling clears on its own, the per-day one does not, and the
  guarded arm's fallback sentence is what you say when it was the second kind.
- The unguarded branch is `answer = self._ask_model()` with **no `try` at all**, which is not a straw
  man — it is what you write when you have not thought about it, and it is what
  `to_mcp_server(build_desk())` gives you if the agent underneath has no retry policy.
- `await asyncio.sleep(exc.retry_after * LAB_SCALE)` honours the delay **the provider named** rather
  than a constant somebody guessed. This is Addendum 02's rule in one line: read `retry-after`, wait
  that long, then escalate.
- The retry is **once**, not a loop. A loop against a daily ceiling is a loop that never succeeds and
  spends the caller's patience; the second failure escalates to a sentence instead.
- The fallback answer is a sentence written for a model: it names the condition and gives the retry
  boundary. Day 34's
  [4.1](../../../day-34-building-sutra-mcp-tools/parts/04-two-kinds-of-no/4.1-the-tool-said-no.md) is
  the shape, and note that it comes back with `isError: false`, because the tool did answer — it
  answered *"not now"*.

## When it breaks

Unguarded. Measured on 2026-09-05:

```text
arm: unguarded (the exception escapes)
isError : True
caller sees (543 characters):
  Error executing tool sutra_desk: 429 RESOURCE_EXHAUSTED. {'error': {'code': 429, 'message': 'You exceeded your current quota, please check your plan and billing details.', 'status': 'RESOURCE_EXHAUSTED', 'details': [{'@type': 'type.googleapis.com/google.rpc.QuotaFailure', 'violations': [{'quotaMetric': 'generativelanguage.googleapis.com/generate_content_free_tier_requests', 'quotaId': 'GenerateRequestsPerMinutePerProjectPerModel-FreeTier', 'quotaValue': '5'}]}, {'@type': 'type.googleapis.com/google.rpc.RetryInfo', 'retryDelay': '47s'}]}}
```

Read what a stranger now knows about you:

| From the body | What it tells them |
| --- | --- |
| `generativelanguage.googleapis.com` | which provider you are on |
| `generate_content_free_tier_requests` | that you are on the **free tier** |
| `GenerateRequestsPerMinutePerProjectPerModel-FreeTier` | your quota is per project, per model, per minute |
| `quotaValue: '5'` | the actual ceiling |
| `check your plan and billing details` | a sentence addressed to you, delivered to them |

None of that is a credential and all of it is reconnaissance. It tells somebody deciding whether to
depend on your service that you are on a hobby tier, and it tells somebody less friendly exactly how
many requests it takes to keep you refused.

It is also **useless to the caller's model**. Five hundred and forty-three characters of nested JSON
in a text block, from which the model has to extract one actionable fact, and the fact it is most
likely to extract is *"an error, try again"* — which is the worst possible response.

Guarded, one flag, same agent:

```text
arm: --guarded
  server log: quota refusal, waited 47s, retrying once
isError : False
caller sees (32 characters):
  KB-104 explains the logout loop.
```

Five hundred and forty-three characters against thirty-two. `isError: True` against `False`. And the
line beginning `server log:` is the operator getting *more* than they did before — the refusal, the
delay honoured, and the retry — while the caller gets less. That asymmetry is the whole design: Day
34's [4.3](../../../day-34-building-sutra-mcp-tools/parts/04-two-kinds-of-no/4.3-the-message-that-escaped.md)
called it logging for the operator and answering for the model, and this is that rule applied to the
one exception a served agent raises most.

## In production

**What a professional writes instead:** every model call path in the served agent is wrapped, and the
wrapper does four things in order — log the exception with a traceback and a correlation id, honour
`retry-after` once, escalate to a written sentence, and **never let the provider's text out**. The
last one is best enforced as a check rather than a convention: a test that calls the served tool with
the model stubbed to raise, and asserts that the reply contains none of a list of forbidden
substrings. Day 34's build brief asked you to write that `FORBIDDEN` list; this is the day it gains
`googleapis.com`, `quotaMetric` and `billing`.

**What degrades at scale:** the frequency. At six calls a day the quota body escapes on call seven,
once. As traffic grows it escapes on most calls, which means most of your served responses are
carrying your infrastructure details, and they are being written into other organisations' transcript
stores where you cannot delete them.

**The failure mode that only appears with real traffic:** the *other* provider errors. You will guard
the 429 because you were told to. The 500, the model-overloaded error, the safety-filter refusal and
the malformed-response error all take the same path and none of them is on your list. The right guard
is a wrapper around every model call that catches broadly, logs fully and reveals nothing — not a
`except Throttled` for the one you thought of.

**The review comment a senior engineer leaves:** *"the quota body escapes to the caller. That is our
provider, our tier, our quota metric and our ceiling, in a text block that goes into another
company's model context. Wrap the model call, honour the retry delay once, and return a written
sentence. And add the assertion — `googleapis.com` must never appear in a served response — because
this will regress the first time somebody adds a second model call."*

**The interview question:** *"what does a caller see when your served agent runs out of quota?"* The
honest answer: *"By default, five hundred and forty-three characters of the provider's raw
`RESOURCE_EXHAUSTED` body, because the MCP SDK puts `str(exception)` from a tool body into a text
block and hands it to the caller's model. That leaks the provider, the tier, the quota metric and the
ceiling, and it tells the caller to check their billing details, which they do not have. What I ship
instead is a wrapper on every model call: log the traceback for us with a correlation id, honour the
`retry-after` the provider sent, retry once, and then return a sentence written for a model saying we
are at capacity and when that clears — with `isError` false, because the tool did answer. And a test
asserting the provider's domain never appears in a response, since the next person to add a model
call will not have read this."*
