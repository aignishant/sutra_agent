# 3.2 — The guard ADK already shipped

## One-line answer

Before your plugin sees anything, `ComputerUseToolset` has already wrapped `navigate` in a check that
refuses any URL whose host is not publicly routable — and that check is **on by default**, because an
agent that can be talked into navigating can be talked into fetching your cloud metadata endpoint or
an admin panel on `localhost`.

## The story

There is a goods lift at the back of an office building, the one with the scuffed steel walls that
everybody uses for moving furniture.

You wheel a trolley in, press the button for the fourth floor, and nothing happens. The doors stay
open. Somewhere near the ceiling a small buzzer sounds twice and then stops.

Nobody told you the lift weighs itself. There is no notice about it. The people who installed it
fitted a sensor under the floor and set a number, years ago, and every load since then has been
weighed whether anyone thought about it or not. You take two boxes off the trolley, press again, and
it goes up.

Now think about the person waiting on the fourth floor. They pressed the call button, and the lift
did not come, and then it did. Nothing told them anything was refused. From up there it was a slow
lift.

## The idea in plain language

[3.1](3.1-the-check-outside-every-tool.md) built a door and put it outside every tool. This part is
about a second door that was already there, fitted by the framework, which you did not install and
cannot see from your own code.

The thing it guards against has a name. **Server-side request forgery**, usually written **SSRF**, is
what you have when something on the outside can choose an address that something on the inside then
fetches. The attacker never reaches the private network. They persuade a machine that is already
inside it to make the request for them and hand back the answer.

An agent with a browser is an unusually good SSRF machine, for three reasons that stack:

- The address is chosen from text. `navigate(url=...)` takes whatever URL ends up in the model's
  argument, and Day 66 spent a day on how instructions arrive inside content the model reads.
- The browser is inside your network. It runs where you run it — a container in your cluster, a VM
  in your cloud account, a laptop on the office network — and everything reachable from there is
  reachable from it.
- The interesting targets need no credentials, because they were never meant to be reachable. A
  cloud instance metadata service answers plain HTTP with no authentication at all, on the theory
  that only code running on the instance can reach it. An internal admin panel on `localhost:9000`
  is unauthenticated for the same reason: it is behind a network boundary, so nobody added a login.

So the class of address matters. **Publicly routable** means an address the ordinary internet can
reach. Its complement is the set of addresses that only mean something from where you are standing —
`127.0.0.1` and the rest of loopback, the private ranges like `10.x` and `192.168.x`, and the
**link-local** range `169.254.0.0/16`, which is where the major clouds put their instance metadata
service. ADK's rule is that class: `navigate` refuses anything that is not publicly routable, unless
you have said otherwise.

Two things about that rule are worth stating before the code, because they are what make it a
*default* rather than a *feature*:

1. It is on when you do nothing. `allow_private_network_access: bool = False` is the constructor's
   default value, so a developer who has never heard of SSRF still gets the guard.
2. It broke this lab. The fixture in [2.3](../02-driving-it/2.3-a-site-you-own.md) is served on
   `127.0.0.1:8771`, which is loopback, which is not publicly routable — so every script in this day
   that drives the fixture has to opt out of ADK's guard to work at all. That is not a complaint. A
   default that never inconveniences anybody is a default that was set to the convenient answer.

## Why Sutra needs it

Because the sandbox this day is building is not the only thing standing between the agent and the
network, and a control you do not know about is a control you cannot reason about. Two failures come
from not reading this wrapper:

The first is believing your own plugin is the whole boundary. It is not — and
[3.3](3.3-all-or-nothing.md) shows the two doors catching different things, which is the difference
between two controls and one control written twice.

The second is worse and more common: turning the guard off without noticing, because a tutorial you
copied had `allow_private_network_access=True` in it. Every script in this day's lab carries that
flag, with a comment saying why — `surface.py`'s says the sandbox sections are about *"what that flag
is protecting you from everywhere else."* A reader who copies the line without the comment has taken
a lab's convenience into a production service.

Later days inherit this. When the desk grows a browser worker on a real host, the host has a metadata
endpoint, and the question *"is `allow_private_network_access` set, and who set it"* becomes a
deployment question rather than a lab one. [3.3](3.3-all-or-nothing.md) is where that gets measured.

## The mechanism

Everything below is quoted verbatim from
`.venv/Lib/site-packages/google/adk/tools/computer_use/computer_use_toolset.py` in the installed
**`google-adk==2.7.1`**, read on 2026-09-06. It is ADK's code, in ADK's formatting, not retyped — the
version matters because this is an `@experimental(FeatureName.COMPUTER_USE)` toolset and an
experimental surface is one that moves.

Start with the constructor, because the default is the argument:

> Quoted verbatim from the installed `google-adk==2.7.1`. The two-space indentation is that
> project's own style, so the block is tagged `text` rather than `python` to keep it exact.

```text
  def __init__(
      self,
      *,
      computer: BaseComputer,
      excluded_predefined_functions: Optional[list[str]] = None,
      allow_private_network_access: bool = False,
  ):
    """Initializes the ComputerUseToolset.

    Args:
      computer: The computer environment to expose as tools.
      excluded_predefined_functions: Names of BaseComputer methods that should
        not be exposed as tools.
      allow_private_network_access: By default `navigate` refuses urls whose
        host is not publicly routable. Set this to True when the agent is
        meant to drive the browser against localhost or an internal host.
    """
```

**Line by line:**

- `*` makes every parameter keyword-only, so `ComputerUseToolset(computer, True)` will not even
  parse. A boolean this consequential cannot be passed positionally by accident.
- `allow_private_network_access: bool = False` is the whole story of this part in one line. The
  guard is not something you enable. It is something you would have to disable.
- The docstring names the two legitimate reasons to disable it — *localhost or an internal host* —
  and both are exactly this lab's situation. Read it as a permission slip with a narrow scope, and
  then read [3.3](3.3-all-or-nothing.md), which is about what else the slip covers.
- `excluded_predefined_functions` sits right beside it and is a different control on the same
  surface: it removes actions from the toolset entirely, so the model never sees them. Refusing an
  action and never declaring it are not the same thing, and
  [Day 68's 3.1](../../../day-68-least-privilege-tools/parts/03-absent-not-forbidden/3.1-deny-by-default-at-the-toolset.md)
  is the part that argues for the second.

Here is the message the refusal carries, defined at module level:

> Quoted verbatim from the installed `google-adk==2.7.1`. The two-space indentation is that
> project's own style, so the block is tagged `text` rather than `python` to keep it exact.

```text
_URL_REFUSED_ERROR = (
    "navigate refused: url must be http(s) and must not target a private or"
    " link-local address."
)
```

**Line by line:**

- One constant, used at one place, so the string the model receives is the same string every time —
  which is what makes it greppable in a log six weeks later.
- Read what it actually says. Two conditions: the scheme must be `http` or `https`, and the target
  must not be private or link-local. That is the whole policy, and *link-local* is in the sentence
  because `169.254.169.254` is link-local and is the single most valuable address on a cloud
  instance.
- The leading underscore says this is ADK's, not yours. Do not match on it in your own code; it can
  change without a deprecation.

And here is the guard:

> Quoted verbatim from the installed `google-adk==2.7.1`. The two-space indentation is that
> project's own style, so the block is tagged `text` rather than `python` to keep it exact.

```text
  def _wrap_navigate_with_url_validation(
      self, navigate_method: Callable[..., Any]
  ) -> Callable[..., Any]:
    """Checks a model-supplied url before `navigate` hands it to the browser."""

    @functools.wraps(navigate_method)
    async def wrapper(url: str) -> Any:
      # Deferred to keep `requests` off the computer-use import path.
      from ..load_web_page import _is_blocked_hostname
      from ..load_web_page import _parse_request_target
      from ..load_web_page import _resolve_direct_addresses

      try:
        if not isinstance(url, str):
          raise ValueError("url is not a string")
        target = _parse_request_target(url)
        # A browser ends the authority at "\" but urlparse does not: in
        # `http://169.254.169.254\@example.com/` the host is example.com here
        # and 169.254.169.254 in Chrome, so refuse instead of checking it.
        if "\\" in target.parsed_url.netloc:
          raise ValueError("backslash in hostname")
        if not self._allow_private_network_access:
          if _is_blocked_hostname(target.hostname):
            raise ValueError("hostname is blocked")
          # getaddrinfo blocks, so keep it off the event loop.
          await asyncio.to_thread(_resolve_direct_addresses, target.hostname)
      except ValueError:
        logger.warning("Refusing navigate(): url failed safety validation.")
        # The computer-use model rejects a function response with no url,
        # so report the page the browser is currently on.
        state: ComputerState = await self._computer.current_state()
        return {"error": _URL_REFUSED_ERROR, "url": state.url}
      return await navigate_method(url)

    return wrapper
```

**Line by line:**

- The whole thing is a **wrapper**: a function that takes your `navigate` and returns a new function
  which does the checking and then calls yours. The toolset applies it while building the tool list,
  so `SiteComputer.navigate` — the method in `lab/_computer.py` — is never what the model calls
  directly.
  This is the same structural argument as
  [3.1](3.1-the-check-outside-every-tool.md), made by the framework: the check is *outside* the
  method it guards, so the method needs no security code in it.
- `@functools.wraps(navigate_method)` copies the wrapped function's name, docstring and signature
  onto the wrapper. That is not cosmetic here: ADK builds the tool declaration the model sees from
  that signature, so without this line the model would be offered a tool called `wrapper`.
- `if not isinstance(url, str)` is the first check and it looks paranoid. It is not. The argument
  came from a model, through JSON, and a model that emits `{"url": ["http://…"]}` is a model that
  would otherwise reach `urlparse` with a list.
- The backslash check is the sharpest line in the file, and it is worth reading twice. Two parsers
  disagree about where the hostname ends in `http://169.254.169.254\@example.com/`: Python's
  `urlparse` treats the whole `169.254.169.254\@example.com` as the authority and reports the host as
  `example.com` — which is public and passes every check below — while Chrome ends the authority at
  the backslash and connects to `169.254.169.254`. So the string that a validator approves and the
  string that a browser fetches describe **different machines**. The response is not to teach the
  validator Chrome's rule. It is to refuse the URL, because the class of bug is *two parsers
  disagreeing*, and matching one more parser's quirk today does nothing about the next quirk. Refuse
  what is ambiguous; do not adjudicate it.
- `if not self._allow_private_network_access:` is the opt-out, and notice what it does **not** cover:
  the scheme check and the backslash check run either way. Turning the flag on relaxes the address
  class and nothing else.
- `_is_blocked_hostname(target.hostname)` is the cheap, textual half — in this version it rejects the
  name `localhost` and anything ending in `.localhost`, with no network involved.
- `await asyncio.to_thread(_resolve_direct_addresses, target.hostname)` is the expensive, honest
  half, and it is the reason this guard is worth more than a regular expression over the URL. It
  **resolves the name** and vets every address that comes back, raising if any is not globally
  routable. A textual check sees `internal-tools.example.com` and shrugs; this one sees the `10.0.0.7`
  behind it and refuses. That is the defence against a hostname deliberately pointed at a private
  address — the family of attacks around **DNS rebinding**, where an attacker controls a name and can
  make it answer with whatever address suits them.
- `asyncio.to_thread` is there because `getaddrinfo` is a blocking C call. Calling it directly on the
  event loop would stall every other coroutine in the process for the duration of a DNS lookup, which
  in the bad case is a timeout.
- `except ValueError:` catches all four raises above, plus the ones raised inside the helpers. Every
  refusal path arrives at one place, which is why every refusal produces one identical message.
- `logger.warning(...)` — **the guard reports by logging.** It does not raise into your code. Nothing
  in your call stack observes it. Come back to this in *When it breaks*.
- The dictionary is returned to the **model**, not to you, and it carries the current page's URL
  alongside the error because a computer-use model rejects a function response with no URL in it. So
  the model learns it was refused, and your code learns nothing.

Run the day's fixture with the guard left exactly as it ships:

```bash
uv run python days/day-71-computer-use-and-the-sandbox/lab/guard.py 2>/dev/null
```

**Line by line:**

- No flag, so `guard.py` constructs `ComputerUseToolset(computer=computer, allow_private_network_access=False)` —
  the shipped default, spelled out rather than omitted, so the measurement names what it measured.
- The script asks for three navigations, one after another, and none of them is blocked by anything
  this day wrote. There is no plugin registered in this run at all.
- `guard.py` attaches a logging handler to
  `google_adk.google.adk.tools.computer_use.computer_use_toolset` before it starts, because — as the
  walkthrough above found — a refusal here is a log line and nothing else. Without that handler the
  run would print three refusals and no reason for any of them.

Measured on 2026-09-06:

```text
allow_private_network_access = False   (the default)
the model asked to navigate to 3 urls

  refused   the lab's fixture            http://127.0.0.1:8771/status.html
  refused   cloud metadata               http://169.254.169.254/latest/meta-data/
  refused   an admin panel on localhost  http://127.0.0.1:9000/admin

  navigations that reached the browser  0 of 3

  what ADK logged:
    Refusing navigate(): url failed safety validation.
    Refusing navigate(): url failed safety validation.
    Refusing navigate(): url failed safety validation.
```

**Zero of three.** Chromium was started, the page was open, the model asked three times, and the
browser was never handed a URL. The count is taken from the `Trace` in `_computer.py`, which
`SiteComputer.navigate` writes to — and `SiteComputer.navigate` did not run, so there is nothing in
it. The refusal happened one layer above your computer object.

Three identical log lines are the only evidence in the process that anything was stopped.

## When it breaks

The failure is not that the guard is wrong. It is that **the guard is quiet**, and quiet is
indistinguishable from absent unless you go looking.

Here is the entire record the run above left behind, copied from its own output:

```text
    Refusing navigate(): url failed safety validation.
```

That line is written at `WARNING` on the logger
`google_adk.google.adk.tools.computer_use.computer_use_toolset`, and it appeared in the measurement
only because `guard.py` attached a handler to that logger on purpose. It does not name the URL, the
tool, the agent or the run. The model, separately, receives the dictionary the wrapper returns —
`_URL_REFUSED_ERROR` under `"error"`, and the page the browser is currently on under `"url"`.

Now count what a normal application sees. No exception is raised, so a `try/except` around the run
catches nothing. The run does not fail, so a health check stays green. The tool returns a value, so
the agent loop continues normally — and what it continues with is a model that has been told the
navigation failed and will now say something reasonable about it, like *"I wasn't able to open the
status page."* That sentence reaches your user. Nothing in it says a security control fired.

Two consequences follow, and they point in opposite directions:

- **A legitimate failure looks like a bug in your code.** This is what happened in this lab. The
  fixture on `127.0.0.1:8771` is refused by the default, the agent says it could not open the page,
  and an afternoon goes into checking whether the server was running.
- **A genuine attack looks like nothing at all.** A model that has been talked into fetching
  `169.254.169.254` is refused, the log line is written at `WARNING` into a stream nobody reads, and
  the only place the event exists is a string in a container's stdout with a retention of a day.

The smallest fix for the first is to set `allow_private_network_access=True` deliberately, at the one
construction site, with a comment — which is what every script in this lab does. The fix for the
second is not a fix to ADK. It is [3.4](3.4-what-a-refusal-leaves-behind.md): your own door records
its refusals as events, in a structure you can count, and the framework's refusals are pulled out of
the log and counted beside them.

## In production

**Why a default-closed guard is right even though it broke this lab.** The rule for choosing a
default is not *what does the common case want*, it is *which mistake is recoverable*. Get this
default wrong in the closed direction and a developer loses an afternoon to a page that will not
load, then finds a flag whose docstring explains exactly what to do. Get it wrong in the open
direction and a service ships with an agent that will fetch anything on its own network on request,
nobody notices, and the discovery event is an incident rather than a debugging session. One of those
costs an afternoon and the other costs credentials. A framework serving thousands of applications
also has to weigh who is affected: the people helped by a permissive default are the ones driving
localhost, who are almost always developers on their own machine and can read a docstring, while the
people harmed are the ones who never thought about SSRF, who are exactly the ones who cannot fix it
after the fact. This is [Day 68's 3.1](../../../day-68-least-privilege-tools/parts/03-absent-not-forbidden/3.1-deny-by-default-at-the-toolset.md)'s
deny-by-default argument arriving from the framework's side rather than yours, and it is the same
reason `gate.py` counts a check that cannot run as a **failure** rather than as skipped.

**What a professional does with a framework control like this.** They write it down. A control you
inherited is a control that can be removed by an upgrade, a refactor, or a copied line, and the only
defence is that somebody wrote down that it exists and what it covers.
[Day 66's 7.3](../../../day-66-injection-threat-model/parts/07-writing-it-down/7.3-accept-mitigate-refuse.md)'s
threat model gets a row: *SSRF via `navigate` — mitigated by `ComputerUseToolset`'s default address
check, and by our own origin allowlist; the framework's half is disabled in the browser worker
because it drives an internal host.* Then the flag's value is asserted in a test, so that a change to
it is a failing test rather than a diff nobody reads.

**What degrades at scale.** The address check costs a DNS resolution per navigation, on a thread, on
every URL the agent visits. On one fixture that is free. On a fleet doing thousands of navigations a
minute it is a real dependency on your resolver: when DNS is slow, navigation is slow, and when DNS
fails, `_resolve_direct_addresses` raises `ValueError` and the guard refuses — which is the correct
direction to fail and will still look like an outage. It also means the check and the browser resolve
the name **separately**, a few milliseconds apart, and an attacker who controls the name can answer
differently each time. That gap is inherent to checking a name and then handing it to something else
that resolves it again; closing it means resolving once and connecting to the address, which a
browser will not let you do.

**The review comment a senior engineer leaves:** *"You've set `allow_private_network_access=True` in
three files. That's ADK's SSRF guard and it is off in all three. I'm fine with it in the lab — you're
driving 127.0.0.1 — but say so in a comment at every site, and in the worker add a test asserting the
flag's value so nobody flips it back by accident. And put the framework's refusals in your metrics:
right now they're a `logger.warning` in a library namespace, so if that guard starts firing in
production the first person to know will be whoever happens to grep the logs."*

**The interview question:** *"Your agent can browse. What stops it hitting your internal network?"*
An answer that has read the code: *"Two things, and I'd want both. The framework's own guard comes
first — ADK wraps `navigate` and refuses any URL whose host isn't publicly routable, and it's
default-on, so `allow_private_network_access=False` unless you deliberately change it. It doesn't
just pattern-match the string either: it resolves the hostname and vets the addresses, which is what
catches a public-looking name pointed at 10.x or at the metadata endpoint. There's a nice detail in
there — it refuses any URL with a backslash in the authority, because `urlparse` and Chrome disagree
about where the host ends, and rather than teach the validator Chrome's parsing they refuse the
ambiguous input. I measured the default against three targets and got zero of three through,
including our own fixture on loopback, which is why every script in the lab opts out with a comment.
The thing I'd flag is that the guard reports by logging a warning and returning an error dict to the
model — it never raises — so if you're only watching for exceptions you'll never know it fired, and
your own layer has to record the refusal as an event."*
