# 3.2 — The zero-budget lint

## One-line answer

Two of the four config checks exist only because this repository has a spending rule, and encoding a
policy as a lint is what turns "we only use free models" from a thing everybody remembers into a
thing the build refuses to break.

## The story

The canteen card with a daily cap.

A school gives every child a card for the canteen and puts a limit on it — a fixed amount a day, no
more. The child can spend it on anything on the counter.

What the cap replaces is a conversation. Without it, the rule is "don't spend too much", which
requires the child to know what too much is, to remember it at the counter, and to apply it while
hungry and in a queue. With it, the rule is enforced by the till, at the moment of spending, by
something that does not get tired.

Nobody thinks the cap means the child is untrustworthy. It means the rule has been moved from
somebody's memory into the machine that could actually enforce it, which is where rules belong when
they matter.

## The idea in plain language

Addendum 02 is this repository's spending rule, and it is unusually specific: only free-tier
models — Gemini Flash-class, Groq, OpenRouter strings ending in `:free`, or local Ollama — and never
code that requires a billing account.

A rule like that is followed perfectly for about three weeks. Then somebody copies a config from an
example, or changes a model to debug something and does not change it back, or adds a provider
without noticing which tier it lands in. None of that is carelessness; it is what rules that live in
a document do.

So two of the four checks in `validate.py` are not really about configuration. They are the spending
rule, encoded:

**No model outside the free tier.** A substring match against markers that identify paid families.
This is the check that would catch a `gpt-` or a `claude-` model string arriving from a copied
example.

**The model is pinned at all.** An unpinned model is not obviously a spending problem until you
notice that the default is a decision made by the library, on a schedule you do not control, and
that "whatever ADK defaults to this month" is not a tier.

There is one more of these in the repository already and it is the model for this part: from Day 31,
`openrouter/` strings must end in `:free`, and it is linted. The missing suffix does not error — it
bills a paid model, quietly, correctly, for as long as nobody looks.

## Why Sutra needs it

Because Principle 15 says zero budget is a feature, and a feature has tests. A constraint that is
only ever stated is a constraint that erodes at exactly the rate that people join, leave and copy
things.

And because this day is the highest-risk day in the phase for it. Every other day's code runs
locally; this one is about a command that creates a billed resource, surrounded by examples of that
command. The chance of something billable ending up in the repository is higher here than anywhere
else, which is why part [3.3](3.3-the-parked-day-that-billed.md) exists as well.

## The mechanism

The paid-model check, in full:

```python
def paid_models_in(config: dict) -> list[str]:
    env = config.get("env_vars") or {}
    return [
        f"{k}={v}"
        for k, v in env.items()
        if isinstance(v, str) and any(marker in v for marker in PAID_MODEL_MARKERS)
    ]
```

**Line by line:**

- `PAID_MODEL_MARKERS` is `("gpt-", "claude-", "-pro", "openrouter/")`. Four substrings that appear
  in model families this repository does not pay for.
- `"-pro"` is the interesting entry. Within the free-tier provider this repository does use, the
  Flash-class models are the free ones and the Pro-class are not, so a single hyphenated fragment
  separates two members of the same family. It is crude and it is the check that would catch
  somebody upgrading a model to fix a quality problem.
- `"openrouter/"` catches the Day 31 case from the other direction: any OpenRouter string is
  reported here so a human looks at whether it ends in `:free`. A stricter version would test the
  suffix directly, and the reason this one does not is that being asked to look is the right
  outcome for a provider whose free roster moves.
- `isinstance(v, str)` because a config's env values are usually strings and are not guaranteed to
  be. A number in there should not raise a `TypeError` inside a policy check.
- It returns `f"{k}={v}"` — the name *and* the value — which is the opposite of the secret check in
  part [3.1](3.1-a-config-checker-that-fails.md). A model name is not a credential, and the whole
  point of the finding is which model it was.

The pin check is three lines and its output does the work:

```python
    model = env.get("SUTRA_MODEL")
    print(f"  model pinned explicitly: {model or 'NO - the default would be used'}")
```

**Line by line:**

- It prints the model rather than a tick. A reader who sees `gemini-2.5-flash-lite` has verified
  something; a reader who sees `pinned: yes` has verified that a check ran.
- The `or` branch spells out the consequence in the same line as the finding, so the output does not
  need a legend.

```bash
cd days/day-87-config-not-billed/lab
uv run python validate.py --fixed | sed -n '7,10p'
```

**Line by line:**

- `sed -n '7,10p'` for the three policy lines; the required-field rows are part
  [3.1](3.1-a-config-checker-that-fails.md)'s subject.

Measured on 2026-09-07:

```text
  secret-shaped env vars carried in the file: 0
  model strings this repository will not deploy: 0
  model pinned explicitly: gemini-2.5-flash-lite
```

Zero paid models, and the pin printed by name. That third line is the one to copy into your own
projects: a policy check that prints the value it approved is auditable, and one that prints a tick
is not.

## When it breaks

The lint breaks in the ordinary way lints do — by being a substring match against a naming
convention nobody promised to keep.

**A free model whose name contains a paid marker.** A hypothetical `gemini-3.0-pro-flash-free`
would be caught by `-pro` and refused. That is a false positive, it is annoying, and it is the right
side to be wrong on: the cost of a false positive is a conversation, and the cost of a false
negative is a bill.

**A paid model whose name contains none of them.** This is the real hole. A new provider, a new
family, a model called something the marker list has never seen — it passes. The list is a record of
what this repository has met, not a taxonomy.

**A model that is free today.** Addendum 02 exists because free rosters move; the December 2025
precedent is written into this repository's rules. A pinned model that was free when it was pinned
can stop being free, and no local check will ever notice. The only mechanism that does is the dated
row in `docs/PACKAGES.md` and somebody re-reading it.

There is no error text for any of these, because a lint that passes prints nothing interesting. What
there is, is the failure mode Day 31 was built around, and it is worth the reminder:

```text
openrouter/some-model        -> billed
openrouter/some-model:free   -> free
```

Four characters. No error either way. The request succeeds in both cases and one of them costs money
— which is exactly why it is a lint and not a note in a document.

## In production

**What a professional does.** Encodes the money rule in the pipeline, not the wiki. Whatever the
constraint is — a model tier, an instance size, a region, a data-residency rule — if breaking it
costs money or breaks a promise, it becomes a check that fails the build. The test of whether a
policy is real is whether anything would stop you violating it.

**What degrades at scale.** Marker lists rot. Providers rename families, add tiers, and split
free rosters, and a substring list written today is a partial one by the end of the year. The
sustainable version inverts it: an **allowlist** of models this project may use, rather than a
denylist of ones it may not, so an unknown model fails closed. This repository uses a denylist here
because the allowlist lives in `docs/PACKAGES.md` and is not yet machine-readable, which is an
honest limitation rather than a design choice.

**The failure that only shows with real traffic.** The lint passes and the *quota* does not. A free
model is free until the daily allowance runs out, and then it either refuses or, on some providers,
silently degrades to a slower lane. Day 78 measured a live refusal for this repository — twenty
requests a day on the observed lane — and no config check can see that number, which is part
[4.1](../04-what-it-costs/4.1-priced-in-requests.md)'s subject.

**The review comment a senior engineer leaves:** *"Turn this into an allowlist. A denylist of paid
model prefixes means a model we have never heard of is approved by default, and that is the wrong
default for the one rule we cannot undo after the fact."*

**The interview question:** *"How do you stop somebody accidentally using an expensive model?"* The
answer that shows experience does not describe a policy. It describes where the check runs, what it
fails, and — the part that shows real experience — which direction it fails in when it meets
something it does not recognise.
