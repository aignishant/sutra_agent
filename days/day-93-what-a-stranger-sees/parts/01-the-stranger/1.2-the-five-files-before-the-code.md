# 1.2 — The five files before the code

## One-line answer

A stranger checks five files before reading a line of code — what is this, may I use it, how do I
send a change back, where do I report something dangerous, and what keys will I need — and this
repository answers two of them.

## The story

The shop sign painted before the shop is finished.

A new place on the main road. The board is up, beautifully lettered, with the name and *"opening
shortly"*. People slow down and look. Over the following weeks the shutter goes up some days and
not others; there is stock inside; somebody is clearly working.

What nobody can tell from the road is whether it is open. Not the hours — whether it is a shop yet
at all. Can you walk in? Is that person inside a customer or the owner's cousin? Is the price on
that box a price, or is it just a box?

One line on the board would settle all of it. Its absence does not make the shop worse; it makes
every passer-by run their own guess, and most of them guess *not yet* and keep walking.

## The idea in plain language

A stranger who lands on a public repository runs a checklist before deciding to spend attention on
it. It is not a formal checklist and they would not describe it as one, but it is remarkably
consistent, and every item is a file.

| File | The question it answers | What happens when it is missing |
| --- | --- | --- |
| `README.md` | what is this, and what do I run first | they leave immediately |
| `LICENSE` | am I allowed to use it | they assume no, correctly |
| `CONTRIBUTING.md` | how do I send a change back | they do not send one |
| `SECURITY.md` | where do I report something dangerous, privately | they open a public issue, or say nothing |
| `.env.example` | which keys will I need, before I clone | they clone and find out |

The middle three are the ones that get skipped, and `LICENSE` is the expensive one. Under copyright
law, a work with no licence is **all rights reserved by default**. Publishing it does not grant
anybody permission to use, copy or modify it. So a public repository with no `LICENSE` file is
visible and legally unusable — which is very nearly the worst combination, because it looks like an
invitation and is not one.

`SECURITY.md` matters for a narrower reason and it is worth being precise about: without it, a
person who finds something dangerous has no private channel, so their options are to open a public
issue describing the problem in public, or to say nothing. Most say nothing.

## Why Sutra needs it

Because this repository's licence sentence currently reads *"See `LICENSE` if present; otherwise all
rights reserved by the repository owner"* — and `LICENSE` is not present. That is an accurate
sentence describing an unusable repository, and it was written by somebody who intended to add the
file.

And because Principle 13 — blast radius before capability — has a documentation half. Day 68 gave
every tool the narrowest permission that works; `SECURITY.md` is the same instinct applied to the
repository's own failure reports, and it costs one file.

## The mechanism

The check is five calls to `Path.exists`, and one to git for each that exists:

```python
FRONT_DOOR = (
    ("README.md", "what this is, and the first command to run"),
    ("LICENSE", "whether anyone is allowed to use it"),
    ("CONTRIBUTING.md", "how to send a change back"),
    ("SECURITY.md", "where to report something dangerous, privately"),
    (".env.example", "which keys are needed, names only"),
)
```

**Line by line:**

- Each entry carries **the question**, not a description of the file. That is what makes the output
  readable by somebody who does not already know why `SECURITY.md` matters — the report says what
  the stranger cannot find out, rather than which filename is absent.
- `LICENSE` with no extension, which is the conventional spelling git forges recognise. A
  `LICENSE.md` or `LICENCE` is a file the tooling will not identify as a licence.
- `.env.example` is in the list because it is the one that saves a stranger a clone. Day 0 wrote it,
  and it is the only item here this repository already gets right on purpose.

Presence is not the whole question — a file that exists and is not committed helps nobody, so the
check asks git too:

```python
        is_tracked = bool(git("ls-files", "--error-unmatch", name)) if present else False
```

**Line by line:**

- `ls-files --error-unmatch` is the precise question: it prints the path if git is tracking it and
  fails if not. `git ls-files <name>` alone prints nothing for an untracked file, which is
  indistinguishable from an error, so the explicit flag is what makes the answer trustworthy.
- Guarded on `present`, because asking git about a file that does not exist is a different question
  with the same answer, and conflating the two produces a report that says "untracked" when it means
  "absent".

Run it:

```bash
cd days/day-93-what-a-stranger-sees/lab
uv run python firstfiles.py; echo "exit: $?"
```

**Line by line:**

- No flag: all five.

Measured on 2026-09-07:

```text
  file                present  tracked  answers
  README.md               yes      yes  what this is, and the first command to run
  LICENSE                  NO        -  whether anyone is allowed to use it
  CONTRIBUTING.md          NO        -  how to send a change back
  SECURITY.md              NO        -  where to report something dangerous, privately
  .env.example            yes      yes  which keys are needed, names only

  2 of 5 present
    - LICENSE is absent
    - CONTRIBUTING.md is absent
    - SECURITY.md is absent

  each absent file is a question the stranger answers by assuming
exit: 1
```

**Two of five.** Both present ones are tracked, which is the part that is right.

## When it breaks

The check breaks by narrowing until it passes, and the narrowing is always defensible in the moment:

```bash
uv run python firstfiles.py --readme-only; echo "exit: $?"
```

Measured on 2026-09-07:

```text
  file                present  tracked  answers
  README.md               yes      yes  what this is, and the first command to run

  1 of 1 present
  the front door answers every question a stranger asks before cloning
exit: 0
```

**One of one, and a green exit.** The closing sentence is now false, and no line of it is a lie —
the check reported exactly what it was asked, and what it was asked had shrunk. This is the
`--lenient` shape from Day 83 part 1.3 in its documentation form: a threshold nothing can fail.

The subtler break has no error text at all. A `LICENSE` file that is present but says nothing usable
— a stub, a placeholder, a licence chosen without reading it — passes this check and answers the
stranger's question wrongly. Presence is checkable; **suitability is not**, and this check does not
pretend otherwise. The candidate in `lab/candidates/LICENSE.candidate` is a real MIT text for that
reason: choosing a licence is a decision, and the day leaves the decision with the reader.

## In production

**What a professional does.** Adds the four small files on the day the repository is created, not
the day it is published, because at creation they cost a template and at publication they cost a
decision under time pressure. Forges make this easy — the licence picker writes the file — and the
main reason it does not happen is that a private repository never punishes its absence.

**What degrades at scale.** `CONTRIBUTING.md` gets more valuable the more strangers arrive, and its
absence is silent in exactly the way Day 78's shrunken run was silent: you do not receive the pull
requests that were never opened, so the metric that would tell you it is missing is a number you
never see.

**The failure that only shows with real traffic.** A licence added later does not fully apply
backwards. Every copy someone made while the repository had no licence was made under all-rights-
reserved, and the history stays visible. For a teaching repository this is a footnote; for anything
a company might build on, it is the reason the file goes in first.

**The review comment a senior engineer leaves:** *"Pick a licence before it goes public, not after.
And write SECURITY.md even though nothing here is deployed — the point is the private channel, and
one paragraph is a whole channel."*

**The interview question:** *"What does a repository with no LICENSE file mean?"* The answer that
shows experience is *"all rights reserved"* — that publishing is not permission — and then the
practical half: that it is the single cheapest fix in this whole list and the one most often left.
