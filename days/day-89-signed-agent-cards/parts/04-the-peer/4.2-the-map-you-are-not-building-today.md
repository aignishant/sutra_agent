# 4.2 — 🅿️ The map you are not building today

## One-line answer

🅿️ Beside A2A sit a payments protocol built on signed mandates and two payment-rail proposals, and
this day's discipline is to be able to place them on a map and say why none of them is in this
repository: each one needs money to move, and Sutra's budget is denominated in requests.

## The story

The road sign listing towns you are not going to.

At a junction there is a board with six names on it and distances beside them. You are going to one
of them. The other five are still worth the two seconds it takes to read, because now you know which
direction they are in — and more usefully, you know that the road you are on is the road that leads
to them, so when somebody mentions one you are not starting from nothing.

Reading the board is not a detour. Taking the turning would be.

## The idea in plain language

**🅿️ = parked**: awareness-level, interview-ready, deliberately not built. The plan's own instruction
for this day is *know the map, build only A2A*, and this part is the map.

A2A moves **work** between agents. The moment agents are asked to move **money**, a different set of
problems appears — authorisation, non-repudiation, dispute, settlement — and a different set of
specifications has grown up beside A2A to address them. Verified live on 2026-09-07 by fetching the
project's own documentation site:

**AP2 — Agent Payments Protocol.** Its documentation navigation lists an *Agent Authorization
Framework*, a *Checkout Mandate*, a *Payment Mandate*, and a *Security and Privacy Considerations*
section, with sample flows split into *Human Present* and *Human Not Present*. The organising idea is
the **mandate**: a signed artefact recording what a human authorised an agent to do, so that when the
agent later acts, there is a document saying it was allowed to.

That should sound familiar, because it is this day's mechanism pointed at a different noun. An agent
card is a signed statement about *what an agent is*. A mandate is a signed statement about *what an
agent may do*. Same primitive, higher stakes, and the stakes are why the specification has a
human-present and a human-not-present variant at all.

**x402** is a payment-rail proposal built around the long-unused HTTP status code `402 Payment
Required` — the idea being that a resource can answer a request by naming a price, and the client can
pay and retry. AP2's own samples directory carries x402 variants beside its card variants, which
places the two as alternative rails under the same authorisation model.

**TAP** appears in the same conversation as a transaction-authorisation layer. This repository has
not verified its specification and will not describe it further, which is the honest position.

None of these is built here, and the reason is Principle 15 rather than difficulty. Every one of them
is about moving money, and a repository whose budget is measured in requests per day has no way to
exercise them honestly. A payments integration that cannot be run is a description, and this
curriculum's rule is that a description is a parked topic, marked as one.

## Why Sutra needs it

Because "we did not build it" and "we do not know what it is" are different sentences, and only one
of them survives an interview. Day 71 parked computer use the same way and Day 87 parked a managed
deployment platform; the pattern is deliberate and it is what keeps the curriculum honest about its
budget without leaving holes in the map.

And because the *primitive* is transferable and is the reason this belongs on today of all days.
Having signed a card, verified it against a key set that the document could not influence, and
watched an `alg: none` forgery walk through a permissive verifier, a reader is equipped to read a
mandate specification and ask the right three questions of it immediately.

## The mechanism

There is no mechanism to run, and that is what parked means. What there is instead is a set of
questions this day has earned the right to ask of any signed-artefact protocol:

| Question | Where this day answered it for A2A |
| --- | --- |
| What exactly is signed — which bytes? | part [2.1](../02-signing-it/2.1-a-signature-is-over-bytes.md) |
| Who decides the algorithm, the document or the verifier? | part [3.1](../03-the-verifier-decides/3.1-the-algorithm-the-card-chose.md) |
| Where does the key come from, and can the document influence it? | part [3.2](../03-the-verifier-decides/3.2-which-key.md) |
| Is the signature optional, and what does an unsigned artefact mean? | part [3.3](../03-the-verifier-decides/3.3-the-field-the-spec-made-optional.md) |
| What happens on rotation, and what happens on revocation? | part 3.2, and Day 90 |

For a card, a wrong answer means talking to the wrong agent. For a mandate, it means a payment that
somebody has to dispute. The questions do not change; the cost of getting them wrong does.

What is left, then, is the lookup — written as a command rather than a summary, because summarising a
specification this repository has not read is exactly the failure mode Principle 7 exists to prevent:

```text
TODO(me): read the AP2 specification and answer the five questions in the table above for a
Payment Mandate rather than an Agent Card. Two paragraphs, in your own words, in this file.
  curl -sL https://ap2-protocol.org/specification/ | less
  curl -sL https://ap2-protocol.org/topics/what-is-ap2/ | less
Both paths returned a 404 body when fetched on 2026-09-07 from this machine while the site's
navigation listed them, so start by finding the current path from the site index.
```

```text
TODO(me): x402 — find the specification, and answer one question: when a client retries after
paying, what binds the payment to the retried request? If the answer is "nothing", say what that
means for a replay.
  curl -sL https://www.x402.org/ | less
```

```text
TODO(me): TAP — establish what the acronym expands to in this context and who publishes it,
before writing a single sentence about it anywhere.
```

**Line by line:**

- Each is a `TODO(me)` with the **exact command**, not a description of where to look. That is
  Principle 7's form: a lookup that can be run, rather than a claim that has to be trusted.
- The AP2 note records what actually happened when the fetch was tried — the navigation listed the
  pages and the pages returned 404 bodies — because a reader who hits the same thing should know it
  was seen and is not their mistake.
- The x402 item is phrased as one sharp question rather than "read the spec", because a parked topic
  earns its place by leaving behind the question worth asking, not a reading list.
- The TAP item deliberately asks for the expansion first. An acronym this repository cannot resolve
  is not a topic it is parking; it is a note that the map has an unlabelled road on it.

## When it breaks

Parking breaks in two directions and both are worth naming.

**Parked becomes forgotten.** A 🅿️ marker with no question attached is indistinguishable from an
omission six months later. The countermeasure is the table above: the topic is parked, and what is
recorded is not "we skipped payments" but the five specific questions a reader can now answer for
themselves, plus the commands to go and read.

**Parked becomes pretended.** The worse direction, and the one this part had to actively resist. It
would have been easy to write three confident paragraphs about mandate structures and payment
binding, from general knowledge, in the register of the rest of this day — and every sentence would
have been unverified. The fetch above returned a navigation and a 404, so what this part can honestly
say is: the protocol exists, it is organised around mandates, its documentation names Checkout and
Payment mandates and a human-present and human-not-present split. Everything past that is a `TODO`.

There is no error text for the second failure, ever. A confident paragraph about a specification
nobody read looks exactly like a confident paragraph about one somebody did, which is why §17.4.1's
rule against inventing citations is stricter than the rule against inventing version numbers: a wrong
pin fails on the next install, and a plausible description of a protocol fails silently for years.

## In production

**What a professional does.** Keeps a written map of the adjacent standards with a one-line position
on each — *using it*, *watching it*, *decided against it, because* — and dates the entries. The value
is not the descriptions; it is that when somebody proposes one in a meeting, the answer is a
paragraph from last quarter rather than a two-week investigation.

**What degrades at scale.** Map rot. Protocol landscapes at this stage move quarterly, and a
confident, undated summary of a specification is worse than no summary because people stop checking.
Anything written here would need a date on it — which is why what is written here is a set of
commands instead.

**The failure that only shows with real traffic.** Adopting a payments protocol for the primitive
rather than the payments. Signed mandates are a good design and it is tempting to reach for one as a
general-purpose "signed authorisation" artefact. The specification's constraints — dispute windows,
settlement semantics, regulatory shape — come along with the primitive, and they are constraints
about money that do not simplify when the thing being authorised is not money.

**The review comment a senior engineer leaves:** *"Good that it is parked. Put the date on the fetch
and keep the commands — in six months I want to know whether we looked and it did not fit, or we
never looked."*

**The interview question:** *"How would agents handle payments?"* The answer that shows experience
does not recite a protocol. It names the primitive — a signed, human-authorised mandate that the
agent presents when it acts — says which of the five questions above it would ask of any candidate
specification, and then says plainly which ones it has read and which it has not.

## Check yourself

There is no command to run here, which is the point of a parked part.

Answer the five questions in the table for A2A, from memory, without opening the linked parts. If any
of them is shaky, that question is the one you would get wrong about a payments protocol too, at
considerably greater expense.

Then take the three `TODO(me)` blocks and put a date beside each of them in your own copy — the date
you intend to do the lookup. A parked topic with no date is Day 82's quarantine all over again: an
entry added for a good reason that nobody ever revisits.

**Out loud, without scrolling up:** what does 🅿️ mean in this curriculum, what is a mandate in one
sentence, and what is the honest answer when somebody asks you what TAP is?
