# 2.1 — The 479-token preamble you did not write

## One-line answer

Attaching a `SkillToolset` appends about two thousand characters of instructions to your system
prompt — 479 tokens, measured — that you did not write, cannot see in your source, and pay for on
every single request for the rest of the conversation.

## The story

You have taken the same flight enough times to know the announcement by heart.

Seat belt low and tight across the hips. Exits here, here and here. In the unlikely event of a
decompression, a mask will drop; pull it towards you to start the flow. Secure your own before helping
others. Life jacket under the seat, whistle attached, do not inflate inside the cabin.

Four minutes, every flight, whether or not anybody on board has ever seen a life jacket. It plays on
the twenty-minute hop and on the eleven-hour crossing, and it costs the same four minutes on both. On
the long flight nobody notices. On the short one, it is a visible fraction of the time you are in the
air.

Nobody thinks that announcement is a bad idea. But if you were paid by the minute for cabin time, you
would know exactly what it cost you, and you would know it before somebody else worked it out.

## The idea in plain language

Day 19 opened the envelope and counted what was in it: the system instruction, the tool declarations,
the conversation, the current turn
([19.2.2](../../../day-19-context-engineering-selection/parts/02-anatomy/2.2-six-organs-and-who-packed-them.md)).
The finding that surprised people was that the **tool menu costs more than the handbook**
([19.2.3](../../../day-19-context-engineering-selection/parts/02-anatomy/2.3-the-menu-costs-more-than-the-handbook.md)).

A toolset is allowed to add to that envelope, and `SkillToolset` uses the privilege. Every ADK toolset
gets a hook called `process_llm_request`, which runs before each request and may edit what is about to
be sent. `SkillToolset`'s implementation does one thing: it appends a block of instructions telling
the model that skills exist and how it is expected to interact with them.

Here is the shape of what it appends, in plain terms. One paragraph saying skills are folders and what
is inside them. Then seven numbered rules:

1. If a skill seems relevant, you **MUST** call `load_skill` before proceeding.
2. Once you have the instructions, follow them exactly, including every step in order.
3. `load_skill_resource` is only for files bundled with a skill, never for the user's files.
4. Use `run_skill_script` for scripts in `scripts/`.
5. If `load_skill_resource` errors, do not retry a path — report it and stop.
6. If `run_skill_script` errors, do not guess another script — report it and stop.
7. Loading a skill does **not** end your turn; keep going and answer in the same turn.

Read those as what they are: a **prompt**, written by the framework's authors, shipped in the package,
and prepended to yours. Rules 5, 6 and 7 are especially interesting, because each one is scar tissue.
Somebody watched a model retry a hallucinated path in a loop, and somebody watched a model call
`load_skill` and then stop talking. Those two failures are why two of your seven rules exist.

The number to hold on to is the cost, and it has a property worth naming: **it does not depend on how
many skills you have.** One skill or two hundred, the preamble is the same. It is a fixed charge for
having the feature switched on.

## Why Sutra needs it

Because Sutra's budget is denominated in requests and its context is denominated in tokens, and this
is a token cost that appears in no file you can grep.

Day 24 established the arithmetic that makes this matter: a chat model is stateless, so everything in
the system instruction is paid for again on **every turn** of a conversation
([24.1.2](../../../day-24-token-accounting-and-budgets/parts/01-what-a-request-costs/1.2-charged-again-every-turn.md)).
An eight-turn triage conversation therefore pays the preamble eight times. That is not a reason to
avoid skills. It is a reason to know the number before somebody in a review asks you what skills cost,
and to be able to answer with a measurement instead of an opinion.

It also matters because Sutra's own instruction is short on purpose. Day 6 argued that every line in
the handbook is a tax
([6.1.5](../../../day-06-instructions-and-personas/parts/01-writing-the-handbook/1.5-every-line-is-a-tax.md)),
and the desk's instruction was kept to a few sentences on that argument. Attaching a toolset that adds
479 tokens to the same field, silently, is the kind of thing that makes a carefully-trimmed prompt
irrelevant without anybody noticing.

## The mechanism

The preamble is not hidden — it is reachable, and reading it is the point of this part. Build a
request the way the runtime does, hand it to the toolset, and print what came back.

```python
# days/day-26-loading-skills-into-adk/lab/read_preamble.py
"""Print exactly what SkillToolset adds to the system instruction, and what it costs."""

import asyncio
import os
import pathlib

from google import genai
from google.adk.models.llm_request import LlmRequest
from google.adk.skills import load_skill_from_dir
from google.adk.tools import skill_toolset

from sutra.config import load_env

MODEL = "gemini-3.7-flash"
SKILL_DIR = pathlib.Path("days/day-25-skills-the-open-spec/lab/skills/ticket-triage")


async def main() -> None:
    """Append the toolset's instructions to an empty request and measure them."""
    skill = load_skill_from_dir(SKILL_DIR)
    toolset = skill_toolset.SkillToolset(skills=[skill])

    request = LlmRequest()
    await toolset.process_llm_request(tool_context=None, llm_request=request)
    preamble = request.config.system_instruction

    print(preamble)
    print("-" * 72)
    print("characters      :", len(preamble))
    print("mentions a skill:", "ticket-triage" in preamble)

    load_env()
    client = genai.Client(api_key=os.environ["GOOGLE_API_KEY"])
    counted = client.models.count_tokens(model=MODEL, contents=preamble)
    print("tokens          :", counted.total_tokens)


asyncio.run(main())
```

**Line by line:**

- `LlmRequest()` with no arguments is an empty outgoing request — the object ADK fills in before every
  model call. Building one by hand is the trick that makes this measurable without a runner, and it is
  the same move Day 13 used to look inside a request
  ([13.2.1](../../../day-13-callbacks-four-doors/parts/02-the-model-doors/2.1-what-is-actually-in-the-request.md)).
- `process_llm_request` is `async`, so the whole script is in an `async def` and run with
  `asyncio.run`. Day 8's rule still holds: the runtime is asynchronous, and pretending otherwise
  produces a coroutine object where you wanted a value.
- `tool_context=None` is legal here because `SkillToolset.process_llm_request` never reads the
  context — checked by reading its body in the installed package on 2026-09-04, not by trying it and
  seeing what happened. The parameter is part of the hook's shared signature, and this implementation
  ignores it. The four **tools**, in the next four parts, do read it, and
  [2.2](2.2-the-index-is-a-tool-call.md) builds the double they need.
- `request.config.system_instruction` is where `append_instructions` puts things. The name is worth
  remembering: the preamble does not arrive as a tool declaration or a user message. It lands in the
  **same field as your own instruction**, which is why it is invisible unless you look.
- `"ticket-triage" in preamble` is the assertion that sets up the next part. It prints `False`, and
  that single word is the most surprising measurement of the day.
- `count_tokens` rather than a character estimate, for the reason Day 24 gave: tokens are not
  characters, and the ratio is not stable across text
  ([24.1.1](../../../day-24-token-accounting-and-budgets/parts/01-what-a-request-costs/1.1-a-ticket-id-costs-five-tokens.md)).
  It is also a separate endpoint on a separate quota, so this measurement costs **zero** generations.
- `os.environ["GOOGLE_API_KEY"]` after `load_env()` — the subscript raises `KeyError` if the key is
  absent, which is the honest failure. Day 1's `require` helper gives a better message; the subscript
  keeps this script to one idea.

Run it from the repository root:

```bash
uv run python days/day-26-loading-skills-into-adk/lab/read_preamble.py
```

**Line by line:**

- Needs `GOOGLE_API_KEY` for the token count, and spends **0** of the twenty daily generations. Delete
  the last four lines and it needs no key at all.

Measured on 2026-09-04 against `google-adk` 2.7.1 and `gemini-3.7-flash`:

```text
You can use specialized 'skills' to help you with complex tasks. You MUST use the skill tools to interact with these skills.

Skills are folders of instructions and resources that extend your capabilities for specialized tasks. Each skill folder contains:
- **SKILL.md** (required): The main instruction file with skill metadata and detailed markdown instructions.
- **references/** (Optional): Additional documentation or examples for skill usage.
- **assets/** (Optional): Templates, scripts or other resources used by the skill.
- **scripts/** (Optional): Executable scripts that can be run via bash.

This is very important:

1. If a skill seems relevant to the current user query, you MUST use the `load_skill` tool with `skill_name="<SKILL_NAME>"` to read its full instructions before proceeding.
...
------------------------------------------------------------------------
characters      : 2054
mentions a skill: False
tokens          : 479
```

**479 tokens, and not one of them is the name of a skill.** Both halves of that line are the day's
turning point, and the second half is section 2.2.

Add a second skill and a third and run it again: 2054 characters, every time. The preamble is built
from the toolset's configuration, not from its contents.

## When it breaks

**The key is missing.** The measurement half needs one:

```text
KeyError: 'GOOGLE_API_KEY'
```

Blunt, and it names the variable. The fix is a `.env` with the key in it
([1.3.3](../../../day-01-bootstrap-and-map/parts/03-keys-and-env/3.3-loading-keys-failing-loudly.md)), and the reason
the script does not catch it is Principle 10: a measurement that silently prints an estimate when it
could not measure is worse than one that stops.

**The coroutine you forgot to await.** Drop the `await` in front of `process_llm_request` and there is
no error at all — the request is simply never modified:

```text
characters      : 0
```

A zero-length preamble looks like a finding. It is not; it is a missing `await`, and Python only warns
about it as the interpreter shuts down. When a measurement of an async API comes back suspiciously
clean, check that you awaited it before you write it down.

**The arguments passed positionally.** Both parameters are keyword-only, and the message counts
arguments rather than naming them:

```text
TypeError: SkillToolset.process_llm_request() takes 1 positional argument but 3 were given
```

"1 positional argument" is `self`. Keyword-only parameters are a deliberate choice by ADK's authors on
methods where the argument order could plausibly be remembered wrong, and this is one of them.

**The preamble appended twice.** Call `process_llm_request` twice on the same request object — easy to
do when you are experimenting in a notebook, or when two toolsets wrap the same one — and it appends
again rather than replacing:

```text
after one call : 2054
after two calls: 4110
```

Nothing errors, and the model receives the seven rules twice. The runtime builds a fresh `LlmRequest`
per call so this cannot happen to you by accident in normal use, but it is worth knowing that the hook
is **additive and not idempotent**, because that is the assumption every custom `process_llm_request`
you write later has to honour too.

## In production

**Count the preamble in your context budget, and put it in the same table as your own prompt.** Day 19
argued for a budget per organ of the request
([19.6.2](../../../day-19-context-engineering-selection/parts/06-in-production/6.2-a-budget-per-organ.md)).
This is a new organ, it is 479 tokens, and it did not exist in your budget yesterday. A team that
tracks its system-instruction size and then attaches three toolsets without re-measuring is tracking a
number that no longer describes anything.

**Re-measure it on every ADK upgrade.** It is a string literal in the package, so a minor version can
change it, lengthen it, or add an eighth rule — and nothing in your code or your tests would notice. A
single test that asserts the preamble is under some ceiling is cheap and turns a silent cost increase
into a red build. That is the same discipline Day 15 arrived at when a page and a package disagreed
([15.5.1](../../../day-15-toolsets-and-openapi/parts/05-where-it-bites/5.1-the-page-and-the-package-disagree.md)).

**Know that it can argue with your own instruction.** The preamble says *"you MUST use the skill tools"*
in capitals. If your handbook says *"answer briefly and do not use tools unless the user asks"*, you
have written a contradiction into one field, and Day 6 showed what a contradiction in an instruction
produces: not an error, but behaviour that varies run to run
([6.1.4](../../../day-06-instructions-and-personas/parts/01-writing-the-handbook/1.4-contradictions-are-randomised-behaviour.md)).
Read the preamble once, properly, and check your own instruction against it.

**What changes at scale** is that fixed costs stop being the thing you optimise and start being the
thing you audit. 479 tokens on a million requests is real money on a paid tier and real quota on a
free one, but it is not a number you can reduce — you can only decide whether the feature is worth it.
The costs you *can* reduce are the per-skill ones, and they are the next four parts.

**The review comment a senior engineer leaves:** *"we trimmed the system prompt by 200 tokens last
sprint and then attached a skills toolset that adds 479. Add the toolset's contribution to the prompt
budget test so the next trimming exercise is measured against what we actually send."*

**The interview question:** *"what does attaching a toolset do to your prompt?"* The answer that shows
you have looked: *"any ADK toolset can edit the outgoing request through `process_llm_request`, and
`SkillToolset` uses it to append about 480 tokens of instructions to the system instruction — seven
numbered rules about how to use the skill tools. It is a fixed cost, independent of how many skills you
have, and it is paid on every turn because the model is stateless. I measured it rather than guessed,
and I keep a test on it because it is a string in the framework and can change on an upgrade."*
