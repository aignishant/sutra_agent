# 3.2 — What the lint must read

<!-- allow-unfree-file: this part pastes the lint's own findings verbatim, so every model string in
     it is quoted evidence rather than a billing bug. See 3.3 for why this marker exists. -->

## One-line answer

`tools/lint_free_suffix.py` walks every text file in the repository except history and caches — day
documents included, because a model string in a build brief is a string somebody will copy — matches
`openrouter/…` with one regular expression, and reports every occurrence that is not immediately
followed by `:free`.

## The story

The librarian is asked to find every book that mentions a particular town.

Her first question is not *how* to search. It is **where**. The fiction shelves, obviously. Local
history, obviously. But also the parish magazines in the back room, the bound newspapers, the boxes
of unsorted pamphlets — and here is the one people forget — **the card catalogue itself**, because the
catalogue has descriptions in it, and a description can mention the town while the book it describes
does not.

She also decides what she is *not* going to open. The reading-room copies are duplicates of what is
already on the shelves. The archive in the basement is sealed and has not changed since before the
question was asked, and nothing found there could be acted on anyway.

The search takes an afternoon and the decision took a minute, and the decision is the part that
determined whether the answer was any good. Somebody who searched only the fiction shelves would have
finished sooner and been wrong.

## The idea in plain language

A lint that matches a pattern has two halves, and the interesting one is not the pattern.

**The scan set** — which files it opens. Get this too narrow and the rule is enforced in some places
and not others, which is worse than no rule, because people believe it. Get it too wide and it is
slow and full of noise.

**The pattern** — what counts as a hit. Get this too loose and it fires on things that are not model
strings. Get it too tight and a real one slips through.

For this rule the scan set has four decisions in it.

**Not only `.py`.** The obvious choice is to scan Python source, and it is wrong here. Model strings
in this repository live in day documents — in build briefs, in setup blocks, in tables of pins. A
string in a build brief is a string a reader will copy into code tomorrow, so it is exactly as
dangerous as one already in code. `.md` is in the scan set for that reason.

**Not `legacy/`.** That directory is the frozen v1 run, read-only, never executed and never edited.
Findings there cannot be acted on, so reporting them is pure noise. This is the librarian's sealed
basement.

**Not `.venv/`, `.git/`, caches, or build output.** Not because they are unimportant but because they
are not *yours*. A finding inside an installed third-party package is not something you can fix, and
walking them costs far more than everything else combined.

**Text only.** Reading a `.png` as UTF-8 raises, and a lint that crashes on a binary file is a lint
that gets removed. An explicit list of text suffixes is more honest than catching the exception,
because it says what you meant.

The pattern has one decision that matters more than the rest: it must capture the **whole** model
identifier including any suffix, and then ask whether that suffix is `:free`. A pattern that stopped
at the first slash would match `openrouter/z-ai` and report a false positive on a perfectly good
string, which is the bug Day 9 warned about in prose and this lint has to avoid in code.

## Why Sutra needs it

Because the rule has to hold in the places the repository actually grows, and from tomorrow it grows
in files that are not Python.

Phase 5 adds MCP servers with configuration. Phase 6 adds deploy-shaped entry points. Phase 7 adds
memory services. Every one of those days will write a hub with a setup block and a build brief, and
every one of them can name a model. If the lint reads only `sutra/**/*.py`, then the rule quietly
stops applying to the majority of new text in the repository, and it stops applying without anyone
deciding that it should.

There is a second reason, and it is the one that makes this part a real part rather than a
walkthrough: the wide scan set immediately produces a genuine conflict. Day 5 and Day 9 both teach
this exact trap, which means they both have to *print the wrong string*. Scanning day documents makes
ten teaching lines into ten findings. That tension is not a flaw in the design — it is the design
meeting reality — and it is what [3.3](3.3-the-alarm-that-fires-on-toast.md) exists to resolve.

## The mechanism

The whole file.

```python
# tools/lint_free_suffix.py
"""Addendum 02 section 7 as a program: every openrouter/ model string ends in ':free' (OPS-08).

The same model is sold under two identifiers and only one of them is free, the requests are
indistinguishable, and the feedback arrives on a billing page weeks later - so the rule is
mechanised rather than remembered (part 3.1).

Two escape hatches, both deliberate and both narrow (part 3.3):

    allow-unfree        anywhere on a line   - exempts that line
    allow-unfree-file   anywhere in a file   - exempts the whole file, for a document that
                                               pastes this lint's own findings

Run it as a module, from the repository root:

    uv run python -m tools.lint_free_suffix
    uv run python -m tools.lint_free_suffix days/day-09-four-free-providers
"""

from __future__ import annotations

import re
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]

MODEL = re.compile(
    r"openrouter/[A-Za-z0-9][A-Za-z0-9._-]*"
    r"(?:/[A-Za-z0-9][A-Za-z0-9._-]*)*"
    r"(?::[A-Za-z0-9._-]+)?"
)

ALLOW_LINE = "allow-unfree"
ALLOW_FILE = "allow-unfree-file"

TEXT_SUFFIXES = {".py", ".md", ".toml", ".sh", ".yaml", ".yml", ".json", ".txt", ".cfg"}
SKIP_DIRS = {
    ".git",
    ".venv",
    ".ruff_cache",
    ".pytest_cache",
    "__pycache__",
    "dist",
    "node_modules",
    "legacy",
}


def scannable(root: Path) -> list[Path]:
    """Every text file the rule applies to, sorted, with history and caches pruned."""
    found: list[Path] = []
    for folder, dirnames, filenames in root.walk():
        dirnames[:] = [d for d in dirnames if d not in SKIP_DIRS]
        for name in filenames:
            path = folder / name
            if path.suffix.lower() in TEXT_SUFFIXES:
                found.append(path)
    return sorted(found)


def offenders(root: Path) -> list[str]:
    """One finding per openrouter/ model string that is missing its ':free' suffix."""
    found: list[str] = []
    for path in scannable(root):
        try:
            text = path.read_text(encoding="utf-8")
        except (UnicodeDecodeError, OSError):
            continue
        if ALLOW_FILE in text:
            continue
        for number, line in enumerate(text.splitlines(), start=1):
            if ALLOW_LINE in line:
                continue
            for match in MODEL.finditer(line):
                if not match.group(0).endswith(":free"):
                    rel = path.relative_to(root).as_posix()
                    found.append(f"{rel}:{number}: {match.group(0)} is missing ':free'")
    return found


def main(argv: list[str] | None = None) -> int:
    """Scan the repository. Return 0 when every model string is free, else 1."""
    args = sys.argv[1:] if argv is None else argv
    root = Path(args[0]).resolve() if args else ROOT
    bad = offenders(root)
    for finding in bad:
        print("FAIL", finding)
    if bad:
        print(f"free-suffix: {len(bad)} model string(s) missing ':free' (Addendum 02 section 7)")
        return 1
    print("free-suffix: every openrouter/ model string ends in ':free'")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

**Line by line:**

- `ROOT = Path(__file__).resolve().parents[1]` is the repository root computed from the file's own
  location: `tools/lint_free_suffix.py` → `resolve()` gives the absolute path → `parents[1]` climbs
  two levels, past `tools/`, to the root. Deriving it rather than using `Path(".")` means the lint
  scans the whole repository even when somebody runs it from a subdirectory, which is the difference
  between a check and a surprise.
- The `MODEL` pattern is written as three adjacent string literals, which Python concatenates. That
  is not decoration — a regular expression on one line is unreadable, and each line here is one idea.
- `openrouter/[A-Za-z0-9][A-Za-z0-9._-]*` — the literal prefix, then a first segment that **must
  start with a letter or a digit**. That leading class is the whole reason the earlier draft of this
  lint reported `openrouter/...` in prose as a model: dots are legal inside a segment but not at the
  start of one, and requiring an alphanumeric first character removes an entire family of false
  alarms in one bracket.
- `(?:/[A-Za-z0-9][A-Za-z0-9._-]*)*` — zero or more further `/segment` groups, so `openrouter/z-ai`
  and `openrouter/z-ai/glm-5.2` both match in full. `(?:...)` is a non-capturing group: you want the
  grouping for the repetition and you do not want a capture, because `finditer` with capture groups
  invites reading the wrong thing out of the match.
- `(?::[A-Za-z0-9._-]+)?` — an optional `:tag` at the end. This is the load-bearing piece. Without
  it, the pattern would stop before the colon, `match.group(0)` would never end in `:free`, and the
  lint would report every string in the repository including the correct ones. Capturing the suffix
  is what lets the next line *ask about* the suffix.
- `ALLOW_LINE` and `ALLOW_FILE` are the two escape hatches, as constants so they appear once and can
  be grepped. Note `"allow-unfree-file"` contains `"allow-unfree"`, which is deliberate: a file-level
  marker also reads as a line-level one, so the order of the two checks cannot produce a surprise.
- `TEXT_SUFFIXES` is an allowlist rather than a blocklist of binary types. An allowlist fails safe: a
  file type nobody thought about is skipped rather than opened and decoded.
- `SKIP_DIRS` holds `legacy` alongside the caches, and that is a real decision rather than tidiness —
  the frozen v1 run is full of the old model strings and none of them can be acted on
  ([the plan's §16](../../../../docs/00_MASTER_PLAN.md) freezes it).
- `for folder, dirnames, filenames in root.walk():` uses `Path.walk`, added in Python 3.12, which
  yields three values per directory and — crucially — lets you edit `dirnames`.
- `dirnames[:] = [d for d in dirnames if d not in SKIP_DIRS]` is the line that makes this fast. The
  slice assignment mutates the list **in place**, which is what the walker requires; rebinding with
  `dirnames = [...]` would create a new list, leave the walker's own list untouched, and silently do
  nothing. Pruning here means the walker never descends into `.venv/` at all. Measured on
  2026-09-04 on this repository, the pruning walk finished in about half a second where the same
  scan built with `rglob("*")` — which yields every path first and filters afterwards — took several
  seconds, and the gap grows with the size of the virtual environment.
- `path.suffix.lower()` lowercases before the membership test, so a stray `.MD` is not skipped on a
  case-sensitive filesystem.
- `return sorted(found)` gives stable output. Directory walk order is filesystem-dependent, and a
  lint whose findings come out in a different order on each machine cannot be diffed between runs.
- `except (UnicodeDecodeError, OSError): continue` catches exactly two things and names them.
  `UnicodeDecodeError` is a file that is not text after all; `OSError` covers a permission problem or
  a broken symlink. It is deliberately not `except Exception`, because a `MemoryError` or a
  programming mistake in this loop must surface rather than be quietly skipped — that is Principle 10
  applied to the lint itself.
- `if ALLOW_FILE in text: continue` tests the whole file before splitting it into lines, so the
  marker works wherever the author put it — in an HTML comment at the top, in a docstring, at the
  bottom.
- `for number, line in enumerate(text.splitlines(), start=1)` — `start=1` because editors count lines
  from one, and a finding that is off by one wastes the reader's time in a small, infuriating way.
- `if ALLOW_LINE in line: continue` is a plain substring test rather than a regular expression.
  Simplicity is the point: the marker should be trivially greppable and impossible to get subtly
  wrong.
- `for match in MODEL.finditer(line)` — `finditer` rather than `findall`, because `findall` returns
  the capture groups when there are any and the whole match when there are not, which is a footgun
  the moment somebody adds a group to the pattern. `finditer` always gives match objects and
  `match.group(0)` is always the whole match.
- `if not match.group(0).endswith(":free")` is the rule, in one line, exactly as Addendum 02 words
  it.
- `f"{rel}:{number}: {match.group(0)} is missing ':free'"` is the `path:line: message` format every
  editor and every log viewer already knows how to turn into a clickable jump. Matching an existing
  convention is free and saves every future reader a step.
- `main` mirrors `lint_skills` exactly — optional argv, a returned `int`, and `raise
  SystemExit(main())` at the module boundary. Two linters with the same shape is one shape to learn
  ([2.3](../02-a-lint-is-a-test/2.3-the-exit-code-is-the-api.md)).

Now run it against the repository:

```bash
uv run python -m tools.lint_free_suffix; echo "exit: $?"
```

**Line by line:**

- `-m tools.lint_free_suffix` again, not a path, for the reason in
  [4.2](../04-wiring-the-gate/4.2-the-module-the-script-cannot-find.md) — although note that *this*
  file has no intra-package import, so it would in fact run either way. Use `-m` anyway: the two
  linters should be invoked identically, because an inconsistency in the gate is a thing somebody has
  to hold in their head.
- No argument, so it scans from `ROOT`, which is the repository root regardless of your working
  directory.

## When it breaks

**The scan set is too narrow and the rule silently stops applying.** Restrict `TEXT_SUFFIXES` to
`{".py"}` and re-run:

```text
free-suffix: every openrouter/ model string ends in ':free'
exit: 0
```

Green, on a repository containing ten unmarked occurrences of the wrong string. Nothing failed. The
lint answered exactly the question it was asked, and the question had quietly become a smaller one.
This is the most dangerous failure in the whole part because its symptom is a pass.

**The pattern stops at the first slash and invents a finding.** Drop the repeating group and the same
run reports:

```text
FAIL days/day-09-four-free-providers/LESSON.md:254: openrouter/z-ai is missing ':free'
```

on the line `free_only("openrouter/z-ai/glm-5.2:free")`, which is correct code. One false alarm on a
line that is right is more corrosive than one missed line that is wrong, because it teaches the
reader that the lint is unreliable.

**`dirnames = [...]` instead of `dirnames[:] = [...]`.** No error, no warning, no visible difference
except that the run gets much slower and starts reporting model strings from inside installed
packages:

```text
FAIL .venv/Lib/site-packages/litellm/... : openrouter/... is missing ':free'
```

The rebinding created a new local list and the walker kept its own. This is the single most common
mistake with a pruning walk, and the tell is always the same: findings from directories you thought
you had excluded.

**A binary file with a text suffix.**

```text
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 0: invalid start byte
```

Without the `try`, one committed `.txt` that is not text takes down the whole gate stage. Catching
it and continuing is right; catching everything and continuing is not.

## In production

**What a professional writes instead.** At company scale this check is not a bespoke script at all —
it is a custom rule in the linter the project already runs, so it inherits caching, per-directory
configuration, editor integration and the `# noqa` mechanism for free. In `ruff` that means a plugin;
in other ecosystems a rule file. The bespoke script is right *here*, for two reasons: it is twenty
lines against a plugin's build and release cycle, and — this is the reason that decides it — a linter
plugin only ever sees `.py` files, and half of this repository's model strings are in Markdown.

**What degrades at scale.** Reading every file on every run stops being free somewhere in the tens of
thousands of files. Two moves fix it and both are ordinary: restrict the scan to files changed since
the merge base when running on a branch, and keep the full scan for the main branch. The second is
essential — an incremental-only check never notices a violation introduced by a merge that touched no
scanned file. Under concurrency there is nothing to worry about here, because the lint only reads.

**The failure mode that only appears with real traffic** is drift in the *scan set* rather than in
the rule. Somebody adds a `config/` directory of `.env`-style files, or a `.jsonc`, and the rule
silently does not apply there. Nobody sees a failure. The professional countermeasure is to print
what was examined — *`889 files scanned, 10 findings`* — so the number is on screen every run and a
sudden drop is visible. That is the same argument as `lint_skills` printing its skill count
([2.3](../02-a-lint-is-a-test/2.3-the-exit-code-is-the-api.md)), and it is a good `TODO(me)`.

**The review comment a senior engineer leaves:** *"Nice, but this only walks `sutra/`. Our model
strings live in day documents too, and a string in a build brief is a string someone will paste into
code next week. Widen the scan set and deal with the false positives properly — don't narrow the rule
to make the output quiet."*

**The interview question:** *"You wrote a repository-wide lint. How did you decide what it reads?"*
The honest spoken answer: *"The scan set turned out to matter more than the pattern. The instinct is
to scan source files, and that was wrong for us — our model identifiers appear in documentation build
briefs, and a string in a build brief is one somebody copies into code. So we scan every text file we
own: source, Markdown, config. We exclude frozen history and the virtual environment, because
findings there aren't actionable, and we prune those directories during the walk rather than
filtering afterwards — that took the scan from about three seconds to half a second, because
otherwise you're still crawling every installed package. And we print the number of files scanned, so
if somebody adds a directory the rule silently stops covering, the count moves and somebody notices."*
