# 6.1 — Testing a callback without a model

## One-line answer

A callback is a plain function, so most of it is tested by calling it — and the one assertion that
catches [5.1](../05-failure-lab/5.1-the-note-that-became-the-result.md), *"the tool actually ran"*,
needs a whole agent run, which a scripted local model gives you for no key and no quota.

---

## The story

Learning to drive on an empty ground.

Before anybody puts you on a road, you spend a weekend on a bare patch of ground behind the stadium.
No traffic, no signals, nobody's bumper. You start, you stall, you start again. You find the biting
point about forty times.

Nothing about that ground is realistic. That is the entire value of it. On a real road you would
learn the same clutch in the same number of attempts, plus a great deal of adrenaline, plus somebody
else's insurance claim — and you would learn it *slower*, because you would be attending to five
things instead of one.

The empty ground is not a lesser version of driving. It is the only place where you can make the same
mistake forty times cheaply enough to learn from it.

---

## The idea in plain language

Testing an agent is usually expensive: a model call costs quota, takes a network round trip, and
returns something slightly different each time. That is a bad foundation for a test suite, and it is
why [Day 11, part 6.1](../../../day-11-tool-context/parts/06-in-production/6.1-a-tool-without-a-model.md)
tested a tool by calling it directly.

Callbacks split cleanly into two kinds of test, and only one of them needs an agent at all.

**Call the function.** A callback is a function with three or four parameters. Build the parameters,
call it, assert on the return value. This covers everything about *what it decides*: does the guard
block this query, does the observer return `None`, does the refusal carry the right fields. No agent,
no runner, no model, no session.

**Run the agent.** One question cannot be answered by calling the function: *did the tool actually
run?* That is a fact about the framework's behaviour given your return value, and the only honest way
to check it is to let the framework act. This is the assertion that goes red on
[5.1](../05-failure-lab/5.1-the-note-that-became-the-result.md), and no amount of unit testing the
callback in isolation will produce it — the poisoned observer returns a perfectly good dict, and every
assertion about that dict passes.

The second kind needs a model, and a **scripted model** — the `ScriptedModel` from
[1.3](../01-the-four-doors/1.3-none-means-carry-on.md) — is one. It is a real `BaseLlm` subclass, so
the real flow runs: real callbacks, real tool dispatch, real events, real session state. It just reads
its replies off a list instead of the network. Free, instant, and identical every time.

Three things you need to build a call-the-function test, and none of them are hard:

| Parameter | How to build one |
| --- | --- |
| `tool` | `FunctionTool(func=your_tool)` — a real tool object wrapping your real function |
| `args` | a plain dict, exactly what you expect the model to send |
| `tool_context` | ADK builds this from an `InvocationContext`, so for a pure decision test, pass a small stand-in |

That third row is the awkward one, and it is worth being honest about rather than pretending. A real
`Context` needs an `InvocationContext`, which needs a session, a session service and an agent — a lot
of machinery for a function that only reads `state`. The pragmatic answer for a guard that touches
state is to test it through a scripted-model run instead, where ADK builds a genuine context for you.
For a guard that does not touch state, a stand-in with a `state` dict is enough and is what the test
below uses.

---

## Why Sutra needs it

**Principle 11: evals are tests, and every day ends with a check that can go RED.** Today's check has
to be able to catch today's failure, and today's failure produces no exception.

**The whole suite must run on a fresh clone with no `.env`.** Every assertion below costs zero
requests and needs no key, which is what makes it something you can run on every commit rather than
something you run when you remember.

**Day 25 is evaluation proper.** By then you will be grading an agent's *answers*, which is a
different and much harder problem. Grading a callback's *decisions* is the easy half, and it should
be done in the cheap place so that Day 25's budget goes on the hard half.

## The mechanism

The day's eval, in full. Five assertions, no key, no quota.

```python
# tests/test_callbacks.py - the day's eval. Zero model calls, no .env required.
import asyncio
from collections.abc import AsyncGenerator

import pytest
from google.adk.agents import LlmAgent
from google.adk.models import BaseLlm, LlmRequest, LlmResponse
from google.adk.runners import InMemoryRunner
from google.adk.tools import FunctionTool
from google.genai import types

from sutra.desk.callbacks import audit_tool_calls, block_forbidden_queries
from sutra.desk.tools import search_kb

CREDENTIAL_QUERY = "how to reset the admin password"
ORDINARY_QUERY = "duplicate charge on renewal"


class Stub:
    """The smallest thing a state-free callback can be handed."""

    def __init__(self) -> None:
        self.state: dict[str, object] = {}
        self.agent_name = "desk"
        self.invocation_id = "test-invocation"


class ScriptedModel(BaseLlm):
    """A model that reads its replies off a list. No network, no key, no quota."""

    replies: list[types.Content] = []
    calls: int = 0

    async def generate_content_async(
        self, llm_request: LlmRequest, stream: bool = False
    ) -> AsyncGenerator[LlmResponse, None]:
        turn = self.replies[min(self.calls, len(self.replies) - 1)]
        self.calls += 1
        yield LlmResponse(content=turn)


def test_the_observer_returns_nothing() -> None:
    """5.1: an observer that returns a value replaces every tool result."""
    tool = FunctionTool(func=search_kb)
    assert audit_tool_calls(tool=tool, args={"query": ORDINARY_QUERY}, tool_context=Stub()) is None


def test_an_ordinary_query_is_not_blocked() -> None:
    """3.2: the guard's carry-on path. Returning anything here vetoes real work."""
    tool = FunctionTool(func=search_kb)
    assert (
        block_forbidden_queries(tool=tool, args={"query": ORDINARY_QUERY}, tool_context=Stub())
        is None
    )


def test_a_credential_query_is_blocked_legibly() -> None:
    """3.2: a refusal the model can branch on and act on."""
    tool = FunctionTool(func=search_kb)
    refusal = block_forbidden_queries(
        tool=tool, args={"query": CREDENTIAL_QUERY}, tool_context=Stub()
    )
    assert refusal is not None
    assert refusal["status"] == "blocked"
    assert refusal["next"], "a refusal with no way forward becomes a retry loop"


def test_the_refusal_does_not_echo_the_query() -> None:
    """3.2: a refusal that quotes the input puts the credential in the transcript."""
    tool = FunctionTool(func=search_kb)
    refusal = block_forbidden_queries(
        tool=tool, args={"query": CREDENTIAL_QUERY}, tool_context=Stub()
    )
    assert "password" not in " ".join(str(v) for v in refusal.values()).lower()


def test_the_tool_actually_runs_on_the_ordinary_path() -> None:
    """5.1: the only assertion that catches an observer with a stray return."""
    ran: list[str] = []

    def search_kb_spy(query: str) -> dict:
        """Search the knowledge base for articles matching a query."""
        ran.append(query)
        return {"status": "ok", "hits": []}

    agent = LlmAgent(
        name="desk",
        model=ScriptedModel(
            model="scripted",
            replies=[
                types.Content(
                    role="model",
                    parts=[
                        types.Part(
                            function_call=types.FunctionCall(
                                name="search_kb_spy", args={"query": ORDINARY_QUERY}
                            )
                        )
                    ],
                ),
                types.Content(role="model", parts=[types.Part(text="done")]),
            ],
        ),
        instruction="Triage the ticket.",
        tools=[search_kb_spy],
        before_tool_callback=[audit_tool_calls, block_forbidden_queries],
    )

    async def run() -> None:
        runner = InMemoryRunner(agent=agent)
        session = await runner.session_service.create_session(
            app_name=runner.app_name, user_id="test"
        )
        async for _ in runner.run_async(
            user_id="test",
            session_id=session.id,
            new_message=types.Content(role="user", parts=[types.Part(text="charged twice")]),
        ):
            pass

    asyncio.run(run())
    assert ran == [ORDINARY_QUERY], "the callbacks vetoed a call they should have let through"


# TODO(me): the sixth test - does the guard block the queries that MATTER?
# Every query above is one you thought of. See Day 25.
@pytest.mark.skip(reason="TODO(me): decide the corpus, then delete this skip")
def test_the_guard_catches_real_attempts() -> None:
    raise NotImplementedError
```

**Line by line:**

- The first four tests **call the callback directly**, with keyword arguments — the same way ADK does
  ([1.2](../01-the-four-doors/1.2-the-names-are-the-contract.md)). Calling positionally would pass even
  if the parameter names were wrong, so the test would not catch the failure that actually happens.
- `Stub` is a five-line class, not a mock library. It has the three attributes a state-free callback
  reads, and nothing else — so the day somebody's callback starts reading `tool_context.session`, the
  test fails loudly with an `AttributeError` rather than quietly returning a `Mock` that is truthy.
  That is the argument for a hand-written stub over `unittest.mock.Mock` in exactly this position.
- `FunctionTool(func=search_kb)` is the **real** tool object wrapping the **real** tool function. A
  fake with a `.name` attribute would also work and would not catch a callback that reaches for
  `tool.description`.
- `test_the_observer_returns_nothing` is the cheapest test in the file and the one that goes red the
  moment somebody adds `return summary`. One line, and it is the direct counter to
  [5.1](../05-failure-lab/5.1-the-note-that-became-the-result.md).
- `test_an_ordinary_query_is_not_blocked` tests the **carry-on** path, which is the path taken by
  almost every real call and the one nobody thinks to test. It is also the assertion that catches
  [4.1](../04-where-the-rule-bites/4.1-truthy-is-not-the-same-as-not-none.md)'s empty-dict bug, because
  `{} is None` is `False`.
- `assert refusal["next"], "..."` — a message on the assertion, because a bare `assert refusal["next"]`
  failing tells the next reader nothing about *why* an empty string is a bug.
- `test_the_refusal_does_not_echo_the_query` joins the refusal's **values** and searches them. It is a
  crude check and it is the right kind of crude: it will still be true after somebody rewrites the
  message, because it asserts a property rather than a string.
- `ScriptedModel` is duplicated here rather than imported from `lab/`. That is deliberate: `lab/` is a
  scratchpad that is not on the import path and may be deleted, while a test suite must stand alone on
  a fresh clone. When a second day needs it, it moves to `tests/` — see *In production*.
- `search_kb_spy` is a **local** function with a `ran` list closed over, so there is no module-level
  state to leak between tests — [1.1](../01-the-four-doors/1.1-the-function-you-never-call.md)'s
  mutable-default trap, avoided by construction.
- `before_tool_callback=[audit_tool_calls, block_forbidden_queries]` — the real chain in the real
  order, so this test also covers [1.4](../01-the-four-doors/1.4-a-list-not-just-a-function.md)'s
  ordering. If somebody puts the guard first, the audit stops running and this test still passes,
  which is a real limitation worth knowing about rather than papering over.
- `assert ran == [ORDINARY_QUERY]` compares the whole list, not `len(ran) == 1`. It catches a callback
  that mutated `args` as well as one that vetoed the call.
- `asyncio.run(run())` inside a synchronous test, rather than `pytest.mark.asyncio` — because that
  marker needs `pytest-asyncio`, which is not in `pyproject.toml`, and Principle 7 says a package
  arrives on the day it is first used. One `asyncio.run` avoids a dependency.
- The final `TODO(me)` is skipped rather than deleted, so `pytest -q` prints `1 skipped` and the gap is
  visible in every run. A gap you can see is a gap somebody will close.

How to watch each one go RED before it goes green:

```bash
uv run python -m pytest tests/test_callbacks.py -q -m "not live"   # RED: sutra/desk/callbacks.py is empty
# ... write the module from the hub's §4 ...
uv run python -m pytest tests/test_callbacks.py -q -m "not live"   # green
```

**Line by line:**

- `uv run` rather than a bare `python`, so the command uses the locked environment rather than whatever
  interpreter happens to be on your path — the Day 0 rule, and the reason a fresh clone behaves the
  same as your machine.
- `-m "not live"` deselects anything marked `live` in `pyproject.toml`'s markers. Nothing in this file
  is marked live, and the flag is here anyway because it is the project's standing invocation: a test
  that needs a key should be skipped by default, and typing the filter every time is what keeps that
  true.
- The **first** line is the point. Running it before the module exists gives a collection error, not a
  passing suite, which is Principle 11 — a check that cannot go red has not been tested.
- `-q` because the useful output is which test failed, not the progress dots.

Then break each one on purpose, and read what it says:

| Break this | Which test goes red | What it is really telling you |
| --- | --- | --- |
| add `return summary` to `audit_tool_calls` | 1 **and** 5 | an observer became an override, and the tool stopped running |
| make the guard `return {}` on the carry-on path | 2 and 5 | falsy is not `None` at this door ([4.1](../04-where-the-rule-bites/4.1-truthy-is-not-the-same-as-not-none.md)) |
| drop the `next` field from the refusal | 3 | the model's only remaining move is to retry the forbidden call |
| put the query into the refusal message | 4 | the credential is now in the transcript, forever |
| rename a parameter to `arguments` | all five | the names are the contract ([1.2](../01-the-four-doors/1.2-the-names-are-the-contract.md)) |

Only the fifth row fails everything, which is the point of having the first four: they tell you *what*
broke, and the last one tells you *that* something did.

## When it breaks

**💥 The stub that was too clever.**

```text
AssertionError: assert None is None
```

— passing, when it should not. You used `unittest.mock.Mock()` as the tool context. Every attribute
access returns a new truthy `Mock`, so a guard that does
`if tool_context.state.get("blocked"): return refusal` takes the wrong branch and your test asserts the
wrong behaviour, green. A five-line stub cannot do this to you.

**💥 The test that needed a key.**

```text
ValueError: Missing key inputs argument! To use the Google AI API, provide (`api_key`) arguments.
```

You built the agent with `model="gemini-3.7-flash"` out of habit. A test that constructs a real model
client fails on a fresh clone and on CI. The scripted model is not an optimisation here; it is what
makes the test runnable at all.

**💥 The scripted model that ran out of turns.**

Nothing raises, because `ScriptedModel` clamps to its last reply — a deliberate choice in
[1.3](../01-the-four-doors/1.3-none-means-carry-on.md). If your agent makes more model calls than you
scripted, it will loop on the final reply. If that reply is a function call, you have written an
infinite tool loop that ends at `max_llm_calls`. Script one more turn than you expect, and make the
last one plain text.

## In production

**What a professional writes instead of the teaching version** promotes the scripted model out of the
test file the moment a second test file wants it:

```python
# tests/scripted.py - the shared test double. Imported, never duplicated.
class ScriptedModel(BaseLlm):
    """A model that reads its replies off a list. No network, no key, no quota."""
```

**Line by line:**

- `tests/scripted.py` rather than `sutra/testing.py` — a test double is not part of the product, and
  shipping one inside the package invites production code to import it.
- The duplication in today's test file is the honest first step: one copy is not a problem, and moving
  it before there is a second user is speculative structure. **TODO(me):** decide, when Day 25 arrives
  and needs the same double, whether it moves here or whether the eval framework replaces it.

**What degrades at scale** is coverage of the carry-on path. Teams write a test per rule — blocked
this, blocked that — and end up with fifteen assertions about refusals and none about the ordinary
request. Then a change makes the guard return a falsy value on every call, every refusal test still
passes, and the agent quietly stops using its tools. Assert the negative path first; it is the one
that runs a thousand times more often.

**The failure that only shows with real traffic** is the callback that was tested against fixtures you
wrote. Test 3 proves the guard blocks `"how to reset the admin password"`, which you chose. It proves
nothing about the query a real customer sends, and the skipped sixth test says so out loud rather than
letting a green suite imply a guarantee it cannot make. A test suite that quietly overstates its
coverage is worse than a smaller one that is honest about its edges.

**The review comment a senior engineer leaves:** *"Add the negative case. Right now every test here
asserts we block something, so a guard that blocks everything is green."*

**The interview question:** *"How do you test agent code without burning quota?"* The answer that shows
you have a suite: "Two layers. Callbacks and tools are plain functions, so most assertions are just
calling them with the keyword arguments the framework uses — no agent, no runner, no key. The one
thing that needs a real run is whether the framework actually executed the tool, because that depends
on my return value in a way I can't assert from outside, so I subclass the model base class with
something that reads canned replies off a list. That gives me the real flow — real callbacks, real
dispatch, real session state — for zero requests and with identical results every time. The assertion
that earns its place is the boring one: on an ordinary request, did the tool run? That's the only test
that catches a logging callback with a stray `return` in it, and that failure produces no error at
all."
