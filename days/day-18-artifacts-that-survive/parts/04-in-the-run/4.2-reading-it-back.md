# 4.2 — Reading it back

## One-line answer

`await tool_context.load_artifact(filename)` returns a `Part` or `None`, and the tempting shortcut —
`{artifact.name}` in an instruction — puts the **repr of the whole `Part` object** into your prompt
rather than the file's text.

## The story

The ticket from the dry cleaner.

It is a small numbered stub and it does exactly one thing: it turns into your coat. You do not describe
the coat, you do not remember which rail it is on, and the person behind the counter does not either.
The number is the whole conversation.

What makes it work is that the number is *specific*. Not "a grey coat" — a number that identifies one
item. Hand over a description instead and you get a discussion; hand over the number and you get the
coat.

## The idea in plain language

Reading is the mirror of [4.1](4.1-saving-from-a-tool.md):

```
part = await tool_context.load_artifact(filename)            # latest
part = await tool_context.load_artifact(filename, version=0) # a specific one
names = await tool_context.list_artifacts()                  # what is visible here
```

Three things to hold on to.

**You get a `Part`, not bytes and not text.** The bytes are `part.inline_data.data`, and turning them
into a string is your `decode("utf-8")` — the store does not know your encoding, only your MIME type.

**`None` means "not here", for two different reasons.** A missing file and a missing version look the
same ([2.1](../02-versions/2.1-every-save-is-a-new-version.md)), which is why the reference kept in
state should be a *filename and version* rather than a filename alone.

**And there is a shortcut in instructions that looks perfect and is not.**
[Day 17](../../../day-17-state-scopes-and-lifetimes/parts/04-state-in-the-prompt/4.2-the-brace-that-raises.md)
noted that a placeholder can name an artifact: `{artifact.triage-4521.md}`. It works, in the sense that
the substitution happens and the run proceeds. What it substitutes is `str(part)` — the string form of
the whole `Part` object, every unset field included. The measurement below shows what lands in the
prompt, and it is not the note.

So the honest way to put a file's contents in front of a model is to load it in a tool, decode it,
and return the text — or to let the framework do it properly with the `load_artifacts` tool, which is
[4.3](4.3-what-the-model-cannot-see.md).

## Why Sutra needs it

Because the second half of every artifact is somebody reading it, and Sutra's readers are tools.

The concrete case is the follow-up turn: an engineer asks *"what did you put in the note?"*, and a tool
loads `state["note_file"]` at `state["note_version"]`, decodes it, and returns the text. That is three
lines and it is correct. The alternative — templating the artifact into the instruction — produces a
prompt full of `None`s, costs tokens for nothing, and looks fine in the code.

It matters again on Day 20, where compaction summarises old turns. The summary of a document is
produced by loading the document, not by hoping it is still in the context window.

## The mechanism

Loading a saved artifact, and the templating shortcut measured next to it:

```python
# days/day-18-artifacts-that-survive/lab/read_it_back.py
"""Reading an artifact back, and the templating shortcut that does not work. Zero model calls."""

import asyncio
from types import SimpleNamespace

from google.adk.artifacts import InMemoryArtifactService
from google.adk.utils.instructions_utils import inject_session_state
from google.genai import types

APP, USER, SESSION = "sutra", "engineer_a", "ticket-4521"


async def main() -> None:
    service = InMemoryArtifactService()
    await service.save_artifact(
        app_name=APP,
        user_id=USER,
        session_id=SESSION,
        filename="triage-4521.md",
        artifact=types.Part(
            inline_data=types.Blob(data=b"severity: high\n", mime_type="text/markdown")
        ),
    )

    part = await service.load_artifact(
        app_name=APP, user_id=USER, session_id=SESSION, filename="triage-4521.md"
    )
    print("bytes  :", part.inline_data.data)
    print("as text:", part.inline_data.data.decode("utf-8").strip())

    context = SimpleNamespace(
        _invocation_context=SimpleNamespace(
            session=SimpleNamespace(state={}, id=SESSION, app_name=APP, user_id=USER),
            artifact_service=service,
        )
    )
    rendered = await inject_session_state("The note says: {artifact.triage-4521.md}", context)
    print("templated length:", len(rendered), "characters")
    print("templated starts:", rendered[:70], "...")
    try:
        await inject_session_state("Missing: {artifact.nope.md}", context)
    except KeyError as error:
        print("missing artifact:", type(error).__name__ + ":", error)


asyncio.run(main())
```

**Line by line:**

- The save is [1.1](../01-not-a-state-key/1.1-the-thing-state-cannot-hold.md)'s, so the file exists
  before anything reads it.
- `part.inline_data.data` then `.decode("utf-8")` — the two steps between an artifact and a string.
  There is no `part.text` for an artifact; `text` is a different field of `Part` and it is `None` here.
- `SimpleNamespace(...)` — the fake context from
  [17.4.2](../../../day-17-state-scopes-and-lifetimes/parts/04-state-in-the-prompt/4.2-the-brace-that-raises.md),
  extended with an `artifact_service`, because the artifact branch of the substitution engine reaches
  for `session.app_name`, `session.user_id` and `session.id` as well as the service.
- `"{artifact.triage-4521.md}"` — the documented syntax: the literal prefix `artifact.` followed by the
  filename, dots and all.
- `len(rendered)` printed **before** the text, because the length is the finding: a fifteen-byte note
  should not produce a three-hundred-character prompt fragment.
- The `try` block asks what a missing artifact does, which is different from a missing state key: both
  raise `KeyError`, and this one names the artifact.

**Line by line:**

- No model, no key, no network.

Measured on `google-adk` 2.7.1 on 2026-09-03:

```text
bytes  : b'severity: high\n'
as text: severity: high
templated length: 361 characters
templated starts: The note says: media_resolution=None code_execution_result=None execut ...
```

The first two lines are the correct way. The third and fourth are the shortcut: fifteen bytes of note
became **361 characters**, beginning with a list of the `Part` fields that are not set. The model would
be shown `media_resolution=None code_execution_result=None executable_code=None …` and, somewhere
inside it, a `Blob` holding the bytes.

And the missing case:

```text
missing artifact: KeyError: 'Artifact nope.md not found.'
```

Same cliff as a missing state key
([17.4.2](../../../day-17-state-scopes-and-lifetimes/parts/04-state-in-the-prompt/4.2-the-brace-that-raises.md)):
raised inside the runtime, so in a real run it takes the turn down without reaching your code. The
optional form `{artifact.nope.md?}` is accepted here too and substitutes an empty string instead.

## When it breaks

**`AttributeError: 'NoneType' object has no attribute 'inline_data'`**

The load returned `None`. Two causes, indistinguishable
([2.1](../02-versions/2.1-every-save-is-a-new-version.md)): the filename is wrong — including a missing
`user:` prefix ([3.1](../03-two-scopes/3.1-the-user-filename.md)) — or the version is. Guard, and say
which one you are handling.

**`UnicodeDecodeError: 'utf-8' codec can't decode byte …`**

Calling `.decode("utf-8")` on bytes that are not text. It is the same class of mistake as ignoring the
MIME type ([1.2](../01-not-a-state-key/1.2-a-part-not-a-file.md)): check `mime_type` before deciding
that an artifact is a string, because a PNG will happily be handed to you and will not decode.

**The prompt got enormous and nobody knows why.** No error. Somebody templated an artifact into an
instruction, and every turn now carries three hundred characters of `None`s plus a base64-ish blob.
Day 19 is about what earns a place in the context window; this is a way to lose that argument by
accident.

## In production

**Load in a tool, decode explicitly, and return only what is needed.**

The version a professional writes has a small reader — filename in, text out, `None` handled — and it
does not return the whole file to the model by default. A 200-kilobyte log loaded into an answer is
200 kilobytes of context, and the reason artifacts exist is that they do not have to be carried
([1.1](../01-not-a-state-key/1.1-the-thing-state-cannot-hold.md)).

**What changes at scale** is that reading becomes the expensive half. Saves are one write; reads happen
in every later turn that mentions the document, so the read path is where caching, partial reads and
"summarise once and keep the summary" all end up. That summary, incidentally, is a fine thing to keep
in state.

**What fails only under real traffic** is the reference that outlived its artifact. State says
`note_file: "triage-4521.md"`, the artifact was deleted, and the load returns `None` in a turn where
the user is expecting an answer. The pair of stores has to be reasoned about together: deleting an
artifact means clearing whatever points at it.

**The review comment**: *"this templates the artifact into the instruction. That puts the `Part` repr in
the prompt — load it in a tool and return the text."*

**The interview question**: *"how do you get a stored file in front of the model?"* The answer that
shows you have done it: *"load it in a tool and return the part of it that matters, or use the
framework's `load_artifacts` tool, which inserts it into one request properly. What you do not do is
template it into the instruction — that stringifies the whole object."*
