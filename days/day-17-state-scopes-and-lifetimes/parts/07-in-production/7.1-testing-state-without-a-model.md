# 7.1 — Testing state without a model

## One-line answer

Every claim this day makes is assertable with no key and no network — scopes, trimming, the lost
write, the tool's delta, the declared keys and the instruction's placeholders — and the tests that
check them all read back **through the session service**, because reading the object you just wrote to
is what hides the day's worst bug.

## The story

Counting the till before the shop opens.

Nobody has bought anything. There are no customers, the door is still locked, and the person counting
the drawer is not testing whether the shop works — they are checking one specific thing: that the float
is what the sheet says it is.

It takes a couple of minutes and it catches the thing that actually goes wrong, which is never a
dramatic robbery. It is a twenty that went in the wrong compartment on Saturday, found on Monday
morning by somebody counting, before the first customer makes it complicated.

## The idea in plain language

Day 16's tests could not fake a built-in tool, so they asserted the outgoing request instead. Today has
the opposite situation: **almost everything is testable**, because state is a data structure and its
rules are enforced by code that needs no model.

Six claims, six tests, no requests:

| The claim | Where it came from |
| --- | --- |
| a new session keeps `user:` and `app:` and loses the rest | [2.1](../02-four-lifetimes/2.1-the-prefix-is-the-lifetime.md) |
| `temp:` never reaches storage, and is trimmed from the event | [2.4](../02-four-lifetimes/2.4-why-temp-exists.md) |
| a direct write to a fetched session is lost | [6.1](../06-failure-lab/6.1-the-write-that-was-never-written.md) |
| a tool's writes arrive as one delta on one event | [3.1](../03-three-safe-writes/3.1-writing-from-inside-a-tool.md) |
| every unprefixed key Sutra uses is declared | [5.1](../05-a-schema-for-state/5.1-declaring-the-boxes.md) |
| the desk's instruction survives an empty state | [4.2](../04-state-in-the-prompt/4.2-the-brace-that-raises.md) |

Two of those are not ordinary unit tests, and they are the interesting ones.

**The third asserts that something does *not* work.** It performs the anti-pattern and asserts the
value is gone. That reads oddly the first time — a test that checks a bug still bugs — and it earns its
place: it is executable documentation of the rule, and if a future version of ADK ever makes the direct
write stick, this test goes red and tells you the day's advice has changed.

**The sixth renders an instruction.** It has no agent and no model: it calls the same substitution
function the runtime calls, against an empty state, and asserts the result. That is the cheapest
possible defence against [4.2](../04-state-in-the-prompt/4.2-the-brace-that-raises.md)'s cliff, where a
missing key produces a turn with no answer and no exception.

## Why Sutra needs it

Because Phase 3's gate is *state survives restarts*, and Day 47 is where that becomes true. Between now
and then, these tests are what stop the semantics from drifting while nobody is looking.

There is a sharper reason. Three separate mechanisms in this day fail **silently and in a background
thread**: a schema violation ([5.1](../05-a-schema-for-state/5.1-declaring-the-boxes.md)), an
`output_schema` mismatch ([3.2](../03-three-safe-writes/3.2-the-carbon-copy.md)) and a missing
placeholder ([4.2](../04-state-in-the-prompt/4.2-the-brace-that-raises.md)). None of them will ever be
caught by an integration test that only checks that a reply came back, because a reply does come back —
an empty one. They are caught by asserting state directly, which is what this file does.

## The mechanism

One new file. It imports `sutra/state.py`, which is today's build, so **it is red until you write that
module**.

```python
# tests/test_state.py
"""Day 17 - what can be asserted about state without a model."""

from __future__ import annotations

import asyncio
from types import SimpleNamespace

import pytest
from google.adk.agents import Agent
from google.adk.events import Event, EventActions
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.adk.utils.instructions_utils import inject_session_state
from google.genai import types
from scripted import ScriptedModel, call, text

from sutra.state import (
    LAST_TRIAGE,
    RAW_SEARCH,
    REFUND_WINDOW,
    REPLY_STYLE,
    SEVERITY,
    TICKET_ID,
    DeskState,
    record_triage,
)

APP, USER = "sutra", "engineer_a"


def _service_with(delta: dict):
    """A service and a session carrying `delta`, written the safe way (3.3)."""
    service = InMemorySessionService()
    session = service.create_session_sync(app_name=APP, user_id=USER)
    asyncio.run(
        service.append_event(
            session=session,
            event=Event(author="test", actions=EventActions(state_delta=delta)),
        )
    )
    return service, session


def test_the_prefixes_carry_the_lifetimes_we_think() -> None:
    """2.1: a new session keeps user: and app: and loses the rest."""
    service, session = _service_with(
        {SEVERITY: "high", REPLY_STYLE: "short", REFUND_WINDOW: 30, RAW_SEARCH: "blob"}
    )
    fresh = service.create_session_sync(app_name=APP, user_id=USER)
    assert set(fresh.state) == {REPLY_STYLE, REFUND_WINDOW}


def test_temp_keys_never_reach_storage() -> None:
    """2.4: temp: is live during the invocation and trimmed from the event."""
    service, session = _service_with({RAW_SEARCH: "blob", SEVERITY: "high"})
    stored = service.get_session_sync(app_name=APP, user_id=USER, session_id=session.id)
    assert RAW_SEARCH not in stored.state
    assert stored.events[0].actions.state_delta == {SEVERITY: "high"}


def test_a_direct_write_is_lost() -> None:
    """6.1: assigning to a fetched session changes a copy and nothing else."""
    service, session = _service_with({SEVERITY: "high"})
    fetched = service.get_session_sync(app_name=APP, user_id=USER, session_id=session.id)
    fetched.state["escalated"] = True
    again = service.get_session_sync(app_name=APP, user_id=USER, session_id=session.id)
    assert "escalated" not in again.state


def test_record_triage_writes_both_keys_through_an_event() -> None:
    """3.1: a tool's writes arrive as one delta on one event."""
    service = InMemorySessionService()
    session = service.create_session_sync(app_name=APP, user_id=USER)
    agent = Agent(
        name="desk",
        model=ScriptedModel(
            model="scripted",
            replies=[[call("record_triage", severity="high", ticket_id=4521)], [text("done")]],
        ),
        tools=[record_triage],
        output_key=LAST_TRIAGE,
    )
    runner = Runner(app_name=APP, agent=agent, session_service=service)
    for _ in runner.run(
        user_id=USER,
        session_id=session.id,
        new_message=types.Content(role="user", parts=[types.Part(text="triage 4521")]),
    ):
        pass
    stored = service.get_session_sync(app_name=APP, user_id=USER, session_id=session.id)
    assert stored.state[SEVERITY] == "high"
    assert stored.state[TICKET_ID] == 4521
    assert stored.state[LAST_TRIAGE] == "done"
    deltas = [e.actions.state_delta for e in stored.events if e.actions and e.actions.state_delta]
    assert {SEVERITY: "high", TICKET_ID: 4521} in deltas


def test_every_unprefixed_key_is_declared() -> None:
    """5.1: a key nobody declared is a key the runtime will refuse."""
    keys = {SEVERITY, TICKET_ID, LAST_TRIAGE}
    assert keys <= set(DeskState.model_fields)


def test_the_desk_instruction_survives_an_empty_state() -> None:
    """4.2: a placeholder for a key that is not set yet must be optional."""
    instruction = "This ticket is severity {severity?}. Reply {user:reply_style?}."
    context = SimpleNamespace(
        _invocation_context=SimpleNamespace(
            session=SimpleNamespace(state={}), artifact_service=None
        )
    )
    assert asyncio.run(inject_session_state(instruction, context)) == (
        "This ticket is severity . Reply ."
    )


@pytest.mark.skip(reason="TODO(me): needs DatabaseSessionService, which arrives on day 47")
def test_state_survives_a_restart() -> None:
    """Phase 3's gate, and the one claim an in-memory service cannot make."""
    raise AssertionError("write me on day 47")
```

**Line by line:**

- `from scripted import ScriptedModel, call, text` — the test double that moved into `tests/` on
  [Day 15](../../../day-15-toolsets-and-openapi/LESSON.md), so no test imports from a day folder.
- `_service_with(delta)` — one helper that builds a session already carrying state, written through
  `append_event` because that is the only write that counts
  ([6.1](../06-failure-lab/6.1-the-write-that-was-never-written.md)).
- `asyncio.run(...)` inside the helper — `append_event` is async and the tests are sync. One `asyncio.run`
  per call is fine here and keeps the tests readable; a project with many async tests would reach for
  `pytest-asyncio` instead, which is a dependency today does not need.
- `set(fresh.state) == {REPLY_STYLE, REFUND_WINDOW}` — an **exact set**, not a subset. Subset assertions
  pass when a key leaks into the wrong scope, which is precisely the bug
  ([2.1](../02-four-lifetimes/2.1-the-prefix-is-the-lifetime.md)).
- `stored.events[0].actions.state_delta == {SEVERITY: "high"}` — asserting the **event's** delta, not
  just the state, so the test proves the trim rather than only its consequence.
- `fetched.state["escalated"] = True` followed by `assert "escalated" not in again.state` — the test
  that asserts a failure. Rename it and a reader will think it is a bug.
- `assert stored.state[TICKET_ID] == 4521` — an integer, on purpose: the schema will not convert for
  you ([5.2](../05-a-schema-for-state/5.2-what-the-schema-does-not-do.md)), so the tool must, and this
  is the assertion that says so.
- `keys <= set(DeskState.model_fields)` — subset, because the model may declare more than the desk
  currently writes. The direction that matters is that nothing written is undeclared.
- `@pytest.mark.skip(reason="TODO(me): ...")` — the one claim this file cannot make. Phase 3's gate is
  *state survives restarts*, an in-memory service cannot survive one, and pretending otherwise would be
  the dishonest kind of green.

**Line by line:**

Then break each thing on purpose. These were **measured**, each mutation applied on its own to a green
suite, on 2026-09-03:

| Break this | Which test goes red | What it is telling you |
| --- | --- | --- |
| `REPLY_STYLE = "reply_style"` (drop `user:`) | the prefixes test | the prefix *is* the lifetime (2.1) |
| `RAW_SEARCH = "raw_search"` (drop `temp:`) | the trimming test | the intermediate is now persisted for ever (2.4) |
| `state[TICKET_ID] = str(ticket_id)` | the `record_triage` test | the schema validates, it does not convert (5.2) |

Each mutation is one character to a few characters, and each is a bug that would otherwise be found by
a reader of a later conversation.

## When it breaks

**The first run fails at collection, and it should.**

```text
ModuleNotFoundError: No module named 'sutra.state'
```

Not a broken test — an unwritten module.

**A test passes because it asserted the wrong object.**

```python
session.state["severity"] = "high"
assert session.state["severity"] == "high"  # passes, and proves nothing
```

**Line by line:**

- The write is [6.1](../06-failure-lab/6.1-the-write-that-was-never-written.md)'s forbidden one.
- The assertion reads the same object, so it agrees with the write.
- Nothing here touches the service, so the test would pass on a system where every write is discarded.
- The rule: **assert through the service.** `get_session_sync(...)` and then check, always.

**`RuntimeError: asyncio.run() cannot be called from a running event loop.** Raised if you call the
helper from inside an async test. Either keep the tests synchronous, as here, or make them all async
and await directly — mixing the two is where this appears.

## In production

**Test the store's rules once, and the code's use of them everywhere.**

The version a professional writes separates the two. The rules — scopes, trimming, the lost write — are
properties of the framework, and one test each is enough to pin the version's behaviour and to notice
an upgrade that changes it. The uses — *this* tool writes *these* keys with *these* types — deserve a
test per fact, because that is where a change actually breaks something.

**What changes at scale** is that state assertions become the fastest tests you own. They need no model,
no network and no fixtures beyond a service, so a suite of a hundred of them runs in a second and
catches the majority of agent regressions, which are far more often about the wrong value in the wrong
key than about the model saying something unexpected.

**What fails only under real traffic** is everything this file cannot see: whether the model actually
calls `record_triage`, whether it passes a sensible severity, whether a long conversation grows state
without bound. The first two need a live model and belong in Day 79's evals; the third is a size
assertion worth adding the day a session gets big.

**The review comment**: *"this test writes state on the session object and asserts on the same object.
Read it back through the service or it proves nothing."*

**The interview question**: *"how do you test an agent's memory without calling a model?"* The answer
that shows you have done it: *"state is a data structure with rules — scopes, deltas, trimming — so you
assert the rules directly through the session service, and you keep a scripted model for the cases
where a tool has to actually run."*
