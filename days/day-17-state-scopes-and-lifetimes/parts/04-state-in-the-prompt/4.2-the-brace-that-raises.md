# 4.2 — The brace that raises

## One-line answer

A placeholder for a key that is not in state raises `KeyError` while the request is being built — and
the exception does not reach your loop, so what you actually see is an agent that produced no answer
at all.

## The story

The vending machine and the torn note.

The note is legal tender. It is the right note, it is yours, and the top corner has come away where it
was folded in a pocket. You feed it in, the rollers take it half way, hold it for a second, and push it
back out.

There is no partial outcome. You do not get a partial packet of crisps, or the crisps with a note
explaining that payment was incomplete. The machine either takes the note and works, or refuses the
whole transaction — and the refusal is silent, unexplained, and identical to the refusal it gives for a
note from a different country.

## The idea in plain language

[4.1](4.1-state-steers-the-next-turn.md) showed the happy case. This is the rest of the truth about
that substitution, and every line of it is a rule in `instructions_utils.py` in `google-adk` 2.7.1.

The engine scans the instruction for `{...}`, and for each one decides what to do by looking at the
name inside:

| What you wrote | State | What happens |
| --- | --- | --- |
| `{severity}` | present | replaced with `str(value)` |
| `{severity}` | **absent** | **`KeyError`** — the whole call fails |
| `{severity?}` | absent | replaced with the empty string |
| `{severity}` | present, `None` | replaced with the empty string |
| `{user:reply_style}` | present | replaced — a known prefix plus an identifier is a valid name |
| `{"severity": "high"}` | — | **left exactly as written** — not a valid state name |
| `{not-an-identifier}` | — | left exactly as written |
| `{artifact.notes.txt}` | — | loads an **artifact**, which is tomorrow's subject |

Two rows are load-bearing in opposite directions.

**The `KeyError` row is a cliff.** Not a warning, not a blank: the request never gets built. And the
failure is worse than a raised exception, because of where it is raised — the substitution happens
inside the runtime while assembling the model call, and the exception does not travel back out to the
code iterating over events. What your caller sees is a run that finished having produced nothing.

**The "left exactly as written" rows are a mercy.** Any brace whose contents are not a valid state name
is passed through untouched, which is why an instruction containing a JSON example does not explode.
The test is exactly Python's `isidentifier()`, optionally after one of the three known prefixes — so
`{severity}` is a placeholder, `{"severity": "high"}` is not, and `{ticket-id}` is not.

The escape hatch, when a template is not enough: an instruction may be a **function** rather than a
string — an `InstructionProvider`, which is given a read-only context and returns the text. Inside it
you can read state yourself, decide what to include, and call `inject_session_state` explicitly on the
parts you want templated. That is also the supported answer for an instruction that must contain
literal braces.

## Why Sutra needs it

Because Sutra's instruction is about to contain placeholders for keys that are not always set, and the
default behaviour for "not set" is to break the turn.

The concrete case is today's build. `{severity}` is meaningful once triage has run and absent on the
first turn of every conversation, which is exactly when the desk is most needed. Written naively, the
desk raises on the first message of every ticket. Written with `{severity?}`, it degrades to a blank —
and then the instruction has to make sense with a hole in it, which is a sentence you have to write
deliberately.

This also matters for Day 21's error handling, which is the day after tomorrow's neighbour in the
phase. A failure that produces no answer, no exception in your code and a traceback in a background
thread is the exact shape Day 21 exists to fix, and today is where you meet it first.

## The mechanism

Every case from the table, in one run against a fake context, followed by what the failure looks like
in a real one:

```python
# days/day-17-state-scopes-and-lifetimes/lab/braces.py
"""Every rule the placeholder engine applies, in one output. Zero model calls."""

import asyncio
from types import SimpleNamespace

from google.adk.utils.instructions_utils import inject_session_state

STATE = {"severity": "high", "user:reply_style": "short", "empty": None}

context = SimpleNamespace(
    _invocation_context=SimpleNamespace(
        session=SimpleNamespace(state=STATE),
        artifact_service=None,
    )
)

TEMPLATES = [
    "Severity is {severity}.",
    "Reply {user:reply_style}.",
    "Missing: {nickname}.",
    "Optional: [{nickname?}]",
    "Null: [{empty}]",
    'JSON: {"severity": "high"}',
    "Dashed: {not-an-identifier}",
]


async def main() -> None:
    for template in TEMPLATES:
        try:
            print(f"{template!r:45} -> {await inject_session_state(template, context)!r}")
        except KeyError as error:
            print(f"{template!r:45} -> KeyError: {error}")


asyncio.run(main())
```

**Line by line:**

- `SimpleNamespace(...)` twice — the smallest thing that satisfies what `inject_session_state` reads:
  an object with `_invocation_context`, which has a `session` with a `state`, and an
  `artifact_service`. Building it by hand is how this becomes a unit test rather than a run.
- `STATE` holds one plain key, one prefixed key, and one key whose value is `None`, because those are
  three different rows in the table.
- The templates are in the table's order, so the output can be read against it line for line.
- `inject_session_state` is the **same function** the runtime calls for an instruction, imported
  directly. Nothing here is a re-implementation.
- `except KeyError` around each one, so a single failing template does not stop the rest.
- `{template!r:45}` — `repr` and a fixed width, so the arrow lines up and an empty result is visible as
  `''` rather than as nothing at all.

```bash
cd days/day-17-state-scopes-and-lifetimes/lab
uv run python braces.py
```

**Line by line:**

- No agent, no session service, no model. The substitution engine is a pure function of a template and
  a state dictionary.

Measured on `google-adk` 2.7.1 on 2026-09-03:

```text
'Severity is {severity}.'                     -> 'Severity is high.'
'Reply {user:reply_style}.'                   -> 'Reply short.'
'Missing: {nickname}.'                        -> KeyError: 'Context variable not found: `nickname`.'
'Optional: [{nickname?}]'                     -> 'Optional: []'
'Null: [{empty}]'                             -> 'Null: []'
'JSON: {"severity": "high"}'                  -> 'JSON: {"severity": "high"}'
'Dashed: {not-an-identifier}'                 -> 'Dashed: {not-an-identifier}'
```

Seven templates, seven rules, and the third one is the cliff.

## When it breaks

**In a real run, the `KeyError` never reaches you.**

Measured on 2026-09-03 by running an agent whose instruction is `"This ticket is severity
{severity}."` against a session with no `severity` key:

```text
  File "...\google\adk\utils\instructions_utils.py", line 174, in _replace_match
    raise KeyError(f'Context variable not found: `{var_name}`.')
KeyError: 'Context variable not found: `severity`.'
Exception in thread Thread-1 (_asyncio_thread_main):
...
run finished; events = 1
```

Read the last two lines together. The traceback says `Exception in thread`, and the caller's own loop
printed `run finished` — with **one** event, the user's own message, and no answer. From the outside
this is indistinguishable from a model that had nothing to say.

The fixes, in order of preference:

1. `{severity?}` — the placeholder is optional and the instruction has to read sensibly with a blank
   there;
2. seed the key when the session is created, from outside the run
   ([3.3](../03-three-safe-writes/3.3-writing-from-outside-a-run.md)), so it is never absent;
3. use an `InstructionProvider` function and decide in Python what to include.

**A JSON example in your instruction disappears.** The opposite failure, and it happens when the JSON
key happens to be a valid identifier: `{severity}` inside an example block is a placeholder as far as
the engine is concerned, and it will be substituted or will raise. If your instruction must contain
literal braces around an identifier, an `InstructionProvider` is the supported way out.

**The capital letter.** `{Severity}` and `{severity}` are different keys, and the first raises with a
message naming a key you never meant to use. There is no case-insensitive matching and no suggestion.

## In production

**Treat every placeholder as a required argument, and write down who guarantees it.**

The version a professional ships has a rule per placeholder: either the key is seeded when the session
is created, or the placeholder is optional. The middle ground — a key that some path writes and others
do not — is where the outages come from, and it is invisible in review because the instruction reads
perfectly well.

**What changes at scale** is that instructions become a dependency on state that nothing type-checks.
An engineer renaming a state key breaks an instruction in a different module, and the break appears as
answerless turns rather than as an import error. A state schema
([5.1](../05-a-schema-for-state/5.1-declaring-the-boxes.md)) catches the writer's side; a test that
renders every instruction against a representative state catches the reader's, and is worth the ten
lines.

**What fails only under real traffic** is the first turn. Every conversation starts with an empty
state, so every placeholder that depends on work done *during* a conversation is missing exactly once
per conversation, at the beginning — the turn most likely to be the one a user judges you on.

**The review comment**: *"`{severity}` is not set until triage runs. On the first turn this raises and
the user gets nothing. Make it optional, or seed it."*

**The interview question**: *"what happens if a prompt template refers to a value that is not there?"*
The answer that shows you have been burned: *"in ADK it raises while the request is being assembled,
and because it happens inside the runtime the caller just sees a turn that produced no answer — so you
mark optional placeholders with a question mark and seed the rest."*
