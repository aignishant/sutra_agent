# 1.3 — Two ways to start it, and one is safer

## One-line answer

`adk api_server` and `get_fast_api_app` build the same twenty-seven routes, and the command passes
two arguments the factory defaults to nothing — so the supported way to start the server has a
protection on that the embeddable way silently does not.

## The story

Buying a ceiling fan assembled, or in a box.

The showroom model hangs from the ceiling with the guard on, the down-rod the right length, and the
regulator wired in. Take the boxed one home and you get the same fan: same motor, same blades, same
part numbers on the carton. What you do not get is the fitting. The guard is in the box. The earth
wire is your problem.

Neither is wrong. The boxed one exists precisely so you can fit it where the assembled one does not
go. But the person who assumes "same fan, same fitting" has quietly taken responsibility for a set of
small decisions that were previously made for them, and the fan spins perfectly either way.

## The idea in plain language

There are two supported ways to serve an ADK agent over HTTP.

**The command.** `adk api_server path/to/agents` starts a server. It parses flags, builds the app,
and runs uvicorn. This is what you use to try things and what most deployments run.

**The factory.** `get_fast_api_app(agents_dir=..., web=False)` returns a `FastAPI` object. You mount
it, wrap it, add your own routes and middleware, and serve it however you like. This is what you use
when the desk is one component of a larger service — which, by Day 88, it is.

They are the same code. The command calls the factory. What differs is the **arguments the command
fills in that the factory leaves as defaults**, and there are two worth knowing:

| Argument | `adk api_server` | `get_fast_api_app` default |
| --- | --- | --- |
| `host` / `bind_host` | both set to the `--host` value, `127.0.0.1` unless changed | `host="127.0.0.1"`, `bind_host=None` |
| `allow_origins` | whatever `--allow_origins` says, otherwise none | `None` |

The first row is the one that matters and it is not obvious from either name. `host` is *unused by
the returned app* — the factory's own docstring says so. `bind_host` is the one with teeth: passing
it turns on a guard that rejects requests addressed to a host that is not this machine. Part
[4.3](../04-blast-radius/4.3-the-guard-in-the-box.md) is what that guard prevents and what it costs
to leave off.

So the honest summary is: **the command is the assembled fan.** Embedding the factory is entirely
supported and entirely correct, and it hands you two fittings that were previously done for you.

And one thing both ways share, which the command says out loud in its own help text:

```text
  This server's endpoints are unauthenticated. Run it on a trusted network
  only, and put it behind your own authentication and authorization layer
  before exposing it to untrusted or public networks or serving multiple
  users.
```

That is not a finding this day discovered. It is documented, in the first paragraph of
`adk api_server --help`, and section 4 is about how easy it is to read the URL scheme instead.

## Why Sutra needs it

Because Sutra will embed the factory rather than run the command. The desk has to sit behind
authentication, alongside the MCP server from Day 42, with the tracing from Day 84 already wired in —
and none of that is expressible as flags to a command. The build brief in this day's hub is
`sutra/api.py`, and it is a factory call.

And because the two-arguments difference is exactly the kind of thing that survives into production
unnoticed. Nothing fails. The server starts, the routes answer, the tests pass. The only observable
difference is a request that would have been refused and was not.

## The mechanism

The factory's signature is long — twenty-eight keyword-only parameters on `google-adk==2.7.1` — and
three of them decide this part. Read from the installed library on 2026-09-07:

```text
    host: str = "127.0.0.1",
    bind_host: str | None = None,
    allow_origins: list[str] | None = None,
```

**Line by line:**

- Every parameter is keyword-only — the signature opens with a bare `*` — so nothing can be passed
  positionally by accident. That is a good API decision and it also means every call site reads like
  a list of choices, which is what makes the defaults visible.
- `host` has a value that looks protective and is not. Its own documentation says *"Unused by the
  returned app; pass `bind_host` to guard it."* A reader who sets `host` and stops has done nothing.
- `bind_host` defaults to `None`, and `None` means *"I was not told where this will be bound"* rather
  than *"bind to nothing"*. The library's comment is explicit about why: an app behind a same-machine
  proxy would reject its own traffic if the guard guessed. That is the right default for a library
  and the wrong outcome for an embedder who did not read it.
- `allow_origins=None` means no CORS middleware is installed at all, which is the safe default. Part
  [4.2](../04-blast-radius/4.2-which-pages-may-call-it.md) measures what happens when it is set to
  `["*"]`.

The command fills two of them in. From `google/adk/cli/cli_tools_click.py`, lines 2071–2072:

```text
      host=host,
      bind_host=host,
```

**Line by line:**

- The same value goes to both. `host` for the record, `bind_host` for the guard.
- Because `--host` defaults to `127.0.0.1`, the plain `adk api_server` has the guard **on**. Somebody
  who runs `--host 0.0.0.0` to reach it from another machine turns it off, correctly — a non-loopback
  bind is not a rebinding target — and simultaneously exposes an unauthenticated server to the
  network, which is the sentence in the help text.

Building the app yourself is three lines, and the lab's `_desk.py` is where every measurement in this
day starts:

```python
def build(**overrides) -> FastAPI:
    """The app as an embedder gets it: ADK's factory, sessions in memory, no web UI."""
    options = {
        "agents_dir": str(AGENTS_DIR),
        "web": False,
        "session_service_uri": "memory://",
    }
    options.update(overrides)
    return get_fast_api_app(**options)
```

**Line by line:**

- `agents_dir` must be absolute. The factory resolves it and the agent loader puts it on the import
  path; a relative path works only when the process happens to start in the right directory, which is
  the sort of thing that works locally and fails in a container.
- `web=False` skips the browser UI and its static assets. It also changes which loader is used —
  `AgentLoader` rather than `NestedAgentLoader` — and turns off a YAML key denylist that the UI
  enables. Serving the UI is a bigger decision than a boolean looks.
- `session_service_uri="memory://"` so nothing is written to disk. The default is per-agent local
  SQLite, which is fine for a workstation and is exactly the thing Day 86 has to remove before the
  desk can run in a container that may be replaced at any moment.
- `**overrides` so every measurement in this day is the same app with one thing changed. When part
  4.2 builds with `allow_origins=["*"]`, that flag is the *only* difference from the baseline, and a
  finding is attributable.

Building it is not silent:

```text
UserWarning: [EXPERIMENTAL] InMemoryCredentialService: This feature is experimental and may change
or be removed in future versions without notice. It may introduce breaking changes at any time.
UserWarning: [EXPERIMENTAL] BaseCredentialService: This feature is experimental and may change or
be removed in future versions without notice.
```

Two warnings, on every construction, from the credential service the app installs by default. They
are worth reading rather than filtering: the part of this server that would hold credentials is the
part ADK marks as not yet settled.

## When it breaks

The interesting break is not an exception, it is the guard that is off:

```bash
cd days/day-85-the-api-surface/lab
uv run python rebind.py; echo "exit: $?"
```

Measured on 2026-09-07:

```text
  bind_host not given (the default)

    GET /health   Host: 127.0.0.1:8000           -> 200 {"status":"ok"}
    GET /health   Host: desk.internal.example    -> 200 {"status":"ok"}
```

Same app, same route, a `Host` header naming a machine this server is not. Served, with a `200`. Part
[4.3](../04-blast-radius/4.3-the-guard-in-the-box.md) is why that matters and what turns it on.

**The break that does raise** is the agents directory. Give the factory a path with no agent
packages in it and the app builds fine — the failure arrives later, per request, as the 404 in part
[3.2](../03-when-it-refuses/3.2-the-404-that-reads-out-the-disk.md). There is no startup validation
that the server has anything to serve, which is the same shape as part
[1.1](1.1-a-desk-with-a-street-address.md)'s empty routing table: a healthy process with nothing
behind it.

## In production

**What a professional does.** Picks the factory, and then writes down every argument the command
would have passed, because moving from a command to an embedded app is a migration of defaults. The
practical form of that is a single function in your own code that builds the app, with every
non-default argument spelled out and a comment on each — which is what this day's build brief asks
for.

**What degrades at scale.** Defaults drift between versions. `bind_host` did not exist in every
release; `allow_origins` semantics gained a `regex:` prefix. An embedder pinned to a version they
read once is embedding a snapshot of somebody else's defaults, and the pin in `pyproject.toml` is the
only thing that makes that reproducible — which is Principle 7 pointed at a library's behaviour
rather than its API.

**The failure that only shows with real traffic.** A reverse proxy in front. Once the desk is behind
a gateway (Day 88), the `Host` the app sees is whatever the proxy forwards, and a rebinding guard
configured for loopback will start refusing legitimate traffic — which is precisely why the library
refuses to guess. The right answer there is `url_prefix` plus a deliberate `bind_host`, decided once,
with the proxy's behaviour in front of you.

**The review comment a senior engineer leaves:** *"If we are calling the factory, pass `bind_host`
explicitly even when it is the same as the default — I want to see in the diff that somebody decided,
not that nobody typed it."*

**The interview question:** *"You are embedding a vendor's app object instead of running their
server. What do you check?"* The answer that shows experience diffs the arguments: what does their
command-line entry point pass that the factory defaults to? That set is exactly the protections you
have just taken over.
