# 2.2 — Which endpoints cost nothing

## One-line answer

Twenty-four of the twenty-seven routes answer from the process's own state and cost nothing to call;
three hand the turn to an agent and spend provider quota — and the three refuse a bad session id
before they spend anything, which is the difference between a typo and a bill.

## The story

The menu on the wall and the kitchen behind it.

You can stand and read the whole board for as long as you like. Ask what is in the sambar, ask
whether the dosa is big enough for two, ask the price of a coffee, ask if they have change for a
five-hundred. None of it costs anything and the man at the counter answers all of it.

The moment you say "one masala dosa", something different has happened. A burner is lit. Batter goes
on the tawa. That step is not free and cannot be taken back, and everything before it was.

Every counter in the world has this line running through it, and everybody knows instinctively where
it is. On an HTTP API, nobody does, because both sides of it look like a URL.

## The idea in plain language

An ADK server's routes fall into two groups with completely different economics.

**Free.** Answered from state this process already has: the routing table, the agent directory, the
session store, the artifact store. `/health`, `/version`, `/list-apps`, `/apps/{app}/app-info`, every
session route, every artifact route, the memory route. Twenty-four routes. Calling them a thousand
times costs a thousand cheap function calls.

**Paid.** `POST /run`, `POST /run_sse`, and the `/run_live` WebSocket. Each one starts an agent turn,
which means at least one model call, which under Principle 15 means a slice of a daily allowance
nobody has finished measuring — Day 83's criterion 6 is still open on that number.

The ratio is the useful thing to hold on to: **most of an agent server is not the agent.** Which
means most of it can be tested exhaustively, in continuous integration, on every commit, for nothing
— and that is the free half of Day 82's two-cadence split arriving in a new place.

There is a third category worth naming because it is where money leaks: routes that are free *today*.
`/list-apps` reads a directory. If a future version cached agent cards from a registry, or resolved a
remote app, it would start making network calls with the same URL and the same name. The only defence
is to check rather than assume, which is what this part's script does.

## Why Sutra needs it

Because Day 86 puts a liveness probe on this server and Day 88 puts a load balancer in front of it,
and both of those call an endpoint on a schedule for ever. A probe pointed at a paid route is a
standing order against the day's quota, and it will be discovered in a 429 rather than in a review.

And because the desk's own tests need to know where the line is. Everything in sections 3 and 4 of
this day is measured against free routes, which is why this day costs nothing at all — and that is a
property somebody has to have checked, not assumed.

## The mechanism

The two lists are data, so the claim is inspectable rather than asserted in prose:

```python
FREE = (
    ("GET", "/health", None),
    ("GET", "/version", None),
    ("GET", "/list-apps", None),
    ("GET", f"/apps/{APP_NAME}/app-info", None),
    ("POST", f"/apps/{APP_NAME}/users/{USER}/sessions", {}),
    ("GET", f"/apps/{APP_NAME}/users/{USER}/sessions", None),
)

PAID = (
    ("POST", "/run", "one turn, whole response buffered"),
    ("POST", "/run_sse", "one turn, server-sent events as they arrive"),
    ("WEBSOCKET", "/run_live", "a bidirectional session, open until somebody closes it"),
)
```

**Line by line:**

- `FREE` is a sample rather than all twenty-four, chosen to cover every *kind* of free route: two
  liveness, two discovery, two session. The artifact routes behave the same way and would only make
  the transcript longer.
- Each entry carries its body, so a POST is a real POST with a real payload and the script does not
  have to special-case anything.
- `PAID` carries a description instead of a body, because the script deliberately does not call these.
  The description is what one call *is*, which is the thing a reader needs in order to decide whether
  to spend it.
- `/run_live` is listed with the method `WEBSOCKET`, which is not an HTTP method. That is honest: it
  is not an HTTP request at all, and giving it a fake `GET` would hide that this route has no
  request-and-response shape and therefore no natural place to stop.

The check is that every route in `FREE` answered:

```python
            if response.status_code >= 400:
                failures += 1
```

**Line by line:**

- The assertion is on the status, not on the body. This is not a test that the endpoints are correct —
  Day 79's suite is for that — it is a test that they are *reachable without a model*, and a 4xx
  would mean the sample is wrong.
- Counting rather than raising on the first one, so a run reports every problem at once. That is the
  same decision as Day 83's gate not stopping at the first finding.

Run both arms:

```bash
cd days/day-85-the-api-surface/lab
uv run python free.py --paid; echo "exit: $?"
```

**Line by line:**

- `--paid` prints the list and calls nothing. A script whose purpose is *not* spending quota should
  not have a code path that can.

Measured on 2026-09-07:

```text
endpoints this day does not call, because each one spends provider quota:

  method      path        what one call is
  POST        /run        one turn, whole response buffered
  POST        /run_sse    one turn, server-sent events as they arrive
  WEBSOCKET   /run_live   a bidirectional session, open until somebody closes it

  every other route in the table answers from local state
```

And the useful surprise: the paid routes are **not** paid when you get the session wrong.

```bash
uv run python stream.py --refusal; echo "exit: $?"
```

**Line by line:**

- `--refusal` posts a well-formed body naming a session that does not exist, to both `/run` and
  `/run_sse`. The body is valid, so this gets past validation and into the handler.

Measured on 2026-09-07:

```text
a run against a session that does not exist:

  POST /run       -> 404 application/json  {"detail":"Session not found: nope"}
  POST /run_sse   -> 404 application/json  {"detail":"Session not found: nope"}

  refused before any agent was started, so a wrong session id costs nothing
```

**Both refuse with a 404 before starting an agent.** That is a real and slightly lucky property of
this server: the session lookup happens first, so the overwhelmingly common client bug — a stale or
mistyped session id — costs a database read rather than a model call.

It also means the paid routes have a free branch, which is exactly the kind of thing a load-testing
script accidentally exercises while proving nothing.

## When it breaks

The classification breaks in the direction that costs money, and there is no error text for it:

```text
1. a route is free today
2. a probe, a dashboard or a health check is pointed at it
3. the probe runs every few seconds, for ever, on every replica
4. a later version makes that route do slightly more work
5. the bill arrives as a 429 on an unrelated request
```

Step 5 is the one to recognise, because the symptom appears somewhere else entirely. Day 78's
recorded refusal is what it looks like:

```text
429 RESOURCE_EXHAUSTED
generativelanguage.googleapis.com/generate_content_free_tier_requests
Please retry in ~53s
```

The failing request is whichever one happened to be unlucky, and it has nothing to do with the probe
that spent the quota.

**The second break is the reverse mistake**: treating a route as paid when it is free, and therefore
not testing it. Twenty-four routes is a lot of surface to leave unexercised out of misplaced caution,
and every finding in sections 3 and 4 of this day came from one of them.

## In production

**What a professional does.** Writes the classification down next to the routing table and puts a
test on it — the list is a claim, and a claim that nothing checks decays. In a service with real
money attached, the stronger version is a wrapper around the provider client that counts calls, and a
test that asserts the count is zero for the free routes. That turns "I believe this is free" into
something a build can fail on.

**What degrades at scale.** The line moves. Caching, retrieval, a moderation pass, a routing model in
front of the real one — every one of those makes a formerly free path spend something, and none of
them changes the URL. The classification therefore has to be re-derived rather than inherited, which
is an argument for measuring it in code rather than documenting it in prose.

**The failure that only shows with real traffic.** Concurrency. A free route stays free under load; a
paid route under load is a quota exhausted in the first minute and a queue of requests behind it.
That is Day 78's admission-control problem arriving at an HTTP boundary, and this API has no way to
express it — every caller gets in, and the refusals come from the provider rather than the door.

**The review comment a senior engineer leaves:** *"Point the readiness probe at `/health` and nothing
else, and add a comment saying why. The next person will want it to 'actually check the agent', and
that is a model call every five seconds on every pod."*

**The interview question:** *"Which of your endpoints are expensive?"* The answer that shows
experience does not list them from memory. It says how the list is maintained and what would catch a
route that quietly changed sides — because in a system with a model behind it, that is a change that
looks like a refactor.

## Check yourself

```bash
cd days/day-85-the-api-surface/lab
uv run python free.py; echo "exit: $?"
uv run python free.py --paid; echo "exit: $?"
uv run python stream.py --refusal; echo "exit: $?"
```

Twenty-four routes are free and three are not. Say which one of the three you would still be willing
to call in a test, and under what condition.

Now work out what a liveness probe on `/run` would cost. Take the probe interval as five seconds, one
replica, and Day 78's observed allowance of twenty requests a day, and say how long the day's quota
lasts.

**Out loud, without scrolling up:** where is the line between the menu and the kitchen on this
server, and what does the server do when you order from a table that does not exist?
