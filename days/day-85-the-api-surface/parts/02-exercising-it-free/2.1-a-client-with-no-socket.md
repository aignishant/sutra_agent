# 2.1 — A client with no socket

## One-line answer

`httpx.ASGITransport(app=app)` calls the application object the way a web server would — through
every middleware, every dependency and every exception handler — without binding a port, so an HTTP
test is as cheap and as deterministic as a function call and still exercises the real HTTP path.

## The story

Testing the intercom from inside the gate.

The gate has a button on the street and a handset in the flat. To check the wiring you do not need
to walk out, close the gate behind you and stand on the pavement. You press the button at the panel,
with the gate still open, and somebody upstairs picks up.

That test is not a pretence. The same button, the same wire, the same handset, the same bell. What
you have skipped is only the walk — and the walk is the part that takes time, needs the gate to be
shut, and cannot be repeated forty times in a minute.

There is one thing the inside test cannot tell you, and it is worth knowing which: whether the gate
actually opens for somebody standing outside it.

## The idea in plain language

A web application in Python is, at bottom, one function. **ASGI** — the Asynchronous Server Gateway
Interface — is the agreement about its shape: the server hands the application a `scope` describing
the request, plus two callables for receiving the body and sending the response. Uvicorn's job is to
turn bytes on a socket into that call and the result back into bytes.

Which means the socket is optional. If you already have the application object, you can make the call
yourself.

`httpx` ships a transport that does exactly that. `httpx.ASGITransport(app=app)` builds the scope,
invokes the app, and turns what comes back into a normal `httpx.Response`. From the caller's side it
is indistinguishable from a real request:

```text
  a real request                      an ASGI-transport request
  ------------------------------      ------------------------------
  socket accept                       (skipped)
  HTTP parse                          (skipped)
  ASGI scope built by uvicorn         ASGI scope built by httpx
  middleware stack                    middleware stack
  routing                             routing
  dependencies + validation           dependencies + validation
  handler                             handler
  exception handlers                  exception handlers
  response serialised                 response serialised
  bytes on the socket                 (skipped)
```

Everything that could contain a bug in *your* application is in both columns. What is skipped is the
part that belongs to the web server and the operating system.

For this day that matters twice. It makes every measurement free — no port, no listener, no firewall
prompt, nothing to clean up — and it makes them **deterministic**, because there is no timing, no
connection reuse and no risk of a leftover process from the previous run answering instead.

## Why Sutra needs it

Because every finding in sections 3 and 4 is a status code and a response body, and a finding is only
worth writing down if the reader can reproduce it. A test that needs a free port is a test that fails
on somebody's machine for a reason unrelated to the finding.

And because this is how the desk's HTTP layer gets tested from Day 86 onwards. Day 23 established
the repository's testing posture — mock roles, not objects — and this is that idea at the transport
level: the thing being faked is the socket, which is nobody's role, and everything that *is* a role
stays real.

## The mechanism

The whole client is a context manager in `_desk.py`:

```python
@asynccontextmanager
async def client(app: FastAPI):
    """An HTTP client wired straight to the app object - no port, no listener, no network."""
    transport = httpx.ASGITransport(app=app)
    async with httpx.AsyncClient(transport=transport, base_url="http://desk") as http:
        yield http
```

**Line by line:**

- `ASGITransport(app=app)` takes the application object, not a URL. This is the whole trick: `httpx`
  will call `app(scope, receive, send)` instead of opening a connection.
- `base_url="http://desk"` is required and arbitrary. Something has to fill the `Host` header and the
  scheme in the scope, and no DNS lookup happens for it. The name is deliberately not `localhost`,
  so that part [4.3](../04-blast-radius/4.3-the-guard-in-the-box.md) can set `Host` explicitly and
  the reader can see it is the header being tested rather than a real hostname.
- `AsyncClient` rather than `Client`, because ASGI applications are async all the way down. Every
  measurement script in this day is therefore `asyncio.run(main(...))`.
- `@asynccontextmanager` so the client is closed even when a measurement raises. An unclosed
  `AsyncClient` warns at interpreter shutdown, and a warning in the middle of a transcript is noise
  the reader has to learn to ignore.

Using it is ordinary httpx:

```python
async with client(app) as http:
    for method, path, body in FREE:
        response = await (http.get(path) if method == "GET" else http.post(path, json=body or {}))
```

**Line by line:**

- `await` on a conditional expression, so one line covers both verbs. The parentheses matter: without
  them the `await` binds to the `if` branch only.
- `json=body or {}` sends a JSON body even when the fixture's body is `None`, because a POST with no
  body at all is a different request from a POST with `{}` — the first fails validation before
  reaching the handler and the second reaches it.
- `response` is a plain `httpx.Response`: `.status_code`, `.headers`, `.json()`, `.text`. Nothing in
  the measurement code knows the socket is missing.

Run it:

```bash

```

**Line by line:**

- No flag: exercise the endpoints that answer from local state. Part
  [2.2](2.2-which-endpoints-cost-nothing.md) is which those are and why.

Measured on 2026-09-07:

```text
exercising 6 endpoints that answer without a model

  method  path                                         status  body
  GET     /health                                         200  {"status":"ok"}
  GET     /version                                        200  {"version":"2.7.1","language":"python","language_version
  GET     /list-apps                                      200  ["echo"]
  GET     /apps/echo/app-info                             200  {"name":"echo","rootAgentName":"echo","description":"","
  POST    /apps/echo/users/u1/sessions                    200  {"id":"<uuid>","appName":"echo","userId":"u1","state":{}
  GET     /apps/echo/users/u1/sessions                    200  [{"id":"<uuid>","appName":"echo","userId":"u1","state":{

  6 of 6 answered, 0 provider requests
  the whole discovery and session surface is free to exercise
```

Six real HTTP exchanges, no port opened. The `<uuid>` is a substitution the lab makes so the
transcript is the same on your machine as on mine:

```python
def mask(text: str) -> str:
    """Replace the two fields that differ on every run, so a transcript is reproducible."""
    return _EPOCH.sub("<epoch>", _UUID.sub("<uuid>", text))
```

**Line by line:**

- Two fields genuinely differ every run: the server-generated session id and the last-update
  timestamp. Everything else in these bodies is stable.
- The substitution replaces rather than trims, so the reader still sees that a field is *there*. A
  transcript that quietly cut the id would be hiding the shape of the response.
- This is a presentation choice inside the lab, and it is the only one in this day. Every status code
  and every other byte in every transcript is what the server sent.

## When it breaks

The transport skips the socket, so it cannot find anything that lives in the socket. Four things fall
in that gap, and knowing them is what stops this technique from being over-trusted:

| What it cannot see | Why | Where it is caught |
| --- | --- | --- |
| binding, ports, address in use | no listener is created | day 86, the container's port |
| TLS, certificates, protocol version | no bytes are encrypted | outside this repository |
| the web server's own limits — body size, header count, timeouts | those are uvicorn's, not the app's | day 86's readiness work |
| whether the process actually starts | the app object already exists | part 5.1's liveness discussion |

There is no error text for any of those. They simply are not exercised, and a suite that only uses
this transport will be green about an application that cannot be reached.

There is a fifth gap that does not merely go unexercised — it actively lies, and it is the one to
know. When a handler raises something nobody caught, the transport **re-raises it in the caller**
rather than turning it into a response, because `raise_app_exceptions` defaults to `True`.

Measured on 2026-09-07, against a one-route app whose handler raises `RuntimeError`:

```text
raise_app_exceptions=True: raised RuntimeError: the session store is not reachable
raise_app_exceptions=False: response 500 'Internal Server Error'
```

The second line is what a real client sees. The first is what your test sees, and it is a different
thing in two ways: the test gets the server's exception type and message, which no HTTP client ever
receives, and the test never observes that the status code is `500`. A suite written against the
default is therefore unable to assert anything about how the service behaves when it fails — which is
most of what section 3 is about. Pass `raise_app_exceptions=False` when the failure is the subject.

## In production

**What a professional does.** Uses the in-process transport for the hundreds of tests that are about
the application, and keeps a small number — often one — that starts the real server and makes a real
request. That one test is the gate in the story: it proves the thing opens from outside. Everything
else proves the wiring, and it does so in milliseconds.

**What degrades at scale.** Nothing about the transport, but the temptation grows. Once a suite is
fast, it accumulates tests that assert on behaviour the transport does not model — connection reuse,
streaming backpressure, client timeouts — and those tests pass regardless of the truth. The rule that
holds is: if the assertion is about the *network*, the in-process transport cannot make it.

**The failure that only shows with real traffic.** Streaming. `/run_sse` returns a response the
server writes over time, and an in-process transport will happily buffer the whole thing, so a test
of it "passes" without ever exercising the incremental delivery a real client depends on. Part
[2.3](2.3-the-endpoint-that-sends-a-stream.md) is what that endpoint declares and what it actually
sends.

**The review comment a senior engineer leaves:** *"Good, keep everything on ASGITransport. Add one
smoke test that boots uvicorn on port zero and curls `/health`, and run it in CI only — that is the
whole of what the fast tests cannot tell us."*

**The interview question:** *"How do you test an HTTP API without a server?"* The answer that shows
experience names the interface — the app is a callable with a known contract — and then, unprompted,
names the four things that approach cannot cover. The second half is what distinguishes somebody who
has used it from somebody who has read about it.
