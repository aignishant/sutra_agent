# 1.4 — The first interaction: Sutra's first words

## One-line answer

One call — `client.interactions.create(model=..., input=...)` — returns an object carrying the
model's text **and a receipt**, and learning to care about the second one as much as the first is the
difference between someone who uses an LLM and someone who operates one.

---

## The story

A team ships an internal assistant. It works. People like it. Six weeks later finance forwards a bill
with a question mark drawn next to a number, and the team cannot answer it.

Not because the information is unavailable — every single response the API returned included a
precise accounting of what that request consumed. The team had simply never looked at it. Their code
did the natural thing, the thing every tutorial does:

*take the response, pull out the text, throw the rest away.*

Every call, for six weeks, discarded its own receipt. The information existed exactly once, in
memory, for a few milliseconds, and was garbage collected. Reconstructing it afterwards meant
re-running six weeks of traffic, which nobody was going to do.

They had built something that worked and had no idea what it cost, and the fix — three lines,
logging a field they already had — was something they could have written on day one if anyone had
thought of the response as a receipt rather than as a string.

---

## The idea in plain language

A **request** to the API carries three things: which model, everything the model may know, and
optionally some dials for how it should pick its words. A **response** carries two: the text, and
metadata about the transaction.

In the Interactions API, one call is one **interaction** — the vendor's word for a complete turn.
Some vocabulary, defined once and used for the rest of the project:

| Term | What it means here |
| --- | --- |
| **Interaction** | One complete turn: your input, the model's work, the output. What `create()` returns |
| **`input`** | Everything the model is allowed to know for this turn — a string, or a structured list |
| **`store`** | Whether the provider keeps this interaction on their side. **Defaults to `True`** |
| **`output_text`** | Convenience field: the model's text, already extracted |
| **`usage`** | The receipt: token counts for what you just spent |

Two of those deserve a flag right now.

**`store` defaults to `True`.** The straightforward call — the one in the official quickstart, the
one you would write without thinking — **persists your conversation on the provider's servers.** On
the free tier it is retained one day; on paid, fifty-five. That is not a scandal, it is a documented
product feature, and it is genuinely useful for the server-side conversation state that
[3.3](../03-context-and-memory/3.3-the-server-will-remember.md) covers. But it is a decision, and a
default is a decision somebody else made for you. Principle 13 — **blast radius before capability** —
says a new power arrives with its containment story, so Sutra writes `store=False` by default and
turns it on deliberately when it wants the feature.

**`output_text` is a convenience, not the whole response.** It is the flattened text. The full
interaction object also carries the execution steps, the finish reason, and the usage receipt from
the story above. Reaching for `output_text` and discarding the rest is exactly the habit that cost
that team six weeks of data.

---

## Why Sutra needs it

This call is the primitive. Everything after it is arrangement.

- **[1.5](1.5-the-only-door-429.md)** wraps this exact call in the one function Sutra uses for every
  model request it will ever make, so that quota failures are handled in one place rather than
  eighteen.
- **Day 3 (AG-03)** wraps it in a loop. Think → act → observe is this call, three times, with a
  growing `input`.
- **Day 4 (AG-04)** adds tools: the same call, plus a description of functions the model may request,
  plus a second call carrying the result back.
- **Day 5 (ADK-01, ADK-02)** hands the call to a framework. **You will recognise every parameter**,
  which is the entire point of Principle 4 — build the mechanism once by hand, then adopt the
  framework as a convenience rather than a mystery. Days 3 and 4 exist so that Day 5 teaches you
  nothing new about *what* is happening, only about who is typing it.
- **Day 24 (OPS-07, AG-11)** budgets on the `usage` field. It can only do that if you started
  reading it today.

## The mechanism

Build it in the file the hub's §4 asks for, `sutra/mechanics.py`. Start with the smallest complete
call:

```python
"""Day 2 — LLM mechanics probes: tokens, context, sampling.

Importable with no side effects. Run a demo with:
    uv run python -m sutra.mechanics ask
"""

from __future__ import annotations

from google import genai

from sutra.config import load_env

# Pinned explicitly, never an alias (see 1.3). Verified callable on this key
# 2026-08-24 against ai.google.dev/gemini-api/docs/models.
MODEL = "gemini-3.7-flash"


def demo_ask(client: genai.Client) -> None:
    """One prompt in, one answer out — plus the receipt nobody reads."""
    interaction = client.interactions.create(
        model=MODEL,
        input="In one sentence: what is a support-ticket triage desk?",
        store=False,
    )
    print("text :", interaction.output_text)
    print("usage:", interaction.usage)
```

**Line by line:**

- `"""Day 2 — ..."""` — the module docstring names how to run it. A file whose demos are invoked from
  the command line should say so at the top, because the next person to open it is you in a month.
- `from __future__ import annotations` — makes type hints lazily evaluated. House style across this
  repo; it keeps annotations cheap and avoids import-order problems as files grow.
- `MODEL = "gemini-3.7-flash"` — **one place, named constant, explicit pin.** Not an alias, per
  [1.3](1.3-listed-is-not-callable.md). The comment carries the verification date because a pin
  without a date is a claim without evidence (Principle 8).
- `def demo_ask(client: genai.Client) -> None:` — the client is a **parameter, not a global**. The
  module can then be imported by a test that passes a fake, which is what makes
  [1.5](1.5-the-only-door-429.md)'s retry logic testable without spending quota. Building a client at
  import time would make every import require a valid key.
- `client.interactions.create(...)` — the call. This is the surface Google's own quickstart now
  leads with, and the one ADR-0006 records as this project's teaching surface.
- `model=MODEL` — which model. Required; there is no default worth relying on.
- `input="In one sentence: ..."` — everything the model may know. Note **"In one sentence"**: brevity
  belongs in the prompt. [5.1](../05-the-failure-lab/5.1-the-cap-that-ate-the-answer.md) shows what
  happens when you try to enforce brevity with a token cap instead, and it is not what you expect.
- `store=False` — **deliberate.** The default is `True`, which would persist this on the provider's
  side. Sutra opts in to storage rather than out of it, and
  [3.3](../03-context-and-memory/3.3-the-server-will-remember.md) is where that gets argued properly.
- `print("text :", interaction.output_text)` — the flattened text. What everyone keeps.
- `print("usage:", interaction.usage)` — **the receipt. What almost everyone throws away**, and the
  reason the team in the story could not answer a question about their own system.
  [2.2](../02-tokens-the-meter/2.2-reading-the-receipt.md) takes this object apart field by field.

Now the entry point. It stays deliberately dumb — a dictionary and a lookup:

```python
def main() -> None:
    """Run one named demo: uv run python -m sutra.mechanics <name>."""
    import sys

    demos = {"ask": demo_ask}
    name = sys.argv[1] if len(sys.argv) > 1 else "ask"
    if name not in demos:
        print(f"usage: uv run python -m sutra.mechanics [{'|'.join(demos)}]")
        raise SystemExit(2)

    load_env()
    demos[name](genai.Client())


if __name__ == "__main__":
    main()
```

**Line by line:**

- `import sys` **inside the function** — it is only needed when run as a script, so importing it at
  module level would make every importer pay for it. A small thing; the habit matters more than this
  instance.
- `demos = {"ask": demo_ask}` — a dict of name to function. Each following part adds one entry. The
  dictionary lookup is also the validation: an unknown name cannot dispatch to anything.
- `raise SystemExit(2)` — exit **non-zero** on bad usage. A script that prints an error and exits `0`
  is a script that lies to every tool that runs it, and Day 1's
  [4.3](../../../day-01-bootstrap-and-map/parts/04-ledgers/4.3-reading-the-shipped-generator.md)
  made exactly this point about `trace.py`. `2` is the conventional code for a usage error.
- `load_env()` — called here, **once, at the entry point** — not at import time. A module that reads
  the environment when imported is a module that cannot be imported by a test, a linter, or a
  documentation tool without a valid key present.
- `demos[name](genai.Client())` — construct the client **after** `load_env()`, for the ordering
  reason [1.3](1.3-listed-is-not-callable.md) gave: the client reads `GOOGLE_API_KEY` at construction.
- `if __name__ == "__main__":` — the guard that separates "run as a script" from "imported". Without
  it, importing this module would fire a live model call, which is a real way to spend quota by
  accident.

Run it:

```bash
uv run python -m sutra.mechanics ask
```

**Line by line:**

- `uv run` — executes inside the project's virtual environment, where `google-genai` was installed in
  [1.2](1.2-pinning-before-installing.md). A bare `python` may resolve to a different interpreter.
- `python -m sutra.mechanics` — `-m` runs a **module** rather than a file path, which means Python
  sets up `sys.path` from the project root and `from sutra.config import load_env` resolves. Running
  `python sutra/mechanics.py` directly is the classic way to get `ModuleNotFoundError: No module
  named 'sutra'`.
- `ask` — lands in `sys.argv[1]` and selects the demo.

Those are Sutra's first words.

## When it breaks

**Called before the keys were loaded:**

```text
Traceback (most recent call last):
  File "sutra/mechanics.py", line 31, in demo_ask
    interaction = client.interactions.create(
google.genai.errors.ClientError: 400 INVALID_ARGUMENT. {'error': {'code': 400,
'message': 'API key not valid. Please pass a valid API key.', 'status':
'INVALID_ARGUMENT'}}
```

**What it means.** Nine times out of ten the key is fine and was simply not in the environment when
`genai.Client()` ran. **The smallest fix** is ordering: `load_env()` first, client second. Confirm
with Day 1's `describe()`, which prints presence and length and never the value.

**Run as a file instead of a module:**

```text
Traceback (most recent call last):
  File "sutra/mechanics.py", line 8, in <module>
    from sutra.config import load_env
ModuleNotFoundError: No module named 'sutra'
```

**What it means.** You ran `python sutra/mechanics.py`. Python put `sutra/` on the path instead of the
project root, so the package `sutra` is invisible from inside itself. **The fix is the `-m` form**,
which is why the docstring at the top of the file spells it out.

**The response with no text in it:**

```text
text : None
usage: total_input_tokens=9 total_output_tokens=0 total_thought_tokens=512 total_tokens=521
```

**What it means.** The call succeeded — note there is no exception — and `output_text` is `None`
anyway. **This is the single most confusing result on this day**, and it is why the receipt matters:
the usage line shows the entire output budget went to `total_thought_tokens`, tokens the model spent
reasoning that you never see. Had you printed only `output_text`, you would be debugging a "broken
API" with no evidence. [2.3](../02-tokens-the-meter/2.3-the-thinking-tax.md) explains the mechanism
and [5.1](../05-the-failure-lab/5.1-the-cap-that-ate-the-answer.md) reproduces it deliberately.

**The quota ceiling, which you will meet today:**

```text
google.genai.errors.ClientError: 429 RESOURCE_EXHAUSTED. {'error': {'code': 429,
'message': 'You exceeded your current quota', 'status': 'RESOURCE_EXHAUSTED',
'details': [{'@type': 'type.googleapis.com/google.rpc.RetryInfo',
'retryDelay': '47s'}]}}
```

This one is not a mistake — it is the free tier working as designed, and handling it honestly is the
whole of [1.5](1.5-the-only-door-429.md).

## In production

**What a professional writes instead of `print`** is a structured log line carrying the model id, the
token counts, a request id and the latency — emitted on **every** call, not just failures. That is
the three-line fix the team in the story never got around to. The reason it must be every call is
that the interesting questions are all statistical: which prompts are expensive, which tenant is
consuming the quota, whether output length is drifting after a prompt change. **You cannot answer any
of them from a sample, and you cannot go back and collect it later.** Sutra builds this properly on
Day 84 (ADK-63, ADK-74, OPS-16) with OpenTelemetry, and the habit starts today with `print`.

**What degrades at scale is the client and the connection, not the call.** One `genai.Client()` per
process, constructed once and reused, is correct. Constructing a client per request is a classic
performance bug: each one re-establishes TLS and re-reads credentials, adding latency to every
request for no benefit. Under concurrency the failure sharpens — hundreds of clients means hundreds
of connection pools, file descriptor exhaustion, and a service that falls over under a load its CPU
graph says it should handle easily. **The rule of thumb: clients are long-lived and shared;
requests are short-lived and cheap.**

**The failure that only appears with real traffic** is the one hiding in `output_text`. In
development every response has text, so `output_text` is a string and your code that calls
`.strip()` on it works perfectly. In production some fraction of responses come back with no text at
all — the thinking-budget case above, a safety filter, a truncated stream — and `output_text` is
`None`. Then `AttributeError: 'NoneType' object has no attribute 'strip'` arrives at 2am from a
codepath that has run flawlessly ten thousand times. **A field that is "always" populated in testing
is a field you must still handle as optional**, and the honest handling is to check the finish reason
rather than silently substituting an empty string, because an empty answer that looks like a real
answer is Principle 10's fabricated result wearing a disguise.

**The review comment a senior engineer leaves:** *"We're calling `.create()` with the default
`store`, which means every customer conversation is being persisted on the vendor's side. Was that a
decision? If it was, where's it written down and who told legal? If it wasn't, set `store=False` and
let's talk about which conversations we actually want retained."* The general form of this comment —
**"is this default a decision or an accident?"** — is worth learning to ask yourself, because
defaults are where most of a system's unexamined behaviour lives.

**The interview question.** *"Walk me through what happens when you call an LLM API."* The answer that
sounds junior stops at "you send a prompt and get text back." The answer that sounds like someone who
has operated one keeps going: you send a model id, the full context, and generation settings; you get
back text, a finish reason that tells you **why generation stopped**, and a usage record you should
be logging on every call. Then the detail that ends the question well: **the text can be empty while
the call succeeds** — hit an output cap on a thinking model and you will pay for tokens that produce
no visible answer — which is exactly why you read the finish reason and the usage rather than
assuming the text field is populated.
