# 1.3 — What the crate is allowed to see

## One-line answer

`get_tools` is handed a `ReadonlyContext` carrying the session's state, the agent's name and the
user's id, so a crate can decide its inventory from what has already happened — and it may also be
handed nothing at all, which is why the `None` check is not optional.

## The story

A tool hire shop, on a Saturday morning.

You ask for a floor sander. The person behind the counter does not go and fetch one. They ask what
the job is. You say you are taking up carpet in a rented flat, and the answer changes: not that
sander, this smaller one, and no, they will not hire you the industrial drum sander at all, because
you have not hired from them before and that machine takes a floor down to nothing in about a
minute.

Nobody wrote a rule saying *no drum sanders on Saturdays*. The counter asked one question and used
the answer. Someone with a trade account and three previous hires gets a different reply to the same
sentence, from the same shop, with the same machines in the same room.

And there is a version of this that goes wrong. Ask over the phone, where there is no account on the
screen and no way to see the history, and the shop has to answer with nothing to go on. What it says
then is the cautious answer — the one it gives when it does not know who is asking.

## The idea in plain language

[Day 11](../../../day-11-tool-context/LESSON.md) introduced **session state**: a dictionary that
lives across the turns of one conversation, so a tool can write something in one turn and another
tool can read it in the next. A **session** is one conversation with one user; **state** is the
notes kept beside it.

`get_tools` receives a `ReadonlyContext`. It is a small object that lets a toolset look at what is
going on without changing it — the word **readonly** is the whole design. The crate is being asked
to *decide*, not to *act*, and giving it write access would let an inventory question quietly become
a side effect.

What is on it:

| Property | What it is | The obvious use |
| --- | --- | --- |
| `state` | the session's state, as a read-only mapping | offer a tool only once something exists for it to work on |
| `agent_name` | the name of the agent asking | give the FAQ agent a smaller inventory than the desk |
| `user_id` | who the conversation belongs to | offer refund tools only to staff accounts |
| `invocation_id` | the id of this one request | logging, and the whole of [2.2](../02-when-asked/2.2-asked-once-a-run.md) |
| `session` | the session object itself | rarely; prefer `state` |
| `user_content` | what the user actually sent | rarely, and see *In production* |

And one thing that is not on the table: **it can be `None`**. The parameter has a default of `None`
for a reason — anything that calls `get_tools()` without a live request in progress passes nothing,
and your own test code is the most common such caller. A crate that does `readonly_context.state`
unguarded works perfectly inside a run and raises the moment anyone inspects it outside one.

## Why Sutra needs it

Day 11 built `recall_last_triage`, a tool that reads a triage the desk recorded earlier in the same
session. In a fresh session there is nothing to recall, so the tool can only return "nothing yet".

Offering it anyway is not free. It costs tokens in the request on every turn, and — worse — it is an
invitation. A model shown a tool called `recall_last_triage` in a conversation that has recalled
nothing will sometimes call it, get an empty answer, and then explain that empty answer to the
customer. That is a wasted model call and a confusing reply, produced by a tool that had no business
being on the list.

You meet this again in **Phase 5**, on Day 40, where the same mechanism becomes a security control:
an MCP server offers thirty tools and the agent is only allowed four of them. Today's `if` statement
is that allowlist in miniature.

## The mechanism

```python
# lab/by_context.py - the same crate, two sessions, two inventories. Zero model calls.
from __future__ import annotations

import asyncio

from google.adk.agents import LlmAgent
from google.adk.apps import App
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.adk.tools.base_toolset import BaseToolset
from google.adk.tools.function_tool import FunctionTool
from google.genai import types

from stateless import ReactiveModel


def lookup_ticket(ticket_id: str) -> dict:
    """Look up a support ticket by its id."""
    return {"id": ticket_id, "summary": "charged twice"}


def recall_last_triage() -> dict:
    """Recall the triage recorded earlier in this session."""
    return {"recalled": "KB-104"}


class DeskTools(BaseToolset):
    """`recall_last_triage` is offered only once something has been recorded."""

    async def get_tools(self, readonly_context=None):
        tools = [FunctionTool(func=lookup_ticket)]
        if readonly_context is not None and readonly_context.state.get("triage"):
            tools.append(FunctionTool(func=recall_last_triage))
        print(
            f"   agent={readonly_context.agent_name!r}"
            f" user={readonly_context.user_id!r}"
            f" state={dict(readonly_context.state)}"
        )
        print(f"   offered: {[t.name for t in tools]}")
        return tools


async def run(state: dict) -> None:
    agent = LlmAgent(name="desk", model=ReactiveModel(model="s", chain=[]), tools=[DeskTools()])
    runner = Runner(app=App(name="d15", root_agent=agent), session_service=InMemorySessionService())
    session = await runner.session_service.create_session(
        app_name="d15", user_id="alia", state=state
    )
    async for _ in runner.run_async(
        user_id="alia",
        session_id=session.id,
        new_message=types.Content(role="user", parts=[types.Part(text="ticket 4521?")]),
    ):
        pass


async def main() -> None:
    print("a) a fresh session")
    await run({})
    print("b) a session where a triage was already recorded")
    await run({"triage": "KB-104"})


asyncio.run(main())
```

**Line by line:**

- `if readonly_context is not None and readonly_context.state.get("triage")` — the guard first, the
  question second. Python's `and` short-circuits, so the state is only touched once the context is
  known to exist. Reverse the two halves and the guard does nothing.
- `.state.get("triage")` rather than `.state["triage"]` — a missing key is the normal case here, not
  an error. `state` is a read-only mapping, so `.get` behaves exactly as it does on a dict.
- `dict(readonly_context.state)` in the print — `state` is a `MappingProxyType`, which prints as
  `mappingproxy({...})` and buries the thing you are looking at. Converting to a plain dict is for
  reading, not for use; the proxy is what stops you writing to it, and that is the point.
- `ReactiveModel(model="s", chain=[])` — an empty chain, so the scripted model answers with text and
  calls no tools. The experiment is about **what is offered**, not about what gets used, and a model
  call would only add noise.
- `create_session(..., state=state)` — the session starts with state already in it. That is the whole
  difference between the two cases: one dictionary key, set before the run begins.
- `async for _ in runner.run_async(...)` — the run is driven to completion and its events are thrown
  away. The measurement is the two `print` lines **inside** the crate, which is deliberate: printing
  the inventory from outside the run would be measuring a different call. That trap is
  [2.1](../02-when-asked/2.1-the-wrapper-adk-actually-calls.md).

Run it:

```text
$ cd days/day-15-toolsets-and-openapi/lab && uv run python by_context.py

a) a fresh session
   agent='desk' user='alia' state={}
   offered: ['lookup_ticket']
b) a session where a triage was already recorded
   agent='desk' user='alia' state={'triage': 'KB-104'}

```

Same class, same agent, same code. One key in a dictionary, and the model is shown a different set
of tools. Verified against `adk.dev/tools-custom/` and the installed `google-adk` 2.7.1 on
2026-08-30.

## When it breaks

Drop the `None` guard — `if readonly_context.state.get("triage")` — and the run still works
perfectly, because ADK always passes a context. Then write a test, or call the crate by hand to see
what is in it:

```text
Traceback (most recent call last):
  File "lab/by_context.py", line 44, in <module>
    asyncio.run(DeskTools().get_tools())
  File "lab/by_context.py", line 33, in get_tools
    if readonly_context.state.get("triage"):
       ^^^^^^^^^^^^^^^^^^^^^^
AttributeError: 'NoneType' object has no attribute 'state'
```

The reason this is worth a section rather than a footnote: the failure appears **only outside a
run**, so it lands in your test suite and not in production. That is the right way round, and it
still costs an hour if you go looking for it in ADK rather than in your own default argument.

The second failure has no traceback. Write the guard as

```python
if readonly_context and readonly_context.state.get("triage"):
```

and it looks identical and behaves identically — until a context arrives that is falsy for some
reason other than being absent. Prefer `is not None`: it says the thing you actually mean, and it is
the same lesson [Day 13](../../../day-13-callbacks-four-doors/LESSON.md) spent a whole section on
with callback return values.

## In production

**Do not branch on `user_content`.** It is on the context, and using it to pick tools is the
tempting shortcut: *if the message mentions a refund, offer the refund tool*. That is a keyword
matcher deciding capability, and it fails in both directions — a customer who writes "money back"
gets no refund tool, and a customer who writes "I do not want a refund" gets one. Worse, it is
reachable by anyone who can type. If which tools exist depends on the text of a message, then the
text of a message is a permission system. Branch on `state`, `user_id` and `agent_name`, which are
things your own code set.

**Keep `get_tools` cheap, and remember it runs on the request path.** A database query inside
`get_tools` is a database query added to every request, before the model has even been called. It
is not amortised the way you would hope — see [2.2](../02-when-asked/2.2-asked-once-a-run.md) for
exactly how often it runs — and it happens while the user is waiting. Read from `state`, which is
already in memory. If the answer genuinely requires a network call, cache it on the instance with a
deliberate expiry and be able to say what happens when the cache is stale.

**The inventory is a security boundary the moment it depends on `user_id`.** A crate that offers
refund tools to staff and not to customers is doing access control, and it is doing it in a place
nobody reviews as access control. Two rules follow. The check belongs somewhere it can be tested
without a model — [7.2](../07-in-production/7.2-testing-a-toolset-without-a-model.md) is that test.
And it must not be the *only* check: the tool itself must still refuse, because not offering a tool
is not the same as preventing its use. A senior reviewer's comment is exactly that sentence, and the
interview version is: *"you hide the admin tool from non-admins in `get_tools` — is that
authorisation, and what else would you want?"*
