# 2.1 — The wrapper ADK actually calls

## One-line answer

The agent never calls your `get_tools`; it calls `get_tools_with_prefix`, a method on the base class
that calls yours and then does two more things to the answer — so testing through your own method
tests something the agent never does.

## The story

You post a letter.

You write the address, stick the stamp on, walk to the box on the corner and drop it in. From where
you are standing, that is the whole operation: your handwriting goes in one end and a letter comes
out at the other.

It is not the whole operation. Between the box and the van there is a sorting office. Your envelope
is read by a machine, printed with a barcode along the bottom that you did not write and cannot see
in the dark, and put into a bag for a region. If the address is one you have used a hundred times,
the machine sometimes already knows the route and does not read it properly at all.

None of that is hidden from you. It is just not the part you did. And the day it matters is the day
you post a letter, watch a friend receive something with the wrong barcode, and try to work out
which handwriting caused it — because you have been thinking about the box on the corner, and the
thing that touched your envelope last was not the box.

## The idea in plain language

You implement `get_tools`. The agent does not call it.

The agent calls a different method, `get_tools_with_prefix`, which lives on `BaseToolset` and which
you inherit. That method calls yours, and then does two things to what comes back:

1. **It caches the answer** for the rest of the current request. That is
   [2.2](2.2-asked-once-a-run.md), and it is the more surprising of the two.
2. **It renames the tools**, if you asked it to, by putting a prefix on the front of every name.
   That is [2.3](2.3-two-crates-one-name.md).

So there are two answers to "what does my crate return", and they are not the same list. Yours is
the raw one. ADK's is the one the model is shown.

The method is marked `@final` in ADK's source. `@final` is a note to type-checking tools — *do not
override this* — and it is worth being precise: **Python does not enforce it**. Override it and your
version runs, quite happily, with no warning at all. What you lose is the caching and the renaming,
because those live in the method you replaced.

## Why Sutra needs it

This is the part that decides whether the test you write in
[7.2](../07-in-production/7.2-testing-a-toolset-without-a-model.md) means anything.

The obvious way to test a toolset is to build one and call `get_tools()` on it. That test is fast,
needs no model, and passes. It also cannot see a prefix, cannot see the cache, and therefore cannot
tell you whether the tools the agent actually receives are the ones you think. A green suite built
entirely on direct calls to your own method is a suite that has tested your method, not your agent.

You meet the same shape on **Day 33**, where an MCP toolset does real work in this wrapper, and
again on **Day 40**, where the filter that keeps a stranger's tools out of your agent runs in a place
your direct call skips.

## The mechanism

From `.venv/Lib/site-packages/google/adk/agents/llm_agent.py`, this is what an agent does with each
entry on its `tools` list:

```python
if isinstance(tool_union, BaseTool):
    return [tool_union]
if callable(tool_union):
    return [FunctionTool(func=tool_union)]

# At this point, tool_union must be a BaseToolset
try:
    return await tool_union.get_tools_with_prefix(ctx)
except Exception as e:
    logger.warning(
        "Failed to get tools from toolset %s: %s",
        type(tool_union).__name__,
        e,
    )
    return []
```

**Line by line:**

- The `isinstance` and `callable` tests run **in that order**, which is why a class passed without
  brackets is caught by the `callable` arm — [1.1](../01-crate-not-list/1.1-one-line-many-tools.md)'s
  first failure.
- `await tool_union.get_tools_with_prefix(ctx)` — the call, and the name. Not `get_tools`. This one
  line is the whole part.
- `ctx` is the `ReadonlyContext` from [1.3](../01-crate-not-list/1.3-what-the-crate-can-see.md),
  handed straight through.
- `except Exception ... return []` — a toolset that raises contributes **no tools**, and the run
  carries on. That is the day's failure lab and it has a part of its own:
  [6.1](../06-failure-lab/6.1-the-crate-that-arrived-empty.md). Note it here and read it there.

Here is the mechanism made visible. The crate announces every entry into either method:

```python
# lab/the_wrapper.py - which method does the agent actually call? Zero model calls.
from __future__ import annotations

import asyncio

from google.adk.agents import LlmAgent
from google.adk.apps import App
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.adk.tools.base_toolset import BaseToolset
from google.adk.tools.function_tool import FunctionTool
from google.genai import types

from stateless import ReactiveModel


def lookup_ticket(ticket_id: str) -> dict:
    """Look up a support ticket by its id."""
    return {"id": ticket_id, "summary": "charged twice"}


class Loud(BaseToolset):
    """Announces every entry into either method."""

    async def get_tools(self, readonly_context=None):
        print("      -> get_tools  (yours)")
        return [FunctionTool(func=lookup_ticket)]

    async def get_tools_with_prefix(self, readonly_context=None):
        print("      -> get_tools_with_prefix  (ADK's, @final)")
        return await super().get_tools_with_prefix(readonly_context)


async def main() -> None:
    crate = Loud(tool_name_prefix="vendor")

    print("a) inside a real run")
    agent = LlmAgent(name="desk", model=ReactiveModel(model="s", chain=[]), tools=[crate])
    runner = Runner(app=App(name="d15", root_agent=agent), session_service=InMemorySessionService())
    session = await runner.session_service.create_session(app_name="d15", user_id="alia")
    async for _ in runner.run_async(
        user_id="alia",
        session_id=session.id,
        new_message=types.Content(role="user", parts=[types.Part(text="ticket 4521?")]),
    ):
        pass

    print("b) calling your method yourself")
    print("      names:", [t.name for t in await crate.get_tools()])
    print("c) calling ADK's method yourself")
    print("      names:", [t.name for t in await crate.get_tools_with_prefix(None)])


asyncio.run(main())
```

**Line by line:**

- `async def get_tools_with_prefix(self, readonly_context=None)` — overriding the `@final` method on
  purpose, purely to watch it being entered. This is the one place in the day where doing that is
  correct, and the next line is why it stays correct.
- `return await super().get_tools_with_prefix(readonly_context)` — the override delegates rather than
  replaces, so the caching and the renaming still happen. Drop this line and return your own list
  instead, and the script would still run and would silently be measuring a crate that no longer
  behaves like a crate.
- `Loud(tool_name_prefix="vendor")` — a prefix is set, which makes the difference between cases
  **b** and **c** visible in one word rather than requiring a second experiment.
- Case **b** calls `crate.get_tools()` — the method you wrote, directly. This is exactly what a
  naive test does.
- Case **c** calls `crate.get_tools_with_prefix(None)` — what the agent does, with `None` standing in
  for the context the agent would have supplied.

Run it:

```text
$ cd days/day-15-toolsets-and-openapi/lab && uv run python the_wrapper.py

a) inside a real run
      -> get_tools_with_prefix  (ADK's, @final)
      -> get_tools  (yours)
b) calling your method yourself
      -> get_tools  (yours)
      names: ['lookup_ticket']
c) calling ADK's method yourself
      -> get_tools_with_prefix  (ADK's, @final)
      -> get_tools  (yours)
      names: ['vendor_lookup_ticket']
```

**Read case b against case c.** Same crate, same instant, two names for one tool. `lookup_ticket`
is what your method returns. `vendor_lookup_ticket` is what the agent receives, and it is the only
one of the two the model will ever see.

Verified against `adk.dev/tools-custom/` and the installed `google-adk` 2.7.1 on 2026-08-30.

## When it breaks

The failure here does not raise. It passes.

```python
async def test_the_crate_offers_two_tools():
    tools = await DeskTools(tool_filter=["lookup_ticket"]).get_tools()
    assert [t.name for t in tools] == ["lookup_ticket"]
```

Green. And it stays green when the prefix is wrong, when the filter is never applied
([3.1](../03-the-filter/3.1-a-filter-you-have-to-apply-yourself.md)), and when the agent is receiving
names nothing else in your codebase expects. The assertion is about a list the agent never sees.

The version that fails honestly is one word different:

```python
async def test_the_crate_offers_two_tools():
    tools = await DeskTools(tool_filter=["lookup_ticket"]).get_tools_with_prefix(None)
    assert [t.name for t in tools] == ["lookup_ticket"]
```

**Line by line:**

- `get_tools_with_prefix(None)` — the same entry point the agent uses, so the assertion is about the
  same list the agent gets.
- `(None)` — the context argument is required here even though it is optional in your own method,
  because you are calling ADK's signature and not yours. Passing `None` says *no live request*, which
  is honest for a test.
- The assertion is unchanged, and it can now go red for a reason that matters.

There is a second, louder failure worth knowing. Override `get_tools_with_prefix` **without**
delegating to `super()`, and nothing warns you:

```python
async def get_tools_with_prefix(self, readonly_context=None):
    return await self.get_tools(readonly_context)
```

`@final` produces no runtime error — Python does not enforce it, and the override simply runs. The
crate keeps working. What is gone is the prefix and the cache, so
[2.2](2.2-asked-once-a-run.md)'s "asked once per run" quietly becomes "asked every time", and a
`get_tools` that queries a database is now querying it repeatedly inside one request. Your type
checker would have said so; Sutra does not have one yet, which is the open `TODO` at the Day 31
quality gate.

## In production

**Test through the wrapper, always.** This is the concrete rule to take away, and it is one line in a
test file. Anything asserted about the tools an agent receives goes through `get_tools_with_prefix`;
anything asserted about your own decision logic can call `get_tools` directly, and should say so in
the test name. Two different questions, two different entry points, and mixing them is how a suite
becomes decorative.

**Do not override the wrapper.** If you find yourself wanting to, the thing you actually want is
almost always one of three things ADK already gives you: a different inventory (`get_tools`), a
different set of names (`tool_name_prefix`, [2.3](2.3-two-crates-one-name.md)), or a subset
(`tool_filter`, [3.1](../03-the-filter/3.1-a-filter-you-have-to-apply-yourself.md)). A reviewer who
sees `get_tools_with_prefix` in a diff will ask which of those three you meant, and the honest answer
is usually one of them.

**The swallowed exception in the snippet above is the thing to remember from this part.** Every
production incident this day can produce runs through those four lines: the crate raises, the
warning is logged at `WARNING` rather than `ERROR`, and the agent continues with fewer tools than it
should have. If your logging is set to `ERROR` in production — and a great many deployments are —
that line does not appear anywhere. The interview question is the one a good interviewer asks after
you describe toolsets confidently: *"what happens to the run if the toolset cannot answer?"*
