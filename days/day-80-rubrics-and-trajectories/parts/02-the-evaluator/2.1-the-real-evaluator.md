# 2.1 — The real evaluator, at zero cost

## One-line answer

`LlmAsJudge` resolves its rater through `LLMRegistry`, so registering a scripted `BaseLlm` under a
model id runs **ADK's own evaluator** — its prompt assembly, its parser, its majority vote, its
threshold — against a judge that costs nothing, and the only thing simulated is the sentence the
rater says.

## The story

The wedding rehearsal, the evening before.

Everybody is there. The priest is there, the family is there, the person who has to hand over the
ring is there and has been told twice which pocket. The chairs are where they will be. The order is
the order.

The bride is not there. Somebody's cousin is standing in her place, holding a dupatta, being told
where to walk.

Nothing about that makes the rehearsal fake. The whole point of the evening is to find out that the
music cue is too early, that the aunt cannot get past the second row, that the priest wants the
garland on the other side. Every one of those is a real fact about the real ceremony, discovered by
running the real ceremony with one person substituted.

What the rehearsal cannot tell you is how the bride will feel. That is the one thing the stand-in
cannot stand in for, and everybody knows it, and nobody pretends otherwise. It is a rehearsal, and
naming what it does not cover is what makes the rest of it trustworthy.

## The idea in plain language

Every rubric metric in ADK inherits from `LlmAsJudge`, and `LlmAsJudge` needs a model. That looks,
at first, like the end of this day for a curriculum that spends no money.

It is not, because of one method. `LlmAsJudge._setup_auto_rater` does not construct a Gemini client
directly. It asks a registry:

```text
model_id = self._judge_model_options.judge_model
llm_registry = LLMRegistry()
llm_class = llm_registry.resolve(model_id)
return llm_class(model=model_id)
```

`LLMRegistry` maps a **regex on the model id** to a `BaseLlm` subclass, and `LLMRegistry.register`
is a public static method that reads `supported_models()` off whatever class you hand it. So a class
whose `supported_models()` returns `[r"scripted-judge.*"]`, registered before the evaluator is built,
is what the evaluator will call for a judge model named `scripted-judge-1`.

This is the same seam Day 75 used from the other side.
[Day 75 part 1.2](../../../day-75-the-bidi-voice-loop/parts/01-the-open-line/1.2-five-methods.md)
found that a live model is five methods behind a context manager, and that anything implementing
those five can be driven by the real runtime. Here a judge is **one method**:
`generate_content_async(llm_request)`, an async generator of `LlmResponse`.

What that buys, and it is worth being precise because the value depends on the precision:

| Real, unmodified ADK code | Scripted |
| --- | --- |
| the prompt template and the dialogue assembly | the rater's answer |
| `DefaultAutoRaterResponseParser` and its four regexes | |
| `MajorityVotePerInvocationResultsAggregator` | |
| `MeanInvocationResultsSummarizer` | |
| the threshold, the `EvalStatus`, the `EvaluationResult` shape | |

**One cell on the right, five on the left.** Every claim this day makes about how a rubric score is
computed is a claim about code that ran. The one claim it cannot make is about how a real model
answers — which is the bride, and which is Day 81's subject.

## Why Sutra needs it

Because part [5.1](../05-in-production/5.1-what-a-rubric-costs.md) prices this metric at 30 requests
for three conversations, against the 20-per-day allowance Day 78 measured. Running it for real, even
once, would spend a day and a half of the only quota this repository has ever observed — and Day 78's
criterion 3 could not determine whether the lane Addendum 02 recommends has any allowance at all.

The alternative to the scripted judge is not "run it properly". It is "read the source and describe
what it would do", which is exactly the thing plan §17.8 calls stopping at the toy example.

## The mechanism

The whole seam is one class and one call. From `lab/_judge.py`:

```python
class ScriptedJudge(BaseLlm):
    """A BaseLlm that answers from the script instead of from a provider."""

    @classmethod
    def supported_models(cls) -> list[str]:
        """The regex LLMRegistry matches a model id against."""
        return [r"scripted-judge.*"]

    async def generate_content_async(
        self, llm_request: LlmRequest, stream: bool = False
    ) -> AsyncGenerator[LlmResponse, None]:
        global _calls
        prompts.append(llm_request.contents[0].parts[0].text)
        verdicts = _script(_calls) if _script else {}
        _calls += 1
        text = render(_rubrics, verdicts)
        yield LlmResponse(
            content=genai_types.Content(parts=[genai_types.Part(text=text)], role="model")
        )


LLMRegistry.register(ScriptedJudge)
```

**Line by line:**

- `BaseLlm` is a pydantic model with one field, `model`, so subclassing it needs no `__init__` at
  all. Verified against the installed `google-adk==2.7.1`, where `BaseLlm.model_fields` is exactly
  `['model']`.
- `supported_models()` returns a list of **regexes**, and `LLMRegistry.register` iterates them. The
  pattern `scripted-judge.*` is deliberately unlike any real model id, so registering this class
  cannot shadow `gemini-2.5-flash` or anything else — `_register` logs an "Updating LLM class"
  message when a pattern collides, and a lab that quietly replaced the real Gemini class would be a
  trap rather than a seam.
- `generate_content_async` is an **async generator** — `yield`, not `return` — because the caller
  wraps it in `Aclosing(...)` and iterates. Writing it as a coroutine returning a list fails at the
  `async for`, and the error is about `__aiter__` rather than about the shape of your function.
- `prompts.append(llm_request.contents[0].parts[0].text)` records what the judge was handed. That is
  not part of the seam; it is what part [2.2](2.2-what-the-judge-is-shown.md) reads, and it is the
  only reason this lab can show you the prompt at all.
- `stream: bool = False` has to be in the signature even though nothing here streams, because the
  base class declares it and the caller may pass it.
- `LLMRegistry.register(ScriptedJudge)` runs at **import time**, at module level. It has to happen
  before any evaluator is constructed, because `_setup_auto_rater` resolves the class in
  `LlmAsJudge.__init__` — not lazily at call time. Importing `_judge` after building the evaluator
  is a `ValueError: Model scripted-judge-1 not found.`

And the script itself — what the rater says:

```python
def render(rubrics: list[Rubric], verdicts: Verdicts) -> str:
    """One block per rubric, in the shape DefaultAutoRaterResponseParser reads."""
    lines = []
    for rubric in rubrics:
        lines += [
            f"ID: {rubric.rubric_id}",
            f"Property: {rubric.rubric_content.text_property}",
            f"Rationale: scripted verdict for {rubric.rubric_id}",
            f"Verdict: {verdicts.get(rubric.rubric_id, 'yes')}",
            "",
        ]
    return "\n".join(lines)
```

**Line by line:**

- Four lines per rubric, in this order, because the parser looks for exactly four things.
  `DefaultAutoRaterResponseParser`'s patterns on 2.7.1 are `(?m)^\s*ID: (.*)$`,
  `(?m)^\s*Property: (.*)$`, `(?<=Rationale: )(.*)` and `(?<=Verdict: )(.*)`.
- `Property:` repeats the rubric's own `text_property` verbatim, because that is what the real prompt
  instructs a rater to do — *"Repeat the property, word for word, without making any changes"* — and
  the parser uses the property lines to find the block boundaries.
- `verdicts.get(rubric.rubric_id, "yes")` defaults to yes for a line the script did not mention. That
  default is a deliberate convenience and it is also a small trap the lab writes down: a script that
  forgets a line silently passes it.
- The blank string at the end of each block gives one empty line between blocks. The regexes do not
  require it; a human reading the transcript does.

## When it breaks

Import this evaluator and the first thing that happens is a warning, and it is worth quoting because
it is a fact about the API you are building on:

```text
UserWarning: [EXPERIMENTAL] RubricBasedEvaluator: This feature is experimental and may change or be
removed in future versions without notice. It may introduce breaking changes at any time.
UserWarning: [EXPERIMENTAL] LlmAsJudge: This feature is experimental and may change or be removed in
future versions without notice. It may introduce breaking changes at any time.
```

Both `LlmAsJudge` and every rubric evaluator carry ADK's `@experimental` decorator on
`google-adk==2.7.1`. That is not a reason to avoid them — the plan assigns ADK-75 to this day — and
it is a reason to pin the version and to expect this surface to move. Principle 14 applies: if it
changes, the plan is amended before the code is.

The lab silences the warning in `_judge.py` so the measured output is readable, and says so in the
file. Silencing a warning without recording it is how a team forgets that a load-bearing dependency
is marked unstable.

The second break is the registration order:

```text
ValueError: Model scripted-judge-1 not found.
```

That is what `LLMRegistry.resolve` raises when nothing matches, and it arrives from inside
`LlmAsJudge.__init__` rather than from the call — because the judge is resolved when the evaluator is
constructed. `resolve` is also `@cache`d, and `_register` calls `resolve.cache_clear()`, so a class
registered late does take effect for evaluators built after it; the failure is only for the ones
built before.

The third break is the shape of the generator, and it is the one that costs an hour:

```text
TypeError: 'async for' requires an object with __aiter__ method, got coroutine
```

`async def` plus `return` gives a coroutine. `async def` plus `yield` gives an async generator. The
caller does `async for llm_response in agen`, so it needs the second.

## In production

**What a professional uses this seam for.** Not for pretending to have a judge — for **testing the
harness around one**. The retry behaviour, the parser, the aggregation, the threshold, the way
results are written to disk: all of that is code you wrote or configured, all of it is where the
bugs actually are, and none of it needs a model to exercise. Teams that only ever test their eval
pipeline against a live judge are paying money to test their own `if` statements.

**What degrades at scale.** A registry is global mutable state. Registering a fake model in a test
process changes what every other test in that process resolves, and the pattern `scripted-judge.*`
is safe only because nothing else matches it. A pattern like `.*-test` or, worse, `gemini.*` in one
test file will silently redirect an unrelated test's model, and the failure will appear somewhere
else entirely.

**The failure that only shows with real traffic.** Everything the scripted judge cannot tell you.
A real rater is inconsistent between samples, is influenced by the order things appear in, and gives
longer answers higher marks — none of which a script reproduces, because a script says what it was
told. Part [4.1](../04-when-raters-disagree/4.1-three-samples-three-answers.md) simulates the first
of those deliberately, and Day 81 measures all three against a judge that is not scripted.

**The review comment a senior engineer leaves:** *"Good — this tests our parser and our aggregation
without spending anything, and I want it in CI. Two conditions. Keep the fake model's pattern
obviously fake, because that registry is process-global. And put a comment on the silenced warning
saying which classes are `@experimental` on which version, so the next upgrade has somewhere to
start."*

**The interview question:** *"How would you test an LLM-as-judge pipeline without calling an LLM?"*
The answer that shows experience finds the seam — the interface the library resolves its model
through — and substitutes there, then says precisely what the substitution does and does not cover.
A candidate who says "mock the API call" has usually mocked at the wrong layer and is testing their
mock.
