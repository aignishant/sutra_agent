# 6.1 — Run the pack against the routing gate

## One-line answer

A sourced pack can pass the security audit clean and still make your shelf worse, because four
well-meant, honestly-described skills narrow every routing margin they touch — so a sourced pack is run
against Day 28's routing gate before it merges, exactly as Day 28 promised Day 29 would.

## The story

A new bus route is added to the board at the stop, and every other route on the board got harder to read.

Nothing is wrong with the new route. It goes somewhere people want to go, its times are honest, its
number is clear. But the board only has so much room, and now the 12 and the 12A and the new 12B sit
together, and a person who used to glance up and find their bus in a second is standing there reading
three near-identical entries, checking the small print about which one goes past the hospital.

The person who added the route did everything right. They could not see the board as a whole from inside
their own timetable, because their job was to describe *their* route well — and they did. The damage is
not in any route. It is on the board, and no single route-planner can see it from their own desk.

## The idea in plain language

Day 28 proved that adding vague skills to a shelf does not merely fail to help — it actively degrades the
skills already there, dropping every routing margin without a word of the good descriptions changing
([28.2.4](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.4-the-crowded-shelf.md)).
That part ended with a promise: *"this is precisely what Day 29 will do to Sutra's shelf, and it will do
it in one commit."* This is that commit.

The key idea is that a sourced pack brings **two separate audits**, and passing one says nothing about
the other:

- The **security audit** ([Section 2](../02-the-five-pass-audit/2.1-read-it-like-the-thing-that-will-obey-it.md))
  asks *should my agent obey this?* — the poisoned-fixture question.
- The **routing gate** ([28.2.3](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.3-measuring-routing-without-a-model.md))
  asks *does adding this make the shelf harder to route?* — the crowded-board question.

A pack can sail through the first and fail the second. The sourced pack in this part is written to do
exactly that: four plausible support-desk skills — incident escalation, SLA-breach checking, customer
refunds, bug-report triage — each honestly described in the vocabulary of the domain, each ships no
script and hides nothing. The security audit comes back with **zero findings**. And they still wreck the
routing, because "the vocabulary of the domain" is the vocabulary Sutra's own descriptions already use
([1.3](../01-the-doors/1.3-freshness-is-not-trust.md) said popularity would not save you here; neither
does honesty).

So the rule for a sourced pack is: **run it against the routing gate before you merge it, with the pack
included**, because a pull request that adds a skill and drops the worst margin is a pull request that
made the existing shelf worse — and the author cannot see it by reading their own file.

## Why Sutra needs it

Because sourcing is where Day 28's warning stops being hypothetical. The whole reason to install a
sourced pack is that someone else wrote skills you would otherwise write yourself — which guarantees
their descriptions are in your domain's words, which is exactly the condition that collides on the shelf.
Nothing in the pack has to be bad for your routing to get worse; it only has to be *about the same
things* your skills are about.

This part also settles, with a number, a question that would otherwise be argued: *"is it fine to install
a general support pack alongside our two skills?"* The answer is not a preference. It is a margin, and the
margin is in the output below.

## The mechanism

The measurement reuses Day 28's routing instrument — `route.py`, its `rank` and `report` and the fixed
request list — and adds the sourced pack to Sutra's real shelf:

```python
# lab/sourced_shelf.py
import pathlib
import sys

from google.adk.skills import load_skills_from_dir

sys.path.insert(0, str(pathlib.Path("days/day-28-progressive-disclosure-design/lab").resolve()))

from route import REQUESTS, rank, report  # noqa: E402

PACK = pathlib.Path("tests/fixtures/skills/sourced-pack")
MINIMUM_MARGIN = 1

mine = sorted(load_skills_from_dir(pathlib.Path("skills")), key=lambda s: s.name)
theirs = sorted(load_skills_from_dir(PACK), key=lambda s: s.name)
scored = [r for r in REQUESTS if rank(mine, r)[0][0] > 0]

print(f"--- Sutra's shelf: {len(mine)} skills ---")
print(f"ties: {report(mine, scored)}")

merged = sorted(mine + theirs, key=lambda s: s.name)
print(f"\n--- plus the sourced pack: {len(merged)} skills ---")
print(f"ties: {report(merged, scored)}")

worst = min(rank(merged, r)[0][0] - rank(merged, r)[1][0] for r in scored)
print(f"\nworst margin after the merge: {worst} (threshold {MINIMUM_MARGIN})")
sys.exit(0 if worst >= MINIMUM_MARGIN else 1)
```

**Line by line:**

- `sys.path.insert(0, ...day-28...lab)` imports Day 28's routing module rather than copying it. Two copies
  of the scorer would drift, and the gate you trust is the one Day 28 already tuned
  ([28.2.3](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.3-measuring-routing-without-a-model.md)).
  The `# noqa: E402` is because the import follows the path insertion by necessity.
- `mine` is Sutra's real shelf loaded from `skills/`; `theirs` is the sourced pack from
  `tests/fixtures/`. They are loaded separately so the two runs differ in exactly one thing — the pack —
  which is the same one-variable discipline the crowded-shelf experiment used
  ([28.2.4](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.4-the-crowded-shelf.md)).
- `scored` drops any request that matches nothing on the real shelf, because a margin is meaningless for
  an unmatched request and a coverage gap is a different finding
  ([28.2.2](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.2-coverage-orthogonality-specificity.md)).
- `report` is called on both shelves against the same requests, so the two tie counts are directly
  comparable and the tables print identically.
- `worst = min(...margin...)` and `sys.exit(0 if worst >= MINIMUM_MARGIN else 1)` make this a **gate**:
  the pack is a merge blocker if it drops the worst margin below the threshold Sutra's shelf already
  achieves.
- **Zero model calls.** Set arithmetic over descriptions, exactly like Day 28.

Run it from the repository root. On 2026-09-04:

```bash
uv run python days/day-29-sourcing-and-auditing-skills/lab/sourced_shelf.py
echo "exit: $?"
```

**Line by line:**

- The exit code is the deliverable. **Zero generations, no key.**

```text

what priority should this ticket get     ticket-triage         2  margin  2
triage this ticket for me                ticket-triage         2  margin  2

how do we word an answer that cites a    kb-answer-style       4  margin  4

--- plus the sourced pack: 6 skills ---
how urgent is this ticket                ticket-triage         2  margin  1
what priority should this ticket get     ticket-triage         2  margin  0
triage this ticket for me                ticket-triage         2  margin  1
draft a reply to the customer on this    sla-breach-check      2  margin  0

```

Read the two tables against each other. **No score of a real skill changed** — `ticket-triage` still
scores 2 on every request it should win, its description byte-for-byte the same. But four margins dropped
and two collapsed to zero: *"what priority should this ticket get"* is now a tie, and *"draft a reply to
the customer on this ticket"* is now **won by `sla-breach-check`**, a sourced skill whose job has nothing
to do with drafting replies. It won on the words `ticket` and `customer`, which it happens to share, and
the margin of zero means the tie broke on sort order rather than on merit. The security audit found
nothing wrong with this pack, and the routing gate exits 1.

## When it breaks

**Merging a pack because the security audit was clean.** Zero findings from the five passes means the
pack is not hostile. It says nothing about whether the pack belongs on your shelf. These are two audits,
and a pull request needs to pass both — the security audit *and* the routing gate — before it merges.

**Installing the pack all at once and measuring afterwards.** A pack of four added in one commit tells you
the shelf got worse and not which of the four did it. Add them one at a time against the gate, or accept
that the diagnosis will be a bisection ([28.2.4](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.4-the-crowded-shelf.md)
made the same point). The provenance row is per-pack, but the routing decision is often per-skill.

**Trying to fix it by sharpening your own descriptions.** Rewriting `kb-answer-style` to win against four
skills that describe the whole domain is work against the wrong opponent. The fix is upstream: sharpen the
*sourced* skill's description into a specific job, or do not install it
([28.2.4](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.4-the-crowded-shelf.md)).
The routing gate tells you which; the crowded-shelf part told you why.

## In production

**A professional treats "adds a skill" as "changes every skill" in review.** The routing gate runs in CI
on any change to `skills/`, and a diff that adds a sourced skill and drops the worst margin is a diff that
regressed the shelf, stated as an exit code the author cannot talk their way past. This is the same
ratchet as Day 28's threshold: the gate does not demand improvement, it forbids regression
([28.2.3](../../../day-28-progressive-disclosure-design/parts/02-descriptions-as-routing/2.3-measuring-routing-without-a-model.md)).

**What changes at scale** is that curation stops being enough. At forty skills the domain vocabulary is
exhausted, every margin is one, and no rewrite produces orthogonal descriptions because the skills really
are all about tickets. The structural answers then are hierarchy — one routing skill that leads to a
family — or search instead of listing ([28.5.1](../../../day-28-progressive-disclosure-design/parts/05-in-production/5.1-when-the-index-outgrows-listing.md)),
and a runtime registry is one way to reach the search shape ([5.1](../05-the-registry/5.1-search-fetch-and-parked.md)),
with the audit cost that part described. Both are architecture, and both are easier to adopt before the
shelf is a mess than after.

**The failure mode that only appears with real traffic** is the sourced skill that wins a request it
should not. In this run `sla-breach-check` now wins *"draft a reply"*; in production that is a real
conversation routed to the wrong procedure, and it looks like a model mistake rather than a shelf problem.
The margin of zero is where that lives — a coin flip on sort order — and it is invisible until you measure
it, which is the entire reason the gate exists.

**The review comment a senior engineer leaves:** *"this pack passes the security audit — good. Now run the
routing gate with it: I expect the worst margin to drop to zero and the reply-drafting request to be won
by an SLA skill. The pack isn't malicious, it's just a shelf full of the domain's words. Sharpen the
sourced descriptions into specific jobs or drop the pack — and add it one skill at a time so we know which
one costs what."*

**The interview question:** *"a security-clean skill pack — is there any reason not to install it?"* The
honest spoken answer: *"Yes — it can wreck your routing. A sourced pack is written by people who describe
their skills honestly in the domain's vocabulary, which is the exact vocabulary your own descriptions use,
so adding it narrows every routing margin it touches without a single score of yours changing. I measured
it: two skills plus a four-skill support pack, no real score moved, four margins dropped, two collapsed to
zero, and a reply-drafting request got won by an SLA-breach skill on shared words. Security audit and
routing are two different audits; a pack has to pass both. So the rule is run the routing gate with the
pack before merging, add skills one at a time so you know which costs what, and fix it upstream by
sharpening the sourced descriptions or not installing — not by rewriting your own good skills to compete."*
