# 6.1 — Testing what goes in the window

## One-line answer

Prompts are testable: a recording model plus a scale gives you seven assertions about size, growth and
presence that run in a second with no key — and writing them exposed two of them as too weak, which is
the part worth copying.

## The story

The checklist by the front door.

Keys, wallet, phone. Three words on a bit of card, at eye level, and it is faintly embarrassing that it
is there. Nobody needs a checklist for three things.

Except that the day you leave without your keys is not a day you were being stupid. It is a day the
post arrived as you were going out and something ordinary broke the sequence — and the card is not
there for your competence, it is there for the interruption.

## The idea in plain language

Everything this day measured can be asserted, because none of it needs a model. The recording model
from [2.1](../02-anatomy/2.1-opening-the-envelope.md) gives you the exact request; the scale from
[4.1](../04-measuring/4.1-a-scale-for-prompts.md) gives you a number per organ; and the assertions
follow directly from the parts:

| The claim | Where it came from |
| --- | --- |
| `weigh` names every organ | [2.2](../02-anatomy/2.2-six-organs-and-who-packed-them.md) |
| the instruction is the same size every turn | [2.4](../02-anatomy/2.4-a-subscription-not-a-purchase.md) |
| the history grows and nothing else does | [1.3](../01-the-binder/1.3-the-organ-that-grows-by-itself.md) |
| a state key is not in the window unless templated | [5.1](../05-failure-lab/5.1-in-state-and-not-in-the-window.md) |
| `distil` keeps only the unusual lines, and caps them | [3.2](../03-selection/3.2-facts-not-blobs.md) |
| the desk's request stays inside its budget | [6.2](6.2-a-budget-per-organ.md) |
| a pasted log blows the message budget | [4.2](../04-measuring/4.2-curated-against-kitchen-sink.md) |

Two of those are unusual and worth naming.

**One asserts an absence.** *A state key is not in the window unless templated* checks that
`note_file` does **not** appear in the request. Tests that assert absence are rare and they are the
right shape here: the bug being prevented is a belief, and the test is the belief written down as
something that can go red.

**And one asserts a limit rather than a value.** *The desk stays inside its budget* does not care what
the prompt says. It cares that no organ has grown past its allowance
([6.2](6.2-a-budget-per-organ.md)), which is a regression test for a quantity nobody would otherwise
watch.

## Why Sutra needs it

Because prompt size regresses silently and continuously.

Every future day adds a candidate: a tool ([2.3](../02-anatomy/2.3-the-menu-costs-more-than-the-handbook.md)),
a sentence in the instruction ([2.4](../02-anatomy/2.4-a-subscription-not-a-purchase.md)), a fact
templated because it seemed useful. None of those is wrong on its own and none of them fails a test
today. In six weeks the desk's request is four times the size and nobody can name the change that did
it.

A budget assertion in the suite converts that from an archaeology problem into a failing build on the
commit that caused it.

## The mechanism

The suite, and — more usefully — what happened when it was checked against deliberate breakage.

```python
# tests/test_context.py  (four of the seven; the rest follow the same shape)
"""Day 19 - what can be asserted about a prompt without sending it."""

from sutra.context import BUDGET, ORGANS, distil, over_budget, weigh


def test_the_history_grows_and_nothing_else_does() -> None:
    """1.3: exactly one organ grows on its own."""
    requests = _run(_desk(tools=[lookup_ticket]), ["one", "two", "three"])
    sizes = [weigh(request) for request in requests]
    assert sizes[0]["history"] < sizes[-1]["history"]
    assert sizes[0]["tools"] == sizes[-1]["tools"] > 0


def test_a_state_key_is_not_in_the_window_unless_templated() -> None:
    """5.1: state is your code's memory, not the model's."""
    agent = _desk(instruction="You are Sutra. Severity is {severity?}.")
    requests = _run(agent, ["what is this?"], state={"severity": "high", "note_file": "n.md"})
    body = str(requests[-1].config.system_instruction) + str(requests[-1].contents)
    assert "high" in body
    assert "note_file" not in body
    assert "n.md" not in body


def test_distil_keeps_only_the_unusual_lines_and_caps_them() -> None:
    """3.2: send the finding, not the evidence - and the cap is what saves a bad day."""
    finding = distil(LOG)
    assert finding.count("\n") + 1 == 2
    assert "INFO" not in finding
    assert len(finding) < len(LOG) / 10

    every_line_is_a_warning = "2026-09-03T10:00:00Z WARN auth.session cookie_rejected\n" * 40
    assert distil(every_line_is_a_warning, keep=5).count("\n") + 1 == 5


def test_a_pasted_log_blows_the_message_budget() -> None:
    """3.2, from the other side: this is what the budget is for."""
    requests = _run(_desk(), [f"here is the log:\n{LOG * 4}"])
    assert "message" in over_budget(weigh(requests[-1]))
    assert BUDGET["message"] < len(LOG * 4)
```

**Line by line:**

- `_run(agent, messages, state=None)` is a helper the file defines once: it builds a service and a
  runner, optionally seeds state, drives the agent over the messages and returns **every** request the
  recording model saw. Every test is then three lines.
- `sizes[0]["tools"] == sizes[-1]["tools"] > 0` — chained comparison, and the `> 0` is the important
  half. Without it the assertion passes when `weigh` returns zero for tools, which is exactly the bug
  the mutation table below found.
- `assert "note_file" not in body` — the absence assertion. Note it checks the **key** and the
  **value**, because either appearing would mean the fact reached the model.
- The second half of the `distil` test uses a log where **every** line matches, so the cap is exercised.
  Without it, `keep` is never reached and a distiller with no cap passes.
- `over_budget(weigh(...))` returns a list of organ names, so the assertion says which organ rather than
  that "something" was too big.

Watch it go red, then green:

```bash
uv run python -m pytest tests/test_context.py -q -m "not live"   # RED: no sutra/context.py yet
# ... write the module from the hub's build brief ...
uv run python -m pytest tests/test_context.py -q -m "not live"   # 7 passed
```

**Line by line:**

- The first run fails at collection with `ModuleNotFoundError: No module named 'sutra.context'`.
- No key and no network: every test uses the recording model.

Then break each thing on purpose. This table was **measured**, each mutation applied on its own to a
green suite, on 2026-09-03 — and the first run of it is the reason this part exists:

| Break this | Which test goes red | What it is telling you |
| --- | --- | --- |
| `distil` matches `INFO` too | 1 — the distil test | the filter selects nothing (3.2) |
| `distil` loses its cap | 1 — the distil test | a filter with no bound does nothing on a bad day (3.2) |
| the message budget becomes generous | 1 — the pasted-log test | the budget is the detector (6.2) |
| `weigh` reports `0` for tool declarations | 1 — the growth test | the scale itself can lie (4.1) |

**Two of those four went green the first time.** The `distil` cap mutation and the `weigh` mutation both
passed against the original suite: the distil test used a log with only two matching lines, so the cap
never bound, and the growth test compared tools between two turns without checking they were non-zero —
so a scale returning zero satisfied it perfectly.

That is the part worth copying. A mutation that does not go red means the test was checking a weaker
claim than its name says, and the only reliable way to find that out is to break the code on purpose
and look. Both tests above are the strengthened versions.

## When it breaks

**The suite is green and the assertion is vacuous.**

No error, by definition. The measured example is above: `sizes[0]["tools"] == sizes[-1]["tools"]` is
true when both are zero, so a test named *"nothing else grows"* passed against a scale that had stopped
measuring. The habit that catches it is the mutation table — not once, but as part of writing each
assertion: *what would I break to make this fail?*

**The recording model diverges from the real one.** These tests assert what ADK **assembles**, not what
a provider receives. If ADK changes what it appends — the identity line it adds after your instruction
([2.1](../02-anatomy/2.1-opening-the-envelope.md)) is exactly such a thing — the numbers move and a
budget test may go red for a reason that is not your change. That is a good failure: it is a pinned
dependency's behaviour changing, and Principle 14 says amend first.

**A budget test goes red on an unrelated change.** It will, occasionally, and the right response is
usually to look rather than to raise the limit. When the limit really is wrong, raising it deliberately
with a one-line reason in the commit is the whole point of having it.

## In production

**Assert on shape and size, not on wording.**

The version a professional keeps does not assert that the prompt contains a particular sentence — that
is brittle and it fights every improvement. It asserts the things that are invariant: which organs
exist, which facts are present, which are absent, and that no organ has grown past its allowance.

**What changes at scale** is that this becomes the cheapest part of the eval suite. Day 79 builds evals
that need a model and cost quota; these need neither, run in a second, and catch the class of
regression that quota-based evals are too expensive to catch on every commit.

**What fails only under real traffic** is everything about *quality*. Nothing in this file knows whether
the prompt is any good — only whether it is the shape you intended. That is the honest division: shape
and size here, behaviour in evals, and the third cost from
[1.2](../01-the-binder/1.2-three-costs-in-one-scene.md) — attention — measurable only through outcomes.

**The review comment**: *"this test would pass if `weigh` returned zeros. Add the bound that makes it
mean what its name says."*

**The interview question**: *"how do you test a prompt?"* The answer that shows practice rather than
theory: *"with a stand-in model that records the request, and assertions about shape and size rather
than wording — which organs exist, which facts are present, which are deliberately absent, and a budget
per organ. And I check the assertions by breaking the code on purpose, because two of mine were
vacuous."*
