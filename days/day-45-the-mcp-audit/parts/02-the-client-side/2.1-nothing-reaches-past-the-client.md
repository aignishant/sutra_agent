# 2.1 — A01: nothing reaches past the client

## One-line answer

`A01` parses every module under `sutra/` except `sutra/mcp/` and fails on any import of a database
driver or an HTTP library, which turns Day 32's *"the boundary is MCP"* from a design intention into a
statement the repository can contradict.

## The story

The campus has one gate, and a register at it, and a man who looks at the register.

Everybody who comes in signs. Parents, the courier, the man who services the water cooler. If you want
to know who was on the grounds on a Tuesday afternoon, you look at one book.

There is also a gap in the hedge behind the sports field. It has been there for years. It is how the
boys get to the shop at the corner during the lunch break, and everybody knows about it, including the
man at the gate, who was a boy at a school with a hedge himself.

Nobody thinks the gap is a security problem, and in the ordinary run of things they are right — it is
used by fourteen-year-olds buying sweets. What the gap actually costs is the *sentence*. Before the gap
existed, "everyone on the grounds signed the book" was true. After it, the book is a record of the
people who used the gate, which is a different and much less useful claim, and the difference does not
show up on any ordinary day.

The morning it matters, somebody will ask who was on the grounds, and the honest answer will be "these
people, plus anybody who came through the hedge", and nobody will be able to say how many that is.

## The idea in plain language

Day 32's
[1.5 — One gate to guard](../../../day-32-mcp-stateless-core/parts/01-the-socket/1.5-one-gate-to-guard.md)
made the argument: Sutra's **data boundary** — the line every piece of outside data must cross to get
in — is MCP, and the value of that is not elegance. It is that a boundary you can point at is one you
can guard, measure and replace.

That part ended with a measurement and a promise. It printed the modules under `sutra/` that import a
database driver or an HTTP library, and it said, in as many words:

> It prints rather than asserts, because on Day 32 this is a measurement and not yet a gate. Turning it
> into a test with an `assert` is Day 45's work.

`A01` is that promise, kept. The rule in one sentence: **no module under `sutra/`, outside
`sutra/mcp/`, may import a way of reaching outside data directly.**

Three parts of that sentence are decisions rather than facts, and each is worth defending.

**Why `sutra/` and not everything.** `sutra_mcp/` is *expected* to import a database driver — Day 39
gives it SQL-backed tools, and that is its job. A check that failed there would be saying the boundary
is in the wrong place. The scope of the rule *is* the statement of where the line runs.

**Why `sutra/mcp/` is exempt.** That package is the gate. It imports `mcp` because it is the client;
excluding it is not a loophole, it is the definition of the one legitimate crossing point. The
exemption is written as a path prefix rather than a per-file marker, so adding a second exempt file
means moving it into that package — which is exactly the review conversation you want to force.

**Why imports rather than calls.** An import is a static, honest signal that survives every kind of
indirection. A file that imports `sqlite3` might not call it today, and it can tomorrow, from anywhere,
without a further import. Checking calls would mean tracking values through the program; checking
imports means reading the top of a syntax tree.

## Why Sutra needs it

Because by the end of Phase 6 there are three ways into Sutra's data and only one of them is supposed
to exist.

Day 39 put ticket data in SQLite behind `sutra_mcp/db_tools.py`. Day 33 wrote the client that reaches
it. And the shortcut is always one import away: somebody needs a field the MCP tool does not return,
the connection string is already in the environment, and `sqlite3` is in the standard library so there
is not even a dependency to add. Day 32 predicted the exact filename it would appear in, and the audit
prints it if it ever does.

The consequence is not a breach. It is that four things Sutra has built stop being true at once. The
allowlist from Day 40 only filters what goes through the client. The token accounting from
[Day 24](../../../day-24-token-accounting-and-budgets/LESSON.md) only counts what goes through the
client. The structured log from [Day 22](../../../day-22-structured-logging/LESSON.md) only records
what goes through the client. And *"what can this agent reach?"* only has one answer while there is one
gate.

## The paper behind it

> **End-to-end arguments in system design** · `doi:10.1145/357401.357402` · 1984 ·
> `https://doi.org/10.1145/357401.357402`

It argued that a function belongs at the layer with enough knowledge to complete it correctly, and that
implementing it lower down is justified as an optimisation rather than as correctness.

Applied here: only the host knows who the user is, what the run may spend and what has already been
read, so the guard belongs on the host side of the boundary — and a second, unguarded path out of the
host is not a lower-level optimisation, it is the function being skipped. The paper is taught in full
on Day 21, at
[`../../../day-21-errors-surface-not-swallow/papers/01-end-to-end-arguments.md`](../../../day-21-errors-surface-not-swallow/papers/01-end-to-end-arguments.md).

## The mechanism

```python
# tools/mcp_audit.py
FORBIDDEN = {"sqlite3", "psycopg", "psycopg2", "httpx", "requests", "aiohttp", "urllib", "mcp"}


def _imports(tree: ast.Module) -> set[str]:
    found: set[str] = set()
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            found |= {alias.name.split(".")[0] for alias in node.names}
        elif isinstance(node, ast.ImportFrom) and node.module:
            found.add(node.module.split(".")[0])
    return found


def check_boundary(root: Path) -> list[Finding]:
    """A01 boundary: no module under `sutra/` outside `sutra/mcp/` reaches outside."""
    agent = root / "sutra"
    if not agent.exists():
        return [_missing("A01", "sutra/", "day 1")]
    findings = []
    for path in _py_files(agent, exclude="sutra/mcp/"):
        tree = _parse(path)
        if tree is None:
            continue
        crossing = sorted(_imports(tree) & FORBIDDEN)
        if crossing:
            findings.append(
                Finding("A01", "block", path.as_posix(), f"imports {', '.join(crossing)}")
            )
    return findings
```

**Line by line:**

- `FORBIDDEN` grew by one name since Day 32 measured this: **`mcp` itself**. A module under `sutra/`
  outside `sutra/mcp/` that imports the protocol library has built a second client, which is the same
  hole with better manners. The other seven are the ways to reach a database or an HTTP endpoint
  without one.
- `urllib` is in the set and `json` is not, which is the line the set is drawing: parsing is fine,
  *fetching* is not.
- **`FORBIDDEN` is a `TODO(me)` in the hub.** The set above is defensible and it is not the only
  defensible one — a repository that legitimately uses `httpx` for something unrelated to data needs a
  different answer, and the answer must be written down rather than discovered by whoever hits it.
- `ast.walk` rather than a `grep`, for the reason Day 32 gave and which is worth repeating: a grep
  matches the word `requests` in a docstring and in a comment, and a check that reports a comment is a
  check somebody disables. `ast.walk` also descends into function bodies, so an import hidden inside a
  function — the classic way a shortcut avoids a reviewer skimming the top of a file — is caught.
- `alias.name.split(".")[0]` reduces `sqlite3.dbapi2` to `sqlite3`, so the rule is written once per
  library rather than once per submodule.
- `ast.ImportFrom` with `node.module` guarded, because a relative import writes `from . import x` and
  leaves `module` as `None`. Without the guard this raises `AttributeError` on the first relative
  import in the package.
- `_py_files(agent, exclude="sutra/mcp/")` is the exemption, expressed as a path fragment on the posix
  form of the path so it reads the same on Windows and Linux. `Path.rglob` returns backslash-separated
  paths on Windows, and a substring test against `"sutra/mcp/"` would silently match nothing there —
  which is a check that is green on one operating system and red on another, the least useful kind.
- `if tree is None: continue` — a file that does not parse is skipped by this check rather than
  reported. That is a deliberate division of labour: `ruff check .` already runs first in the gate and
  a syntax error stops it there ([Day 31's
  1.2](../../../day-31-the-quality-gate/parts/01-what-a-gate-is/1.2-six-stages-cheapest-first.md)), so
  reporting it again here would be a second voice saying the same thing.
- `_missing(...)` when `sutra/` is absent. **A missing target is a finding, not a skip** — the single
  most important line in the whole module, and [6.1](../06-failure-lab/6.1-green-because-the-path-did-not-exist.md)
  is what happens without it.
- `sorted(...)` on the crossing set so the message is stable between runs. An unsorted set prints in a
  different order each time, which makes the audit's own output produce spurious diffs.

Here is the rule going red. A file is planted in a scratch copy of the tree — never in `sutra/` itself,
because you do not break the thing you are measuring — with the exact shortcut Day 32 predicted:

```python
# a scratch copy of sutra/desk/quick_lookup.py - the shortcut, as it actually gets written
import sqlite3


def rows(ticket_id: str) -> list[str]:
    con = sqlite3.connect("data/tickets.sqlite3")
    return [r[0] for r in con.execute("select body from tickets where id = ?", (ticket_id,))]
```

**Line by line:**

- Six lines, correct, parameterised against injection, and it works. That is the point: the person who
  writes this is not being careless, they are being effective, and nothing about the code itself is
  wrong.
- What it costs is the sentence. From this commit onward, *"what can this agent reach?"* has two
  answers and every later guarantee has to be checked in two places.
- The scratch copy is a real directory holding a `sutra/` and a `sutra_mcp/` tree with one deliberate
  violation in each — a fixture, in the sense Day 29 used the word for its poisoned skill. Building the
  fixture is how you find out that a check works, and it is the one honest alternative to breaking the
  repository to test the alarm.

Run the check against that tree:

```bash
python -c "
from pathlib import Path
import audit_preview as a
for f in a.check_boundary(Path('.')):
    print(f)
"
```

**Line by line:**

- `check_boundary(Path('.'))` — the check takes its root as an argument, which is the entire reason it
  can be pointed at a fixture. A check that computed the repository root internally could only ever
  audit one tree, and could therefore never be tested.
- The loop prints each finding through `Finding.__str__`, so the fixture output has exactly the format
  the gate produces.

Measured on 2026-09-05:

```text
  [A01] block sutra/desk/quick_lookup.py: imports sqlite3
```

One line, and it names the file and the import. That is enough to act on without opening anything.

## When it breaks

**The check is green and the hole is there anyway.** The shortcut moved into `sutra/mcp/`, which is
exempt. Somebody put a direct database read in the client package because that felt like the honest
place for it, and the exemption swallowed it. The audit is doing exactly what it was told; the rule is
too coarse. The fix is a second, narrower rule inside the exempt package — the one
[2.3](2.3-nothing-holds-a-connection.md) writes — and the general lesson is that an exemption is a
place to look, not a place to stop looking.

**The check is red on a false positive.** A module under `sutra/` imports `urllib.parse` to split a
URL, which reaches nothing:

```text
  [A01] block sutra/mcp_uri.py: imports urllib
```

This is a real design question wearing the clothes of a bug. Two answers are defensible — drop `urllib`
from `FORBIDDEN` and accept that a fetch through it goes unnoticed, or keep it and move the parsing
helper into the exempt package. What is **not** defensible is a `# noqa`-style suppression on the line,
because the next person will copy it.

**The whole check disappears.** Somebody renames `sutra/` to `sutra_agent/` and this check reports
`target does not exist` — which is a finding, loudly, exactly as designed. Compare it with what a
`if not agent.exists(): return []` would have printed, which is nothing at all, forever.

## In production

**What a professional writes instead:** the boundary is enforced by packaging, not only by a check. The
agent distribution does not *depend* on a database driver, so importing one fails at install time in a
clean environment rather than at review time. Large codebases push this further with import-linter
style contracts — layers declared in configuration, with forbidden edges between them — so the rule
reads as an architecture diagram rather than as a set of module names. The check here is the
lightweight version, and it is the one that fits in a repository with a `pyproject.toml` and no
architecture tooling.

**What degrades at scale:** the forbidden list stops being maintainable. Every new way to reach the
network is a new name, and the list is always one library behind. Teams that hit this invert the rule —
an **allowlist** of what the agent package may import, rather than a denylist of what it may not, for
the same reason Day 40's
[1.1](../../../day-40-filtering-and-allowlists/parts/01-the-list-you-agreed-to/1.1-the-list-of-things-you-thought-of.md)
gives about tools. Inverting it is more work up front and it is the version that survives.

**The failure mode that only appears with real traffic** is the transitive one. A module under `sutra/`
imports a small internal helper that itself imports `httpx`. No forbidden name appears in the audited
file, the rule passes, and the second pipe exists one hop away. Catching that means resolving the
import graph rather than reading one file's imports, which is exactly what an import-linter does and
what this fifty-line check does not.

**The review comment a senior engineer leaves:** *"This adds `httpx` to the agent package to fetch one
status page. That page is a server, or it is a tool on an existing server. As written it is a hole in
the only line we have, and the next person will widen it because you set the precedent."*

**The interview question:** *"You say your agent has a data boundary — how do you know it still does?"*
The honest spoken answer: *"With a check in the build that parses every module on the agent side and
fails if any of them imports a database driver or an HTTP client. The exemption is one package — the
MCP client — and it's expressed as a path, so adding a second exempt file means moving it there, which
is a conversation instead of a diff. The honest limit is that it reads one file's imports, so a helper
two hops away that reaches out is invisible to it; at a certain size you replace it with a real import
contract between layers. But the cheap version catches the failure that actually happens, which is
somebody adding a direct read at six o'clock on a Friday because the proper route was one import away
and the shortcut was zero."*
