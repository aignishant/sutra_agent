# 4.3 — Testing that a hook returns `None`

## One-line answer

A recorder must observe and change nothing, and since `on_event_callback` is declared
`-> Optional[Event]` the framework will happily use whatever it returns — so the assertion that keeps a
logger from rewriting the record is `assert returned is None`, and it is the only one that can.

## The story

The invigilator in the exam hall walks up and down the rows and does not answer questions.

A boy in the third row puts his hand up and asks what the word "aggregate" means. She says she cannot
help with that. She is not being unkind; the whole value of her presence depends on her not
participating. She checks the clock, counts the papers, notices the girl at the back who has run out
of ink and gives her a pen — and that is the line, because a pen is not an answer.

If she leaned over one desk and clarified one word, the paper from that desk would no longer be
comparable with the others. Nobody would find out. The paper would be marked and the mark would go on
a certificate, and the only thing that changed was that the record now describes a different exam from
the one that happened.

## The idea in plain language

[Day 22](../../../day-22-structured-logging/LESSON.md) added a `Flight` recorder to Sutra: a plugin
whose hooks write one JSON line per happening. Its job is to produce a record of the run, and its
absolute requirement is that the run it records is the run that occurred.

Now put that next to [4.1](4.1-the-return-value-is-the-contract.md)'s rule. Verified against the
installed `google-adk` 2.7.1 on 2026-09-04, `on_event_callback` is declared:

```
on_event_callback(self, *, invocation_context: InvocationContext, event: Event) -> Optional[Event]
```

**`Optional[Event]`.** The hook is *allowed* to return an event, and if it does, that event is what gets
persisted instead of the original. The framework offers the recorder the power to rewrite the thing it
is recording, because the same hook is used by plugins that legitimately want to modify events.

So a recorder has a contract with exactly one clause: **return `None`, always.** And that clause is
invisible in the source. `return None`, a bare `return`, and falling off the end of the function all
look equally correct — and so does `return event`, which is one word longer and completely changes what
the system does.

This is why the day's tests for the recorder assert on the return value rather than on the log. A test
that checks *"a line was written"* is checking the useful half of the behaviour and missing the
dangerous half. Both matter, and they are two assertions:

```
assert returned is None      # it changed nothing
assert flight.lines == [...] # it recorded the right thing
```

The general form of the rule is worth naming, because it applies far beyond logging: **an observer is
defined by what it does not do, and only a test can express that.** Documentation says "this plugin is
read-only"; a type hint says `Optional[Event]`; a code review says "looks fine". The assertion is the
only one of the three that fails when somebody adds a return statement.

## Why Sutra needs it

Because Sutra now runs **two plugins side by side**, and the split between them was a deliberate design
decision on Day 22 that nothing currently enforces.

`plugins=[Flight(...), Policy(...)]` — a recorder and a policy, kept as two objects rather than one,
because *a recorder that can decide can corrupt the record of what was decided*. That sentence is the
architecture. It is currently protected by the fact that whoever wrote `Flight` did not put a return
statement in it.

Somebody will. The most likely route is entirely reasonable: a future day wants the recorder to redact
a field before the event is persisted — which is a genuine requirement, and Day 22's leak part is why —
and the shortest path is to modify the event in `on_event_callback` and return it. At that moment
`Flight` stops being a recorder, and nothing anywhere reports it. The test in this part is the thing
that turns that into a conversation instead of a silent change of architecture.

## The mechanism

The recorder, and the two assertions that hold it to its job.

```python
# days/day-23-testing-tools-and-callbacks/lab/hooks_demo.py
class Flight:
    """Day 22's recorder. It watches and writes a line; it must never change anything."""

    def __init__(self) -> None:
        self.lines: list[dict[str, object]] = []

    async def on_event_callback(self, *, invocation_context: object, event: object) -> None:
        """Declared `-> None` on purpose: returning an Event here would rewrite the record."""
        self.lines.append({"event": "event", "author": event.author})
        return None
```

**Line by line:**

- The return annotation is **`-> None`**, narrower than ADK's `-> Optional[Event]`. That is deliberate
  and it is a design statement: ADK permits a return, this class does not. Python does not enforce
  annotations at runtime, so the annotation is a promise to readers and to static tools, and the test
  below is what enforces it.
- `self.lines` is a list on the instance, built in `__init__`. A class-level list would be shared by
  every `Flight` ever constructed, so a second test would see the first test's lines — the same trap as
  `SpyKb` in [1.4](../01-where-the-line-falls/1.4-four-doubles.md).
- `event.author` is the only thing read off the event. It answers *who produced this* — the agent, the
  user, a tool — which is the field that makes a log line correlatable to a participant. The double in
  the test therefore needs exactly one attribute.
- The hook **appends and returns**. Two statements, and the second one is the whole contract. Deleting
  it would change nothing today, because falling off the end returns `None` too — which is precisely
  why writing it is worth the line: it makes the contract something a reader can see and a reviewer can
  discuss.
- No `try`/`except` around the append. If recording fails the run should fail, because a run whose
  record silently did not happen is worse than a run that stopped. That is
  [22.4.3](../../../day-22-structured-logging/parts/04-in-production/4.3-testing-that-you-logged.md)'s
  argument in the other direction, and the two are reconciled by the size of the operation: appending
  to a list cannot fail in a way worth handling.

```python
# days/day-23-testing-tools-and-callbacks/lab/test_hooks_demo.py
@dataclass
class FakeEvent:
    """An Event double, for the recorder that only reads the author."""

    author: str


def test_the_recorder_writes_a_line_and_returns_none() -> None:
    flight = Flight()
    returned = asyncio.run(
        flight.on_event_callback(invocation_context=None, event=FakeEvent("desk"))
    )
    assert returned is None, "on_event_callback returning an Event rewrites what gets persisted"
    assert flight.lines == [{"event": "event", "author": "desk"}]
```

**Line by line:**

- `FakeEvent` is a one-field dataclass. ADK's real `Event` is a pydantic model with a long list of
  fields — content, actions, invocation id, branch, timestamp — and constructing a valid one for a test
  about a list append would be work in service of nothing.
- `invocation_context=None` is a dummy again: the hook does not touch it, so passing `None` means any
  future use of it fails loudly rather than silently working against a half-built double.
- `returned = asyncio.run(...)` **captures** the return value into a name. That sounds obvious and it is
  the thing people skip — `asyncio.run(flight.on_event_callback(...))` on its own line runs the hook,
  discards what it returned, and the test then asserts only on the lines. Half the contract, silently
  untested.
- `assert returned is None` comes **first**, before the assertion about the recording. Ordering matters
  in a test the same way it does in a story: the most dangerous claim goes first, so a failure reports
  it rather than reporting a mismatched list.
- The message says what the consequence is — *rewrites what gets persisted* — rather than restating the
  assertion. A future reader who has just added `return event` needs to know what that does, not that
  a test expected `None`.
- `assert flight.lines == [...]` compares the **whole list**, which asserts three things at once: that
  a line was recorded, that it has the right content, and that exactly **one** was recorded. A hook
  that fired twice would pass `len(flight.lines) >= 1` and fail this.


**Line by line:**

- One test, no ADK, no key. The recorder's entire contract fits in one assertion pair.

## When it breaks

Change the last line of the hook from `return None` to `return event` — a one-word edit, the kind that
arrives in a commit titled *"redact author before persisting"* — and the assertion fires:

```text
E       AssertionError: on_event_callback returning an Event rewrites what gets persisted
E       assert FakeEvent(author='desk') is None
```

Two useful things in that output. The message explains the consequence, and `FakeEvent(author='desk')`
is readable because `FakeEvent` is a dataclass — an ordinary class would have printed
`<test_hooks_demo.FakeEvent object at 0x000001F1BCA51D80>`, which identifies nothing.

**And notice what does not fail.** `flight.lines` is still exactly right. The recording is perfect. The
only thing that changed is that the recorder is now also an editor, and no assertion about the log
could ever have seen it.

The failure that this test cannot catch is the mirror image: a hook that returns `None` correctly and
**mutates the event in place** before doing so. `event.content.parts[0].text = "[redacted]"` followed by
`return None` changes what gets persisted while satisfying every assertion on this page. Catching that
needs an assertion that the event is unchanged — comparing it against a copy taken before the call —
and it is the reason the strongest form of this rule is not "return `None`" but "**a recorder receives
no mutable reference it is allowed to touch**", which is a design constraint rather than a test.

## In production

**Every observer in a system gets this test, not just loggers.** Metrics collectors, tracers, audit
plugins, request-id stampers: anything whose purpose is to watch. The assertion is always the same
shape and always cheap, and the alternative is a class of bug that is undetectable from the outside
because the system's own record agrees with the corruption.

**What changes at scale** is that the observer stops being cheap. A recorder that appends to a list is
free; one that writes to a file, sends to a collector, or serialises a large event is on the hot path of
**every event in every invocation**. The production version buffers and flushes on a timer, or hands
off to a queue — and at that point the failure mode changes from "corrupted the record" to "dropped it
under load", which is a different test: fill the buffer, assert nothing was lost.

**The failure that only appears with real traffic** is the observer that raises on an unusual event.
`event.author` is always present; `event.content.parts[0].text` is not, and a recorder that reaches for
it crashes the first time an event arrives with no parts — a function call, a state-delta-only event,
a compaction summary. Because the recorder sits on every event, one unusual shape takes down every
invocation. The defence is a parametrized test over the event shapes the system actually produces,
which is the [2.4](../02-pytest-house-rules/2.4-parametrize.md) pattern pointed at a real inventory.

**The review comment a senior engineer leaves:** *"this test asserts the line was written but throws
away the return value. Capture it and assert it's `None` — otherwise nothing stops this plugin from
starting to rewrite events."*

**The interview question:** *"you have a plugin that logs every event. What do you test about it?"* The
answer that shows you have read the framework's signatures: *"that it returns `None`. The hook is typed
to allow returning a modified event, so a logger that returns one silently changes what gets persisted
— and every assertion about the log file still passes. Then the ordinary half: that the right line was
written, exactly once."*
