# 2.3 — Fixtures: the arrange step, named and handed out fresh

## One-line answer

A fixture is the *arrange* step given a name and requested by writing that name as a parameter, and
its **scope** decides whether each test gets its own — three tests asking for a function-scoped
fixture built it three times, while four tests asking for a module-scoped one shared a single object.

## The story

The hotel corridor has fourteen doors and one trolley.

Between one guest leaving and the next arriving, somebody goes into the room and puts it back to a
known state. Fresh sheets, empty bin, towels folded, kettle descaled, the little card back on the
desk. It does not matter what the last guest did in there. The next guest walks into the same room
every time.

Downstairs, the lobby is not reset. The newspapers on the coffee table have been read by whoever was
there this morning, the water jug is half empty, and the sofa has a dent in it. Nobody minds, because
nothing in the lobby is supposed to be private to one guest — and cleaning it fourteen times a day
would cost more than it is worth.

Both policies are correct. They apply to different things, and the hotel had to decide which was
which.

## The idea in plain language

A **fixture** is a function that produces something a test needs, marked with `@pytest.fixture`. A
test asks for it by taking a parameter with the same name. pytest sees the parameter, finds the
fixture, runs it, and passes the result in.

That is a small mechanism with two large consequences.

**The first is naming.** The arrange step stops being three anonymous lines at the top of every test
and becomes a word: `desk_state`, `fake_context`, `quota_ledger`. A test that reads
`def test_a_high_severity_is_recorded(desk_state):` announces what world it runs in before it does
anything at all.

**The second is freshness, and it is the one that matters.** By default a fixture has **function
scope**: it runs again for every single test that asks for it. So whatever one test writes into it
cannot possibly reach the next test — the room is cleaned between guests. This is
[1.2](../01-where-the-line-falls/1.2-fast-isolated-specific.md)'s *isolated* property, enforced by
the framework instead of by everyone remembering.

Scope is a parameter, and there are four values worth knowing:

| Scope | Built once per | Use it for |
| --- | --- | --- |
| `function` (default) | test | anything a test can write to |
| `class` | test class | shared setup inside one grouped set of tests |
| `module` | file | something expensive and read-only |
| `session` | whole run | something very expensive and read-only: a loaded model, a container |

The rule for choosing is one sentence: **widen the scope only for things no test can modify.** The
moment a shared object can be written to, the tests are coupled through it and the suite starts
passing or failing depending on the order it happens to run in — which is the hardest class of bug in
a test suite, because reproducing it means reproducing an ordering.

pytest also ships fixtures you did not write. `tmp_path` gives a fresh empty directory per test.
`capsys` captures what was printed. `monkeypatch` sets and un-sets attributes and environment
variables, undoing them afterwards. Knowing `tmp_path` exists is worth a great deal on
[Day 18](../../../day-18-artifacts-that-survive/LESSON.md)'s artifact code, because it removes every
reason to write a temporary file into the repository.

## Why Sutra needs it

Because the doubles from [1.4](../01-where-the-line-falls/1.4-four-doubles.md) are mutable, and a
mutable double shared between tests is a bug waiting for a busy afternoon.

Sutra's `FakeToolContext` ([3.2](../03-testing-tools/3.2-the-fake-tool-context.md)) has a `state`
dictionary and a `saved` list. Both get written to. If one instance is built at the top of the test
file and reused, then `test_save_note_saves_the_artifact` leaves a filename in `state`, and
`test_an_unknown_severity_does_not_touch_state` — which asserts that state is empty — fails for a
reason that has nothing to do with the code it is testing. Worse, it passes when run alone, which is
exactly how you lose an hour.

A fixture makes that impossible without anybody having to think about it, which is the only kind of
discipline that survives a project of ninety-seven days.

## The mechanism

Two counters, so the scopes are not a claim but a measurement.

```python
# days/day-23-testing-tools-and-callbacks/lab/test_fixtures_demo.py
from pathlib import Path

import pytest

BUILDS = {"per_test": 0, "per_module": 0}


@pytest.fixture
def desk_state() -> dict[str, object]:
    """A fresh state dict for one test. Default scope is `function`: one build per test."""
    BUILDS["per_test"] += 1
    return {}


@pytest.fixture(scope="module")
def shared_ledger() -> list[str]:
    """One list for the whole file. Cheap to build, and every test sees the same object."""
    BUILDS["per_module"] += 1
    return []


def test_the_first_test_writes_to_its_state(desk_state: dict[str, object]) -> None:
    desk_state["severity"] = "high"
    assert desk_state == {"severity": "high"}


def test_the_second_test_gets_a_state_the_first_one_never_touched(
    desk_state: dict[str, object],
) -> None:
    assert desk_state == {}, "a function-scoped fixture leaked between tests"


def test_the_module_fixture_is_shared_on_purpose(shared_ledger: list[str]) -> None:
    shared_ledger.append("first")
    assert shared_ledger == ["first"]


def test_and_the_next_test_can_see_what_the_last_one_wrote(shared_ledger: list[str]) -> None:
    assert shared_ledger == ["first"], "module scope is shared - that is the trade it makes"
    shared_ledger.append("second")


def test_the_build_counts_say_which_scope_did_what(desk_state: dict[str, object]) -> None:
    assert BUILDS["per_test"] == 3, BUILDS
    assert BUILDS["per_module"] == 1, BUILDS


def test_tmp_path_is_a_fixture_pytest_already_ships(tmp_path: Path) -> None:
    note = tmp_path / "note.md"
    note.write_text("KB-104 refund window is 30 days", encoding="utf-8")
    assert note.read_text(encoding="utf-8").startswith("KB-104")
```

**Line by line:**

- `@pytest.fixture` with no arguments is function scope. Writing `scope="function"` explicitly is
  allowed and most people leave it off, which is why it is worth saying out loud that **the default is
  the safe one**.
- `BUILDS` is a module-level dictionary that both fixtures increment. It is the instrument, not the
  subject: without it, "a fixture runs once per test" is something you are asked to believe rather
  than something you can see.
- `desk_state` returns a **new empty dict every call**. Returning a module-level dict instead would
  hand every test the same object and defeat the entire mechanism — which is the single most common
  fixture bug, and it looks almost identical on the page.
- The second test asserts `desk_state == {}` with a message. That assertion is the freshness proof: it
  runs *after* a test that wrote `severity` into a `desk_state`, and it sees nothing.
- `@pytest.fixture(scope="module")` builds `shared_ledger` once for the file. The fourth test asserts
  it can see what the third wrote — which is not a bug being demonstrated, it is the **trade being
  made explicit**, and the message says so.
- `test_the_build_counts_say_which_scope_did_what` asserts `3` and `1`. Three, because three tests in
  this file ask for `desk_state` — the two above it and itself. One, because the module fixture was
  built once no matter how many tests asked. Both assertions pass `BUILDS` as the message so a failure
  prints the actual counts instead of `assert 4 == 3`.
- The count `3` also makes this file **order-dependent on purpose**: it is the one test here that
  would break if you added another `desk_state` user above it. That is a deliberate demonstration of
  why counting builds is a teaching device and not a pattern to copy into real tests.
- `tmp_path: Path` is requested by name and nobody defined it — it comes from pytest itself. It is a
  fresh directory per test, cleaned up afterwards, and it is the correct answer to every "where do I
  put a test file" question.
- `encoding="utf-8"` on both calls. On Windows the default text encoding is not UTF-8, so a file
  written without it and read with it is a real, platform-specific failure — the kind that is green on
  one developer's machine and red on another's.

Measured with `pytest` 9.1.1 on 2026-09-04:

the second test saw an empty dictionary, and the fourth saw the third test's write.

## When it breaks

Ask for a fixture that does not exist and pytest tells you clearly, which is the good case:

```text
E       fixture 'desk_stat' not found
>       available fixtures: anyio_backend, anyio_backend_name, anyio_backend_options, cache, capfd, capfdbinary, caplog, capsys, capsysbinary, capteesys, doctest_namespace, free_tcp_port, free_tcp_port_factory, free_udp_port, free_udp_port_factory, monkeypatch, pytestconfig, record_property, record_testsuite_property, record_xml_attribute, recwarn, subtests, tmp_path, tmp_path_factory, tmpdir, tmpdir_factory
>       use 'pytest --fixtures [testpath]' for help on them.
```

The typo in a parameter name is not a `NameError`, because the parameter is legal Python — it is
pytest failing to resolve it, and the error lists every fixture it *does* know about. That list is
also the fastest way to discover the built-in fixtures.

The failure with no error text is the one to be afraid of: **a fixture whose scope is too wide.** It
does not raise. It produces a suite that is green when run in file order and red when run in reverse,
or in parallel, or when somebody adds a test in the middle. The symptom is always the same sentence —
*"it passes on my machine but not in CI"* — and the diagnosis is to run the suite in a shuffled order
and see whether the failure moves.

There is a third one worth naming because it looks like a fixture problem and is not:

```text
ScopeMismatch: You tried to access the function scoped fixture inner with a module scoped request object. Requesting fixture stack:
```

A wider-scoped fixture may not depend on a narrower one, because it would outlive it. The fix is to
narrow the outer fixture rather than to widen the inner one — widening is how a shared mutable object
gets created by accident.

## In production

**Shared fixtures live in `conftest.py`.** A file with that exact name makes its fixtures available to
every test file in its directory and below, with no import. That is where a project's `fake_context`,
`quota_ledger` and `sample_session` end up, and it is the reason a mature suite's individual test files
are so short.

**What changes at scale** is that session-scoped fixtures become the thing you optimise. Starting a
container, loading a model, or building a large index once per session instead of once per test is the
difference between a suite people run and one they avoid — and it is also the moment the shared-mutable
danger becomes real. The pattern that squares the circle: a session-scoped fixture builds the expensive
thing, and a function-scoped fixture wraps it and resets it, so tests get the cheap object and the
expensive one is never written to.

**The failure that only appears with real traffic** is the fixture with a side effect outside the
process — one that writes to a shared database, a shared bucket, or a fixed port. It works when one
person runs the suite and collides the moment two do, or the moment CI runs two branches at once. The
tell is a fixed name: a constant table name, a constant filename, a constant port. `tmp_path` exists
precisely so that filenames never have to be constants.

**The review comment a senior engineer leaves:** *"this fixture is module-scoped and returns a
dictionary the tests write to. Make it function-scoped, or make it frozen."*

**The interview question:** *"how do you stop tests interfering with each other?"* The answer that
sounds like experience: *"function-scoped fixtures for anything mutable, and widen the scope only for
things that are read-only. If a suite ever passes in one order and fails in another, I stop and find
the shared object rather than adding a sleep or an ordering marker, because the ordering marker just
hides it until somebody else finds it."*
