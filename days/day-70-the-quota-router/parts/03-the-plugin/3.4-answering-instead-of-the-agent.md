# 3.4 — Answering instead of the agent

## One-line answer

Twenty-four tickets through a real `InMemoryRunner`, with one `BasePlugin` registered on it, spread
across four lanes as `{'gemini': 4, 'groq': 9, 'openrouter': 11, 'ollama': 0}` and the agent's own
model running **zero** times — while the same twenty-four tickets with the plugin removed all go to
one lane whose ceiling is ten a minute.

## The story

You send the parcels for a small shop. Twenty-four go out today.

There are four courier offices on the same street, and the shop has a prepaid account with each one.
Each account has a cap on how many parcels it will take in a day. The big office takes plenty. The
one next door takes fewer. The little office at the corner, run by one person with a scooter, takes
only a handful.

Nobody has ever thought about any of this. You walk to the same office you have always walked to, and
you hand over all twenty-four, and the clerk takes them all without a word. The counter is not where
the cap is checked. The cap is checked at the depot that night, and whatever is over it comes back
the next morning with a sticker on it.

So put somebody at the shop door with the four caps written on a card. Every parcel goes past him. He
looks at the card and says which office this one goes to. The same twenty-four parcels leave the
shop, they leave through four doors instead of one, and nothing comes back.

Notice what he does *not* do. He never walks to a depot to ask anything, he never opens a parcel, and
he never overrules what is written on the card. He is one person at one door with one card, and that
is the entire intervention.

## The idea in plain language

Everything section 3 has argued is now one program.

- [3.1](3.1-where-a-router-has-to-stand.md) said the router has to be a plugin on the `Runner`,
  because that is the only place that sees every model call.
- [3.2](3.2-observe-block-answer-instead.md) said the plugin has to return an `LlmResponse`, because
  answering instead is the only outcome that can move work to another lane.
- [3.3](3.3-the-field-that-does-not-reroute.md) closed off the shortcut, so the router has to hold
  the lane objects and make the call itself.

`lab/desk.py` is those three sentences, run twenty-four times. What is real in it and what is
simulated matters, so here it is plainly. The `Agent` is a real ADK agent. The `InMemoryRunner` is a
real Runner. The plugin is a real `BasePlugin` and it is registered the way adk.dev says to register
one. The **only** simulated thing is the provider behind each lane: a `Lane` from `lab/_lane.py`
counts requests against two sliding windows and refuses with a real-shaped `429` when a window is
full, and no socket is opened anywhere.

That split is a deliberate choice rather than a convenience. This is a day about quota, and a day
about quota that spends a day's quota to demonstrate itself has failed on its own terms — Principle
15 says quota is the currency. It also buys something a live run could not give: the clock is
`lab/_lane.py`'s `Clock`, moved by hand, so the same numbers come out every time and a reader can
argue with them.

The comparison is the whole part. Same twenty-four tickets, same agent, same Runner. One plugin, or
no plugin.

## Why Sutra needs it

This is where [2.1](../02-choosing-a-lane/2.1-headroom-is-not-a-preference.md) is paid. That part
promised a measurement — *"24 tickets, all of them to the agent's own lane, against a ceiling of ten a
minute"* — and left it here, because the argument it was making could not be settled by arguing. A
preference-shaped router and a scheduling-shaped router produce the same output on one request, and
they part company somewhere between the tenth and the eleventh.

It is also Phase 10's gate in its smallest honest form. *Quota router live* means a request that goes
somewhere the agent did not name, chosen from live counters, with a refusal path when nothing is
available. Both halves of that are in one file, and the `--naked` arm is the eval that can go red,
which is Principle 11.

## The mechanism

The plugin, in full, from `lab/desk.py`. It is a method on `QuotaRouter`, so it is indented here as
it is in the file:

```python
class QuotaRouter(BasePlugin):
    async def before_model_callback(
        self, *, callback_context: CallbackContext, llm_request: LlmRequest
    ) -> LlmResponse | None:
        try:
            answer = self.router.send("classify")
        except AllDry as dry:
            self.refused += 1
            return LlmResponse(
                content=types.Content(
                    role="model", parts=[types.Part(text=f"ROUTER REFUSED: {dry}")]
                )
            )
        return LlmResponse(content=types.Content(role="model", parts=[types.Part(text=answer)]))
```

**Line by line:**

- `self.router.send("classify")` is the whole of section 2 arriving in one call: filter by
  capability, drop cold lanes, sample two, keep the one with more headroom, spend against both
  windows. The plugin does not re-implement any of that, and it should not — the routing policy is
  testable on its own in `lab/_router.py` precisely because it knows nothing about ADK.
- `"classify"` is hard-coded because this desk does one kind of work. In a real desk the skill comes
  from the agent — its name, or a field on it — and that is the one thing the agent legitimately gets
  to say. It says *what kind of work this is*, never *which provider does it*, which is
  [2.1](../02-choosing-a-lane/2.1-headroom-is-not-a-preference.md)'s division exactly.
- `except AllDry` is the refusal path. `AllDry` is raised by the router when every capable lane is
  out of headroom or cold, and catching it here rather than letting it escape is deliberate: an
  exception thrown out of a plugin hook becomes a crashed run, and "the fleet is busy" is not a
  crash. [4.3](../04-when-a-lane-says-no/4.3-every-lane-dry.md) is what that refusal has to say.
- The refusal is returned as an `LlmResponse` too, not raised. Both outcomes leave through the same
  door, because [3.2](3.2-observe-block-answer-instead.md) established that the hook's only way to
  end a call is to hand back a response object.
- `f"ROUTER REFUSED: {dry}"` puts the exception's own message into the text, and that message carries
  the per-lane waits. A refusal that says only "busy" forces the caller to guess whether to retry in
  seconds or tomorrow, which is
  [1.1](../01-what-headroom-is/1.1-a-ceiling-is-a-window-not-a-number.md)'s point about naming the
  window.
- The final line is the ordinary path, and notice what it does **not** do: it never touches
  `llm_request`. After [3.3](3.3-the-field-that-does-not-reroute.md) that is not an oversight, it is
  the finding.

Now the registration, from the same file's `main`:

```python
    agent = Agent(
        name="triage_desk",
        model=NamedLlm(model="fake/gemini", lane="gemini"),
        instruction="Classify the ticket.",
    )
    runner = InMemoryRunner(agent=agent, app_name=APP, plugins=[] if naked else [plugin])
    session = await runner.session_service.create_session(app_name=APP, user_id="learner")
```

**Line by line:**

- The `Agent` is built on `gemini` and stays built on `gemini` in both arms of the experiment. That
  is the control: nothing about the agent changes between the routed run and the naked one.
- `model=NamedLlm(...)` passes a model **object**, so the binding is the object itself — the case
  [3.3](3.3-the-field-that-does-not-reroute.md) traced through `canonical_model`. This model reports
  its own lane when it runs, which is how the run can prove it did not.
- `plugins=[...]` is a parameter of the Runner, not of the agent. adk.dev's plugins page, checked on
  2026-09-06, says to register plugins in your `Runner` class using the `plugins` parameter, and
  <https://adk.dev/plugins/> states the consequence: *"Plugin hooks are global. You register a Plugin
  once on the `Runner`, and its hooks apply universally to every Agent, Model, and Tool it manages."*
- `[] if naked else [plugin]` is the ablation switch. The entire difference between the two runs
  below is the contents of that list — one item, or none. Nothing else in the file branches on
  `naked` except the summary it prints.
- `app_name=APP` keys the session store. It is the same in both arms so that the two runs are
  comparable, and each run creates a fresh session anyway.

Run the routed arm:

```bash
cd days/day-70-the-quota-router/lab
uv run python desk.py
```

**Line by line:**

- No flag, so the plugin is in the Runner's `plugins` list and every model call is intercepted.
- The loop inside sets `clock.now = i * 1.0`, so the twenty-four tickets arrive one second apart and
  the whole run happens inside a single sixty-second window. Nothing expires; every request competes
  with every other one. That is the hard case on purpose.

Measured on 2026-09-06:

```text
24 tickets, router in the Runner

  answered              24
  router refused        0
  lanes that answered   {'gemini': 4, 'groq': 9, 'openrouter': 11, 'ollama': 0}
  the agent's own model ran 0 times
```

Now the same file with the plugin removed:

```bash
uv run python desk.py --naked
```

**Line by line:**

- `--naked` puts an empty list in `plugins=`. The agent, the model object, the Runner, the twenty-four
  tickets and the clock are untouched.

Measured on 2026-09-06:

```text
24 tickets, no router

  answered              24
  router refused        0
  lanes that answered   {'gemini': 24}

  every request went to the agent's own lane. Its ceiling is 10/min,
  and nothing in this run consulted it: the counters read {'gemini': 0, 'groq': 0, 'openrouter': 0, 'ollama': 0}.
```

**Same tickets, same agents, one plugin.** Four lanes carried the work, or one did.

Two lines deserve to be read twice.

`the agent's own model ran 0 times` is not a claim the plugin makes about itself. It is
`len(NamedLlm.answered)`, and `NamedLlm.answered` is appended to inside the fake model's own
`generate_content_async` in `lab/_fake.py`. Zero means that method never executed — twenty-four
tickets were answered and the model the agent was constructed with was never asked anything. That is
[3.2](3.2-observe-block-answer-instead.md)'s "the call to the LLM is skipped", measured from inside
the thing that was skipped.

`the counters read {'gemini': 0, ...}` in the naked arm is the more uncomfortable one. Twenty-four
requests went out and every lane's counter says nought, because in that arm nothing ever consulted
a lane. The accounting is not wrong; it does not exist.

### Why `ollama` got nothing

`ollama: 0` is the line that looks like a bug and is not one, and working out which of those it is
takes two facts from `lab/_lane.py`:

```bash
cd days/day-70-the-quota-router/lab
python -c "
from _lane import Clock, fleet

for ln in fleet(Clock(0.0)):
    print(f'{ln.name:<11} headroom={ln.headroom():<6} classify={ln.can(\"classify\")}')
"
```

**Line by line:**

- `fleet(Clock(0.0))` builds the four lanes at their Addendum 02 limits on a clock that has not
  moved, so these are the numbers the first ticket of the run saw.
- `ln.can("classify")` is the capability filter from
  [2.2](../02-choosing-a-lane/2.2-the-lane-that-cannot-do-the-job.md). It is printed first because
  incapability is the *innocent* explanation and it needs ruling out before anything else is worth
  saying.
- `ln.headroom()` is `min(minute, day)` from
  [1.1](../01-what-headroom-is/1.1-a-ceiling-is-a-window-not-a-number.md).

Measured on 2026-09-06:

```text
gemini      headroom=10     classify=True
groq        headroom=30     classify=True
openrouter  headroom=20     classify=True
ollama      headroom=6      classify=True
```

So `ollama` **can** do this work. It was never cold, never out of headroom, and never filtered out —
it was a candidate for all twenty-four requests. It simply lost every comparison it was in, and the
reason is the last line of `Router.choose` in `lab/_router.py`: `return a if a.headroom() >=
b.headroom() else b`. The policy keeps the lane with **more** headroom, `ollama` starts with the
smallest number in the fleet, and it never serves, so its number never moves while the others' do.
The only way it can win is for both random draws to land on it.

You can watch that happen — or rather, not happen:

```bash
cd days/day-70-the-quota-router/lab
python -c "
from _lane import Clock, fleet
from _router import Router

c = Clock(0.0)
r = Router(lanes=fleet(c), clock=c)
pairs = []


def traced(skill):
    opts = r.candidates(skill)
    a, b = opts[r._draw() % len(opts)], opts[r._draw() % len(opts)]
    pairs.append((a.name, b.name))
    return a if a.headroom() >= b.headroom() else b


r.choose = traced
for i in range(24):
    c.now = i * 1.0
    r.send('classify')
print('served                        :', r.spread())
print('ollama was one of the two     :', sum(1 for p in pairs if 'ollama' in p))
print('both draws landed on ollama   :', sum(1 for a, b in pairs if a == b == 'ollama'))
"
```

**Line by line:**

- `traced` is `Router.choose` with one extra line: it records the pair it sampled before applying the
  same comparison. Everything else — the draw order, the number of draws per request, the tie rule —
  is identical, which matters because `_draw()` walks a fixed sequence and taking one extra value
  would desynchronise the whole run.
- `r.choose = traced` replaces the method on the instance rather than editing `_router.py`. The lab
  file stays the file the rest of the day runs.
- `r.spread()` is printed first as the control. If it does not match `desk.py`'s spread exactly, the
  trace is describing some other run and nothing below it means anything.

Measured on 2026-09-06:

```text
served                        : {'gemini': 4, 'groq': 9, 'openrouter': 11, 'ollama': 0}
ollama was one of the two     : 8
both draws landed on ollama   : 0
```

The spread matches `desk.py` exactly, so this is the same run seen from inside. `ollama` was sampled
in eight of the twenty-four decisions and lost all eight, and the one pairing that would have let it
win never came up.

**Is that the right behaviour?** Under the policy as written, yes, and for a defensible reason:
`ollama` has the tightest ceiling in the fleet, so leaving it alone while roomier lanes have space
keeps the scarcest lane in reserve for when the others are gone. Under any wider view, no — and it is
worth being blunt about why. `ollama` is the local lane. A request to it costs nothing at all, and
its `rpm=6` is a **throughput** limit rather than an allowance that depletes. The router ranks lanes
by headroom and headroom alone, so the one lane that is genuinely free is the one it starves. That is
not a bug in the code; it is the model of the world the code was given.
[2.1](../02-choosing-a-lane/2.1-headroom-is-not-a-preference.md)'s ordering — capability, then
availability, then preference — has a third stage that this fleet never got to express, and cost
belongs in it.

## When it breaks

Read the `--naked` arm as an eval and it is the day's red alarm, which makes it worth stating exactly
what it proves and what it does not.

The assertion a team would naturally write after that run is *"all twenty-four tickets were
answered"*. It passes. `answered 24`, `router refused 0`, no exception, no error line anywhere in the
output. A CI job built on it is green.

It is green because **nothing in that arm ever consulted a ceiling**. The counters printed at the end
read zero for all four lanes, and they read zero because no lane object was involved in serving
anything. The agent's model answered directly, and the agent's model is a fake that never says no.

Put a lane's accounting behind those same twenty-four tickets and the run stops on the eleventh:

```bash
cd days/day-70-the-quota-router/lab
python -c "
from _lane import Clock, Refused, fleet

c = Clock(0.0)
gem = fleet(c)[0]
for i in range(24):
    c.now = i * 1.0
    try:
        gem.call()
    except Refused as refusal:
        print(f'ticket {i + 1} at t={c.now:.0f}s -> {refusal}')
        break
"
```

Measured on 2026-09-06:

```text
ticket 11 at t=10s -> 429 gemini: minute window exhausted, retry-after 50s
```

Twenty-four requests one second apart, against `rpm=10`, inside one sixty-second window. Ten get
through, and the eleventh is refused with fifty seconds to wait — and in the naked arm nothing in the
code path has anywhere else to go, because the model was chosen when the agent was constructed.

So the eval that can go red is not *"were the tickets answered"*. It is one of these, and a day that
ends without one of them has not built a router:

- `NamedLlm.answered` is empty — the agent's own model never ran, so the plugin really did intercept.
- `router.spread()` has more than one non-zero lane — the work was actually spread, not merely
  routed to the same place by a longer path.
- The sum of `spread()` equals the number of tickets — every request was accounted against some
  lane's windows, which is the property [5.1](../05-failure-lab/5.1-the-tally-that-counts-only-sales.md)
  breaks.

Each of those goes red the moment the plugin is removed, and the third goes red on a subtler bug
than that. "Twenty-four were answered" goes red on nothing at all.

## In production

**What changes with real providers behind the lanes.** Three things, and all of them land on the
plugin, because [3.3](3.3-the-field-that-does-not-reroute.md) put the call in its hands.

*Latency stops being uniform.* The lab's lanes answer instantly and identically, so choosing between
them is free. Real lanes differ by a lot, and a router that optimises only for headroom will happily
route a user-facing ticket to the roomiest lane at the moment that lane is also the slowest one. The
production version of `choose` filters on headroom and then breaks ties on something the fleet has
measured — which is [Day 9's benchmark](../../../day-09-four-free-providers/parts/04-the-benchmark/4.2-the-mileage-on-the-sticker.md)
finally being used for something other than a table.

*Streaming does not survive this design unchanged.* `before_model_callback` returns one `LlmResponse`,
and the run above builds it from a string the lane already produced. A streaming lane produces a
sequence, so a router that wants to keep streaming has to either buffer the whole answer before it
returns — which throws away the reason to stream — or move the interception somewhere that can yield.
Deciding which of those you are doing is a design decision, and the honest version of this day's
plugin would say in a comment that it has chosen buffering.

*The response shape differs per provider.* The lab returns a plain text part every time. Real lanes
return tool calls, structured output, refusals, and finish reasons that mean different things, and
the plugin is now the thing that has to normalise all of it into one `LlmResponse`. That is the
translation layer [Day 9's 2.1](../../../day-09-four-free-providers/parts/02-the-translator/2.1-one-charger-many-sockets.md)
described, arriving inside the router rather than around it.

**What degrades at scale.** The plugin is now on the critical path of every model call in the
process, and it holds mutable counters. At one request at a time that is free. Under concurrency it
is a shared data structure being read and written by every in-flight turn, and both of the failures
this day has already measured are waiting there: the stale snapshot of
[2.4](../02-choosing-a-lane/2.4-everyone-read-the-same-board.md) and the two-meters problem of
[3.1](3.1-where-a-router-has-to-stand.md). Neither is solved by anything in `desk.py`, and
[6.1](../06-in-production/6.1-one-till-two-cashiers.md) is where they are.

**The failure that only appears with real traffic.** The refusal path is the least-tested code in the
file. In this run `router refused 0`, so the entire `except AllDry` branch never executed — the only
arm of the plugin that will ever run during an incident is the one no measurement here exercised. The
production habit is to force it: run the fleet dry deliberately, in a test, and assert on what the
caller receives. That is [4.3](../04-when-a-lane-says-no/4.3-every-lane-dry.md), and it is not
optional.

**The review comment a senior engineer leaves:** *"The happy path is fine and the spread proves it
works. But `router refused 0` means the `AllDry` branch has never run, and that is the branch our
customers meet on a bad day. Add a case that exhausts every lane and assert on the text the caller
gets — including that it names a wait. And `ollama: 0` needs a comment: we are ranking by headroom
only, so the free local lane is the one we starve. That is a policy choice and right now it is an
accident."*

**The interview question:** *"You have a multi-provider setup. How do you know your router is
actually routing?"* An answer that has measured it: *"I made the models report their own identity and
I asserted on which one answered, not on which one was configured or requested. In my run the agent
was built on one provider and its own model ran zero times, while the plugin spread twenty-four
requests across three of four lanes. The check that matters is the ablation: I ran the identical
tickets with the plugin removed, and everything still passed — twenty-four answered, no errors —
because with no router nothing consults a ceiling at all. An eval that only asks whether the requests
succeeded goes green in exactly the case you are trying to prevent, so the assertion has to be on
the spread and on the agent's own model never running."*
